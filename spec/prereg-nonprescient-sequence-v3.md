## 1. 目标与两个差额

C5 修正后的实测：紧能量格上"能量族"候选在应用边沿就回退，黄级交付只剩 559/2016（A）、1194/3528（B），
而不看能量的固定 TTL8 拿到 849/2016、2020/3528 且 0 死亡。这个反差说明"候选失败、保护可能有代价"，
但**不能**说明保护必然牺牲多少服务。参照就是用来回答后者的。

```
可实现策略差额 = value(非预知) − value(普通)
信息差额       = value(全知)   − value(非预知)
恒等式         = 两者之和     = value(全知) − value(普通)
```

**两个差额分别计算、分别判定**：可实现差额为正本身就是结果，不因仍低于全知而被取消。

| 判定项 | 结论 |
|---|---|
| strict 口径（§3 的 α=0 端点）下无可行策略 | 报告**该口径**不可行；不说"任务不可行"、不说"物理不可行"；继续跑计价口径 |
| 计价口径下可实现差额 ≈ 0 | 普通组合已追平非预知参照：这一格无需新机制 |
| 计价口径下可实现差额 > 0 | **这是一个结果**，不论信息差额是否也为正 |
| 信息差额 ≈ 0 | 该格没有信息瓶颈：新的观测通道不是增量来源 |

## 2. "零失电"放在哪一层（这是 v2 的层级错误）

**结论：它是风险口径层的一个端点，不是任务要求。** 依据是仓库自身的来源，逐条列出并由
`task_semantics_evidence()` 写进结果文件：

| 来源 | 原文要点 | 读法 |
|---|---|---|
| `paper/zh/main.tex` 系统模型（目标函数段） | 目标函数计三项：按期交付的义务（服务）、**节点永久死亡**、以及存活超过释放时刻的状态所占资源 | 死亡是**被计价的项**，不是准入约束 |
| `paper/zh/main.tex` §执行位置决定存活 | A1 服务 0.358、死亡 4；A0 0.296、死亡 35；A0s 0.222、死亡 39 | 死亡按臂**报告**，与服务并列 |
| `results/README.md` 登记 `v3joint_r02_restart.json` | 复机后采集率 .41→.82、服务 .06→.27；**0 存活主要是吸收态产物** | 永久死亡是建模约定，有已知敏感性 |
| `results/README.md` 登记 `r47_lease_energy.json` | ".01 各被测臂 dead=40，**不能外推为全部合法稀疏策略的物理不可行**" | 仓库已有先例：不得把所测失败上升为物理不可行 |

因此 v3 把风险口径显式做成**参数层**并扫描：

* **`strict`**：声明全部未来都必须存活（α=0）。只作端点报告，`audit_seqref.py` 断言其结论带 scope 字段。
* **`priced`（主口径）**：与论文目标函数一致——服务按条计，死亡按次罚 λ：
  `value = 期望服务 − λ · 死亡概率`，并同时报告 `(服务, 死亡概率, λ)`。

λ 的单位是"条黄级义务"。论文的权重未给定，因此**报告扫描**而不是挑一个好看的取值：
`λ ∈ {0, 12, 48, 192, 768}`，其中 `λ = 48` 标为参考点。**没有为了让差额出现而回调 λ 或缩小不确定集合。**

## 3. 模型与执行语义

单节点切片，49 h 地平线，逐拍 60 s。

| 项 | 值 | 层 | 来源 |
|---|---|---|---|
| 电池容量 | **50 mWh** | E | 冻结实例 `capacity_wh` |
| 单次采样能耗 | **0.47 mWh** | E | `admission.py`；由 342 次采样合计 0.16074 Wh 逐位验证 |
| 单次上报射频 | **0.03099046 mWh** | E | 实测 0.0105677455 Wh / 341 次 |
| 小时负载（稀疏/密集） | **3.005943 / 6.011886 mWh/h** | M | = 每小时采样数 ×（采样 + 射频） |
| 采能 | `peak·f·sin(π·rel/12)/60` 每拍 | E | 与 `exogenous.solar_harvest` 同式 |
| 云遮因子均值 / 标准差 σ | **0.7375 / 0.047** | E | 实测 0.0452（280 样本）、理论 0.0462 |
| 不确定性离散化 | 等权三点，**偏移 δ = σ·√(3/2)** | M | 使实际 σ 等于声明值（v1 的错就在把 δ 当 σ） |
| 死亡判定 | 任一拍 `soc < sample_wh` | E | `network.py:_take` |
| 应用边沿 / 黄级窗口 | A：2 h、`[2,6)`；B：1 h、`[1,8)` | E | `mission_schedule`（300 s 网格，每节点 12 条/h，14 节点） |
| 共同过去 | 0..应用边沿按名义因子推进，起始满电 | A | 所有未来共享同一过去 |

**执行语义（v1 的错在这里，v2 已修，v3 保留）**：动作定义在整个地平线 `[应用边沿, 49h)`；
求值器与 DP **不接受任何终点参数**；黄级窗口终点**只用于计分**。跨隐藏终点同一策略的配置轨迹必须
逐位相同，由 `endpoint_invariance_probe` 与 `policy_window_invariance` 直接核对。

**任务表假设（必须与结论一起引用）**：黄级义务的时刻表（窗口 `[up, down)`）在 v3 里视为**公开任务表**，
因此 `priced` 口径的策略**合法地依赖它**（奖励只在窗口内计数）。这**不是**隐藏终点泄漏：
**授权终点（中心何时撤销密集配置）在本模型里根本不是决策输入**——节点只按自己的规则停止，
窗口终点仅进计分，故"隐藏授权终点改变执行"在结构上不可能发生。`strict` 口径的约束只取决于
电量与未来，其策略与窗口**无关**（由 `policy_window_invariance_strict` 断言）。若把任务表也当作
必须靠下行获得的信息，则 `priced` 口径的策略依赖需要重新论证，那是另一个信息条件，须另立口径。

**信息集与动作能力**：策略只用 `(相对小时, 量化剩余电量)`（量化 `1e-5 Wh`，状态向下取整）；
动作是"继续密集 / 终止"，终止吸收、不得重入（回传中断期间无新授权）；不含单次采样控制等新能力。
Task 1 的 `valid_until`（命令携带绝对有效期）是**另一种信息条件**，单列对照，不并入同一张比较表。

## 4. 结构限制：这是**停止**问题，不是**调度**问题（v2 的结构错误）

v2 声称给出一条"序列优化参照"，但它的精确最优其实没有序列内容。原因是一般性的：

> 奖励非负（窗口内 12、窗口外 0）、终止是吸收态且值为 0、且没有死亡代价时，
> "继续"恒弱占优于"终止"，于是精确最优**恰好等于**"只要还能安全多跑一小时就继续"的贪心可行性规则。

v3 用计价恢复取舍，并把三种情形**都**核对并写进结果（`witnesses.degeneracy`）：

| 口径 | 最优规则 | 与贪心可行性规则相同？ |
|---|---|---|
| `strict` | 贪心可行性规则 | **是**（这就是 v2 的空洞之处） |
| `priced, λ=0` | 目标对停止时刻不敏感（死亡免费）；记录到的策略取决于平手判定 | 否，但与"永不终止"也不一致 |
| `priced, λ>0` | 状态相关的停止规则 | **否**（与"永不终止"也不同） |

**同时必须说明它仍不是调度问题**：目标只数"窗口内密集小时数"，窗口内各小时彼此可替代，
所以决策问题是**最优停止**问题，不是"把有限密集预算分配到哪些小时"的调度问题。
本模型能支持的最强结论止于此；要谈调度，必须改目标（例如义务带不同权重或不同期限），
而那属于任务建模的改动，不是本参照能自行决定的事。

## 5. 三方表

| 行 | 定义 | 求解保证 |
|---|---|---|
| 普通组合 | 声明有限族内最优成员：固定租约 `ttl k`（不按窗口长度截断）、`ttl k` + 电量下限、时钟夜门、滚动预期门（开环到日落） | 逐条求值取最优；启发式 |
| 非预知参照 | 同动作族、同信息集下的**精确最优**（全地平线动作；计价口径为期望值反向递推，strict 口径为全未来安全求交 + 期望值） | 精确（在声明动作族与量化网格内） |
| 全知参照 | 逐未来取 `argmax_k (服务_k − λ·死亡_k)`，服务只计**死亡之前**落在窗口内的密集小时；再对 4000 条路径平均 | **蒙特卡洛估计，是参照不是上界** |

DP 与规则求值是两条独立代码路径，两者必须逐位一致（`selfcheck_objective_agrees`）；
核例另用**穷举可达决策格上的每一条规则**独立核对 DP。

## 6. 可手算核例（声明实例）

窗口 2 h（h2、h3）、地平线 4 h、应用边沿电量 2.5 mWh、终末保留量 2.1 mWh、量化 1e-4 Wh，
可达决策格 7 个 → 穷举 128 条规则。**核例只验证递推（strict 口径）**：DP 20.0 = 穷举最优，
最强安全固定租约 12.0（Δ=+8）。它不复现实测数值。

## 7. 截断边界（与结论同时引用）

1. **服务 = 被采集而非被投递**：实测中密集覆盖整个窗口时采集也只有 535/672、投递 283/672；
   应用边沿延迟与备份打包上限不在模型内。
2. **云遮按小时取一个因子**：逐拍抖动被抹掉。
3. **单节点切片**：不含多节点竞争、网关打包与回传。
4. **动作能力限于一次租约**。
5. **λ 是声明旋钮**：论文权重未定，因此报告扫描；引用时必须同时引用所用的 λ。
6. **strict 与 priced 的差别是本质的**：在 .012 上 strict 不可行的原因是"存在（概率极小的）
   全低未来"，而 priced 口径下该格的死亡概率约为 0。两个口径回答的是不同问题，不可互相替代。
