# 这个目录是什么，以及为什么它不再出现在正文主线

这里的材料属于一条已放弃的路线：**采用一个现成的 agent-network benchmark，只修改它的执行层**。路线放弃后，本目录不再被 `README.md` 引用，但保留下来作为过程记录，因为其中若干项仍有独立价值，且部分数字已经失效——直接引用会出错。

## 为什么放弃

原计划假定通信领域的评测对象是任务套件，于是去找"合适的 benchmark"。核对后这条前提不成立。

通读 9 篇近期 JSAC / TCOM / TWC / TMC / TVT 同域论文：用外部 benchmark 或公开数据集作评测基底的仅 **2/9**，且无一采用"公共 benchmark 加统一协议"的形式；运行第三方公开实现作对照的为 **0/9**。领域惯例是从数学描述重实现对照、用标准信道模型、报 Monte Carlo 次数，把可复现性寄托在方法与参数表的完整。JSAC / TCOM / TWC 的作者指南不含代码共享条款。方向上有更强的旁证：2025 年一篇 COMST 综述统计 130 篇同类论文，详审的 27 篇中绝大多数不共享源码，78.46% 未给可用的数据来源信息。

另一条独立的理由：纳入候选的六个 benchmark 全部是港科大或园区尺度的 5G 切片与配置类任务，与本项目的山区监测场景在物理层、能量维度与时间尺度上都不重合。采用它们换取的是"有一个 artifact 可用"，代价是场景本身。

替代方案见 `README.md` 第三节「实验范式」：自建仿真基底，各层选择与参数全部公开。

## 已失效的数字

`s6-2-physical-model-results.md` 里的数值来自两处已修正的错误，未重算：

一是自由空间损耗常数写成 `-27.55`，正确的公里与兆赫口径是 `+32.44`，两者相差 60 dB。该错误使全部地形损耗数值低 60 dB，覆盖网格的可达率由 72.3% 变为 11.5%。

二是 ChirpBox 的列误读：`node_link_matrix` 是链路质量的百分比矩阵，被当成邻接表读，得到的 7.44% 可用率是巧合产物。正确可用率为 68.75%，平均中断突发 6.38 h 而非 3.30 h。

两处修正的详情见 `docs/s4-fault-source/simulation-feasibility.md` 的「实现中修掉的错误」一节。`s6-2` 的相对结论（能量模型的影响大于信道模型；toy 假设会低估问题规模）方向可能仍然成立，但其中的倍数必须重算后才能引用。

该文件同时使用旧的 11 状态词汇（`outcome_unknown` 作为状态名），读的时候要换到现行的三维语义。
