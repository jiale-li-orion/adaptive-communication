# 数据来源与实验协议

本文件回答两个问题：论文里每个数字的来源是什么，以及凭什么算规范。它决定哪些结论可以说、哪些不能说，因此应在写代码之前定稿。

## 证据分层

每个输入归入四层之一，并在论文中标明。把不同层混在一起陈述，是这类工作最容易被审稿人打穿的地方。

| 层 | 定义 | 论文措辞 | 能否声称实测 |
|---|---|---|---|
| M · Measured | 真实观测数据 | measured / field-recorded | 能 |
| S · Standard model | 已发布的标准模型，参数按标准取 | using the standard X model | 不能，但可引用可辩护 |
| F · Fitted | 参数由真实数据估计 | fitted to [dataset] | 不能，须给出拟合方法与拟合优度 |
| A · Assumed | 本文的选择，无外部依据 | we assume | 不能，必须做敏感性分析 |

A 层参数必须扫描，不能只报一个点，否则等于把假设当结论。

### agent 与模型

模型版本层为 M，取值未定，须固定并记录，API 模型还要记录调用日期。解码参数 `temperature=0` 属 A 层，固定以保可复现。种子集未冻结，必须冻结并公开 episode 集。prompt 优先沿用已发布的 harness（例如 NetConfArena 的 ReAct prompt），以减少调参质疑。

### 场景与需求

政策依据与灾害事件记录均为 M 层，已核实文号与数字；其中十五五方案不含通信要求，通信侧只能引 256 号文。网络实测可靠性同样属 M 层，但其内容是「不存在」：到报率与在线率在公开文献中均无数值，本文给出的是估计值。合作方陈述属利益相关方陈述，是动机而非证据。

## 效力威胁

按严重性排列，每条都应在论文中主动承认并给出对策。

| 编号 | 威胁 | 严重性 | 对策 |
|---|---|---|---|
| V1 | 信道统计来自城市 LoRa 而非山区 | 最高 | 只借时间相关结构，绝对损耗用 ITM 与 DEM；做显式域偏移分析 |
| V2 | 温度基线未标定 | 高 | 用真实气象站数据标定，或全参数扫描并报区间 |
| V3 | 无任何自有实测 | 中高 | 定位为 simulation study，通信领域可接受；实证部分全部由已发表数据与标准模型支撑 |
| V4 | 故障分布为合成 | 中高 | 说明空间维来自真实地形（88.5% 死区为 ITM 计算值，地形为实测 SRTM），时间维由标准模型驱动 |
| V5 | baseline 为自实现 | 中 | 通信领域惯例即重实现，给完整实现细节并发布代码 |
| V6 | agent 为脚本驱动 | 高 | 接真实模型 |
| V7 | 种子间波动大（6 至 7393） | 中 | 报置信区间，不能只报均值 |

## 所属领域的实验规范

通信期刊（JSAC、TCOM、TWC、TMC）的惯例是重实现而非复跑他人代码。作者引用已发表算法，按数学描述自行实现，通常体现为几个 MATLAB 脚本，然后在同一组信道实现上给出对比曲线。这样做的原因是 baseline 基本不发布代码。IEEE COMST 2025 对 130 篇无线 ML 资源分配论文的调查给出了量级：只有 18 篇（13.85%）提供了可用的数据来源信息，102 篇（78.46%）完全没有说明，约 40%（52 篇）对验证环境信息不足；逐篇审计的 27 篇中绝大多数不提供源码。数据几乎总是仿真生成的，标准信道模型（3GPP TR 38.901、Rayleigh 或 Rician）加标准拓扑与参数表，引擎为 MATLAB、ns-3 或 Simu5G，结果按蒙特卡洛平均；130 篇中 128 篇用仿真，只有 5 篇用硬件。CDC 是 TCOM 与 TWC 的恰当文化类比，在这个控制与优化社区里，从方程重实现历史上被视为足够。

系统会议（MobiCom、SenSys、NSDI、CoNEXT）的要求相反，artifact 是硬指标。ACM 系统论文中声称有代码的 402 篇里实际共享 56.2%；CoNEXT 2023 接收的 30 篇中有 19 篇提交 artifact；artifact evaluation 徽章获得率为 60% Available、47% Functional、33% Reusable；MobiHoc 仿真论文在 2000 至 2005 年间的可重复率约 15%；134 篇电信政策论文中发布数据的占 33%，发布代码的占 9%；artifact evaluation 的采用率逐年停滞。

LLM-agent 子领域的期望与上述两者都不同，也与本文直接相关。在这个子领域，惯例是同时比较前沿模型与开源权重模型，两者都运行在文档化的 ReAct 或工具使用脚手架内；在公开 benchmark 上评测，或者发布自建 benchmark 并附可执行测试用例，只用 LLM judge 打分不被接受；发布 artifact 已是多数做法。

本文落在第三个子领域，因此适用其中最严的一套标准。baseline 需要重实现并公平调参，数据需要提供公开 benchmark 或自建并附可执行测试用例，模型对比需要同时覆盖前沿与开源权重，artifact 需要发布。本文的数据方案在另一方面强于该领域常规：真实地形加真实轨迹加标准模型，而常规做法是纯仿真，且 78% 的论文不说明数据来源。

## 实验协议

固定项包括地形、节点集与 episode 集（冻结并公开），标准模型与参数（ITM、温度递减率、电池特性），以及模型版本、解码参数与种子。扫描项全部属 A 层，必须报敏感性，包括温度基线与季节振幅、积雪概率、加热电池箱比例、地面电参数与 ACK 丢失率。

统计上要求不少于 10 个种子并报均值与置信区间，采用配对比较（同一 episode 集跑所有方法），并做显著性检验。

可复现要求包括发布代码、episode 集与全部超参，提供一键复现脚本，并记录模型版本与调用成本。

## 三条边界

可以说的是，本文用真实地形（SRTM）与标准传播模型（Longley–Rice）刻画空间维故障，用真实 LoRa 轨迹（ChirpBox）拟合时间相关结构。不能说测量了山区监测网络的可靠性，因为既没有自有实测，全球范围内也不存在这样的公开数据。必须写的是所有 A 层参数的敏感性分析与 V1 的域偏移分析。
