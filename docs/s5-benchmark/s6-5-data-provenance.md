# 实验规范与数据来源（Data Provenance & Experimental Protocol）

**回答两个问题**：我们论文里的每个数字**从哪来**，以及**凭什么算规范**。
本文件应在写代码之前定稿，因为它决定哪些 claim 能说、哪些不能说。

---

## 一、核心原则：四层效力，不能混用

论文里每一个输入都必须能归到下面四层之一，**并在论文里标明**。
把不同层的东西混在一起说，是这类工作最容易被审稿人打穿的地方。

| 层 | 定义 | 论文措辞 | 可否声称"实测" |
|---|---|---|---|
| **M · Measured** | 真实观测数据 | "measured" / "field-recorded" | ✅ |
| **S · Standard model** | 已发布的标准模型，参数按标准取 | "using the standard X model" | ❌ 但**可引用、可辩护** |
| **F · Fitted** | 参数由真实数据估计 | "fitted to [dataset]" | ❌ 必须给出拟合方法与拟合优度 |
| **A · Assumed** | 我们的选择，无外部依据 | "we assume" | ❌ **必须做敏感性分析** |

**关键纪律**：`A` 层参数**必须扫描**，不能只报一个点。否则等于把假设当结论。

## 三、效力威胁清单（审稿人一定会问的）

按严重性排序，**每条都要在论文里主动承认并给对策**：

| # | 威胁 | 严重性 | 对策 |
|---|---|---|---|
| **V1** | **信道统计来自城市 LoRa，不是山区** | 🔴 **最高** | 只借时间相关结构；绝对损耗用 ITM+DEM；**做显式域偏移分析**（在城市数据上训练、在山地条件下使用） |
| **V2** | **温度基线未标定** | 🔴 高 | 用真实气象站数据标定，或全参数扫描并报区间 |
| **V3** | **无任何自有实测** | 🟠 中高 | 定位为 simulation study（通信领域可接受）；**实证部分全部由已发表数据/标准模型支撑** |

## 四、这个领域的实验规范（**已用实据替换此前的印象判断**）

详见 `s6-7-experimental-norms.md`。核心事实：

### 4.1 通信期刊（JSAC/TCOM/TWC/TMC）：**重实现是标准做法，不是权宜之计**

- **惯例**：引用已发表算法 → **自己按数学描述重实现**（通常是几个 MATLAB 脚本）→ 在同一组信道实现上对比曲线
- **几乎没有人跑别人的代码**，因为**baseline 基本不发布代码**
- **硬数字**（IEEE COMST 2025 对 130 篇无线 ML 资源分配论文的调查）：
  - 只有 **18/130（13.85%）** 提供了可用的数据来源信息
  - **102/130（78.46%）** 完全没有清晰的数据来源说明
  - **~40%（52/130）** 对验证环境信息不足
  - 逐篇审计的 27 篇中，**"绝大多数不提供源码"**
- **数据几乎总是仿真生成的**：标准信道模型（**3GPP TR 38.901**、Rayleigh/Rician）+ 标准拓扑与参数表 + MATLAB / ns-3 / Simu5G + **蒙特卡洛平均**
  - 130 篇中 **128 篇用仿真，只有 5 篇用硬件**
- **文化参照**：**CDC（控制会议）是 TCOM/TWC 的恰当类比**——重实现方程历史上被视为足够

### 4.2 系统会议（MobiCom/SenSys/NSDI/CoNEXT）：**artifact 是硬要求**

| 指标 | 数值 |
|---|---|
| ACM 系统论文声称有代码的 402 篇中**实际共享** | **56.2%** |
| CoNEXT 2023 接收 30 篇，**提交 artifact** | **19 篇（63%）** |
| AE 徽章获得率 | 60% Available / 47% Functional / 33% Reusable |
| MobiHoc 仿真论文可重复率（2000–2005） | **~15%** |
| 134 篇电信政策论文：**发布数据** vs **发布代码** | **33%** vs **9%** |
| AE 采用率随年份 | **"stagnates over the years"** |

### 4.3 ⚠️ LLM-agent 子领域：**期望完全相反**

这是**与我们直接相关**的一条。在这个子领域，惯例已经变成：

1. **前沿模型 + 开源权重模型**都要比，且在**文档化的 ReAct/工具使用脚手架**内
2. 在**有名有姓的公开 benchmark** 上评测，**或者发布自己的 benchmark 并附可执行测试用例**（**不能只给 LLM judge 打分**）
3. **发布 artifact 已是多数做法**——"没有 artifact 的 benchmark 不能被称为 benchmark"

### 4.4 对号入座：我们的位置

**我们落在 4.3**，所以适用的是**更严的那套标准**，而不是 ComSoc 期刊那套宽松标准。

| 维度 | ComSoc 期刊要求 | **LLM-agent 子领域要求** | 我们的对策 |
|---|---|---|---|
| baseline | 自己重实现即可 | 同上 + **公平调参** | 重实现 + 给完整推导出处 |
| 数据 | 仿真即可 | **named benchmark 或自发布** | **自发布 benchmark + 可执行测试用例** |
| 模型对比 | 无需 | **前沿 + 开源权重都要** | 5050 跑开源权重，少量 API 跑前沿 |
| artifact | 可选 | **多数做法** | **必须发布** |

**注**：我们现在的数据方案（**真实地形 + 真实轨迹 + 标准模型**）**比该领域的常规更强**——常规是纯仿真且 78% 不说数据来源。

## 五、由此推出的实验协议（草案）

**固定项**
- 地形、节点集、episode 集（**冻结并公开**）
- 标准模型与参数（ITM、温度递减率、电池特性）
- 模型版本、解码参数、种子

**扫描项（`A` 层，必须报敏感性）**
- 温度基线与季节振幅
- 积雪概率
- 加热电池箱比例
- 地面电参数
- ACK 丢失率

**统计要求**
- ≥10 个种子；报**均值 + 置信区间**
- 配对比较（同一 episode 集跑所有方法）
- 显著性检验

**可复现要求**
- 发布代码 + episode 集 + 全部超参
- 提供一键复现脚本
- 记录 LLM 版本与调用成本（token 数）

## 六、现在就能确定的三条边界

1. **可以说**："我们用真实地形（SRTM）与标准传播模型（Longley–Rice）刻画空间维故障，用真实 LoRa 轨迹（ChirpBox）拟合时间相关结构。"
2. **不能说**："我们测量了山区监测网络的可靠性。"（**没有实测，且全球没有这样的公开数据**）
3. **必须写**：所有 `A` 层参数的敏感性分析；以及 V1 的域偏移分析。
