# Task Contract v1.1：灾前山区监测服务连续性

日期：2026-09-13。**正式设计决策：任务结构与证据边界生效；可发布 benchmark 实例尚未封版。** 本文修订 `e8d2eca` 的 [v1](task-contract-v1.md)，保留其历史正文，取代其关于中心必需性、G5 新颖性、证据强度和冻结范围的判断。旧代码尚未迁移，不得把旧结果改名为 v1.1 结果。

## 1. 决策与任务定义

> 给定灾前监测站的角色与设备能力、外生环境事件／监测要求、供能过程以及接入和回传条件，监测系统应持续提供周期测值，捕获来源支持的异常事件观测，并将有效数据送到中心。在通信中断期间，已采数据按声明的存储能力保留；恢复后继续服务当前数据并恢复历史完整性。各方法共享业务义务、硬件、本地自治能力与环境输入，依据其实际收到的证据选择合法动作。分别评价采集、中心数据新鲜度、事件交付、恢复和资源消耗。

这是**监测服务任务**。不训练滑坡预测器，不把降雨触发称为已判定滑坡危险，不把数据到达解释为告警准确率或减灾成效。目标部署的全部评测区间应止于已知灾害发生之前；若来源未给出灾害时间边界，只能称“隐患点监测案例”，不能声称完成了灾前时段标注。

本轮确定：

1. 接受周期服务、外生事件、分离采样／上传、供电与通信约束、分列评价。
2. 采用 Wang 的已发表事件片段作为**来源校验实例**；不把它冒充完整公开 benchmark。
3. 保留现场自治。**任务有效性不以中心或 agent 必需为条件。** 中心介入的增量是待检验命题。
4. 全局能源分配、跨节点升级、显式按区间补传和备用路径控制进入有条件扩展，不作为核心任务成立的前提。
5. 恢复方法实验前，先完成 §11 的实例、接口和评价封版。任何新方法对照不追认现有 toy 负载为目标任务。

## 2. 证据怎样进入规格

沿用 E/A/M 分层，补上取证深度，二者分别登记：

- **E：来源事实**，注明具体地点／设备／文献、章节及全文或摘要；同一来源的能力不能默认转移到另一设备。
- **A：研究选择**，允许存在，明确选择理由、替代设置与结论的适用域。A 不得改标为合作方 SLA。
- **M：本项目输出**，绑定代码、参数与数据版本；传播模型的数值属于模型输出，不能因 DEM 真实而称射频实测。

S0 是用户转述的合作方需求，足以约束问题范围，尚不提供设备／SLA 数值。S1 提供现场服务形状；S2 提供特定设备协议能力；S3/S4 提供扰动存在的证据；S5 提供恢复／采集的产品能力。P1/P3 提供采样—传输与外生更新的形式化先例。**这些来源共同支持一个研究参考任务，不代表它们描述同一套现网。**

## 3. 来源校验实例与目标参考部署

| 实例 | 已确定内容 | 允许的用途 | 未获支持的外推 |
|---|---|---|---|
| **S1 校验实例** | 原文角色；EI01 上的公开降雨事件片段；本地触发 | 核对事件展开、角色、时间戳及测量语义 | 单靠该片段论证 Class A 下行竞争、跨节点升级或完整降雨分布 |
| **目标参考部署 A** | 现场传感器—网关—中心；固定已部署硬件；本地事件检测与缓存；接入采用 Class A 的假设需单列 | 在明确假设下研究端到端监测服务 | 声称复现 Wang MAC、重庆 NB-IoT 系统或中通服现网 |

S1 校验实例按原角色保留网关上的雨量计。目标参考部署若将雨量计放在叶节点，登记为 A，并分别报告事件在网关／叶节点的结果；不可用角色迁移暗中增加控制路径依赖。该 A 实例属于来源支持的工作负载移植，不属于实地部署复现。

5 台角色结构只限定 S1 实例。规模变化记录传感器数、网关数、测项、位置与拓扑，禁止用一个总数混合终端和网关。16 或32均可作为 A 规模；“关键测点”需要传感角色或地质布点依据，未确认时不得默认任意8点拥有特殊业务权重。各节点数据原则上不可互相替代；若允许坡面组内替代，另给物理或业务依据。

Class A 窗口规则沿用 [机会模型](../s6-model/downlink-opportunity.md)，它不等于全网统一的一个报文配额。分别计量终端窗口、网关空口／收发约束和 WAN 服务能力；时段总供给有余不能排除某个节点截止前缺机会。频段、载荷、SF、确认方式与接收窗口设置必须由设备配置绑定，不能混用中国部署与其他地区占空比规定。

## 4. 外生过程、业务义务和信息边界

每个实例包含三个分离对象：

1. **环境真值** `X(t)`：原始传感流或明确标为合成的过程、供能／温度输入、接入／回传条件；只供模拟器与评分器访问。
2. **业务义务** `D`：周期要求，以及由固定外部规则从 `X(t)` 或已记录事件生成的观测要求；包含测项、对象、释放时刻、采集时间范围、来源标识。策略不能删除义务、改变事件阈值来缩小分母。
3. **可见历史** `O_i(t)`：该执行位置截至 t 真正收到的样本、配置报告、回执与超时；每项带生成／采集和接收时间、来源、单位及有效性。策略动作取决于 `O_i(t)`，不读取完整未来事件日程。

**外生义务与观测驱动决策可以并存。** 不再采用“需求必须内生”作为有效性条件。目标事件可以对所有方法相同，某方法因失电未检测到事件仍保留该项义务；不能因没有看到事件而免于评分。事件的原始发生、设备检测、中心获知分别计时。

本地节点在可供电时按共享规则检测事件，中心通过实际路径获知它。上层平台发布的外部指令是另一种来源，应有明确的发布端与到达时刻；不得把现场尚未上传的异常作为中心即时公告。

若评估从数值推导事件或基于读数作决策，`Sample` 必须包含读数、单位、采集时间、质量标记。只有时间戳的模型可以评价投递／AoI，却不能支撑值驱动决策、物理失真或 AoII 结论。事件片段校验可不重构连续 `X(t)`，但应标明只输入已发表事件标记。

## 5. 核心服务及时间尺度

### 5.1 周期服务

以 S1 的 1 h 定时回传作为一个来源支持的配置。它不规定常态采样必为1 h；采样间隔、设备时钟相位、测值有效期单独登记。保持周期观测要求独立于策略配置：策略把上报周期改长不能减少应服务的业务义务。

每个周期请求得到该对象／测项的一份有效测值。理想的单点采样时刻或容差属于 A，需随实例发布。仅心跳、旧样本重传、单纯设置回复均不算新测值。事件与常态义务重叠时，同一合格样本可满足两类服务，但两类分母和结果分别报告，不能加总成一个覆盖分数。

### 5.2 事件服务

S1 降雨配置采用：一次有效触发启动三次观测，首个时刻为触发时刻，其后名义间隔300 s；再次触发的合并规则见 S1。这里的三次是三个采集／回传事件，**不是每次三包**。实际无线帧数由载荷、分包、重传及协议决定。

两种实例明确区分：

- **公开片段校验**：使用 [Table 3 摘录](task-design/wang-2022-table3-excerpt.csv) 的实际时刻和原始字段含义；其中传输时刻不能当作中心接收时刻或独立采样真值。
- **规则实例**：从给定触发生成 `t, t+300, t+600` 的名义采集义务，并显式选择采样容差。这个理想化属于 A，不宣称原站逐秒复现。

0.2 mm 的累计／增量窗口尚未完整恢复。现阶段允许回放公开触发标记；禁止由日雨量或任意插值序列自造高频阈值触发并称真实事件。三个观测名额分别匹配不同样本；相同样本重发不能占满三个名额；匹配仅使用原始采集时间与质量，不使用方法名称或声明。

该任务不要求中心为每次事件发出 W1 或配置写入。本地采样加自动回传满足义务时同样记成功。位移秒级突发暂不进入核心实例；若后续采用，采样时标与无线发送约束分开定义并验证可实现性。

### 5.3 中断与恢复

无线中断而节点仍有电时，继续按现场规则采样，数据进入声明的持久／易失缓存。失电期间不产生实际样本，既有记录是否保留由设备存储能力决定；恢复后不能按旧时间补造当时未采到的读数。

系统允许已有的自动补发（S5），并评价历史恢复。中心的 `upload_records(range,cursor,budget)` 不作为核心任务必需动作。缓存容量、溢出策略、记录保留和恢复后的队列策略属于须公开的设备／研究配置，不假定无限缓存。

72 h 可保留作 A 开发时域，不由 S2 的接入测试证明其业务代表性。短片段不可静默循环成72 h，也不能用于证明跨季节能源可持续性。片段外无数据应标缺测，不能解释为无降雨；完整实例另选连续窗口并声明预热和尾部观察期。

## 6. 动作能力与安全语义

动作是方法可选的实现手段，评分奖励服务结果。下表中的“可用”不意味着必须调用或默认成功。

| 动作／能力 | 核心处置 | 执行与证据要求 |
|---|---|---|
| 被动状态上报、中心缓存读取 | 保留；S2/S5 | 缓存带源时间与接收时间；无额外下行不等于状态实时准确；传输与载荷仍计费 |
| `set_report_period` / `set_sampling_interval` | 可选远程能力，采用前绑定适用型号；S2 | 两个独立字段；读回状态与回复相关性明确；不默认原子提交 |
| `set_monitoring_profile` | 便利包装 | 展开为底层真实命令并计费；若要求原子生效，需要另有实现与证据 |
| 主动 `read_status` / `request_measurement` | 按设备能力开放；S1 查询机制或 S5 可支撑部分能力 | 状态读取与新采集分开；当前测值须有采集时间；不能把 UI 能显示电量推成免费远程 RPC |
| 自动缓存与补发 | 核心恢复能力，S5＋A 存储配置 | 所有基线共享；保持样本身份和原始时间，发送确认和中心收存分开 |
| 显式范围／游标／预算补传 | 扩展 | 需确切协议／适配器及存储语义；禁止把自动补发能力当作该 API 的原文定义 |
| 告警阈值修改 | 核心评价期间禁止改变业务触发判据 | 厂商允许配置阈值不意味着方法可以重定义评分事件；若作为动作另设外部固定评价真值 |
| relay / WAN 切换、重启 | 扩展 | 声明预部署硬件、实际覆盖、控制到达路径、切换能耗与数据后果 |

**S2 的一项附带行为应进入适配器核查**：某类设备回复上报周期设置后还会上报一条监测数据。因此不能先假定“改配置”和“获取数据”必需两个独立下行；也不能反向假定该上报一定是回复后新采的测值。

序列号、持久去重、版本 fencing、TTL、原子配置属于不同能力。字段出处不证明全部能力具备。每个实例公开远端能力矩阵，各方法享有同一能力及持久化条件；不能仅给本文端侧保护，再归因为 runtime 优势。正确性宣告必须来自方法可见证据；评分器独立读取实际效果核对，不能由模拟器替所有方法宣告成功。

## 7. 观测与控制共享路径的精确定义

对于目标参考部署，关于叶节点的遥测、查询回复和控制消息都经声明的接入与回传；没有未申明的健康旁路。网络可以非对称：同一物理路径不意味着上／下行同一成功率、同一发送时刻或同一资源桶。读写是否竞争、竞争多少，须由报文与机会账本证明。

被动遥测是合法证据。其延迟、丢失和陈旧性足以使信息不完整，不强制主动查询来“开启 G5”。无电与丢回复可能产生相同的历史，但中心关于自身连接、网关本地状态的合法知识应保留；可辨识性以具体执行位置和观测历史为准。

该条件登记为**部署假设及解释变量**，不宣称唯一或首次。是否构成新颖性须单独核对部分可观测控制、带不可靠反馈的监测、设备管理及 agent benchmark；α³-Bench 等待读条目不阻塞本任务的现场事实核验，但阻塞相应“首次／未被覆盖”的主张。

## 8. 扰动与能源约束

核心条件覆盖：能源充足且链路可用的参考组、能源不足、接入不可达、回传不可达，以及有依据或标为 A 的联合扰动。正常参考组允许约束不紧；不通过调参保证某方法获胜。

- **供能不足**由采集／待机／发射／接收／启动开销与电池、采能共同产生。方法共用初始电池、外生天气／采能和设备成本，电量与死亡时刻可以因动作不同而变化，不能强行共用预先生成的存活序列。
- **节点电池、网关电源、WAN 能源分别建账**。各电池的能量不可任意互相转移；“全局电量预算”必须说明实际共享资源或管理约束，不能凭全网电量求和虚构可调度资源。
- **低温限制绑定器件**。合作方的供电不足不能被固定翻译成某一种电池的冬季充电阈值。
- **链路按段、方向、时间及恢复过程定义**。上海 ChirpBox 的轨迹可用于迁移／压力研究，不能直接声称西藏分布；秒／分钟事件不能凭粗采样轨迹补出同精度无线真值。
- 外生环境在配对运行中一致；天气同时影响降雨和能源时，应保留可用的相关性。将异地雨量、链路、电源独立拼接，只能称解耦的诊断实例。
- 六类操作故障属于附加语义诊断，不由“山区会断网”直接证明其概率。记录命中、有效危险交错、被拒绝／过期和业务损害；不得按方法不同反复挑故障，直到它变成有害交错。

报告每节点／每时段实际需求、资源供给、用量与失败归因。总利用率、节点存活数或错误次数单列都不能证明约束有效或无效。

## 9. 评分契约

不设大一统加权分数。周期、事件、恢复分开，效果与成本并列。阈值曲线中的阈值均称研究容忍时延，未获业务来源不得称 SLA。

| 层次 | 主量与计算规则 | 防止失真 |
|---|---|---|
| 周期新鲜度 | 中心 AoI：`t - max(taken_at of valid arrived samples)`；时间平均及尾部；每周期有效观测的交付曲线 | 心跳不刷新测值 AoI；晚到旧记录不使最新时间倒退；不同测项分列 |
| 周期完整性 | 固定周期义务中已采与已收到的比例；给定观察宽限的缺报曲线 | 不能按方法实际生成数量作主分母；不采样不能改善得分 |
| 事件采集／交付 | 每事件已匹配的独立观测数／3；首份新观测到中心时延；三份全部到齐时延 | 未采、未到达保留在分母；未完成标右删失，不只报告成功样本平均时延 |
| 事件时效 | 分别报告从源触发至中心获知事件、源触发至首份新数据、中心获知后至交付的时间 | 区分发现慢与服务慢；用成功 CDF `Pr(L≤d)`，未完成不消失 |
| 历史恢复 | 固定恢复观察期末，对原有义务的采集缺失和交付缺失分别报告 | 已采记录补回不能弥补失电时未采；方法自产缓存的清空率只作辅助指标 |
| 配置正确性 | 仅对有明确外部配置要求的区间积分错配时长；记录错误宣告、重复／陈旧效果 | 自主选定的优化配置没有外部唯一正确值时，不将其偏离预置 profile 计为错误 |
| 能源 | 节点／网关分别报告 Wh、电池轨迹、能源不足时间、服务产出 | 不以包数代替能量；不得用方法特有权重折算收益 |
| 通信 | 上下行帧、重传、载荷字节、空口时间、窗口占用、WAN流量分列 | 查询请求／回复、设置附带上报与链路层确认均归账；同报文搭载只计一次 |

周期缺报在有限时域必须给定观察截止；它不是无 deadline 指标。默认报告随观察宽限变化的曲线，而非偷选一个固定10／90 min 门槛。事件时效可按300 s 等来源节奏归一展示，但倍数不等于现场要求。

所有方法采用相同初始化。冷启动未获任何测值的区间单列“尚无观测时长”；AoI 不得默认为0。若采用共同初始样本计算有限 AoI，声明为 A 初始条件，另报冷启动。区间末尾采用固定尾部观察期，期末仍未交付标删失；不能无限等待后将历史补回算按时完成。

## 10. 基线、可辨识性与论文学术边界

最低比较集合包括：现场阈值自治＋缓存／自动补发；同设备能力的成熟影子＋持久状态＋合理固定优先级／截止时间调度；适用于所选任务的简单新鲜度／队列策略；本文 runtime 及明确作用对象的消融。各方法共享现场自治，不能只让对手依赖中心批准本地采样。

同能力条件下全网调度可以由网关或分布式规则承担。**协议有远程设置字段，不能证明只能由中心执行某项工作。** 若比较控制位置，把位置、观测延迟和资源差异作为架构变量报告。

任务复杂性要通过具体的合法决策对证明：同一业务义务下，收到不同证据是否改变一个可行行动的后果；差异是否来自资源／信息约束。无法构成这类决策不否定监测业务存在，但限制该实例用于 agent 决策研究。也不能把“本地规则获胜”解释为设计失败，再为本文追加义务。

一个公开事件片段乘20个信道种子，只有一个业务来源场景。训练／开发／测试按原始站点、连续时段或事件簇拆分；同场雨的三个观测不作为三个独立样本估计置信区间。配对比较共享实例；方法或参数选择后才使用保留场景。若只有单个公开片段，只报告案例级诊断，不认领跨站泛化。

旧配置负载上的数值保留为该实例的工程／机制结果；其正负结论不能移植到 v1.1。若新任务上成熟基线追平，按事实报告；任务真实性与本文独有收益分开判定。顶刊先例支持形式化建模，不能担保本文新颖性或可发表性。

## 12. 待合作方确认的扩展

每个扩展按“工作流事实—接口—部署位置—时效／资源约束”四项确认；仅口头表示某功能有用，不能补全其余三项。

1. **跨节点升级**：何种观测触发哪些测点、由谁作决定、既有本地／网关联动能否完成、响应要求如何定义。
2. **全局约束**：实际共享的是 WAN 额度、网关空口、总运维成本还是站点能源？独立电池不能互相借电；已有规则是否已经分配预算。
3. **历史恢复**：哪些记录必须保留多久；自动补发是否已有；中心是否真有显式区间／游标控制，能否取得协议。
4. **备用路径**：目标站点已有还是待建设；覆盖、供电和控制路径是否独立；启用代价与合法权限。

未确认的扩展不进入主任务的必需义务。中心发送频率仍无现场日志支撑；未来从已获支持的任务中计算出的命令数应称“模型内策略输出”，不当作实测命令率或最优下界。
