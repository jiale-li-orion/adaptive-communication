# doc38 — 审查 doubao 的 R20、任务变更与 Agent 交接

日期：2026-09-16；基点 `6f14e3a`。核查 doc34–37、相关实现、R20 三份 JSON、Git 历史与用户提供的执行报告。**本轮未重跑 R20/R22，未运行新 LLM、未实现候选；R20 数字核对到落盘文件，R22 数字引用报告，实验结构由脚本确认。**

2026-09-18 续审收尾：仓库基点未变化；另做了两个不运行仿真主循环的函数级见证，见 §3–4。此次修改限于研究记录与状态指针。

**判定：接受采用普通 maxcov 工具；任务变更骨架可用，但信息与评分语义待闭合；不接受 doc37 的结构性 NO-GO/普通 MPC 已最优。允许准备和探索少量真实 Agent 轨迹，先纠正观测/评分边界，暂不冻结 A1 全机制、不可兑现金标准或论文贡献。**

## 1. 已经成立的进展

- R15/R16 的分发问题及 R17 的连接键问题已经针对性修复。统一引擎中变体真实可达，新增行为见证与稳定 `oid` 配对，采用最强普通工具的决定合理。
- R20 主表中，r600/78 的 `maxcov=.9285 > cover=.9087`，r900/78 为 `.7727 > .6984`；r1200/200 则 `cover2=.9532 > maxcov=.9216`。保留种子及 .95 丢包文件与报告对应。这是**已比较实现里的相对结果**，没有最优性证明。
- 分段义务由外部 schedule 生成，保留旧窗口、独立于策略输出，方向符合 doc33。标准对变更权限与具体数值的 E/A 区分应保留。
- `dayfeed` 提供了存活与服务的一个普通工作点。不能把其全部行为当作物理可行域，但不需要为了做 Agent 实验先发明新的数值优化器。

## 2. doc37 的 NO-GO 没有被这些实验推出

`r22_ceiling.py` 的所有运行都固定 `mission_mode="dayfeed"`，只改变中断、接入/回传成功率和备用容量。它检验的是**同一策略在放宽通信条件后的结果**。`.718` 既不是控制变量联合最优，也不是采集物理上界。

三个推理不能成立：

1. **不死 ≠ 采集需求已满足。** doc36/37 的错位主口径为缺采 2588，完美链路档为 2136。“0 死亡、缺采 0”来自被报告自身判为边界双配的对齐条件，不能拼接到错位主表。
2. **包用满 ≠ 服务可改善空间为零。** 固定传输条数仍可能携带不同期限、不同有效义务的候选；R20 本身就是改变内容后相同资源得到不同服务的例子。候选总量过剩也不证明每一条重要义务都有及时候选。
3. **最强已测贪心 ≠ 最优；现有规则失败 ≠ 问题不可解。** R20 未证明 maxcov 单包或跨机会最优；doc36 也明确未接完整滚动 MPC、未测 oracle、未做 H2。不能在下一份文档把这些缺项改写成“普通规则/MPC 已最优”。

同样，FIFO/端到端 ACK 条件下 `heard_on_time=0` 是当前缓存/发送机制产生的结果，不是射频接入机会等于零。若队列纪律固定，可作为该部署配置的限制；不得直接泛化为任意控制下的物理不可达。

**当前可写：** 已找到一条避免死亡的普通规则，仍有采集与交付缺口；跨层优化是否能减少缺口未完成判别。研究上可决定暂停数值优化投入，同时保留这个未知。它不等于“联合空间被封死”，也不满足 doc33 原先“强对照已覆盖”的实验关闭条件。

## 3. 接 Agent 前优先闭合的信息边界

`joint_run.py:101–107` 从完整未来 `mission_schedule` 构造所有义务；`:156–162` 将这份集合直接交给现场 `JointControlPlane`；`joint_plane.py:63–65` 初始化 `_obl_index`。网关 `_sample_obl()`/maxcov 据此使用变更后的义务和期限，**没有任务更新经过中断链路的接收事件**。

固定、预装任务下这可以是合法公开配置。改成“h6 中心才获知的新授权，h4–20 回传中断”后，就必须区分两种实例：

- **预告/预装变更**：完整 schedule 事先告知网关，则普通网关条件执行也应获得同样信息与能力。不能以中心直到 h20 才能送命令作为所有策略的必然限制。
- **运行中新增授权**：中心在事件到达后才知道内容，网关只在任务更新真正收到后更新本地义务视图。独立 scorer 仍可持有完整真值；执行器不可直接查它。网关在收到更新前继续执行旧任务，不自动记为 Agent 错误。

继续 doc35 的在线变更叙事时，推荐第二种。逐项记录：`issued_at`、`center_received_at`、`gateway_received_at`、`node_applied_at`；无法送达则保留未知/未到达，不让方法生成一个伪完成时间。现场事件自治照常保留。

验收采用非预知性检查：两次运行只改变尚未通知的任务内容，在某执行位置收到通知前，若其合法观测历史相同，其决策也应相同（随机策略共享随机数）。这比声明“各臂都给了同样真值”更能保证信息边界。

新任务改变网关义务表如何下发、何时生效、消耗什么资源，都要记账。新能力若需要扩展协议，先登记扩展；不能让本文额外获得即时任务同步。

函数级见证：对相同的 `n00/displacement` 样本 `taken_at=22200`，保持周期600的义务表使 `_sample_obl()` 返回最紧截止22800；预装在21750时变为周期300的完整表时，返回22650。两次都没有发生任务消息接收。这证明未经接收的任务内容能进入网关的选择依据；本见证没有声称已经量出它对总体服务的影响。

## 4. 采样频率要求与窗口覆盖不能靠错开相位解决

`Obligation.matches()` 使用闭区间：边界样本可以同时覆盖相邻窗口。这是原有窗口覆盖语义，不是新代码偶然漏行。于是“每 300s 窗口里至少有一份样本”与“采样间隔不超过 300s/每期一份独立新观测”不等价。

函数级见证：`taken_at=300` 的同一份样本对 `[0,300]` 与 `[300,600]` 两个窗口均返回 `True`。它确认评分语义，无需追加一轮相位实验来证明。

如果保留前一种语义，对齐时的双配属于合法结果，就不能称其为假满足；如果授权要求是后一种，则应在**新任务版本**明确独立样本名额、最大采样间隔或半开窗口等相应评价语义，不能依靠事后选择 150s 偏移使它看起来正确。旧 v1.1/R20 评分不追溯改写。

采样与上报还是两个独立字段；要求采样频率、要求上传频率、要求中心数据新鲜度也应分别声明。Agent 不得因旧样本满足覆盖窗口就忽略一条明确的配置义务，反之也不强迫所有服务要求都转成两个字段同时加密。

doc35 的 `schedule` 当前从授权时刻开新窗口，代码并没有等 Class A 命令生效才开窗；“对应生效延迟之后起效”的注释应纠正。外部要求生效时刻必须由任务决定，不能由某个方法实际送达命令的快慢决定分母。

## 5. A0/A1 怎样避免重演恢复公平性问题

doc37 说 A0 不含未决后果簿记、A1 有簿记，又称同信息。只有在 A0 仍拥有同样的原始可见历史、持久状态和读取接口时，这才可能是表示方式的比较；清掉 A0 历史或不提供证据会重演早期恢复审计的混杂。

建议把最小比较拆开：

| 臂 | 能力 | 用途 |
|---|---|---|
| A0 | 通用工具 Agent + 完整合法历史 + 持久 shadow/版本 + 相同普通求解工具 + 明确执行语义说明 | 测自然产生的失败 |
| A0-structured | 相同 Agent，加普通结构化状态/未决操作列表与常规核对流程 | 排除“只是多了工程记忆/清楚提示” |
| A1 | 在上述能力上加入经核验的义务链反例反馈或增量修复，先只开一项 | 隔离候选的增量 |

原始历史与派生摘要都按实际可见证据形成，不含环境未来；求解成本、提示和工具调用预算留痕。A0 有调 dayfeed/maxcov/MPC 的相同能力；也不能把候选独有的提前部署/撤销/查询能力藏在工具实现里。

最初 3–5 条 A0 轨迹可以用来观察，**不能据此宣告显著性、鲁棒性、方法类关闭或论文成立**。先看一条自然失败、一个同条件可行替代，再选择要实现的最小机制。泛用 ReAct 工具循环只称泛用基线；未保留 ICG 的明确验证/修复流程时，不称 ICG-Restore 的复现或强适配。

工具包装也属于共同模型：读状态只返回实际已收到的证据；写配置返回排队/送达/生效中的真实阶段，经原有链路推进；规划工具可返回基于公开模型的预测，但不得调用最终 `evaluate()` 把全程真值交给 Agent。调用 dayfeed/MPC 表示提交何种计划、计划在哪里运行、何时安装生效，都要写清。不能用一个 Python 策略对象的瞬时替换代替真实下发。若工具只是离线计算方案，实验应称计划生成，不能计作在线执行。

## 6. 不能用 dayfeed 结果生成“不可兑现”金标准

将声明拆成三类：

1. **已兑现**：根据独立 scorer 的实际效果核对；Agent 声明时仍只能使用自己可见的完成证据。
2. **尚未兑现/当前不能保证**：是关于进度或知识边界的声明，不自动算拒绝或失败。
3. **在声明条件下不可能兑现**：需要可行域的排除证书，或明确限定的模型与证明；某条启发式未能完成不够。

假阴性至少要有相同初始条件、合法信息/能力下的可行替代轨迹作见证；否则标未定。“错误控制层修复”也不能只按“回传差时加密采样”这种标签打分：它可能服务后续义务或信息获取。要记录被指称动作能否改变具体义务、是否有合法更好替代及资源代价。

若 h6 的新要求在全中断条件下所有方法都来不及传到现场，则该段首先是共同的通信损失。A1 更诚实的报告可以构成声明可靠性改进；没有新增实际交付时，不能写成监测服务性能提升。
