## 1. B：三个现成组合 × 自动备用，交付—代价前沿（full 14 台）

臂：B1 `local`（不下发）；B2 `fixed900`（训练种子选出的最强**固定**上报，bh8 无备用下
fixed300/900 并列最强、取更省的 900）；B3 `ea_aoi`（v1.1 自封"最强传统基线"，能量+AoI 反馈）。
备用档：off / b200(120s·200B) / b78(120s·78B) / t300 / t600（后两者 78B、300/600s 稀疏）。

full、回传中断 4–12h（bh8）、u.74 关键格（routine 交付率 / event / 接入空口秒 / 备用记录数）：

| 臂 | 备用 | routine | event | 接入空口 s | 备用记录 |
|---|---|---|---|---|---|
| local | off | .339 | .452 | 60.1 | 0 |
| local | b200 | **.973** | .929 | 30.2 | 149.8 |
| fixed900 | off | .358 | .452 | **196.6** | 0 |
| fixed900 | b200 | **.996** | .929 | 36.0 | 153.9 |
| ea_aoi | off | .298 | .452 | **641.5** | 0 |
| ea_aoi | b200 | .991 | .929 | 110.9 | 717.5 |
| ea_aoi | t600 | **.443** | .524 | 513.4 | 510.6 |

**B 的三条裁决：**

1. **routine 宽松义务，现成组合+自动备用已基本覆盖**：fixed900+b200 达 .996、local+b200 .973，
   残留 <1–3% 是接入段随机硬丢（见 §3 的 A 类），网关级联合**改不动**。
2. **最强传统基线 ea_aoi 在"主备分离 + 稀疏备用"的联合环境里失效，且被 Pareto 支配**：它只读
   每节点自身 SoC/AoI，**看不到回传 up/down 与备用窗口**。回传断时中心收不到→AoI 持续变大→它
   正反馈地拼命加密：无备用 bh8 空口 641s（local 的 10.7 倍）交付反而更低；稀疏备用 t600 下海量
   冗余涌入网关、挤占稀缺备用窗，routine **从 .99 崩到 .443**。这不是稻草人——ea_aoi 在无中断
   下确实是最强（none .991），它的失效是**环境（分离主备交付）造成的**，公平。
3. **"一直快"的 fixed900 用代价换服务**：bh8 **无备用**时它空口 196.6s（local 60.1s，3.27 倍）
   交付却几乎相同（.358 vs .339）——**中断期盲目加密、数据堆在网关发不出去，纯白费**；它只在
   有备用、需要数据"早点到网关"时才值这个代价。这正是联合控制器要省掉的浪费。

## 2. C-send（发送侧装包优化）被我自己证伪 —— 可辨识性门直接拦下

我先做了"义务级真实截止排序 + 同义务冗余抑制"的备用装包（probe_csend.py），结果：

- **真实 deadline 排序 vs 朴素周期公式 EDF，逐位相同、零增量**（三臂×三频度 routine/event/包数
  全同）。根因：地灾常态数据率极低（14 节点×6B/h），备用容量（每包≈9–14 条、每 2–10 分钟一包）
  **始终大于中断期积压，装包选择从不构成瓶颈**。这正是 Astra 要求的"置常数后动作不变即删"的
  死参数——**C-send 排序优化关闭**。
- **全局冗余抑制方向对但机制错误**：它能把 ea_aoi+t600 的 routine 从 .49 救到 .87（砍冗余洪流
  有效），但一个样本可同时匹配相邻义务名额，全局标记"已送过"会误把相邻义务也标成满足、饿死
  event（.93→.48）。**在发送侧压制是错的；正确做法是上游根本不制造这些冗余**（→ C-up）。

教训与 [07] 一致：带宽不是这个问题的瓶颈，**时序与"是否该产生/上报"才是**。

## 3. 损失分跳定位（diagnose_loss.py，full bh8 local，逐义务三分类）

对每条未交付义务按卡点分类：A 从未到网关（接入硬丢）；B 到网关已晚于 deadline（接入段节奏）；
C 按时到网关但没在 deadline 前到中心（回传/备用**发送时序**，唯一"发送侧"可救）。

| 条件 | routine A / B / C | event A / B / C |
|---|---|---|
| 无备用 | 9 / **541** / 80 | 0 / 72 / 0 |
| rate120 | 9 / 16 / **0** | 0 / 10 / 0 |
| rate300 | 9 / 16 / 0 | 0 / 24 / 0 |
| rate600 | 9 / 16 / 0 | 0 / 26 / 6 |
| u.5+rate600 | 32 / 87 / 16 | 0 / 26 / 8 |

**定位结论**：
- **C 类在合理备用频度（≥1/2min）下为 0**，只在很稀疏/紧接入下零星出现 → 发送侧联合无空间，
  与 §2 互证。
- 开备用后的残留**绝大多数是 B（到网关已晚）+ A（接入硬丢）**，都发生在**接入段**。
  A 是 26% 上行随机丢的硬损失，网关级方案够不到（终端级直连备用是另一种部署，见 09 §1 扩展）；
  **B 是上游上报/重传节奏决定的、可改变的损失**——fixed900 比 local 多救的 routine 正来自更快
  重传把 B 压下去。
- event 的 B：事件虽"即报"，但 26% 上行丢 + 600s 短 grace，重试不及时就晚；对备用频度敏感。

## 4. 联合命题的精确化（收窄到正确位置，不换场景、不预设 LLM）

> **可交付机会感知的上游上报控制（delivery-opportunity-aware reporting control, C-up）**：
> 在接入受损 + 主回传间歇、备用稀疏且 failover 的分离架构下，节点"何时上报/重传"应当与
> **下游下一次可行交付机会（主路恢复 / 备用窗口）和义务剩余时间联合**决定——
> (a) 回传 down、数据须走备用时，让相关义务样本**足够早到网关**以赶上某次备用窗口（治 B/C）；
> (b) 一旦网关已持有足够早的合格副本、或主路恢复健康，**立即放松**（避免 fixed 的常快浪费与
> ea_aoi 的正反馈冗余）；(c) 命令经 Class A 延迟生效（W1），决策必须前置、不能假设即时。

**与现成组合的差别（也是要被检验的增量）**：
- local 恒慢：省，但 B 类救不回（.973）；
- fixed900 恒快：救回 B（.996），但不分下游状态、常付 1.2–3.3 倍空口，中断无备用时纯浪费；
- ea_aoi 按本地 AoI/SoC：**不看下游可交付机会**，中断期正反馈、稀疏备下自毁；
- **C-up**：用网关合法本地观测（转发反馈推断的回传 down 时长、网关积压年龄/窗口副本、确定性
  备用窗口、义务剩余时间），只在"需要且有用"时对**对应节点**临时加密、否则放松。

**目标假设（H，待 C 实验判决，不是结论）**：在相同义务与现场自治下，C-up 的 routine/event
服务率 **≥ fixed900**，而接入空口、下行命令、备用调用**显著低于 fixed900、逼近 local**；并且在
稀疏备用 + 紧接入档不出现 ea_aoi 式崩溃。若做不到，就关闭"联合"这一项，按 [07] 不扩大成 agent 结论。

**文献差位（待写稿时再核，不写"首次"）**：ICLDC（arXiv:2504.14556）到达过程**外生**；Zakeri
（arXiv:2311.06522）是发送端**本地**、单跳、即时无误反馈的 POMDP。本问题的差别在**远端、Class A
延迟、可能永不生效的配置动作** × **接入与主备回传分离** × **到达 H_i(a_up) 被该延迟动作内生改变**。

## 5. C-up 预注册（先写定，防"调到赢"）

- **合法信息**（同 09 §5）：网关转发反馈推断的 down 时长（不直读链路真值）、网关积压深度/最老
  年龄/本窗口副本、备用 rate（配置已知，下次机会确定性可推）、已用额度、公开义务相位/剩余时间、
  各节点已确认 report_period。**不可见**：主路未来恢复时刻、未来到达/采能、其他节点私有缓存。
- **动作**：只产出 `set_report_period`（采样间隔本轮不动，隔离变量），档位 {300,900,1800,3600}，
  经 Class A 正常下发、送达才生效、占下行机会与各臂同口径。
- **对照与消融（全在同一合法信息/预算）**：local / fixed900 / ea_aoi；C-up 全量；**只调上游不看
  备用窗口**消融（去掉下游机会输入，验证是"联合"而非另一个 AoI 启发式）；**控制延迟置 0** 消融
  （W1 是否承重：若 Class A 延迟置 0 后增益消失，说明增益另有来源，必须如实报）。
- **可辨识性门**：把每个输入单独置常数/打乱，若动作不变则该输入是死参数、删除（本轮 C-send 的
  deadline 精确化即如此被删）。
- **判决（五条同时满足才算 C-up 成立）**：①部署自洽（锚点/总检绿）；②合法动作确能改 B 类损失；
  ③对最强公平传统组合 fixed900 仍有服务或真实代价之差；④服务不降且真实代价（空口/下行/备用
  调用）显著下降，或同代价服务更高（配对种子区间，不报单点均值）；⑤消融定位到机制是"下游可
  交付机会"而非本地 AoI。任一条不满足，只关闭该项。
- **不做**：few-shot、滑坡真假判据、给 MPC 错参只让 agent 学、把 RDSS 能耗折 Wh、发送侧装包排序。
