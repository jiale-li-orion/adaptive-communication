## 0. 结论先行

1. doc33 §2.1/§2.2 指出的两处缺陷**确认，且范围比登记的更大**：
   - 装包分发器外层是精确匹配 `if self.backup_chooser == "cover"`。`cover_l0only`、`cover2` 不等于 `"cover"`，全部落入外层 `else` 的通用 EDF 回退；写在 `if` 块内部的 `cover2` 判断**不可达**。
   - “包内记忆版 `cover_local`”在 `joint_plane.py` 中**出现 0 次、从未实现**；`v3joint_r12_cover_local.json` 内容实际是五个标准 chooser（edf/obligation/latest/salvage/cover），文件名误导。
   - 因此 R12/R15/R16 据这些变体得到的组件结论——“跨包全局记忆必要（包内记忆退化 EDF）”“关层1在稀缺 −24~40pp”“层1去纯冗余必崩”——**全部作废**。R14/R19 中真正走 `cover` 分支的主对比不受此缺陷影响，予以保留。
   - R17 逐义务配对使用 rows 中不存在的 `(node, taken_at)` 键（真实键为 `oid/node_id/release_at`），记录折叠到 `(None,None)`，“逐义务成功差为 0”无效。
2. 修复、加分支/行为见证并用稳定 `oid` 重连后，引入 doc33 §2.3 指定的普通强基线 **maxcov-recency**。四档×6 种子 + 保留种子 6–9 一致表明：
   - **两个容量稀缺档（r600/78、r900/78）maxcov 稳定最优且超过手工 cover**；
   - **机会稀疏档（r1200/200）cover2（边际贪心、层1不补纯冗余）略优**，maxcov/cover 并列其后；
   - **饱和档（r300/78）item 级 EDF/latest 最优**，义务级边际规则低约 2.4pp。
3. **决定（按 doc33“普通规则追平即采用、不救 cover”）：装包工具重选为 maxcov-recency；机会稀疏档记录 cover2 这一同族变体。** 手工两层 `cover` 撤回为可替换的历史实现。Finding II 的**现象级结论保留且更干净**：硬稀缺/稀疏备份腿上，**义务级、边际覆盖驱动的内容装包相对 item 级经典规则有稳健的强增益（容量稀缺约 +10~12pp）**；这一结论现在是击败了教科书贪心之外的所有 item 规则、并由教科书贪心本身达成的，不再依赖一个手工两层启发式。

## 3. 组件重估（oid 逐义务配对，r600/seed0，4053 条）

- **义务级覆盖目标是主增益来源**：maxcov 相对 edf 净救回 1523 条（1523 vs 15）、相对 latest 净救回 1380 条；svc .937 vs .565/.605。item 级 EDF/recency 在硬稀缺看不到“这条样本能兑现哪条义务”。
- **第二阶段“补满/包内边际重算”必要**：完整 cover 相对只跑层0、不补满的 cover_l0only 净救回 528 条（531 vs 3），svc .921 vs .791。只挑纯新增、不把剩余字节用起来不够。
- **跨包全局 seen 记忆不是必要组件**：cover 与 cover_local（seen 每包重置）逐义务 120/132，基本持平；r900 上 cover_local .769 反而高于 cover .698（全局 seen 把“曾覆盖义务的更新样本”在边际阶段排除，降低极稀缺下的灵活性）。
- **层1无差别补纯冗余不是必要组件**：cover2 / maxcov 在所有档持平或高于 cover；r1200 cover2 .953 显著高于 cover .922（稀疏大包里不为纯冗余浪费字节）。旧 doc28“冗余保险”机理撤回。
- maxcov 与 cover2 同族、互相打平（94/89），差异只在“阶段2是否发纯冗余”，对应容量稀缺 vs 机会稀疏两种稀缺结构。

## 4. 工具重选与 Finding II 的准确重述

- 代表性装包规则改用 **maxcov-recency**（教科书带权 max-coverage 背包贪心 + recency 补满）；它在 r600/r900 比手工 cover 高 +2.0/+7.4pp（开发种子）、+2.5/+6.3pp（保留种子），且定义更简单、无“两层/绑缚/保险”等手工叙事。cover2 作为机会稀疏档的同族变体报告，不另立方法、不造 cover3。
- Finding II 重述为：**当备份净吞吐低于义务产出（容量稀缺）或备份机会间隔大（机会稀疏）时，item 级装包规则（EDF/FIFO/recency/义务去重/salvage）没有一条通吃；以“每条样本边际新增的可挽救义务覆盖”为目标、包内重算且不停发的义务级边际装包，在同字节、同机会、同可见信息下，把按期交付率相对各档最强 item 规则提高约 +10~12pp（容量稀缺），并在稀疏大包保持竞争力；饱和区 item-EDF/latest 已足够（约 .98）。**
- 两轴描述（doc33 §2.3）：容量（净吞吐/产出）与机会间隔分开；r1200/200（1.15× 总容量但 1200s 一包）是“每小时容量够、截止前无机会”的反例，不再使用“吞吐比=1 单轴相变”措辞。P=600 常态义务率为 **84/h**（13 个位移节点 + 网关雨量），不是 78/h。

## 6. 边界与诚实项

- 饱和档 maxcov（.96）低于 edf/latest（.98）约 2.4pp：富余容量下边际覆盖让位于纯时效/EDF；**不做魔数融合或自适应切换**（doc33 禁止造 cover3）。论文如实报告分区，而非宣称单一规则通吃。
- r900（容量仅产出 0.46）即使最优装包也只到 .75–.77：装包不能凭空创造物理容量，残余缺口是容量硬限，不是选包失误。
- `v3joint_r17_oracle_infcap` 仅为“放宽资源的策略参考”，不称严格上界；严格容量感知闭环最优因 chooser↔接入耦合（doc30）不可干净解耦，仍列未来工作。
- 旧 `v3joint_r12_cover_local / r15_ablation_l0only / r16_cover2` 三份 json 作为**失效消融的历史记录保留**，README 标注“invalid intended ablations, superseded by R20”，不得再被论文/文档当作组件证据引用。
- 本轮不改变任务、事件、能力模型与任何外部数字；maxcov 只使用与其他 chooser 相同的可见信息（样本、义务匹配、自身发送/回执累计），不读未来链路/采认真值。
