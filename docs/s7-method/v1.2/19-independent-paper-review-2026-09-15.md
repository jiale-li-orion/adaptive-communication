# v1.2/19：联合控制迭代与论文主张的独立审查

审查日期：2026-09-15。审查起点：`87e9d49`，覆盖 doc08–18、论文初稿、对应提交与 `code/v3joint/`，并回看 Human 复盘、instance-v1 的准入/位置/节奏关闭记录。审查者未实现新方法，未改变任务、物理模型或原结果文件。

**决策：撤回 doc18「科学内容已闭环、剩余仅成稿工程」的阶段判定。保留具名策略的失败现象；暂停采用 AoI 导致密采、接入拥塞、静态最优、网关反馈唯一正确等机制或最优性主张。下一步是有限的测量修复与可辨识性核验，不是扩种子、定 venue 或补参考文献格式。**

同时，不接受相反的过度推论：这轮没有穷尽联合控制，更没有否定 agent 通信这一方法类别。`C-up` 的关键分支仍存在与旧 `oblig_slack` 相同的结构退化；失败的手写策略不能代替联合规划问题本身。

## 1. 哪些进展可以保留

- 已有可以在原实例循环中运行的网关备用回传原型，关闭备用时的回归检查有价值。但继承旧循环也会继承旧缺陷，不能据此证明整个模型的物理/评分正确性。
- 在指定配置中，`ea_aoi` 发生显著能量耗尽；本审查 seed 0 重放仍得到 12/14 节点被判死。旁路修正首次到达口径后失败依然存在，不能把全部差距归给评分错误。
- 静态工作点与几条启发式的成本—服务比较可以作为探索材料。它们不等于完整策略空间的 Pareto 前沿，也不是已有 AoI 优化算法的公平复现。
- 不强求 LLM 不可替代这一研究门槛是正确的；但把 agent 放进讨论节不构成已测的 agent 贡献。

## 2. 影响主论点的发现

### R1：主表中的 anchor 是常量目标，关键消融没有改变方法

`joint_policy.py::_want` 定义：

```text
k = floor(t / P)
slack = (k + 2)P - t
```

所以任意时刻均有 `P < slack <= 2P`。

1. `use_backup_window=False` 时，`urgent = slack < P` 永远为假。因此主表的 `anchor` 始终要求 `(sample=3600, report=900)`；这对 P=300 也成立。不是轨迹恰巧不需要动作，而是公式不允许动作。
2. 完整 C-up 的 P=3600、默认 lead=900、backup rate=300、hysteresis=600 下，进入/保持快档分别要求 `slack<=1200/1800`，同样不可能。rate=120/600 的已用常态档也不改变这个结论。
3. `probe_sampling_gate.py` 的 `report_only` 与 `anchor_full` 都设 `use_window=False`，只改 `gate_sampling`。由于前者的 `_want` 已恒定给出稀疏采样，两者目标完全相同。这不能支持「必须门控采样，而非只门控上报」的机制判定。
4. `GatewayObserver.next_backup_in_s` 在策略中没有调用；完整策略用了备用周期常数，但没有用下一次实际备用机会的相位。

本轮枚举 48 h 全部 60 s tick 的健康、主路断、无副本视图：

| 义务周期 | use_backup_window | 唯一配置目标（采样，上报） |
|---|---|---|
| 3600 | False | (3600, 900) |
| 3600 | True | (3600, 900) |
| 300 | False | (3600, 900) |
| 300 | True | (600, 300) |

这只是分支审计，最后一行不表示业务获益。完整策略仍可能因副本、供电、主路状态改变上报档位，但不能把它解释成已验证的截止期/机会联合预测。

**结论：doc12 已承认 anchor 退化，但把退化归因为任务结构过度了；其原因至少包含代码构造。doc10 自己规定的「输入可辨识性门」没有闭合。修正的对象应是尚未完成的真实义务及其绝对截止期，不能只把阈值抬到让候选更容易动作。**

### R2：论文的主失败策略并不是「AoI 越大就越密采」

`center.py::EnergyAoiPolicy.plan` 的两个决策是：

```text
采样档：soc >= healthy_wh ? dense : sparse
上报档：AoI unknown / above threshold ? fast : slow
```

采样分支直接依赖电量，不依赖 AoI。AoI 可以经上报、遥测、命令排队等间接路径影响以后状态，但这需要干预对照，不能把直接的六倍密采归给 AoI。

此外，中心/网关的位置对照同时改变电量新鲜度、AoI 来源和命令进入网关的路径。`center_send` 在主回传断时拒收新命令，`gateway_send` 不需要经过该跳。`JointControlPlane` 新增的是数据回传备用，并未同步提供中心下行备用。所以不能仅凭位置差说明问题在 AoI，更不能把「中心继续生成命令」写成「这些新命令在中断中持续生效」。必须区分中断前已生效、中断前入队及中断后生成的命令。

这延续了 Human 复盘中「持续效果与未来纠正能力」的问题；不应把旧问题未经隔离地改名为新的 AoI 失稳定理。

### R3：「无中断损失≈0」与已存结果直接不符

`results/v3joint_phase.json` 中 peak=.005、outage_hours=0：fixed900 为 .9996，ea_aoi 为 .8750，差 **−12.46 个百分点**，ea 存活 **8.25/14**。peak=.003 的对应差为 −5.02 点。

而且这里的 0 只取消人为长中断，`joint_run.py` 默认的随机回传可用率 .62 仍在；`test_joint.py` A2 自己已经指出这个区别。不能把这列当成无回传故障的因果开关。

需分别命名「无额外连续中断」与「主回传始终可用」。原相图可保留为探索曲面，撤回全空间无中断零损失及单调性表述。

### R4：首次到达会被重传覆盖，评分与分跳台账受影响

`network.py::tick` 对同一 sample_id 的 `heard_at`、`received_at` 反复直接赋当前时刻；`Center.receive` 同样覆盖接收时刻。`scoring.py` 据最终字段判断是否按期交付。首次准时、后续重复晚到的样本因此可能被改判迟到。逐义务台账的 `first_*` 只是对这些最终字段取最小，并非真实首次事件。

旁路审计只记录真实接收事件，运行结束后独立重评，不改变行为：

| 已发布 stressed 条件、seed 0 | 原常态交付 | 首次到达重评 | 原事件交付 | 重评 |
|---|---:|---:|---:|---:|
| fixed900 | 671/672 | 671/672 | 16/21 | 16/21 |
| ea_aoi | 139/672 | 148/672 | 13/21 | 14/21 |

两条轨迹都另跑关闭 observer 的对照，**所有结果字段逐位相同**。ea 轨迹中 218 个样本的最终接收时刻晚于真实首次到达；19,010 次接收事件对应 914 个不同样本；208 个样本被备用链路重复交付。不能把 `backup_records` 当成不同有效记录数。

还有 21 次遥测源时间倒退：`Center.receive` 按抵达顺序直接覆盖 SoC 快照。它可能影响控制，但本轮没有修复或测量其业务影响，不能声称它解释了全部失败。数据重复、评分覆盖和遥测倒退须分开处理；去重/按源时间更新本身是标准基线能力，不包装为新贡献。

复现：

```bash
python3 code/v3joint/review_diagnostic.py --output /tmp/v3joint_review_diagnostic.json
```

产物：[主诊断](../../../results/v3joint_review_20260915.json)，包含源码哈希、全部配置、义务反例与分支枚举。原 v3joint 结果未覆盖，尚未全量重评。

### R5：永久死亡是模型选择；紧任务的「不是能量，是拥塞」也被反例否定

`Node._take` 在电量不足一次采样时置 `alive=False`；`_step_power` 此后可继续充电，但不恢复 alive。于是后续缺采是这个吸收态的后果，不能直接作为真实设备不可逆死亡的证据。主诊断的 ea 在运行末有 **9 个已判死节点重新具有至少一次采样的电量**。

本轮另外重放 `probe_diag_tight.py` 的 openloop seed 0（原配置，不新选参数）：

- 常态义务 8,064 条，采集 3,310 条，**缺采 4,754 条**；
- 存活 **0/14**，末电比例 **1.0**；
- 原常态交付 481，首次到达重评 494。

因此该工况并未排除供电影响。所谓 A 类「从未到网关」包括**根本没有产生的样本对应的义务**；`abc()` 未先排除未采集。26,743 是跨四种子的义务计数，不是 26,743 个已采集但发生无线碰撞的样本。

更直接地，`opportunity.py::uplink` 的接收由固定概率或外生突发态决定，没有由并发发射/空口占用决定碰撞的模型。空口被计账不等于共享容量已被建模。因此撤回物理接入拥塞、单网关 .80 容量上限、需要加网关的推导。

该探针还有命名错位：它调用 `fixed900`，只把**初始** report_period 设为 300；策略随后要求上报周期 900，不能叫全程固定 300/300。这不自动否定真正 `grid*` 臂的读数，二者应分开。

补件：[tight 单种子诊断](../../../results/v3joint_review_tight_20260915.json)。这条较慢补件未另跑 observer 关闭对照，不冒充三条均验证保真；可用诊断脚本 `--include-tight` 完整重放并补该验证。

模型处理：保留原吸收态作为明确研究假设；寻找目标器件断电后能否自动复机的依据。缺少依据时至少做「掉电后恢复」的模型敏感性。不能为扩大差距沿用永久死亡，又将重充电当成现实不可逆损害的证明。

### R6：强文献基线与最优性证明没有建立

本轮核读两篇原文：

- [Bacinoglu 等，Optimal Status Updating with a Finite-Battery Energy Harvesting Source](https://arxiv.org/html/1905.06679v3)：原模型下研究按瞬时电池水平变化的年龄门限，提供计算门限的算法，动作为逐次状态更新。仓库 `eh_aoi` 是一个电量阈值与固定年龄阈值的组合，并把一次更新改成持续采样配置；未复现其求解器或原目标。应称「受 EH/AoI 启发的阈值规则」，不能用它的损失反驳原最优策略。
- [Zakeri 等，Semantic-aware Sampling and Transmission in Real-time Tracking Systems](https://arxiv.org/html/2311.06522v2)：发送端控制器观察电池、缓冲与即时无误 ACK/NACK，联合采样/重传并有能量因果约束。其优化策略已可呈非单调年龄结构。仓库没有移植该求解器。因此「AoI 文献都只会越旧越多采」不是成立的文献概括。

`probe_upperbound.py::OracleWindowPolicy` 则是知道中断窗后，窗内快报、窗外慢报的一条手写策略；没有最大化合法动作序列。读未来只能说明不可实现，不说明支配所有可实现策略。它输给 fixed 不能关闭滚动联合控制。

静态网格强于若干阈值规则，是有限集合比较。参数扫描中把阈值调高后少动作而安全，也不证明任何安全控制都必定放弃反馈。相图/参数选择用过 0–3 等种子，后续 0–15 和 0–5 包含它们，不能把这些全集标为与开发种子分离的确证性集合。

### R7：任务与成本解释仍需限界

- P=300 连续 48 h 是研究压力设置；来源支持本地事件突发，不自动支持全网持续 48 h 的五分钟义务。不能借已替换的旧 W1 契约把它写成已证实风险工作负载。
- 当前 routine 窗口含两个端点，`matches` 允许同一边界样本匹配相邻义务。因此「600 s 采样得到很高的 300 s 窗覆盖」不等于产生了两份独立五分钟观测。解释必须服从冻结的窗口语义；如要研究独立采样频率，应另作指标敏感性，不能默改分母。
- 备用只按样本值 4/6 B 和公共头记账，却携带完整 snapshot；未给出完整序列化载荷，也未扣备用链路能耗。「byte- and energy-accurate」与「zero-copy」不能用来说明尚未实现的工程性质。可保留抽象载荷预算和已计入的节点采样/LoRa 能耗。
- `GatewayObserver.primary_up` 直接调用环境的 `backhaul_available`，而 doc10 预注册要求从转发反馈推断。要么为所有臂提供同等有依据的本地接口，要么换为真实可观察量，不能混淆模型真值与执行反馈。

## 3. 更接近场景本质的理解

这个任务需要持续产生与交付合格观测。控制器看到的「缺一条」至少可能指三件不同的事：没有采到、采到但没到网关、已经在网关但没到中心。三种状态的合理动作可以分别是保采集、促上报、使用备用；继续采样不必改善后两种状态。

端到端 AoI 如实说明中心的资料有多旧，**并没有说谎**。问题是将这个结果指标当成足以选择执行动作的状态。单纯改成网关 AoI 也不完整：它不能独立说明中心的交付义务是否完成，更不能保证中心下一次还能纠正持续配置。

当网关最新样本时间为 `U_g`、中心最新样本时间为 `U_c`，且二者均有记录、样本必经网关时：

```text
AoI_center = (t - U_g) + (U_g - U_c)
```

同一个中心 AoI 可来自不同段的差额。这是诊断恒等式，不是创新定理；每个执行位置也未必能实时知道两项。下一次动作的价值还取决于：能否生效、何时生效、配置持续多久、这段期间的能源是否足够，以及实际记录能否赶上某个交付机会。

**有潜力但尚未证明的主张应是：持续配置的价值需要按可执行的跨跳后果评估，不能由单一年龄/电量阈值代替。** 本轮的常量 anchor 和未来窗口规则没有检验完这句话。

## 4. 下一轮只走一个有限路线

完整主张与实验状态见 [20：审查后的实验矩阵](20-review-experiment-matrix-2026-09-15.md)。顺序不可用全量扫参替代。

### 第一步：恢复可信测量与任务解释

统一 earliest heard/received；遥测按源时刻单调更新与数据重传分别处理。修复后先重放本审查反例及原主表少量开发种子，保留旧值、修复值和行为是否改变。建立掉电/复机假设卡；紧任务先分「缺采—未到网关—迟到网关—晚到中心」，不再把前三者混成拥塞。此步即使恢复数值，也只算修复。

### 第二步：证明候选真的在做所宣称的选择

为**仍未完成的具体义务**保存绝对截止期，不在每个新周期把既有负债丢掉。只用所在位置合法可见的状态：没有节点读数不能假装知道已经采到；网关持有记录不等于中心已经交付。

先给两条可达历史，要求它们具有相同标量 AoI/SoC，但因为记录所在位置、剩余期限或下一次可执行机会不同，合理动作不同。再确认候选会作出不同动作，并且这些动作真能通过现有接口生效。没有这种见证，不能因候选名含「联合/机会」就晋级。这里先检查旧候选是否被正确实例化，不认领新方法。

### 第三步：只在存在差额时实例化一个小型联合规划基线

沿用 doc07，而不是另开方向：在既有配置档位上枚举少量短动作序列，同时模拟命令可能生效时刻、未完成义务、当前可持有样本、备用容量及持续能耗。每次只执行第一项，收到新证据再重算。先用可解释的短时域搜索/MPC，不需要 LLM。

它与 C-up 的区别必须落在计算上：从「当前年龄大就快报」变成「这个配置来得及改变哪条尚未完成义务、会持续消耗多少资源」。如果未来动作只是假设即时降档，它又回到了已否定的危险假设。

这个有限搜索是**比较工具**，不是自动成立的创新；普通延迟感知 MPC 必须作为强基线。只允许一个条件：修正后、现有范围内且有来源边界的工作点。不要为了制造差额添加新风险任务或硬件。若 service 已接近 100%，优先看相同服务下可否节省真实成本，不继续追求数个百分点的业务优势。

晋级前须同时满足：

1. 同信息、同动作与机会、同自治/复机能力，胜过公平固定配置与普通规则集合中的相应成本—服务点；
2. 在完全不读未来真值的运行中保留差额；知道未来的可行搜索只作为机会见证，不作上界；
3. 差额来自记录就绪、动作延迟与持续负载的联动；去掉这一项后收益消失，而非来自去重、遥测排序、位置或采样量不公平；
4. 开发区间冻结后再使用未参与本轮开发的种子/片段检验；统计不确定性与所有成本分列报告。

有限候选若又被普通规则/MPC 覆盖，就关闭该候选，不升级成「智能实时控制一概无用」。若胜出，再考虑将这种执行约束输出成 planner 可消费的接口，接真实 agent 测安全/服务及开销；没有这一步，C4 仍仅是应用动机。
