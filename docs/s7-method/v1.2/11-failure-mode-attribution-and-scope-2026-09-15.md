## 1. 三轮自我证伪（都按可辨识性门拦下，不调参硬救）

1. **C-send 发送侧装包优化＝死参数**（probe_csend）：真实义务 deadline 排序与朴素周期 EDF
   **逐位相同、零增量**；全局冗余抑制会误杀相邻义务、饿死 event。根因：地灾数据率极低
   （14 节点×6B/h），备用容量始终大于中断期积压，**装包选择从不构成瓶颈**。
2. **C-up v1（只调上报）被上界否证**（probe_upperbound）：即便**偷看未来中断时刻**、只在窗内
   加密、窗外放松，服务 .991 仍低于全程 fixed900 的 .998，空口只省 5%，下行命令反而更多
   （49.5 vs 18.75，Class A 切换要付信令＋生效延迟）。**上界都赢不了 → 只调上报的闭环无空间。**
   能量账解释：采样 4.7e-4 Wh/次、上报仅 2.33e-5 Wh/次（采样贵 20 倍），采样固定时上报频率对
   电量/存活几乎无影响（fixed 与 local 电量轨迹逐档相同）。
3. **C-up 全量（逐拍下游机会）过度反应**：next_backup 相位逐拍锯齿导致档位震荡、下行命令
   511 条（fixed 19），服务却与稳定简化版相同 → 逐拍下游细节是噪声，正确抽象层级是义务时间结构。

## 2. 能量承重后，最强传统闭环 ea_aoi 暴露结构性失稳（稳健、全能量轴单调）

重开真实采能（solar，含昼夜/云）、动作面含采样间隔，48h、长中断 4–20h、备用 t300：

| 能量档 | local | fixed900 | **ea_aoi** |
|---|---|---|---|
| 宽松（满电、peak.03） | .981 / soc.93 / air115 | .999 / .93 / 139 | **.830 / .32 / 1317** |
| 中等（peak.01、初电.6） | .981 / .89 | .999 / .89 | .830 / **.19 / 13 台活** |
| 紧张（peak.005、初电.5、30%断采能） | .980 / 13.67活 | .999 / 13.67活 | **.292 / 仅 1 台活** |
| 极紧（.003、.4、40%断） | .969 / 8.33活 | .984 / 8.17活 | **.230 / 0.67 台活** |

**反直觉点**：ea_aoi 是 v1.1 精心构造的"最强传统组合"（SoC 定采样＋AoI 定上报，均合法观测），
无中断时它确实最强；但在**接入/回传分离＋长回传中断**下，它把"回传断→中心收不到→端到端 AoI
虚高"误判为"现场需要更密"，于是对**发不出去的数据持续 6 倍密采（dense600）＋300s 快报**，空口
最高 11 倍、电量越紧越先耗尽死亡。这不是 strawman：同一策略换个环境就从最强变最差，失效是
**架构（分离主备）与反馈信号**共同造成的。

## 3. 逐层机制归因（两个消融，定位到底是哪一层的错）

同一条 ea_aoi 策略仅改放置位置得到 `ea_aoi_gw`（其 AoI 自动改用"网关听到"而非"中心收到"）；
再把密采触发从"SoC 阈值"换成"义务相位/可交付性"得到 `cup_noWin`（不看任何逐拍下游量）：

| 能量档 | ea_aoi 中心 | ea_aoi_gw 网关 | cup_noWin 义务相位 | fixed900 |
|---|---|---|---|---|
| 宽松 | .830 / soc.32 | .862 / .32 | **.998 / .93** | .999 |
| 紧张 | .292 / 活1.0 | .652 / 活7.8 | **.997 / 活13.7** | .999 |
| 极紧 | .230 / 活0.7 | .698 / soc.074 | **.982 / 活8.2** | .984 |

- **位置只解释一部分**：网关版比中心版好（紧张 .652 vs .292）——网关在接入网仍通时不被回传
  中断污染 AoI，修好了**上报侧**的误判；但它仍濒死（soc .074），因为**采样侧**"SoC 够就持续
  dense"与可交付性无关，换位置改不了。
- **驱动信号才是主因**：把密采条件改成"义务临近、数据将被需要"（cup_noWin），失稳**彻底消失**，
  服务/存活/电量回到与最省开环臂一致，且 cmd 仅 36、**不需要任何逐拍下游预测**。
- 结论：分离主备架构下，采样/上报的正确驱动量是**监测义务的时间结构与可交付性**，既不是端到端
  AoI（被回传状态污染），也不是单纯 SoC 阈值（不区分数据发不发得出去）。

## 4. 边界（必须诚实写进论文，不夸大）

在 v1.1 冻结 task（routine 1h 窗＋1h grace、低数据率、备用容量≥积压、接入 p=.74）下：

- **开环 fixed900（稀疏固定采样＋900s 上报＋自动备用 failover）以最少信令（cmd19）达到最高服务
  （.999）且全程稳健**；任何自适应闭环（cup/cup_noWin）平均服务收益≈0，只做到"打平开环、不崩"。
- 根因是**该 task 的义务节奏使密采本身几乎不必要**（每窗 1 条稀采即够），"按需密采"没有舞台；
  这是 task 结构决定的边界，**不得靠改紧义务/改场景去制造增益**（场景不换）。
- 因此本场景**不需要 agent/LLM 做实时采样-上报闭环**：这不是失败，而是用强基线＋上界把"智能在
  哪一层有用"精确切出来。

## 5. 贡献定位（不追求"agent 不可替代"，规则获益也是通信贡献）

一篇可成立的**通信执行层**论文，三条承重主张，全部有证据、有消融、有边界：

1. **形式化**：接入/回传分离、Class A 延迟可能永不生效、间歇主/备回传、供电受限下的现场监测
   通信执行层（受控到达 H_i(a) 被延迟配置动作内生改变，区别于 ICLDC 外生到达、Zakeri 单跳即时反馈）。
2. **失效模式（核心、反直觉）**：端到端 AoI/SoC 这类**不区分可交付性**的反馈量，在回传中断期
   驱动闭环正反馈失稳，能量约束放大为节点死亡；位置消融与驱动信号消融逐层定位（§3）。
3. **设计原则与边界**：反馈锚定义务时间结构/网关本地可交付性；给出轻量执行策略，证明其消除失稳、
   不劣于开环；并用上界证明低数据率下开环近最优、闭环价值在**鲁棒/自适保险**而非平均增益。

**对原 agent 命题的意义（重要，回应"不甘心"）**：证据不是"agent+应急通信做不下去"，而是把
agent 的位置**上移**——实时采样/上报闭环是开环最优、不需要智能；agent runtime 的舞台在
**慢时间尺度的任务编排与恢复**：中断/退化/恢复时跨实体选择通信手段、重配置执行层策略、编排
备用/中继/恢复序列（对应谱系第③线 ESWA/SCS，以及把第②阶做成"规则执行层之上，规则 planner vs
tool-agent 的开销/灵活性对比"）。这与 [08] 二阶定位一致，现在有了第一阶的硬证据支撑分层。
