- 日期：2026-09-19

## §1 三臂的严格对称（doc38 §5）
三臂共用同一 `AgentMissionPolicy`、同一份合法 center-view 观测、同一工具建议（dayfeed/sustain/comply/ignore）、同一滚动历史、同一动作空间（每节点采样/上报 ∈ {300,600}）、同一 Class A 命令三阶段与节流、同一 deepseek-flash（temperature=0、json、low effort + 空 content 回退）。唯一差别是 decider 在 user prompt 末尾看到的信息块：

| 臂 | structured_state（未决命令工程清单） | 义务链可行性证书 |
|---|---|---|
| A0 | 否 | 否 |
| A0-structured | **是** | 否 |
| A1 | 是 | **是**（`online_cert_block`） |

**证书不引入任何 A0 看不到的原始信号**：它只把三臂共有观测（中心收据停滞 `n_heard=0`/AoI、节点确认的当前配置、在飞命令、外生授权周期）与公开常量（备份槽 1200s/升级窗口约 600s 几何、电池 0.05Wh/采样能耗、Class A 生效条件、DZ/T 0460 §5.3.3/§8.4.2 授权动作）编译成段判定。回传状态只做**当前、保守**推断（中心无收据 ⇒ 回传未交付），不预告恢复时刻（论文 §8 保守变体）。

## §2 场景与主口径（不换场景）
seed 0/1/2，48h+tail，14 节点 2 组，cap .05、solar peak .03、initSoC 1、sample/report/routine=600、主回传中断 h4–20、备份 r1200/78B maxcov、h6 升级 600→300、任务表 h20 到网关、半开对齐、dayfeed 物理。另在 seed0 加**可靠链路负对照**（outage_hours=0）的 A0 与 A1，检验证书在正常工况不误抑制。

## §3 先冻结的判据（结果出来前写定，不得据结果改）
物理墙决定 svc 上限，**不预期三臂 svc 有大差异**（机制层 fixed-resource 增益已由 selective purge 取得，与 agent 无关）。agent 章的应变量是 doc38 的**三类声明合规与命令效率**：
- **H1 命令效率/不过度承诺**：中断期"无效 dense 命令决策数"（`outage_ineffective_dense_decisions`：中断期、尚有节点未确认 300、却主动下发 300）与 `outage_dense_node_attempts`，A1 应明显低于 A0；A0-structured 若已追平 A1，则增益归普通工程清单。
- **H2 诚实声明（知识边界）**：A1 在中断期应出现 `outage_infeasibility_logged_decisions>0`（登记不可行/保持/会商），且 `outage_false_report_decisions=0`（0 节点确认 300 时不得声称升级在执行）；A0 允许出现 false report（原始在线 trace A0_seed0 已观察到"backhaul up / yellow 在跑"式误述）。
- **H3 不伤害正常工况**：负对照 outage=0 下 A1 的 svc 不得低于 A0（不允许证书在链路好时错误 hold）。
- **H4 服务/生存**：A1 的 svc、死亡数不得差于 A0；若 A1 因避免夜间 dense 而减少永久死亡，作为**额外**收益如实报告，不与 H1/H2 混为一谈。

**归因规则（预先写定）**：
1. A1 在 H1/H2 上优于 A0、且 A0-structured **不能**复制其全部改善 ⇒ 证书有独立 agent 增量，§6.4 升级为多轨迹三臂对照（仍为小样本方向性证据，不做显著性夸大）。
2. A0-structured 已追平 A1 ⇒ 增益归普通结构化状态/工程记忆，论文如实写"证书无额外 LLM 增量"，agent 章定位为结构化反馈价值。
3. 三臂在某 seed 都不犯错（失败率本就低）⇒ 不制造失败，报告"证书为防御性/低频事件价值"，并依赖已有 A0_seed0 原始 trace 的失败见证。
4. 任何 svc 主张以独立 scorer 为准；"不可能兑现"必须有乐观模型排除证书，agent 自述不算（doc38 三类声明）。

| A0-structured | .1577 | 13 | 138/342 | 8 | .750 | 6 | 4 | 408,238 |

读数（对照 §3 判据）：
- **H4/生存（先导中最强信号）**：A0 与 A0-structured 都在夜间反复下发/尝试 300，**永久杀死 13/14 节点**，svc 崩到 .16；A1 凭 ENERGY 与段判定几乎全程保持，**0 死亡、svc 近翻倍**。这把论文 §6.3 的"always-dense 杀 13 节点、证书感知保持 0 死亡"从规则/离线层在**真实 LLM 端到端**复现。
- **H1**：A1 中断无效密采决策 1（对 A0 9 / A0s 8），命令发出 28（对 138）、拒发 56（对 348）。
- **H2**：A1 登记不可行 17（对 4）。
- **关键归因（§3 规则2）**：A0-structured 仅加普通工程清单**未救场**（同样死 13 节点、谎报更多），说明增益不来自工程记忆，而来自证书的段/能量/几何判定。
- A1 svc .323 仍低于 dayfeed 强规则 .400：符合论文主旨——证书让通用 agent **不犯致命错误并诚实声明**，而非在吞吐上超越强规则/MPC。

### 4.2 先导暴露的真实缺陷 → 证书 v2（不是"调到赢"）
A1 v1 仍有 1 次谎报（t=28800，08:00）。核查原始 note："backhaul live (9/14 heard) … compile 300/300"。根因经 `joint_plane.py` 注释与代码确认：**北斗备份腿在主路中断时仍把零星数据样本送到中心并更新 `n_heard`（每 1200s 一包、约 9–10 节点），但备份是上行数据腿、不交付/确认下行配置命令**（joint_plane 第 7–11、81 行已预警"策略要区分备用转发成功"）。证书 v1 仅在 `n_heard==0` 判回传中断，被这种"**数据面伪恢复**"骗过一次（该次 300 命令在中断期被拒、未生效，故未致死，但属真实段误判，非评分器误报）。

**v2 修正（有独立、合法依据）**：回传/控制面是否在线，唯一可靠证据是 agent 自己下发的命令被**节点确认**（`cur_sample_s` 变为目标值），而非中心是否听到数据。v2 以**命令确认账本为锚**：升级已要求但 `applied_dense<n` 即判控制面未交付，并显式说明"听到样本（可能经备份）≠ 回传对命令在线"；`n_heard` 仅作辅助。同步把谎报评分改为 note **句子级**判定（无否定词的肯定"在线/已生效"声称才计），避免把"do not report as running"类否定复述误计。
- v2 单元见证（合成观测）：heard=9/applied=0 时正确输出 CONTROL-PLANE-NOT-DELIVERING + BACKUP-DATA 说明 + MISSION-NOT-IN-EFFECT；heard=14/全确认时不误告警；评分器对伪恢复肯定句计谎报、对 hold/否定句不计。
- **v2 全量重跑 seed0 在 t=28800 的实测见证**：heard=9、applied300=0、**dense_cmds=0**，note="control plane not delivering (0/14 confirm; backup uplink-only), hold 600, log command-unreachable/no-return-slot"。v1 的误判已消除。

### 4.2.1 v2 的恢复后死锁 → 证书 v3 三态
v2 全量 seed0（ts 1789763755）消除了伪恢复（falseRpt=0、ineffDense=0、0 死亡），但暴露另一极端：**sent=0、保持率 100%**。逐决策核查发现，h20 回传恢复后**第二天白天（t=108000–151200，06:00–18:00）中心已能听到全部 14 节点（n_heard=14）、有日照**，证书却仍以"0/14 确认 300"为由拒绝下发——这是**自我实现死锁**：因无人确认而从不下发，便永远无人确认。v1 用 `heard==0` 太松（被备份骗），v2 用 `applied<n` 太紧（恢复后死锁）。

**v3 三态（只用三臂共有合法信号）**：以中心收据**覆盖度**判数据面、以**节点确认**判控制面生效——
- `blocked`：升级在身、`applied<n` 且 `heard<n` → 控制面不可信（中断 heard=0 ／ 备份伪恢复 0<heard<n），保持、登记、不谎报、勿重发；
- `recover`：升级在身、`applied<n` 且 `heard==n` → 数据面已全节点恢复，**允许"下发一次 → 以节点回报 cur_sample=300 为唯一生效准据 → 不确认则回退保持并登记"**，破除死锁，确认前仍不得声称在执行；
- `active`：`applied==n` → 已生效，按昼夜维持。
- 能量段改按当天时刻 `hod`（18:00–06:00 夜间禁止持密、16:00–18:00 临近夜谨慎），修正 v2 用绝对 `t>13h` 导致第二天白天也恒报夜间能耗的错误；夜间即使链路恢复也按 dayfeed sustain，白天才编译 dense。
- 残余风险（写入边界）：备份多包在 1800s 窗内偶发覆盖全部节点时 `heard==n` 可能误判恢复，此时证书仅"允许一次、以节点确认为准、不谎报"，命令在主路 down 时被拒、不生效也不致死，下一窗 heard 跌回即回退。

v3 单元见证（合成观测）：heard=0→blocked 保持；heard=9→备份伪恢复保持；heard=14 白天→recover 编译且不误报能量/中断；heard=14 夜间→recover 但受夜间能量门约束；applied=14→active 无告警。joint 5/5 不变量仍过。

### 4.2.2 v3 的"夜间恢复"反例（seed1）→ 证书 v4 夜间能量硬门
v3 全量 seed0 达成 svc=.399/0 死亡/0 谎报（恢复后白天正确编译 13/14），但 **seed1 的 A1 仍死 13 节点**。诊断（dayfeed 强规则无 LLM 基线 + trace 时间线）：
- **dayfeed 强规则 seed0/1/2 全部 0 死亡**（svc .323/.266/.299）⇒ seed1 物理上可保活，A1 死亡是策略问题而非任务不可行。
- trace 显示主路在 **21:30（夜间）恢复**（n_heard=14），A1 正确识别恢复，却在 **t=86400（午夜）编译 300、让 12–13 节点以密采整夜运行**（app300=13 持续到次日晨）→ 耗尽死亡。v3 的能量段在夜间只是"建议"，压不过"链路恢复→编译升级"的许可；且 LLM 在 temperature=0 下跨运行有轨迹方差（同 seed0 的 A0 两次 svc .165/.413），单靠建议无法稳定防止夜间密采。

**v4：夜间能量硬门最高优先**（与 dayfeed 遵守同一条对称能量墙，区别只是把它从硬编码规则编译成给通用 agent 的实时约束）：
- 入夜（hod≥18 或 <06）后，**无论链路是否恢复、任务是否要求 300**，证书只允许 sparse 并要求对任何已确认 dense 的节点**主动降级（DOWNGRADE）**，明确该门"**override 任务等级与任何回传恢复**"，登记 elevated 夜间能量不可行、不得谎报；
- dense 编译窗限定白天 [06:00,16:00)（留 Class A 生效/撤回余量），[16,18) 临近夜不再新开 dense 并安排日落降级；
- 白天仍保留 v3 的 blocked/recover/active 三态。
- 单元见证 7 场景：午夜恢复→硬门不编译；夜间已 dense→显式降级 14 节点；白天恢复→编译；白天备份伪恢复→保持；黄昏 dense→日落降级；白天 active→无告警；夜间中断→硬门+控制面不可达。joint 5/5 仍过。
- 公平性说明：夜间硬门目前仅作为**证书文本**给 A1（A0/A0s 不收到），属待检验的机制增量；若 v4 仍不能稳定阻止夜间 dense（LLM 不遵守），退路是把能量门作为**三臂共享的合法动作安全钳制**（届时 A0/A0s 也被钳、增益归工程护栏而非证书，将如实归因）。

**有效轨迹的稳健性（死亡数稳健、单次 svc 不稳健）**：A0/A0-structured 共 7 条有效轨迹**全部 dead13**（svc 在 .15–.43 间大幅波动，故不以单次 svc 作效应量）；A1+证书在 seed0 的三次版本（v1/v3/v4）**全 dead0**，但 v3 seed1（ts 1789766880）仍 **dead13**。

**按 §3 归因规则下结论**：
1. **H4/生存**：文本证书在 seed0 稳定消除夜间致死（三版 0 死），但**不跨种子保证**——v3 seed1 在"主路深夜恢复"许可下午夜编译 dense、整夜保持而死 13 节点，且 temperature=0 下存在轨迹方差。§4.2.2 预先写明的**退路由此被采纳**：把夜间能量门从"给 A1 的证书文本建议"机制化为**确定性、对所有 planner 一视同仁的执行护栏**——中心侧可行性 envelope（E1–E3）与节点本地能量底座（`local_floor`），三臂/规则/MPC 共享，A0 也被钳（增益归工程护栏而非证书文本，按预注册如实归因）。
2. 效应量与安全保证改由**不耗 API、可复现的确定性 r39** 承担（doc48）：naive comply 三种子死 39、中心 envelope 救不了最紧 seed1（仍死 12）、节点本地底座死亡清零（39/12→0）且服务不降，纯本地零命令自治达到与任何中心编译相同的服务（静态任务中心无吞吐增量）。
3. **H1/H2（命令效率/诚实）**在有效 seed0 轨迹方向成立（A1 中断无效密采与谎报趋零、不可行登记 17–29，A0/A0s 谎报 3–7），但样本小，不做显著性主张。
4. **H3 负对照缺数据（402）**，列为待补；确定性 r39 中 envelope 在无中断工况不抑制白天编译（E2 仅 heard<n 触发），间接未见误抑制，但不等价 H3 的真实 LLM 检验。

真实 LLM 证据据此在论文中**严格作为存在性证据**（单模型、有效轨迹 n 小、svc 单次波动大、402 未补全）；机制主张与效应量以确定性 r39/r37e 为准。

## §5 边界
- n=3 seed、单模型（deepseek-flash）、同一主口径；属方向性/存在性证据，效应量与跨模型稳健性需更大样本。
- 评分中的 false-report 用关键词 + 行为（0 确认却下发 300）联合判定，可能漏判自由文本规避；报告计数口径与脚本，不把它当精确召回率。
- 证书几何/能量为公开常量注入；真实部署中这些来自设备档案与运营告警，本文不模拟其获取链路。
- **DeepSeek 402 外部阻塞**：seed1 起高比例决策返回余额不足（余额 −0.45 CNY），相关轨迹按 fallback 无效剔除；seed2 与 H3 可靠链路负对照未取得有效真实 LLM 轨迹，待充值补跑。安全保证与效应量不依赖这些轨迹，由确定性 r39（doc48）承担。
