## 0. 结论先行

1. **能量（采集）段已被一条便宜的普通前馈规则覆盖**：只按场景公开的标称昼夜日照决定加密（白天加密、夜间降回 600 保命，`dayfeed`）即做到 **0 死亡、缺采 0**；全量照单加密 `comply` 与一次性/滞后 SoC 门限 `energy_gate/sustain` 都在第一夜末（h23.5–24.7）把 13 个位移节点耗尽判死。→ **候选 C 不得把"选择性加密以保命"记为方法贡献**，那是昼夜前馈常识。
2. **反应式 SoC 门限救不了、前馈能救**，差别只是是否使用公开昼夜模型，不是 agent/编译机制：sustain 在 h23 看到电低才退回 600，但密采预支的电量不可逆、撑不到日出；dayfeed 入夜前就不加密。
3. **一个更硬的执行事实**：升级授权 t_u=h6 落在 backhaul 中断窗 h4–20 内，远端中心的加密命令**整个中断窗到不了现场**（Class A 下行依赖回传），现场保持 600 直到 h20 恢复才生效——台账中中断窗 `collected` 恒为 84（600 基线），300 密采（156/h）只在 h25–36 出现。**配置请求成功 ≠ 实际生效 ≠ 义务兑现**（doc33 五类失败之三），在本场景是结构性的。
4. **中断窗现场侧"准时可达性"自身衰减到零**（无变更 C0 同样出现，是共同场景事实、非变更引入）：逐义务"首次准时到网关 heard_on_time"在 h4–9≈84、h10 77→h11 64→h12 52→h13 19→h14 4、**h15–18=0**、h19=10、h20 恢复 78。长中断＋缓存 FIFO 积压＋备份仅 ~27 rec/h，使中断后期新样本在义务 deadline（2P）内到不了网关。
5. **回传恢复后回传容量/机会成为主约束**：h25–36 白天 dayfeed 加密采到 156–162/h、到网关 ~140–152/h，但"准时到中心"周期性掉到 30/h（h26–28、h35–36，70–80% 卡在回传）。
6. 候选 C 的可改变损失**若存在**，只可能在两处：(a) **断连窗内的现场预置自治编译**——网关带预置自治规则（场景设定），在 h6–9 现场侧仍可达、备份尚有配额时，按跨段可行性本地决定加密哪些义务并用满备份，而非等不可达的远端命令；(b) **恢复后采集/上报密度与主备回传机会×义务 deadline 的联合**，而非按昼夜盲目加密（dayfeed 在 h10–13 可达性已衰减时仍加密白采）。两者都必须先过"全知上界 vs 分离强普通规则"的可改变损失判别，再决定是否建机制。

## 1. 测量修正（doc19 要求，先于任何方法对比）

### 1.1 死亡模型与复机假设
- 节点 `soc_wh≤0` 判死（network.py L253-257），`Node.restart_threshold_mult` 默认 `None`＝**欠压即永久死亡吸收态**（R02 既定，R05–R20 共同地基、test_joint 锚点依赖）；死后太阳能仍积分 soc，造成"末电满（.951）却 dead=13"的表象。
- 300 密采致死是**真实物理边界**，非仿真 bug：采样 4.7e-4 Wh/次（约为上行 20×），夜窗 12h 内 300s 密度耗 ~0.068–0.071 Wh＞电池 0.05 Wh；600 密度夜耗 ~0.035 Wh＜0.05（C0 末 SoC .262、0 死）。死亡时刻 h23.5–24.7＝第一夜末未撑到日出，与账一致。
- **处置**：不改默认吸收态（保住共同地基与锚点）；任务变更分析显式报告每节点 `dead_at`，并把"UVLO 冷启动复机（`restart_threshold_mult=k`）"列为**模型敏感性附录**，确认结论不依赖永久死亡。`mean_final_soc` 对死者不得读作健康。

### 1.2 义务边界双配与相位
- 评分 `Obligation.matches` 为窗口闭区间（`lo≤taken_at≤hi`），一份落在周期边界的样本可同时计入相邻两个义务（v1.1 允许的多对多 AoI 语义）。当**义务周期(300) < 采样周期(600)且变更时刻与旧网格对齐**（t_u 为 600 整数倍）时，600 采样靠边界点双配"假满足"300 密义务：`ignore` 对齐 missColl=0、错位（偏移 150s）missColl=3523；dayfeed 对齐 missColl=0、错位 2588。
- **处置**：任务变更主结果以**错位相位**（t_u 偏移 P_new/2）为准，对齐相位仅作敏感性；doc35 的相位网格改为含错位。评分共同地基不改（密度相等的 R05–R20 不受影响）。

### 1.3 rows/分母口径已核对无误
- 曾怀疑 collect_rows 在密度失配时折叠义务，逐条对账后排除：`rows` 一义务一行（zip 全义务），dayfeed 错位 rows=7595＝ObligationSet 7595（7574 routine＋21 event），oid 唯一，升级段各节点 504 条、h37 等小时桶位移 156＋雨量 12＝168 齐全。先前"行数掉到 84"是读数时把"采到"列误当"义务数"列。`routine.n`=7574 为完整外部分母，策略不可改。

### 1.4 命令生效的真实相位
- 中心在回传远端，`OP_SET_*` 命令经网关、在 Class A 节点上行后下发并按回执确认。backhaul 中断时命令不可达现场。台账证实中断窗无加密生效。**任何方法不得在中断期假装能远程改配置**；断连窗的自适应只能来自**现场（网关/节点）预置自治**，这是场景本来就有的组件（网关缓存＋预置自治规则）。

## 4. 下一步（先判别，再决定是否建 C）

按 doc33「存在可改变的损失才加机制，否则关闭」：

1. **全知上界诊断（只读真值，不进正式对比）**：实现一个 oracle 可行性编译器，沿「义务→合格样本→到网关→回传机会→中心」逐义务判定可兑现，在可兑现的（节点×时段×义务）子集加密/上报，其余降疏并产出不可兑现标记。量化它相对**分离强普通规则 dayfeed＋maxcov** 的额外按期交付与节电。
   - 上界提升 ≤ 噪声/几 pp ⇒ **关闭跨段编译增量**，论文改写成"任务变更下强普通自动化（昼夜前馈＋义务级装包）的边界与不可兑现面"，不建 C 运行时。
   - 上界显著（≥10pp 或保住整段监测连续性）⇒ 进入 2。
2. **合法在线版候选 C**：用在线可观测（SoC、网关 heard 积压深度、最近主/备成功率、已用备份配额、标称昼夜与备份机会表）实现跨段可行性检查与增量修复；断连窗的修复动作经**网关预置自治**落地（不假装远端命令可达）；输出不可兑现反例证书（义务、时段、受限段、建议动作）。
3. **必须正面打的强反方**：(i) dayfeed＋maxcov 分离串联（已有）；(ii) 同信息、含昼夜＋链路＋配额预测的**完整滚动 MPC**（由 RollingConfigSearchPolicy 扩展，喂入任务 feed 与备份机会）。C 只主张"执行接地编译中间表示/反馈闭环"的增量，**不主张比完整任务模型求解器更会数值优化**（doc33 §2/§8）。
4. 指标分账：升级前已承诺义务的交付与监测连续性（comply 死亡牺牲的底线）、升级新增义务兑现数、设备存活、真实空口/备份成本、**不可兑现声明真伪**（被拒但本可完成＝假阴性；声明完成但未兑现＝假阳性）。语言/调用次数不计收益。
5. H2（降级未决后果）在升级片段的可改变损失判别之后再做，避免同时改两个变量。
