## §0 一句话结论

**GO，但贡献的位置被证据重新规定。** 在固定资源、固定授权、可预装/可预知昼夜节律的静态监测
任务下，**节点本地自治（昼夜能量节律 + 义务级 deadline-purge）与网关本地自治（maxcov 装包、
mission-view 门、到达时段归因）已经以零中心命令、零永久死亡达到可达服务面**；任何中心 planner
（规则、可行性 envelope、乃至全知装包）都不能在固定资源下提高按时交付（与 §frontier 的对称
负结果一致，r39 以执行位置维度再次确认）。让中心**无保护地直接控制采样是有害的**（naive
comply 确定性杀死 39/42 节点）。中心 agent runtime 的**可辩护增量因此被严格限定**到本地无法
独立获得的三类职责：运行中**不可预装**授权变更的编译与协商、义务级**结构不可行的提前诚实
声明**、以及跨段一致的处置；其输出必须经一层**确定性可行性 envelope** 约束，且**安全关键的
能量/生存约束最终在节点本地强制执行**（中心下行经回传+Class A 来不及，见 §2）。

## §1 r39：确定性可行性执行层对照（无 LLM）

### 1.1 两个新机制

- **中心可行性 envelope（`envelope.py`，`EnvelopeDecider`/`enforce_feasibility`）**：包装任意
  planner（LLM / comply / dayfeed / MPC），只用 planner 同样合法可见的 center-view（节点已确认
  配置、近窗听到节点数 `n_heard`、外生要求、当天时刻），把 doc47 文本证书 v4 中**有确定物理/
  协议依据**的硬约束机制化为动作过滤：
  - **E1 夜间能量硬门**：hod∈[18,24)∪[0,6) 全节点钳 sparse，并对当前 dense 节点显式降级；
    [16,18) 临近夜不新开/不留 dense（压过任务等级与任何"恢复"）。
  - **E2 控制面确认门**：白天升级窗 [6,16) 内，`n_heard<n`（主回传未对全部节点恢复，或仅备份
    部分送达）时，未确认 dense 的节点不得升级——命令此刻不可达，发了也不生效。
  - E3：非升级段（blue）自然 sparse。
- **节点本地能量自治门（`network.py`，默认关闭）**：`local_floor=True` 时节点每 tick 用**本地
  时钟**在夜间把采样/上报钳回 sparse、日落自动降级，不依赖任何中心下行；`local_dayfeed=True`
  额外在白天按**预装/已到达**任务表本地执行授权节律（零中心命令）。它建模场景中"网关/节点
  预置自治规则"，不是新增能力。

### 1.3 三个决定性发现

1. **无保护的中心直接控制确定性致命。** comply（升级后全程 dense）在三个种子各死 13/14 节点
   （总 39），服务腰斩到 0.16，且产生 2488 条被拒命令。这无需 LLM 即可复现 r38 中 A0 的灾难。
2. **中心侧可行性 envelope 不能独自保证紧能量生存。** env-comply 把无效命令从 2488 压到 298、
   在 seed0/2 零死亡，但**最紧能量的 seed1 仍死 12 节点**；中心下发的 dayfeed-c 同样在 seed1
   死 12。根因见 §2（不是 planner 不聪明，是下行回路物理时延）。
3. **节点本地能量底座把死亡清零（39/12 → 0），且不牺牲服务。** 任一中心臂加 `local_floor`
   后三种子全部零死亡，服务维持 0.36–0.37。

## §2 执行位置原则（locality of safety）

r39 seed1 是关键反例。节点昼夜节律要求日落（hod 18）由 dense 切回 sparse；整夜 300s 密采约耗
0.071 Wh > 0.05 Wh 电池（吸收态欠压即永久死亡）。中心侧的夜间降级**命令**必须经
`中心 → 蜂窝回传 → 网关 → Class A 接收窗` 才在节点生效；主回传中断/几何丢包 + Class A 仅在
节点上行后开短接收窗，使该命令在能量最紧工况下来不及在日落前生效，节点以 dense 过夜耗尽。
**同一条可行性约束（"夜间不得 dense"）放在中心是建议/迟到命令，放在节点本地是每 tick 强制执行
的不变量。** 这与 selective purge 的结论同构：节点本地 `deadline-purge` 零下行、且略优于网关
`cert-purge`（doc44/46）。

**原则：安全关键、时间关键的可行性约束必须放在物理上能及时执行的位置（节点/网关本地）；中心
runtime 不应、也无法靠更快的实时下行替代本地安全自治。** 场景本就设定"带缓存与预置自治规则的
网关"，本地能量门是对该既有设定的建模，而非为救方法新增的机制（默认关闭时全部既有测试逐位
不变）。

## §3 pure-local 对称上界：静态调度子空间关闭

`pure-local`（节点本地预装昼夜能量节律、零中心命令、网关 maxcov/节点 deadline-purge 维持既有
自治）三种子 **0 死亡、0 条中心命令、svc 均值 0.3600（.317–.387）**。

- 它与所有"中心编译 + 本地底座"臂（0.359–0.368）服务**无实质差别**（差异 <1 点，落在种子波动
  内）；`local-full` 与 `pure-local` 服务**逐位相同**，但前者中心 comply 多发 1274/2354 条
  sent/refused——证明在静态可预知任务下**中心采样命令完全冗余，只增代价**。
- dayfeed-c 无底座时 svc 名义最高（0.3695）但以 seed1 12 个永久死亡为代价，不可接受；其"高
  服务"是杀死节点前的短期密采，不是可生存工作点。
- 采集侧：pure-local 缺采最少（2016，白天按授权密采），缺交最多（2822）；中心 envelope 臂
  中断期抑制密采，缺采多、缺交少，总 svc 接近——**最终瓶颈是回传容量而非采集决策**，与
  §frontier 的 \scap/\stime 墙一致，再次说明中心在采集/调度上无可榨取的固定资源增益。

**据此对称关闭的候选**（有上界背书，符合"普通组合覆盖即关闭"的预注册纪律）：
- 中心 planner 在**静态、可预装、昼夜可预知**任务下提高采样/上报/装包吞吐或生存——**关闭**
  （pure-local 本地对称上界 + §frontier 全知装包上界双重背书）。
- "用更聪明的 LLM/MPC 做夜间能量决策"——**关闭为中心侧问题**；确定性本地不变量即解，且更可靠
  （§4 文本证书不保证、本地门保证）。

## §4 r38 真实 LLM 证据：为什么需要执行机制而非更强提示词

DeepSeek-flash（temp 0）三臂严格对称（同 `AgentMissionPolicy`、同 center-view、同工具建议、同
动作空间，唯一差别是 user prompt 末尾信息块：A0 无结构清单/无证书；A0-structured 加未决命令
工程清单；A1 再加义务链证书）。欠费前**有效**轨迹（无效=该次决策高比例 402 走保守回退，剔除）：

| 批次/种子 | A0 svc/死亡/谎报/不可行登记 | A0-structured | A1+证书 |
|---|---|---|---|
| 证书 v1 先导 seed0 | .165 / **13** / 谎报4 / 4 | .158 / **13** / 谎报6 / 4 | .323 / **0** / 谎报1 / 17 |
| 证书 v3 seed0 | .413 / **13** / 谎报7 / 13 | .431 / **13** / 谎报5 / 13 | .399 / **0** / 0 / 28 |
| 证书 v3 seed1（最紧） | .266 / **13** / – | – | .323 / **13** / 0 / 29 |
| 证书 v4 seed0 | .427 / **13** / 谎报3 / 12 | .164 / **13** / 0 / 10 | .381 / **0** / 0 / 23 |

- **死亡数高度稳健、svc 单次波动大**：A0/A0s 共 7 条有效轨迹**全部 dead13**；A1+证书在 seed0
  三次（v1/v3/v4）全 dead0，但 **v3 seed1 仍 dead13**。
- 工程清单（A0s）单独**不**救场（增益来自证书而非工程记忆）；但**纯文本证书不保证**——它在
  "主路深夜恢复"许可下被模型违反（午夜编译 dense、整夜保持），且 temp0 跨运行有轨迹方差。
- 备份数据面**伪恢复**反直觉发现：北斗备份腿在中断期仍把零星上行数据送到中心、更新 n_heard，
  但它是现场→中心的数据腿，**不交付中心→现场的下行命令**；v1 证书据此误判"backhaul live"而
  compile（该命令被拒未致死，但评分器真阳性捕获）。v2 改以"命令未确认 applied<n"为锚，v3 三态、
  v4 夜间硬门，逐版有独立物理/协议依据（doc47）。

**结论**：文本证书把通用 agent 的致命错误大幅降低但**不跨种子保证**；跨种子保证生存的是 §1 的
**确定性本地底座 + envelope**。这正面回答了 doc38 的担忧——不能把 agent 的正确性寄托在提示词
遵从度上。

## §5 冻结的分层可行性 runtime（论文系统主张）

- **L0 节点本地（零信令安全底座）**：昼夜能量门（夜间强制 sparse、日落自动降级）；义务级
  deadline-purge（释放已过绝对截止期的未确认记录、保留一切可挽救记录）。保证：不发生不可逆
  死亡、缓存不被死记录占满。
- **L1 网关本地（现场自治）**：maxcov 备份装包；mission-view 非预知发布门（任务表随主回传可达
  增量到达，杜绝网关提前按未来义务选包）；任务表到达后的逐义务段归因；中断期自治。
- **L2 中心 agent runtime（只做本地无法获得的事）**：① 运行中**不可预装**授权变更的跨层编译
  与合法重编译/协商（DZ/T 0460 §5.3.3/§8.4.2，agent 不判滑坡风险）；② 编译期**结构不可行证书**
  （无回程槽的 \stime 几何判定，100% 灵敏、0 误报、中位提前 7.2h）与三类声明纪律（已完成/当前
  不保证/在述条件下不可行，不可行须乐观模型也失败）；③ 跨段一致处置与对外诚实声明/请求加配额
  或会商降级。其动作经**确定性 envelope（E1–E3）**钳制，不能绕过 L0/L1 安全。
- L2 在静态可预知部分**无吞吐增量、且应默认静默**（pure-local 已最优）；它的价值是需求变化时
  的可靠编译 + 让系统"承诺的=能兑现的，不能兑现的提前、精确说明原因与所需资源"。

规则/MPC/求解器同样从 L0/L1/envelope 获益——这是**通用通信执行层**贡献，不要求 LLM 不可替代
（符合既定主旨）。

## §6 agent 增量的最终边界与未关闭项

已对称关闭：静态/可预装/可预知昼夜下的采样-上报-装包吞吐与生存中心增量（§3）；中心侧夜间能量
决策（§2/§4）。

**仍开放、且是 L2 唯一值得继续的经验问题**：运行中**不可预装**授权变更（升级 + 降级/解除）在
中断—恢复过渡中的编译。现有证据已覆盖其两面的大部分：
- *不可达面*：任务表与中心命令共用主回传，中断期网关/节点都无法获得新授权，现场合法执行旧
  任务——物理不可达，任何 planner 无解；论文 RQ2 已量化（2136 条 yellow 义务在表 t20h 到达时已
  过期，网关据本地完整日志 100% 段归因），结构证书提前声明。
- *可达面*：任务表一旦到达，节点本地按表执行即达 pure-local 工作点（§3）；自然落地是**网关经
  本地 LoRa 转发/编译**（不经中心长回路，规避 §2 的下行时延）。
- 未被一个完整三位置（中心长回路 / 网关本地 LoRa / 节点预装）对照实验直接量化的，是*降级/解除
  时机延迟*与*在途命令跨代混配、旧配置物理后果残留*对服务/能耗的边际影响。本轮判定其为
  **L2 设计命题 + future work**，不再开大实验：r39 已显示在公平信息与本地安全底下中心采样命令
  冗余，过渡一致性的工程机制（世代/版本、依赖、局部重规划）在 SDN 一致更新文献中成熟，不构成
  独立新机制主张。

## §7 限制、外部阻塞与复现纪律

- **DeepSeek 402（外部阻塞，非方法）**：余额 −0.45 CNY、is_available=false。r38 全量（v4 证书下
  seed1/seed2 三臂、可靠链路负对照）未取得有效真实 LLM 轨迹；需充值后用
  `python3 code/v3joint/r38_agent_three_arm.py 0,1,2 3 1` 补跑。现有 LLM 结论是**存在性证据
  （单模型、有效轨迹 n 小、svc 单次波动大）**，效应量以确定性 r39 为准。
- r39 为 n=3 种子确定性对照（主口径），死亡是确定性/高稳健量；服务均值差 <1 点不主张显著。
  更宽部署区间（备份频度/载荷、节点规模、cap、云遮、复机阈值 k）未扫。
- 本地门默认关闭，关闭时逐位一致（5/5 含 bit-identical、18/18）。`pure-local`/`local-full`
  对应"预告/预装"合法实例（mission_view 明示的两种实例之一）；"运行中增量到达"由 mission-view
  门在网关选包侧实现，节点采样侧的网关本地 LoRa 三位置对照留作 future work（§6）。
- 标准取文渠道与未核实国际文献的限制沿用 doc44–47，未变；本文不新增任何未经核验的外部数字。
