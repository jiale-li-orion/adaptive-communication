# doc44 — E2 执行层可行性证书：deadline-aware 选择性核销（2026-09-18）

> 承接 doc43（E1/E3＋联合上界收尾）。本文关闭 doc43 §6 开放的 **E2 端到端 conformance 定量账**，
> 并在过程中得到一个比原计划更强的正向机制结果。**场景、主口径、义务链、判据一律未换**：
> 灾前山区地灾监测、LoRaWAN Class A、网关现场自治、供电受限、蜂窝主＋北斗短报文备间歇回传。
> 本轮**零 LLM**（机制层全部由确定性规则实现）；agent 实验仍只引用 doc43 的 r36 existence proof。

## 0. 结论（GO，且为正向服务增益）

**义务级可行性证书在现场执行层的兑现，是一个"deadline-aware 选择性核销"动作**：
对**已过义务截止期、被证明不可挽回**的未确认边缘记录，停止持有与自动重传，把受限的接入批次
与能量让给**仍可挽救**的新鲜样本；同时**严格保留一切未到期记录**。

- 同一判定有两个等价部署位置：网关集中式 `cert_purge`（不花备份资费发送、但本地 ack 核销），
  与节点本地 `deadline_purge`（零下行、零信令、用设备已知的公开义务节奏）。**两位置同判定、同结果**，
  节点本地版甚至略优——机制是**位置无关的执行层原则**，不依赖 agent/网关特权。
- 主口径（seed0）相对强基线 `maxcov+fifo`：中断期升级义务 on-time 交付 **202 → 434（+115%）**、
  全时段服务 **.4001 → .4321（+3.2 点）**、中断期过期备份 **219 → 0**、发送承诺 precision
  **.544 → 1.000**，备份字节基本持平（5848 → 5826 B）。
- **留出 seed 6/7/8（全程未参与开发）方向一致且更强**：全时段 svc 分别 +5.6 / +4.4 / +3.7 点，
  中断 on-time 提升 2.2–3.4 倍，过期清零。非单 seed 偶发。
- 强反方全部实测：普通义务感知队列 `obligation_greedy`/`edf` **无增益**（只重排、不释放缓存）；
  AoI 标准 `latest_only` 拿到中断新鲜度（431）却**无差别丢弃、全时段 svc 跌到 .3630**。
  **增益来自证书的"选择性"（只核销被证明不可挽回的），不是"丢得越狠越好"。**

这把 doc43/r35 侧记的"45.6% 备份资费花在过期记录上"从一个**成本抱怨**升级为一个**机制贡献**：
可行性证书在编制侧抑制过度承诺（S_time 不可行证，precision 1.0、零假阳），在执行层把"已确定
失约"转成精确的边缘状态处置；两端是同一个"义务可行性"抽象。

## 1. 起点：E2 要回答什么

doc43 用对称物理墙（r34）证明第一性失败是**任务/命令不可达**而非能量或回传容量，论文主张因此
定为"承诺-执行一致"。但当时只有侧证（r35：中断期 480 条经备份送达，on-time 261 / 过期 219，
45.6% 资费花在过期记录；r36：agent 命令风暴）。E2 要一条完整的 promise-vs-fulfillment 账：

1. **编制侧**：中心在 h6 授权升级时，对中断期升级义务（release≥6h、deadline≤20h，n=2338）
   作的承诺，终局兑现多少？
2. **现场侧**：网关备份选包器"隐式承诺每条发出记录可按期交付"，端到端兑现多少？
3. 若抑制过期发送，是否真如 r35 离线估计的"净节省、零服务代价"？

脚本 `r37_conformance.py` 在同一主口径各跑一次真实 `run_joint`（非离线循环），三档选包对照，
并离线核算编制侧承诺精度。

## 3. 现场侧三档与一个真实跨层耦合（r37、r37b）

主口径 seed0（n=7560 全时段；中断期升级义务 n=2338）：

| 选包器 | 全时段 svc | 中断 delivered | 备份(包/记录/字节) | 中断经备份 on-time / 过期 | 发送承诺 prec |
|---|---|---|---|---|---|
| **maxcov**（强基线，过期样本补满） | .4001 (3025) | 202 | 75 / 750 / 5848 B | 261 (1512 B) / **219 (1270 B)** | **.544** |
| **salvage**（激进抑制 dl≤t＋冗余抑制） | .3972 (3003) | 193 | 56 / 521 / 4140 B | 252 / 0 | 1.000 |
| **maxcov_ontime**（只停阶段2过期补满，阶段1与 maxcov 逐位相同） | .3976 (3006) | 194 | 56 / 522 / 4146 B | 253 (1466 B) / 0 | 1.000 |

**预期"净节省"被端到端证据推翻**：maxcov_ontime 省了 1702 B（29.1%）、过期清零、precision→1.0，
但中断 on-time **少了 8 条**、全时段 svc **−.25 点**。salvage 更少 9 条。这不是口径 bug、也不是
RNG 伪影——`r37b_diff.py` 把丢失样本定位到 sid 级，并由源码确认机制：

- 9 条样本（n00/n01/n02/n05 displacement、gw0 rainfall，taken 42000–50400 s＝h11.7–14）在
  maxcov 下 taken 当刻即 heard，并在当刻 r1200 备份槽即时送达、黄级 on-time；在 maxcov_ontime
  下 **heard 被推迟到 72600/73200 s（h20 主路恢复后）**，dropped=None。
- 源码链：节点 `Node.batch()` 默认 FIFO 取 `cache[:32]` 最老**未确认**记录重传（network.py
  Node.batch）；记录**只有在中心收到时才同步 ack 清节点缓存**（`Instance.tick` 对每个转发样本调
  `nodes[...].ack([sid])`，network.py:750-757；注释明示"本实例的 ack 是中心收到时同步施加、
  不占空口，对所有纪律同等有利"）；**heard 到网关不清缓存**。
- 于是：maxcov 连过期记录一起备份送达 → 顺带 ack 清空节点未确认缓存 → 新鲜样本及时进入批次被
  heard；maxcov_ontime 不发过期记录 → 这些记录不被 ack、滞留节点缓存 → FIFO 每拍以"最老未确认"
  身份占满 32 个批次名额反复重传 → 新鲜样本 heard 被拖到 h20 后旧记录批量 ack。
- 网关 `gateway_pending` **无容量上限**（joint_plane 直接重组赋值），有 240 FIFO 溢出的是**节点
  cache**（network.py cache_slots=240、溢出丢最老）。故根因在**接入段的确认/重传**，不在网关缓存。

**研究含义（本节最关键的一句）**：在"中心收到才确认、未确认即 FIFO 重传"的标准链路语义下，
**"少发钱"若不配合义务感知的缓存/重传核销，只是把成本从回传段搬到接入段**。正确机制不是简单
停发，而是对确定不可救记录**显式本地核销**（等价 ack、不花备份资费）。这同时修正 doc43/r35 与
LaTeX v0.1 §6.3 的"抑制过期不挤占 on-time、净节省"表述——端到端并非零服务代价，除非核销做完整。

## 4. 完整机制：cert_purge（网关）与 deadline_purge（节点本地）

**合法信息**：只用样本采集时刻与设备/网关已知的**公开义务节奏** P（`obligation_period_s=600 s`）。
中断期任务表 h20 才到网关，`_sample_obl` 无台账时退化为周期公式 `dl=(taken//P+2)P`（蓝级 600
口径）——现场当时合法可知；黄级 300 的上帝 deadline 仅用于**事后**核算，不假装现场可知。
按 600 口径判过期的记录，其黄级 300 截止更早，故核销**零假阳**（deadline 是绝对量，t 已过 dl
则此后再无 on-time 可能）。

- **`cert_purge`（网关集中式，joint_plane）**：属于 cover 族，阶段1/阶段2与 maxcov_ontime 逐位
  相同（只发 dl>t 的可挽救记录、全过期槽不发空包）；额外在每个备份拍，对网关积压中 **dl≤t 的
  确定失约记录本地核销**——从网关 pending 移除并对所属节点 `ack()`（清节点未确认缓存、停止 FIFO
  重传），**不发中心、不占备份包/资费**，计入新账本 `backup_local_purge`。
- **`deadline_purge`（节点本地，network.Node.batch 新队列纪律）**：每拍发送前，节点用自己已知
  的公开 P，把缓存中 `dl≤t` 的未确认记录移出并按 dropped 记账，其余正常 FIFO 取批。**零下行、
  零信令、零备份资费**，且覆盖从未成功 heard 的记录。它与 cert_purge 是**同一 deadline 判定的两个
  部署位置**；是 `cache_service` 的一个对称新取值（默认仍 fifo，既有取值与全部锚点不变）。

被核销记录放弃的是其**新鲜度义务**（已数学上不可挽回）及其**过期后的回溯分析次级价值**（r35
曾提示）；这是一个明确、可陈述的取舍。工程上可改为"网关本地留存副本、仅停止回传与节点重传"，
不改变 on-time 结论；本文实现取干净的移除。

## 5. 公平归因（r37c，seed0 六档）

| chooser | 节点队列 | 全时段 svc | 中断 d | 备份 on | 过期 | 本地核销 | prec |
|---|---|---|---|---|---|---|---|
| maxcov | fifo（现状） | .4001 | 202 | 261 | 219 | 0 | .544 |
| maxcov | **deadline_purge** | **.4321** | **434** | 480 | 0 | 0（节点本地） | 1.000 |
| maxcov | obligation_greedy | .3922 | 205 | 264 | 216 | 0 | .550 |
| maxcov | edf | .4001 | 202 | 261 | 219 | 0 | .544 |
| maxcov | latest_only（AoI 标准） | **.3630** | 431 | 480 | 0 | 0 | 1.000 |
| cert_purge | fifo | .4302 | 420 | 465 | 0 | 3396 | 1.000 |
| cert_purge | deadline_purge | .4302 | 420 | 465 | 0 | 2804 | 1.000 |

**归因结论**：

1. **普通义务队列纪律拿不到增益**：`obligation_greedy`（.3922/205）、`edf`（.4001/202）只在
   batch 选批时重排/跳过旧记录，**不丢弃、不 ack、不释放缓存**（network.py 注释"旧记录不丢弃，
   只是不占这次机会"），旧记录仍滞留 cache 并最终 FIFO 溢出，瓶颈未除。
2. **AoI 最新优先是"过度治疗"**：`latest_only` 每拍只发最新、丢弃其余，中断 on-time 431 很高，
   但**无差别丢弃了仍可能在主路恢复后交付的记录**，全时段 svc 暴跌到 .3630（最低）。
3. **选择性是增益来源**：deadline_purge 中断 d=434（≥ latest_only 的 431）且全时段 svc=.4321
   （最高，比 latest_only 高 6.9 点、比现状高 3.2 点）——它只丢"被证明不可挽回"的，保留"还有
   机会"的，在新鲜度与覆盖两个目标上同时占优。
4. **位置无关、无网关特权依赖**：节点本地 deadline_purge（.4321/434）略优于网关 cert_purge
   （.4302/420）；两者叠加无额外增益（.4302/420，网关核销数降到 2804，因节点已先核销）。
   说明增益来自 deadline 可行性判定这一**证书逻辑本身**，不依赖集中化、agent 或额外物理能力。

## 7. 对论文命题的意义

1. **可行性证书是贯穿 plan 与 execute 两端的同一个抽象**。编制侧 S_time 不可行证（§2）回答
   "这条义务在任何合法发送下都无法按期兑现"，precision 1.0、零假阳；执行层 selective purge
   （§4–6）回答"既然这条已不可挽回，边缘应停止为它消耗接入批次/能量/缓存，并把资源让给可挽救
   义务"。缺了执行端，证书只是一句解释；缺了证书端，边缘只有 latest_only 这种无差别启发式。
2. **这是通信执行层贡献，不要求 LLM/agent 不可替代**（与 doc33、Astra 历次审查一致）：固定场景
   下规则即可兑现机制并获益；agent/runtime 的角色是在**任务要求变化、多义务竞争稀缺机会、可见
   证据不完整**时，生成并维护这些义务级判定与跨层一致动作（doc33 H1 按失约链路段修复、H2 变更
   保留未决物理后果）。r36（doc43）已给 agent 同体 A0/A1 existence proof；机制层不依赖 agent 反而是
   优点——它界定了"传统自动化已覆盖的范围"。
3. **它修复了一个真实的跨层盲区**：现有应急/DTN 工作在给定网络角色与基础设施内做组合与恢复，
   AoI/采样-传输-能量联合优化（Zakeri 等、Bacinoglu 等）处理新鲜度-能量取舍，但"**义务已被证明
   失约后，接入段的持有/重传与回传段的发送必须被一致地终止，否则成本在两段间转移**"这一
   execution-grounded 一致性原则，及其与"仍可挽救记录必须保留"的配对，在已核验文献中未见以
   义务级可行性证书形式给出。新颖性仍需成稿前按 doc33 检索纪律独立复审（见 §9）。

## 8. 公平性与合法性清单（防"调到赢"）

- **无额外物理资源/资费/信息**：deadline_purge 与 latest_only 同为节点本地零成本动作，只用
  DeviceProfile 既有字段 `obligation_period_s`（edf/obligation_greedy 也用）；cert_purge 复用
  v1.1 既有的"ack 同步、不占空口"简化（该简化原本就让 maxcov 的送达确认受益，非为本机制新设）。
- **对称取值**：deadline_purge 是 `cache_service` 的一个新取值，与 fifo/lifo/latest_only/edf/
  obligation_greedy 地位相同（network.py 明确"所有臂在同一取值下跑，不存在把更好固件只给本文"）。
- **强反方齐全且非 strawman**：maxcov（R20 强基线）、edf（教科书 EDF）、obligation_greedy（义务
  贪心）、latest_only（AoI 标准队列）均实测；负结果（obligation_greedy/edf 无效）如实保留。
- **零假阳可证**：deadline 为绝对量，dl≤t 后无任何 on-time 交付可能；deadline_purge 全时段 svc
  反升，经验上也无误伤可交付义务。
- **判据先写、场景未换、任务未收紧**：主口径与 doc41–43/r37 完全一致；开发仅用 seed0，结论由
  留出 seed 6/7/8 确认。
- 自检：`run_checks.py` **18/18**、`test_joint.py` **5/5**；默认 chooser/队列逐位不变
  （enable_backup=False 与 v1.1 逐位一致锚点仍通过）。

## 9. 局限与必须声明的建模选择

- **ack 不占空口是 v1.1 既有简化**（network.py 注释），对所有队列纪律同等有利；真实 Class A 下行
  RX1/RX2 窗口有限，集中式 cert_purge 的批量确认可能需要位图/多次窗口。**节点本地 deadline_purge
  不需要任何下行**，是更贴合该约束的部署形态，论文以它为主机制、cert_purge 为集中式等价。
- **被核销记录放弃过期后的回溯次级价值**；可改为网关本地留存、仅停止回传与重传（不影响 on-time）。
- **节奏口径**：节点与网关中断期均用公开 P=600 s；黄级 300 任务表 h20 才到现场，中断期内用黄级
  deadline 核算属事后上帝口径（§1 已声明）。h20 后节奏随任务表/命令更新，deadline_purge 用节点
  当前 `obligation_period_s`，多节奏扩展留待任务变更实验。
- **随机样本仍小**：开发 seed0、留出 3 seed（6/7/8）；方向与量级稳定，但成稿前宜补满开发 0–5、
  留出 6–9 并报均值/置信区间。
- 未测边界（沿用 doc41–43 声明，勿当已证）：复机敏感性 restart_threshold_mult=k、能量宽人工况、
  S_cap 逐义务容量竞争的概率证书、可靠链路负对照（outage 开关化）、一条完整义务链反事实时间线。
