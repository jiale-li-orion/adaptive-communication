## 0. 这一步要回答什么

候选 C 的命题是：**把外部变化的监测要求，编译成在现有采集/通信机会/能源约束下能兑现的跨层执行计划，并对无法兑现部分给出结构化反例与增量修复。**

要在仿真里让它成为可证伪问题，必须先有一个**独立于任何候选方法**的任务变更真值层：外部授权在某时刻改变监测要求（加密/降级），义务集合随之改变，而候选方法与所有强反方面对**同一份**义务与同一条外生链路/能源轨迹。本文冻结这一层。两个待分开验证的假说（doc33 §7）：

- **H1（按失约链路段修复正确控制层）**：升级加密时，失约可能发生在"没采到 / 样本在节点 / 已在网关 / 截止前无回传机会"不同段，正确动作不同；错误的编译器会改无法改善该义务的层。
- **H2（任务变更保留未结束的物理后果）**：降级/解除时，旧密配置的在途命令、已采未传样本、已耗能源、已开窗未到期义务仍然存在；只替换一个目标配置不等于完成任务转换。

升级片段 U 主要压 H1，降级片段 D 主要压 H2（两者在同一运行中可先后发生，分析时分账）。

## 1. 标准出处（逐字引用，E 级）

原文：`/home/orion/Communications/audit_raw/dzt0460.txt`（DZ/T 0460—2023 提取件；取文渠道为文档分享站，托管 A 级文档、复制链 D 级，官方 `gi.mnr.gov.cn` 本机 TLS 失败——沿用 doc34 来源分级，条款文本经两条独立副本复核）。

- **§8.4.1 预警等级（L1184–1197）**：预警分一/二/三/四级，分别对应风险极高/高/较高/一般，依次用**红/橙/黄/蓝**标识，一级最高。红色"数小时内大规模发生概率很大"，橙色"几天内"，黄色"数周内"，蓝色"可能性小、数据有一定变化"。
- **§8.4.2.1 级别提高（L1202）**：原文"监测数据显示，短期发生概率增大，**经会商认定后，可以提高**地质灾害预警级别。"
- **§8.4.2.2 降低与解除（L1205）**：原文"监测数据显示，短期发生概率变小，**经会商认定后，可以降低预警等级或解除预警**。"
- **§5.3.3 设备能力（L444）**：原文"监测仪器应具备双向通信和远程调试功能，**可根据预警等级动态调整采样与上传频率**。"
- **§5.3.6 供电（L449–453）**：太阳能板与蓄电池匹配、无日照至少连续工作 30 d；一次性电池低功耗仪器在"**1h 采集和上报一次**"频率下电池至少供一年。**这是标准文本中唯一出现的具体周期，语境是续航测试基准，不是强制工作频率。**
- **§5.3.7 双模（L454–456）**：地面公网信号覆盖不佳、地灾危险等级较高、极端天气易发地区"应采用地面公用网络与卫星通信相结合的双模通信方式"。

**由此确定的授权链（E）**：存在四级预警；升级、降级、解除都是**外部会商认定后**下达的合法动作（Agent 不判滑坡风险）；现场设备被要求具备按预警等级**远程动态调整采样频率与上传频率**的能力（两个独立字段）。

**标准没有给的（不得编造，doc33 §8）**：每级预警对应的具体采样/上报周期数值；变更发生时刻、提前通知量、相对通信机会的相位；一次任务中变更次数/频度；升级是否伴随预算或备份配额变化；变更作用的节点/测项范围；从会商到命令实际生效的延迟。这些全部是 **A（研究选择）**，见 §3，须显式声明、系统取样，禁止杜撰"红色预警预算削减 30%""关键节点权重""每 10 分钟变更一次"。

## 2. 两个冻结片段

仿真任务时长沿用 v1.1/v3joint 主表：48 h（+1 h tail），14 台（网关 gw0＋n00–n13 位移，网关雨量；节点数以 v1.1 manifest 为准，主表 14）。外生回传中断（h4 起 16 h）与采能（solar peak 0.03 Wh/h、初始 SoC 1.0）沿用 BASE，**不随片段改动、不手挑与变更有害交错的中断**（相位系统取样见 §5）。

### 片段 U（升级，压 H1）

- 调度表（采样/上报**要求**周期，A）：`[(0, 600, 蓝/常态), (t_u, 300, 黄/加密)]`。
- 初始 600 s 是 R05 已验证的能量可行工作点（grid600x600：svc .984、采集缺数 1、末 SoC .265）。
- 升级目标 300 s 取自同一已扫描网格（grid300 档），**不是为结论新造的频率**。采样单价约为上行 20×（sample_wh 4.7e-4 vs UPLINK_WH 2.33e-5 Wh），加密采样使主要能耗近似翻倍；在 solar peak 0.03 的弱采能下，全节点 300 s 是否全程能量可行**不在此断言**，由顺序2在共同模型实测（这正是"合法升级但可能不可全量兑现"分野的来源）。
- 作用范围（A，作为实验变量，非手挑权重）：U-all＝全部位移节点＋网关；U-sub＝一个预先固定的节点子集（按拓扑/位置规则在冻结表中列定，不按运行结果挑选）。
- 升级**不**附带任何杜撰的备份预算增量；备份容量/速率沿用场景档位（78 B/1200 s 或 200 B/78 s）。若加密产生的额外义务在既有备份腿上无法全部兑现，这是真实反例，不是被操纵的约束。

### 片段 D（降级/解除，压 H2）

- 调度表（A）：`[(0, 300, 黄/加密), (t_d, 600, 蓝/回落)]`；解除变体 D-off 为 `[(0,300,黄),(t_d, P_relax, 解除/更疏)]`，P_relax 取已扫描的 1200/1800 s 之一（顺序2冻结其一）。
- 初始即处于加密态，t_d 经会商回落。检验：t_d 时已开窗未到期的密义务（release<t_d、deadline>t_d）仍须兑现；已采未传样本、在途/未生效的配置命令、已消耗能源不被"版本号更新"清空。
- D 不允许控制器通过删除旧义务或重标旧数据来"完成转换"；旧义务的兑现计入同一固定外部分母。

### 无变更负对照 C0

同种子、同外生链路/采能/中断，调度表单段恒定：`[(0,600,蓝)]`（与 U 初始一致）与 `[(0,300,黄)]`（与 D 初始一致）。单段恒定走 `routine_obligations_by_node` 原路径，义务集合与现有 v3joint **bit-identical**（已由 r21 单测断言），保证变更场景与既有 R05–R20 结果严格可比。

## 4. 独立义务生成规则（已实现并单测）

新增 `exogenous.piecewise_routine_obligations(measurands, hours, schedule)`：

- 每段以**段起点为新网格**，按该段周期生成义务（对应新配置在 Class A 生效延迟后起效）；
- 升级后新义务按密周期开窗；**变更前已 release、deadline 未到的旧疏义务由其 release 所在段保留**（H2 真值层）；降级后旧密义务保留到各自 deadline；
- 义务只由外部授权调度表决定，**任何策略/Agent 不能增删义务分母**（v1.1 §5.1）；
- 单段恒定调度委托 `routine_obligations_by_node`，无变更负对照 bit-identical；
- 多段 oid 含绝对 release 秒（`:t{rel}`）保证跨周期唯一，评分只依赖 node/measurand/window。
- 事件义务 `rule_obligations_for_truth` 与现状一致、照常叠加，不受变更影响。

单测 `code/v3joint/r21_piecewise_obligations.py`（15 断言全过）：单段委托数量/oid/window/deadline 完全相同；升级 4h@600＋44h@300 每节点 24＋528 条、跨变更点旧义务 deadline=15000 保留、首密义务起于 t_u 窗口 300；降级 4h@300＋44h@600 为 48＋264 条、release=14100 密义务 deadline=14700 跨过 t_d 保留；集合内 oid 唯一、窗口等距无缺漏。

**注意（顺序2实现边界）**：生成器只冻结"哪些义务有效"。H2 所需的**运行时未决物理后果**（在途命令、已采未传样本、已耗能）由仿真状态承担，顺序2的控制器/编译器必须读真实状态、不得假设版本一切换世界即重置。

## 5. 相位取样（外生，不手挑交错）

变更时刻相对**中断窗（h4–h20）与备份机会相位**系统取样，固定一组相位（A，但预定不调）：

- 对 U：t_u ∈ {中断前(h2)、中断早期(h6)、中断中期(h12)、中断晚期(h18)、恢复后(h22)}；
- 对 D：t_d 取同组相位，并保证 t_d 前加密态持续足够长（≥4 h）以产生未决后果；
- 备份机会相位（78 B/1200 s 或 200 B/78 s）由既有随机/周期过程决定，不为变更对齐或错开；
- 每相位跑开发种子 0–5，保留种子 6–9 做留出；报告跨相位×种子的分布，**不挑最有利相位**。

## 6. 顺序2 的对照、判据与关闭条件（预告冻结）

**臂（同能力、同义务分母、同外生轨迹）**：

1. **固定基线**：全程固定 600/300（C0 两条），不响应变更（用于量化"忽略变更"与"无条件照单全收"的代价）。
2. **最便宜强反方 S0（doc33 §9 顺序2 首要）**：每次变更到达，**重算一个普通固定工作点**——在当前外生条件下用网格搜索找能量可行的最优固定 (采样,上报)，全节点套用，配**最强选包器 maxcov/cover2**（R20 选定）。不含跨段状态、不含 LLM。
3. **完整强反方 S1**：同信息 shadow＋完整执行历史＋周期重规划、带执行延迟/未决效果状态估计的**滚动 MPC**（doc19/ODP 一脉，修正 doc19 指出的紧急分支恒假、逐义务而非阈值余量）。
4. **候选 C**：编译/修复——H1 按失约链路段选择控制层（采集配置 / 节点上行 / 网关回传 / 不可兑现声明），H2 保留并增量修复未决物理后果；输出计划＋不可兑现反例证书（哪条义务、哪个时间区间、哪段能力受限、改哪部分才可能改变结果）。
5. 理想可靠回传（enable_backup 且无中断）作可达性参考（非严格上界，沿用 doc34 措辞）。

**业务指标（独立 scorer，语言/调用次数不计收益，doc33 §8）**：固定外部义务的按期交付率、缺采率、末 SoC/死亡数、空口/备份记录数与包数；**错误完成声明数、不可兑现声明的真伪（被拒但本可完成＝假阴性；声明完成但未兑现＝假阳性）**。

**晋级/关闭（先写定）**：

- 若 **S0（变更重算固定点＋最强选包）已覆盖** U/D（候选 C 无公平差额，置信区间跨 0），则**关闭编译机制增量**，把 maxcov/固定重算作为答案写论文（"强普通自动化已覆盖任务变更"本身是可报告结论），不建设 C 运行时、不扩系统。
- 仅当存在**可达历史**：标量 AoI/SoC 相同但记录位置/期限/执行机会不同、合理动作不同，且 S0/S1 做错段、C 用一个合法改变挽回义务（H1）；以及降级时 S0/S1 丢失未决后果而 C 保住（H2）——才晋级顺序3（真实 Agent 前后对比）。
- **禁止靠"保守拒绝所有升级"赢约束指标**：拒绝必须针对真实不可兑现段，且以"被拒但本可完成"假阴性计数约束；禁止为救 C 改紧任务、改判据、换场景、调到赢。
- 消融须有分支/行为见证（doc33/核心教训）：新增任何机制先单机会 trace 证明它真进目标分支并改变动作，再上统计。
