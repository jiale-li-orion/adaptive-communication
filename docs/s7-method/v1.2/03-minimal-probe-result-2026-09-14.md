## 0. 结论（先给）

**主例（标准工作点：速率 120 s/条、每包 K=9 条义务样本；主档 P1 回传中断 [4h,7h)；20 开发种子）**：

* **P-A 成立**：加一条受限备用短报文链路（failover）相对 `primary_only` 稳健多交付
  **+3.95 条/672（+0.59 pp）**，配对 bootstrap CI **[2.85, 5.10]**、Student-t CI **[2.72, 5.18]**
  均排除 0，**17/20 种子为正、0 为负**，平均每个备用包净换回 **1.10 条**（≥ 0.5 效率门槛）。
* **P-B 不成立**：五个 chooser（盲目序 / FIFO / 最新优先 / **EDF** / 机会感知）在主例**逐义务完全相同**，
  best−worst = **0.00**。
* **⇒ 三分支判定 = 分支②：`FAILOVER_TRADITIONAL`。** 备用链路是**有价值的工程冗余**，
  但"在这条稀缺机会里装哪几条**同权**义务"**被一条 1970 年代的经典规则 EDF（最早截止优先）吃到顶**，
  不需要预测、不需要语义、更不需要 agent。**按 02 号文解读上限，不得写"首次提出 / 新机制 / Agent 必要"。**

**16 格灵敏度（速率 {30,60,120,300} s × K {1,4,9,16}）没有推翻、反而解释了主例**：选择自由度只在一条
**"稀缺走廊"**（K=4/9、机会相对积压既不太宽也不太窄）里统计可检出，且：① 量级极小（**0.6–2.4 条/672，
≤ 0.36 pp**）；② **EDF 与"看主链路历史预测恢复"的机会感知策略逐义务 100% 相同**；③ EDF 比盲目序多救的
**全部是 `h* = deadline` 的"压线"义务**。容量放宽（K=16）无需选；容量极窄（K=1）则选了也救不动（效率跌破
0.5 门槛、P-A 自身不成立）。**结论不依赖单一工作点：在标准给的真实工作点及其邻域，"选谁"都不产生有意义的
智能需求。**

## 2. 实现与正确性锚点

**防火墙（doc 66 §6）**：`code/v2probe/` **只 import** v1.1 的 `one_seed(obligation_ledger=True)` 读逐义务
台账，不改 v1.1 任何文件；备用链路是台账之上的纯内存叠加。每个 (档,种子) 只跑一次 v1.1，六臂×16 格复用同一
台账，保证配对严格。

**三个正确性锚点（全部硬通过）**：

1. **`primary_only` 逐义务 == v1.1 台账交付**：三档 ×20 种子 `anchor mismatch = 0`（不一致即 `raise` 退出）。
   这保证叠加层没有篡改主链路结果，备用效应是干净的"增量"。
2. **failover gate ≡ 并行上界**：主例三档五 chooser 的 final 与 packets 在两种模式下**逐位相同**。
   机制：主链路 up 小时 v1.1 `backhaul_forward()` 当拍全量清空积压（`opportunity.py:419`），备用池本来就空，
   gate 拦掉的机会没有可发对象——**这同时反向验证了 v1.1 结式 `delivered=1[h*≤B(d)]` 在叠加层成立**。
3. **自检 30/30、全仓 `run_checks.py` 18/18**：覆盖锚点、容量守恒、备用不减少交付、chooser 排序正确、
   **机会感知不偷看未来**（仅 >t 不同的历史在 t 排序必须相同）、速率/K 单调性、已确认不占槽、过期不发、统计方向。

## 3. 主例结果（120 s/包，K=9，20 种子；分母 672 条/种子）

| 档 | primary 交付 | 五 chooser 交付（**主例全部相同**） | best−primary [bootstrap] / [t] | W/L/T | 包数 | 净换回/包 |
|---|---|---|---|---|---|---|
| P0 无中断 | 496.20 | 500.75 | **+4.55** [3.30, 5.85] / [3.18, 5.92] | 17/0/3 | 3.95 | 1.15 |
| **P1 回传[4h,7h)** | **392.05** | **396.00** | **+3.95** [2.85, 5.10] / [2.72, 5.18] | **17/0/3** | 3.60 | **1.10** |
| P2 接入[4h,7h) | 399.75 | 409.55（盲目序）/ **409.85（EDF=opp）** | +10.10 [5.30, 15.70] / [4.41, 15.79] | 16/0/4 | 3.90 | 2.59 |

**P-B（best−worst chooser）**：P0/P1 恒 **0.00**；P2 仅 **0.30**（bootstrap [0.05,0.60] 但 **t 区间跨 0**，
按"两区间都排除 0"的冻结口径**判不成立**）。

**必须如实写出的另一面——备用只捞回零头，大头在更前面**：主例下每种子仍有大量义务**任何策略都救不回**
（`expired_unsent`：P0 175.8、P1 280.0、P2 272.2 /672）。这些是 `h*` 本身就 ≥ deadline（采集/上行来不及，
或到网关即过期），**网关级备用在结构上够不到**——与 v1.1"大 loss 在 B(d) 之前"一致：加备用链路只补
网关→中心这一跳的边际，不治愈采集/接入段损失。`wasted_on_recovered`（装时以为要救、主链路后来自救）
20 种子累计 205–238 条，说明 chooser 无法预知主链路恢复、重复发送占了多数包位，但因为**净换回仍为正且
每包 ≥1 条**，failover 作为工程冗余依然成立。

## 4. 灵敏度相图：选择自由度是一条窄"稀缺走廊"，且量级 ≤0.36 pp

主档 P1 的 16 格（数字＝20 种子均值；P0/P2 同构，完整表见 `results/v2probe_minimal.json` 与
`attribute_chooser_gap.py` 可复算）：

| 速率\K | K=1 | K=4 | K=9 | K=16 |
|---|---|---|---|---|
| 30 s | PA +5.95，**PB 0**，eff 0.33（P-A 不达效率门槛） | PA +9.45，**PB +1.55**[0.95,2.15] | PA +9.65，**PB +0.70**[0.30,1.15] | PA +9.65，PB 0 |
| 60 s | 与 30 s 逐位相同 | 同 +1.55 | 同 +0.70 | PB 0 |
| 120 s（主例列） | PA +3.55，eff 0.24，P-A 弱 | PA +3.95，PB +0.05[0,0.15]（**不成立**） | **PB 0（主例）** | PB 0 |
| 300 s | PA +5.95，PB +0.35[0.15,0.55] | PB +1.55 | PB +0.70 | PB 0 |

**三条规律**：

1. **K=16（容量宽）PB 恒 0**：一个包能装下整个待发池，排序无对象。
2. **K=1（容量极窄）P-A 自身弱/不成立**：每包 1 条、被 failover gate 限在主链路 down 小时，净换回/包
   0.24–0.57 跌破 0.5 门槛——**太窄时"怎么选"都救不动，选择自由度没有业务价值**。
3. **只有 K=4/9 的中间走廊 PB 统计可检出，且 best−worst 仅 0.6–2.4 条/672（P2 最大 2.40，≤0.36 pp）**；
   对速率近乎不敏感（30/60 逐位相同、300 同量级），因为争用只发生在"压线义务"截止期附近的那个机会，
   只要速率 ≤300 s 都能覆盖到，再快不改变结果。

**⇒ 不存在"越稀缺、智能越重要"的单调故事**：相图是**两端退化、中间一条低幅走廊**的形态，走廊里的微弱
差异又被 EDF 吃掉（§5）。主例 (120,9) 落在走廊的**宽松侧、PB=0**，是标准数字（≥60 s、≤200 B）派生的
真实工作点，不是为得到某结论挑的点。

## 5. 机制归因：为什么 EDF 已经到顶（`attribute_chooser_gap.py`）

1. **EDF ≡ 机会感知，逐义务 100% 相同**：在 PB 最大的两格（P1，r300/K4 与 r30/K4）×20 种子，
   `backup_edf` 与 `backup_opportunity` 的逐义务交付集合**全部相等**。机会感知额外使用了"截至 t 主链路
   up 经验率 × 剩余小时"去估计"现在不发会不会丢"，**增量为零**。
2. **EDF 比盲目序多救的，全部是压线义务**：所有被 EDF 救、盲目序（oid 序）漏掉的义务，**无一例外
   `h* = deadline`**（样本在截止期那一刻才到网关，必须在当次机会立刻发出，下一次就过期）。例：seed0
   `n07:routine:00001`（release 900、deadline 2700、`h*=2700`）。盲目序按 oid 先装别的、占掉 K=4 槽位，
   压线者错过；EDF 按 deadline 升序先装它。**这是单资源、已知确定截止期、同权作业的经典争用，EDF 最优
   是定理级的，不需要对主链路未来的任何预测。**
3. **主例为什么 PB=0——池规模证据**：P1 主例 72 个非空备用机会，待发池规模均值 **4.49**、最大 12，
   **超过 K=9 的只有 2 个（97% 的机会一次能装完）**，排序在 97% 的机会上没有作用对象；仅剩 2 个机会的
   争用在 K=9 下也被吸收。P2 池更大（均值 6.37、14/78 >9），故残留 0.30 的微差。

## 6. 三分支判定与解读上限（严格按 02 号文）

* **P-A 是、P-B 否（主例及标准工作点邻域）⇒ 分支② failover/传统通信，不接 Agent。**
* 灵敏度里 P-B 统计为是的格子，**不改变判定**，因为：(a) 主例与标准真实工作点 P-B=0；(b) 显著格的效应
  ≤0.36 pp；(c) 该效应被 EDF 完全解释、机会感知零增量。**这正是来源审计 §3.4 预先写下的先验
  "很可能被结构化方法吃掉 → 传统通信/DTN 问题"，现在以预注册方式被实测确认，而不是事后解释。**
* **解读上限（02 号文 §"解读上限"逐字遵守）**：本文**不**声称首次提出稀缺机会装包、**不**声称新机制、
  **不**声称 Agent 必要；连"本实例内存在分配自由度"也只在 K=4/9 走廊内、以 ≤0.36 pp 的量级有条件成立，
  且该自由度是 EDF 可解的。来源审计 §3.4/§3.5 的文献（北斗容量不足优先级装包、SHETLAND-NET 接触内分诊、
  CCSDS overbooking）已经解决"给定优先级的装包"，本文结果与之一致：**这不是 Agentic Communication 的
  方法贡献。**

## 7. 与 v1.1、multipath 探针的三链收敛

三条**相互独立**的证据链现在指向同一结论——在"模型已知、作业同权、期限公开、单资源"的结构里，智能没有残差：

1. **v1.1（已封版）**：数值优化型 agent 三次否证；结式 `delivered=1[h*≤B(d)]`，方法天花板只能动 `h*`，
   网关→中心无调度自由度；唯一干净正结果是架构级 backpressure/placement，非 LLM 机制。
2. **multipath_probe（A 层合成扩展）**：模型正确平稳时，用真实 GE 前滚的强 BeliefMPC 追平全知上界
   （oracle−cheat |Δ|<0.8 pp），"当前状态不可见"的信息残差只在信道难预测/不可逆能量稀缺夹缝出现，且
   oracle 的真值 LLM 同样拿不到。
3. **v1.2 minimal probe（本文，真实标准动作面）**：真实北斗短报文硬约束逼出的稀缺装包问题里，**EDF 到顶、
   机会感知零增量、agent 无残差**。

三者合起来把 doc 65 的统一判据
`useful intelligence = relevant observation × causally-effective action × enough time × residual headroom`
中的 **②动作**与**④剩余余量**在这个实例上钉死：备用链路给了因果有效的动作（②≠0，所以 P-A 是），
但在同权、公开期限、单资源结构下**选择的剩余余量≈0**（④≈0，所以 P-B 否）。

## 8. agent 的唯一候选入口：EDF 的结构性盲区（下一阶段 agent gate 的输入，**不在本文下结论**）

EDF 到顶依赖四个前提，**打破其中任何一个，EDF 的输入就不够了**——这是本 probe 能精确定位、但**没有**检验
的开放面（如实标注为待检验，不预设 agent 会赢）：

| EDF 前提 | 被打破后的问题 | 为什么规则基线不再显然到顶 |
|---|---|---|
| 作业**同权**、价值已知且静态 | 一条临界滑坡报警 vs 一条 routine 心跳，价值**不等且需从非结构化语境推断** | 需要从雨情文本/趋势/设备态判断"这条 200 B 该装什么"，价值不是输入字段 |
| 装的是**整条**、内容不可区分 | 200 B 内装"哪部分"（摘要/特征值/取舍多测项） | 是**内容选择**而非条目选择；来源审计 §3.5：现场适配全是时间维度、从无内容选择 |
| 期限公开确定 | 期限/价值随**演化灾情动态重估** | 排序键本身要被推断和更新 |
| 环境平稳、模型正确 | **model mismatch / 分布漂移**（主链路恢复与历史先验不符） | multipath 探针显示残差唯一通道在此；EDF/机会感知都用历史外推 |

**关键区分（防止重蹈"给定优先级装包"的覆辙）**：SHETLAND-NET/北斗装包论文做的是"**给定**优先级的
装包"＝加权 EDF/价值密度背包，**仍是规则**；真正未被占据、也唯一可能让 agent 有不可替代价值的，是
"**优先级/价值本身如何从开放世界、非结构化、演化的态势中产生并被重估**"。下一阶段的 agent gate 必须：
① 给规则侧一个**该设定下最强的合理基线**（加权 EDF/价值密度背包 + 显式价值规则），不得造 strawman；
② agent 不看真值/未来；③ 预注册判据，正负都闭环。API 优先 DeepSeek flash。

## 9. 简化与"不闭环"声明（随结果声明，不得外推）

1. 备用**成功率取 1、发送时延当拍**（标准：≥95%、平均优于 2 s，相对 1800 s 义务窗可忽略；不忽略只让备用略弱）。
2. **不计字节级分包**，容量＝每包 K 条（K 由 200 B−16 B 固定开销、每样本≈20 B 派生，主例 9）。
3. **不计资费/能量**：北斗—地灾链条无单价/配额来源（审计 §3.6.6），稀缺只由 速率×K 体现。
4. **网关级备用**：以 `h*`（到网关）为入池时刻。标准里卫星是**终端级**直连；终端级只会让入池更早（放松），
   且所有 chooser 用同一入池时刻，**不影响 P-B**；只让 P-A 绝对救回数偏保守。
5. **义务窗 d=release+1800（900 窗+一周期宽限）是合成研究定义，不是标准端到端期限**（两标准均无数字期限，
   审计 §3.5⑤）；备用机会全程均匀、独立于地面中断。
6. **"不闭环"**：本 probe 是 v1.1 台账上的**回放叠加**，未新建终端级卫星拓扑、未做字节级/功耗级/资费级仿真，
   N3 为 12 h、20 **开发**种子（保留种子复核留待 agent gate 阶段一并做）。结论限定为"在该实例与标准工作点邻域，
   同权条目选择不产生智能需求"，**不外推**到 §8 的开放世界设定。
7. 来源可迁移性最大风险（审计 §3.6.4，G4）依旧成立：义务级/机会级状态（剩余配额、下次机会）现实无文档来源，
   本 probe 的 chooser 只用了链路级二值状态 + 公开期限，**没有**假设系统能看到剩余配额，结论因此对 G4 收窄稳健。
