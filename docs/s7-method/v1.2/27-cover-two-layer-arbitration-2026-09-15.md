# doc27 — 方法主线确立：两层义务级备份仲裁 cover（J1–J4 通过）

日期：2026-09-15　状态：**硬稀缺区统一支配四类经典选包规则，held-out 复现；剩饱和 0.7pp 缺口与 J5 上界**
上游：doc25（方向）、doc26（根因＝停发积压）；结果 r12/r14/r15 四 json

## §1 方法：cover（两层贪心义务级装包，纯规则、合法在线信息）

每个离散备份机会（每 backup_rate_s 一个、净荷 cap 字节）执行：
- **跨包全局记忆 `seen`**：累计"已用备份送过的义务 oid"。只用于排序/降优先级，**绝不 suppress、绝不停发**（这是与 obligation 的根本区别，治 doc26 的停发积压）。
- **层0（边际义务覆盖）**：只选 ①其义务与 `seen` **不相交**（纯新增）、②仍可挽救（最紧义务 dl>now）的样本，按 dl 升序装入，装入后把其义务并入 `seen`。
- **层1（机会用满）**：层0后剩余容量，用其余样本按"最新优先"填满，保持数据流转动、不积压。
合法信息与既有 chooser 完全相同（本地义务台账、样本 heard/taken、公开 period/grace、离散机会网格），不读未来、不读中心应用层状态。

## §2 怎么走到这个设计（诚实的失败链，每步有数据）

1. **R12 包内记忆版**：`seen` 只在单包内累积⇒硬稀缺档全部退化为 edf（.46–.55），仅饱和 .984。证明**跨包全局记忆是覆盖增益的必要组件**（J2-a）。
2. **R13 全局+`issuperset` 宽松判据**：稀缺档仍 .50。逐机会 trace 发现层0选中样本从第 5 个机会起 **10/10 全部已过期**——deadline 升序在"到达率>服务率"的过载积压里崩溃：永远在清救不回的最老义务，新义务饿死（EDF 过载失效）。对照 trace：obligation 同机会只挑 3–10 条干净未覆盖义务、过期占比 0–3。
3. **根因**：多对多匹配下一份样本可带多个义务，"带一个已覆盖老义务＋一个新义务"的老样本边际覆盖低，却被宽松判据排在前面占满名额。
4. **R14 修复**：层0收紧为"义务与 seen **不相交**（纯新增）且未过期"，层1再补⇒r600 单种子 .607→.920。

## §6 唯一缺口：饱和区 0.7pp（机理清楚，非硬伤）

饱和时纯新增义务样本在个别备份机会不足一包，层1填入**纯冗余**（义务已全部 seen）副本，轻微扰乱新鲜度（.978 vs latest .984）。J2 显示层1在稀缺区的价值来自补"**带未见义务的绑缚样本**"而非纯冗余。**cover2 精修（R16，机理驱动、无魔数）**：层1只补"仍带≥1个未见义务"的部分相交样本，纯冗余（okeys⊆seen）不补。预期饱和回到 .984、稀缺不掉（绑缚样本仍补）。若成立则四档全支配；若稀缺因此回落，则保留 cover 并如实报告 0.7pp 的冗余—新鲜度权衡，不调到赢。

## §7 J5 与新颖性、边界

- **J5 待做**：知道未来的离线最优装包上界，仅用于回答 cover 离最优多远，不作可实现主张。
- **新颖性区分（已核 1 篇）**：ICLDC（arXiv:2504.14556 / IEEE IoT-J DOI 10.1109/JIOT.2025.3615410）经核为 **UAV 单跳采集＋LLM in-context 调度**（对比 DQN/最大信道增益、目标减累计丢包），**不含**主备双尺度窄通道、义务绝对截止+宽限+样本多对多、网关仅有链路回执而无应用确认、以及本文两层在线装包；只构成"有限服务机会"的形式化邻近。北斗优先级装包/SHETLAND 分诊/CCSDS overbooking 仍需在成稿前逐篇核（doc25 §4），不称首次/空白。
- 边界：紧 regime、grid600x600 上游、14 节点、routine 义务、备份成功率取 1（v2probe 简化）；不扩相图、不造时变义务、不接 LLM、不选 venue。
- 与命题衔接：这是"runtime 在回传退化时维持监测 workflow"收缩后的**通信执行层**贡献——规则实现、规则/MPC 同样获益，不依赖 agent 不可替代性叙事。
