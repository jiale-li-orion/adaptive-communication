## 3. 从完整实验史得到的研究结构

过去多次尝试给出了三个层次，不能互相替代。

**执行语义层。** 日志、稳定身份、单调版本、设备影子是基线能力。公平化后，它们未给本文 runtime 留下独有业务收益。新方向不能再把保存版本、拒绝旧写或不谎报成功改名为创新。

**通信控制层。** `h*`/`B(d)`、能源轨迹、缓存、备份容量和机会时间决定可兑现的服务。实际选择空间受来源限定；有些实例普通固定规则足够，有些实例内容仲裁有差额。它们是 Agent 可调用的控制原语及其条件边界。

**任务到执行的转换层。** 目前多由实验作者提前完成：哪些要求生成哪些义务、需要哪一层动作、何时该沿用缓存、什么叫完成、任务改变怎样作用于未完成历史。给 planner 已算好的目标档位，会跳过这一层。把新的自然语言前缀接在同一档位规则前，也可能继续跳过它。

由此产生的候选问题是：**收到来源支持的监测要求及其修改后，系统怎样利用已有数据、合法设备能力和可见执行状态，构造一条能够兑现这些要求的跨层计划，并修复无法兑现的部分？**

这里的“构造问题”有明确权限：Agent 可构造求解表示、选择合法执行分解；外部要求决定评价义务。Agent 无权删除难以完成的义务、更改评分分母、捏造警级或把未知证据猜成健康。

## 7. 候选 C 的具体方法草案与两个可区分假说

### 7.1 输入、表示、输出

输入为授权任务及变更、设备/协议能力、实际收到的证据和完整执行历史。业务真值在 Agent 外。用一个带来源的中间表示串起：

`义务 → 合格样本 → 到网关的候选 → 截止前可用回传 → 中心完成证据`

其中采样/上报配置是影响后续可行路径的动作，并非另一套独立评分。每条依赖记录位置、时间、证据来源和未知项；发送记录不能直接标成中心覆盖，配置请求被接受不能直接标成生效。

编译器输出一份可执行计划，或结构化的不可行/未能证实可行说明。关键输出不只是报错码，而是**具体义务、限制它的阶段与时间区间、已使用能力及仍缺的证据**。Agent 据此只修改受影响的执行分解；完整重建、无差别重试和等待全部操作也作为对照。

这份表示中“图”“类型”“验证器”本身都无新颖性保证。需要验证的增量是它产生的通信决策和业务后果。

### 7.2 H1：任务可行性需检查截止前的整条链

合法的新档位、足够的每小时吞吐、成功的单次 API 调用，均不足以证明某条具体监测义务能按期兑现。候选检查应区别：未采导致已无解；已采但还在节点需上行机会；已到网关只需回传仲裁；已送出但无完成证据仍有不确定性。

一个可编码的反例证书是：对给定义务集合与区间，即使乐观地使用所有合法未来机会，候选样本也无法在截止前穿过某一段。实现时按样本—义务匹配和逐机会字节容量求可行分配，不能简单用“义务条数×固定字节”忽略一份样本满足多义务或测项尺寸不同。

**乐观模型都不可行，可以给不可能证书；乐观模型可行不构成现实可行保证。** 未知未来链路和采能不能读真值；保证只能相对于声明的模型/边界成立。未知不等于不可行，不得靠保守拒绝所有升级赢约束指标。

预期的通信收益：已有合格缓存时避免无效重新采集；瓶颈在回传时修选包而非继续加密上行；确实缺采时能及时调整合法配置。必须与同信息的跨层滚动规划比较，不能只打分别独立工作的 AoI/EDF。

### 7.3 H2：任务更新需保留旧执行可能继续发生的后果

新任务生效时间、中心获知时间、远端实际配置生效时间分别记录。旧命令尚未确认时，不能在任务版本递增后把已消耗能源、未完成义务、缓存和可能继续生效的配置一起清空。外部降级只改变其授权范围内的要求，历史完成情况如何保留由冻结契约决定。

候选按未决效果集合/状态估计检查**过渡过程**，并只等待有实际依赖的部分；互不依赖的缓存回传可继续。最小修复可能是重排局部计划、利用已有候选、延后一个配置动作、请求必要证据或明确报告暂不可兑现，而非自动补偿物理上不能撤销的效果。

H2 很可能被成熟控制覆盖，不能预认领。**同样的最新遥测、不同未决历史需要不同后续计划**只是证明最新遥测摘要不充分；必须继续击败具备同样未决历史的强对照，才能证明本文机制有增量。若只出现版本倒退而 fencing 已修好，H2 就关闭，不能包装成任务生命周期贡献。

H1/H2 分开判别。如果无未决操作时 H1 有收益而 H2 无增量，论文只保留 H1；如果两者均被普通求解覆盖，C 没有晋级依据。不能预先把二者捆成一个大 runtime。

## 8. 最小判别与公平性：先回答是否值得实现系统

第一步不需要 LLM 大样本：先给全部对照完全正确的结构化任务，找一条**计划合法但端到端失约**的轨迹，以及相同条件下一条合法可行的修复轨迹。这一步区分方法对象是否存在，避免将解析错误当通信洞见。

主对照共享当地自治、持久状态、身份/版本、下行窗口、选包原语和未知信息。

**模型入口先核对证据路径。** `code/instance/network.py` 在中心收到数据时同步调用节点 `ack()`，不占回程空口；这是现有公开简化，不能被当作已经建模了“中心收到但节点不知道”。命令执行确认、网关转发反馈、样本缓存 ACK 分开登记。若某个判别依赖迟到/丢失 ACK，先显式修订共同模型与能力表，再作为新条件运行；不能只对本文开启保护或把模拟器真值变成观测。

先做成本最低的反方：每次收到新任务就重算普通固定采样/上报工作点，并用同一最强选包器服务新义务。若这样已经覆盖两个任务片段，说明仅更换任务参数没有打开新的编排问题，不启动大编译器。通过这一步后，C 的主对照包含：

1. 同一任务的普通约束求解 + 成熟 shadow + 周期重规划；输入完整合法历史，不人为只给最新值。
2. 加入执行延迟/未决效果状态估计的滚动规划。计算预算和预测信息分别登记；不能以仓库一个简化 MPC 的旧分数代替它。
3. C 的同组件去除 H1 或 H2 的版本；分支触发与行为改变都要有见证，不能仅按臂名算消融。
4. 理想可靠控制/回传与无任务变更的负对照，用来界定收益来自通信时序还是普通约束检查。

找到公平差额后立即接入少量真实 Agent，不再等完整平台、第三气象来源或全量图稿。继承原文明确的工作流结构，形成公开标注的 **adaptation**；TopoLLM 的 UAV 拓扑任务不能直接搬来作为本站原生基线。优先比较有显式验证修复的 ICG 风格流程、通用工具循环，以及相同 Agent + C，沿用仓库已有模型调用路径。未跑作者实现前不称原论文复现。

分开报告：同输入同任务的端到端 Agent 比较；给完全正确任务表示的机制比较。后者用于隔离语义翻译的影响，不拿人工已解出的目标当同输入竞争者。

指标沿用独立 scorer 的按期交付、缺采、AoI、能源和通信成本，并补任务变更后的义务级结果、错误完成声明、未能兑现/未知声明的真伪与被拒但本可完成的任务。自然语言流畅、格式通过、调用次数减少都不能替代业务收益。

**预测与反证：** 单一固定任务且资源宽松时增益应小；如果理想执行下仍有全部收益，归因应收窄为任务编译。若强滚动规划匹配，改进属于使用已有控制方法；若同样的明确 prompt 已解决，改进属于接口/提示，不宣称新调度机制。不得增加故障密度或撤掉对手能力来挽救主张。
