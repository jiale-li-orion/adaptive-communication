## 三、证据：负载的精确结构

`build_deployment(0)`，`build_demand(hours=72)`，实测：

| 项 | 值 |
|---|---|
| 总需求 | **430** |
| 风险需求 | **288** = 144 个时刻（风险窗内每 5 min 一个）× 2 个关键节点；样本窗 **300 s**、宽限 **300 s** |
| 正常需求 | **142**（样本窗 3600 s、宽限 5400 s） |
| 关键节点 | **8 / 16**（每组 4 个：6 个位移站 + 2 个雨量计） |
| 风险窗 | 第 12–18 h、48–54 h，共 **12 小时** |
| 机会供给（常态档，每节点每小时一次上行） | 16 × 72 = **1152** |
| `ours` 实际下发 | **664 / 72 h**（8 种子合计 5310） |

### 三条推论，一条比一条致命

**推论一：风险需求不可能靠"按时采样"满足，所以采样频率根本不是变量。**
常态 profile 每 300 s 采一次，样本一定存在于窗内；但常态档的**上传周期是 3600 s**，而宽限只有
**300 s**。因此一条风险需求能否被满足，**等价于"该节点在这一刻是否处于 `risk` 档"**。

**推论二：`risk` 档是时钟的纯函数，而且整份预告给中心。**
`profile_for_hour(hour, RISK_WINDOWS_H)`，中心拿到公告后持有整份日程，**包括窗口什么时候结束**。
三个闭环里：W3 是 W1 的逆操作、W2（补传）默认关闭（D32）、W1 的边际值 **+0.16 点**（§7.36）。
**剩下唯一承重的动作，是把 `profile` 从 normal 改成 risk，再改回来。**

**推论三：于是整个任务可以写成一句话。**

> **在两个窗口开启时，把一次已知的状态写进 8 个节点，越快越好。**

**这是设备管理任务。** 成熟设备影子在每一个业务指标上都赢（96.34% 对 94.53%，成本 0.6 倍），
不是方法差，是**任务就是这样设计的**。

### 三条约束在主表里都不 binding

| 约束 | 实测 | 含义 |
|---|---|---|
| 供电 | 4 个种子、72 h 结束 **0 个节点死亡**，`blackout_ticks` 为空 | 项目两个约束轴之一在主表里是装饰性的 |
| 机会 | 供给 1152 对下发 664，利用率 **≈58%** | 稀缺是**突发**的，不是结构的；"争同一份机会"只在一个瞬间成立 |
| 正确性 | `stale_command` 扣留 21 条命令，**真正迟到释放 1 条**，危险交错 **1 次**，乱序/覆盖效应量 **≈0.125 次/运行** | 指标灵敏（去掉契约字段会出错）但效应量在噪声底下 |

### 尺度问题

**关于风险窗的每一条结论，独立事件数是每轮 2 次窗口开启，不是 288。**
这就是 §7.34 的排序修复能一次移动 **5.5 个点**的原因——**它移动的就是那两个事件本身。**

### 为什么这不是"参数没调好"

需求是**外生**的：`build_demand` 与任何观测无关，D18 明确写了需求集不随种子变化。
**中心看到什么都不影响它下一步要看什么。**

**一个不依赖观测的需求序列，无论参数调到多极端，都只能测出投递能力，测不出监测决策。**
这是结构问题，不是标定问题。

## 六、非 toy 的任务必须具备的四件事（尚未采纳，供决策）

**一、需求必须内生。** 中心下一步看哪里，必须取决于它已经看到了什么。
**这是让"观测通道就是控制通道"这条主张真正承重的唯一办法**——只有当观测有替代用途时，花一次
机会去观测才有代价。当前需求与观测完全无关。

**二、观测之间必须有依赖。** 例如某节点出现位移后，必须在窗口内同时观测邻域，否则无法区分局部
噪声与正在发育的滑动面。**漏掉第二次观测使第一次观测失去价值**——任务从"每次独立投递"变成
"必须花机会完成一个序列"，序列中一次误分配会摧毁后续义务。

**三、覆盖增强必须成为决策而不是背景。** 备用路径现在只出现在 3 种子的旁支实验里，
主表 `runtime_paths=0`。中继/备用回传一旦成为"走不走"的选择，就与网关窗口、电源、最后一跳
产生真实取舍。

**四、供电必须 binding。** "多采一点"与"熬过这个冬天"之间的取舍，是这套场景里最真实也最难的
决策；它把采样策略从调度问题变成不确定未来下的预算分配问题（探索/利用）。

**一与四最关键：设备影子维护的是"被命令的状态"，它没有表达"这次观测比那次更值钱"的词。**

## 七、必须同时说清的风险与反面理由

1. **这不保证方法会赢。** 一个有效的 task 可能仍然给出"成熟影子加合理调度就够了"。到那时
   诚实的结论就是那个，**而且那是可发表的**。
2. **重设计会作废需求生成器、评分口径与四张业务表。** 工程与物理层资产不受影响。
3. **不能只加复杂度。** 上面四条每一条都是"加入一个决策"，不是"加入更多参数"。把 16 个节点变成
   64 个、把风险窗变成 20 个，**仍然没有决策，只是更贵**。
4. **重设计本身可能失败。** 若新负载仍让所有臂打平，需要判断是"方法无用"还是"任务仍无效"
   ——所以闸门 1 必须在动手前用可核查的判据写清楚，而不是事后解释。
5. **本项目已经有过一次"看起来成立的最新叙事"**（跨重启优势）。本文件的全部价值在于：它比那条
   叙事更不可爱，而且判据写在了动手之前。
