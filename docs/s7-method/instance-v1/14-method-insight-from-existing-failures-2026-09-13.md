# 从既有失败到方法假设：持续配置的资源约束

日期：2026-09-13；核查 HEAD：`6be36e6`。

状态：**研究候选审查，未冻结方法、未修改 task、未实施或运行新实验。** 本轮只读现有结果、代码和文献。本文接续 `13-agent-failure-opportunity-review` 的历史去重，不重新提出等待、幂等、fencing 或日志恢复。

## 1. 推荐核验的假设

中心下发的配置改变节点此后的持续工作负载。一次写入即使已被正确确认，资源消耗仍然继续；中心停止生成新意图，也不会撤回端侧已经生效的配置。

候选方法问题：**能否利用合法遥测、可能生效的配置集合和保守能耗模型，在下发前约束配置在失去进一步控制期间的资源消耗，同时保留有价值的中心介入？**

推荐它进入小规模反例核验的理由：已有不可补回的采集损失，现有代码中有明确的“停止下发不等于恢复默认”路径；执行层此前的成功/未知/结算逻辑没有直接表达这种持续资源消耗。能源耦合本身早已研究过，本文不称它新发现。尚未获得相对强安全控制基线的收益，也不认领方法新颖性。

## 3. 代码暴露的状态区别

`code/instance/center.py::EnergyAwarePolicy.plan`：

```python
if soc is None:
    if not self.send_when_unknown:
        continue
```

`ea_nb` 使用 `send_when_unknown=False`。`EnergyAoiPolicy` 的未知读数分支同样直接 `continue`。所以需要区分：

| 已发生历史 | 此刻停止下发的端侧后果 |
|---|---|
| 尚未改变出厂配置 | 继续出厂配置 |
| 加密配置已经生效 | 继续加密配置 |
| 已发送加密或降档，但尚不能确认 | 后果取决于真实到达情况；不能把停止下发当作回退已完成 |

`network.py` 中已生效的 `sample_interval_s` / `report_period_s` 持续支配采样和上报；没有由 `soc is None` 自动触发的端侧回退。指令过期拦截也不等于已生效配置自动到期。

这纠正了 `07-instance-closure` §五中“缺失会退回local”的机制解释；其中的实验结果不因这个解释问题自动失效。

可从实现推出的候选时间线：收到健康电量 → 加密实际生效 → 后续缺少有效电量信息 → planner不再下发 → 加密继续耗电。**现有JSON没有保存完整的逐次观测/意图/生效时间线；上述每一步尚未在同一条保存的运行轨迹中连接起来。** 此处只给出代码允许的路径，不冒充新增测量。

## 4. 方法应增加什么语义

旧运行时可继续结算“配置写入已成功”。另外维护当前配置仍可能造成的资源消耗，直到有证据支持它已被替换；不能因为命令 `applied` 就把未来开销归零。

建议的最小候选是**持续配置的资源核算与准入**：

1. 从带源时间的合法电量遥测开始，维护电量下界；能源参数来自公开的实例模型与声明的误差界，不能读未来采能或环境真值。
2. 对可能已生效及在途的配置做保守核算。不确定是否生效时，覆盖相关可能分支；降档只发出而未确认，不据此提前释放全部资源预留。
3. 检查候选配置在一段声明的无进一步有效控制时域内能否维持业务所需资源。物理模型要逐时推进、计电池上限与采能溢出，不能再用“采能总量够大”代替动态可行性。
4. 不满足时，返回拒绝/延后理由或现有动作域内的可行备选，由planner处理。不能静默修改它的目标并把结果算作原动作成功。

一种待形式化的判据是：对保护时域中的每个时刻 u，所有声明的不确定分支均满足

    battery_lower_bound(u | history, candidate) >= required_reserve(u)

保护时域结束必须对应可论证的边界：任务结束、已有且经证实的端侧自动回退，或明确标风险假设的恢复时域。**不能取真实下一次连通时刻，不能用突发均值作保证。** 当前无配置自动失效能力，因此不能把host租约写成固件已支持的功能。

若连通恢复无上界、未来采能允许为零且任务无限长，有限电池不能获得永续保证。候选只能给声明时域/不确定性集合内的性质；过于保守而始终拒绝介入同样可能使它失去研究价值。

两种年龄也要区分：上报到现在的时间，与一次纠正真正到达端侧之前的时间。收到新上报不等于纠正立刻可执行。当前 `soc_of` 使用接收时间判断年龄，这个接入问题应先澄清；修复它本身不是方法贡献。

## 5. 对早期机制的增量与文献约束

| 对照 | 已有能力 | 本候选要另外回答的问题 |
|---|---|---|
| 版本化影子、幂等、fencing | 维持所需配置，处理重复和过旧写入 | 所需配置持续运行时是否会破坏后续监测的能源条件 |
| 命令TTL、状态新鲜度门槛 | 限制过晚到达或依据过旧信息发起的新操作 | 先前已成功的配置仍在执行时怎么办 |
| 重试/调用预算 | 限制离散请求成本 | 一次成功配置造成数小时持续采样的开销如何计算 |
| 电量固定阈值 | 当前电量达标则加密 | 候选负载、剩余任务时长、控制迟延不同时是否仍可用同一阈值 |
| 鲁棒预测安全过滤器 | 基于状态、模型与不确定性审查控制输入 | 本场景的执行状态不确定及纠正不可及时到达，是否需要额外处理 |

最近的基础方法不能遗漏：

- Wabersich & Zeilinger, *A predictive safety filter for learning-based control of constrained nonlinear dynamical systems*, [作者预印本](https://arxiv.org/abs/1812.05506)。本轮核摘要；已有模型预测、约束与不确定性下的输入过滤。**能源可行性检查本身不能称新颖。**
- Stricker et al., *Self-triggered Control with Energy Harvesting Sensor Nodes*, ACM TCPS 7(3), Article 20, 2023, DOI 10.1145/3597311，[机构记录](https://www.research-collection.ethz.ch/handle/20.500.11850/626180)。本轮核出版信息与作者全文的搜索可见段落；已有长时域能量控制与自触发MPC结合，不得宣称首次联合通信机会与能源控制。
- *A Closed-Loop Measurement Study of Runtime Governance in AI-Driven Smart Building Climate Control*, [出版社页面](https://www.mdpi.com/1424-8220/26/15/4921)。本轮正文打开429，搜索可见§8.5、Table16涉及hold/checkpoint/safe-state的不同后果。属于必须进一步核全文的近邻，**不能声称首次发现不动作和安全回退不同，也不能据当前访问深度声称它没有处理通信问题。**

因此研究增量的候选位置是：对**持续生效、结果可能未知、纠正也走受扰路径**的配置操作，给出可复用且不过度保守的资源约束实现；是否超过标准安全过滤器，尚无答案。

另需注意当前实现空缓存不发上行，不能直接推断“先缩短上报周期就一定更快得到下一次窗口”。本候选不增加心跳或节点新能力。

## 7. 最小判别与停止条件

下一项建议只做现有场景内的因果核验，不扩全量扫描：

1. 提取上述seed 7既有条件的完整时间线，定位第一次引发额外采集损失的配置；区分偏置信息、配置持续时间、纠正到达失败各自的作用。
2. 在现有中断轴中区分“从未介入”和“配置生效后失去有效反馈”。在无进一步有效控制的分支上，核验当前fallback的实际效果。按相同外生时刻配对，不按各方法行为分别挑选有害中断。
3. 同一个提案策略比较：原执行层、可调电量阈值/新鲜度过滤、拥有同等信息和动作能力的鲁棒预测安全过滤器、候选。`aoi`/`local`及传统前沿继续保留。先用确定性提案定位因果，再决定是否接真实LLM。

优先看不可补回的缺采、周期交付、AoI与实际能耗；同时报告被拒绝但原本有益的介入。不能把少发命令当成减少了全部资源开销。

停止或降级条件：损害只由额外放大的错误信息造成；调高一个阈值就全面等效；收益全由改变目标配置取得；标准鲁棒过滤器已覆盖；持续配置核算不能胜过始终采用 `local`/`aoi` 的前沿；任何安全性质依赖未声明的自动回退、未来信息或无来源的恢复时间上界。

当前推荐的是**用现有失败审查持续配置约束这一方法假设**。尚未得到“已有agent失效被新机制修复”的证据，不能进入论文结果主张。
