## 一、候选边界表（谁能读什么、能改什么、谁执行）

| | **候选 1：条件计划下沉网关** | **候选 2：可行配置合成** | **备选 3：按义务选缓存记录** |
|---|---|---|---|
| **能读** | 网关**自己收到**的节点状态（含中心尚未收到的） | 中心已收到的 SoC/配置及其时间、发送记录、任务窗口 | 载荷内容的**监测义务**与缓存积压 |
| **能改** | 节点上**原有两个字段**（不加新无线能力） | 同左 | 节点缓存/打包纪律（**新软件能力**） |
| **谁执行** | **网关** —— **新增 A 层软件执行能力，必须明示** | **中心**（原动作面内） | **节点**（新能力） |
| **能力变化** | 是。任务契约 §10 允许比较，但**不能证明目标设备已有可编程网关** | **无** | 是 |
| **第一项判别（无需 LLM）** | 同一条确定性策略放**中心 vs 网关**，四种中断条件；**接入中断作负对照** | **合法配置的静态前沿 + 简单滚动搜索** | 48 h 缓存对照 + 短任务负对照；加 EDF/LIFO/`latest_only`/义务匹配贪心 |
| **最小证伪** | 若"恢复低电量反馈"对业务与成本均无作用 ⇒ 本候选在当前实例无继续开发理由 | **若找不到合法的、非全知的、超出当前前沿的选择 ⇒ 不接 LLM** | 若标准算法已拿走收益 ⇒ 归为**所有方法共享的成熟本地能力** |

**三者的共同纪律（§31）：** 共享能力、共享预算、共享未来外生过程；**只在预定差异处改变**；
**未来真值只供独立评分，不得反馈给 planner**；**不得把边缘自治或普通 MPC 的收益归给 LLM**。

## 二、候选 2 的前置判别：**现有 38 个臂只覆盖了两条切片，网格内部基本是空的**

从 `center.py` 的 `ARMS` 读出的**实际目标配置**：

| 臂族 | 写法 | 覆盖的 `(sampling, report)` |
|---|---|---|
| `local` | 不写 | **(3600, 3600)** |
| `fixed300` / `fixed900` | 只写 `REPORT_PERIOD` | **(3600, 300)**、**(3600, 900)** |
| `aoi_const300` / `aoi_const3600` | 只写 `REPORT_PERIOD`（定值） | **(3600, 300)**、**(3600, 3600)** |
| `aoi`（自适应） | 只写 `REPORT_PERIOD` | sampling 恒 3600，report ∈ {300, 900} |
| **`denseN`**（`DenseSamplingPolicy(n, 900)`） | **写两个字段** | **(N, 900)**，N ∈ {300, 600, 900, 1200, 1800} |
| `ea_*` / `eh_*` | 写两个字段 | 低电时降到稀疏档（≈(3600, 3600)），否则密集 |

**⇒ 已覆盖的只有两条切片**：`report = 900` 那一行（`dense*` 族），
以及 `sampling = 3600` 那一列（`fixed*` / `aoi*` 族）。

**⇒ 空区是二维网格的内部**，例如 `(600, 3600)`、`(900, 1800)`、`(600, 1800)`、`(900, 3600)`、
`(1200, 3600)`、`(1800, 3600)`……**一个都没跑过。**

### 为什么这个空区在物理上是有意义的（不是形式上的空白）

两个字段的负载贡献**可分离**，而且杠杆差很大（已登记常量，手算可核）：

```
load_h(i, r) = (3600/i)·4.7e-4 + (3600/r)·(2.33e-5 + 2.2e-5)
(600, 900) = 2.8200e-3 + 1.812e-4 = 3.0012e-3 Wh/h   ← 采样占 94.0%
(600, 3600) = 2.8200e-3 + 4.530e-5 = 2.8653e-3 Wh/h   ← 只降 4.5%
```

⇒ **把上报周期从 900 拉到 3600，能在几乎不损失采样密度的前提下少 4.5% 的负载**；
反过来，`report` 从 3600 压到 900 **只增加 4.5%** 负载 —— 而这个方向买的正是**新鲜度与下行机会**
（§21/§23：`report_period` 一阶买"未来控制机会"，能量杠杆低 **10.4×**）。

**⇒ 空区里存在"采样保持密集、上报按需加密"的合法组合**，而现有臂**没有任何一条**跑过它。

> **⚠ 已由 §34 判定（同日）：这句话只对了一半，必须带着"义务节奏"读。**
> 空区的**负载差是真的**——`(600,900)=3.0012e-3` 与 `(600,3600)=2.8653e-3`（降 4.5%）
> 已由测试 [33] 手算钉住。但把它**跑出来之后**
> （[`34-config-grid-search-2026-09-14.md`](34-config-grid-search-2026-09-14.md)，30 个合法点全跑）：
>
> - **3600 s 义务节奏下（N1 无中断 / N2 介入后失联）没有任何网格点在业务上超过 `aoi`**；
>   那 20 多个"非支配网格点"**全部只靠"下行更少"这一维撑着**——去掉下行这一维后 **0/30 非支配**。
> - **只有 900 s 第二来源节奏下（N3）才真的多交付**：`grid900x300` **509.7** vs `aoi` **497.5**
>   （+2.45%），代价**上行 +77.9%**；而且那个增益**全部来自"上报周期"这一个字段**
>   （采样保持场景自带的 900 s 即可，`grid900x900` 与 `local` 逐位相同）。
> - 该增益**已被普通静态选值与普通滚动搜索拿完**（`rolling_search` 509.4 ≈ 509.7）。
>
> ⇒ **"空区有意义"是分节奏的，不是无条件成立的。** 本文第 40、53–57 行的读法
> 请与 §34 的判定合读；**不得**再引用为"网格内部无条件有货"。
按 §31 §四，这**不等于**它改善业务（它同时减少上报次数 = 牺牲 AoI/交付），
**所以它必须用前沿与滚动搜索去判定，不能靠论证。**

## 三、因此候选 2 的第一项判别**可以立即开跑**，且满足全部限制

- **零 API 花费**（不需要 LLM 产生目标，也不需要 LLM 执行）
- **在原动作面内**，**不改任务契约**、**不新增能力**
- 只需在**已登记条件**上补一组**固定 `(sampling, report)` 网格臂**，
  与 `local`/`aoi`/`ea_nb`/`eh_aoi` 已有前沿同图比较

**判定规则（先写死）**：
1. **若网格的所有点都被现有前沿支配** ⇒ **阈值基线覆盖足够，候选 2 关闭，不接 LLM。**
2. **若出现非支配的网格点** ⇒ 记录**它改善的是哪一条固定义务**（交付？缺采？AoI？）**与付出多少资源**，
   再分离收益来自**联合选值**、**预测**、**持续配置建模**还是**信息估计**。
3. **强对照**（§31 §四）：合理固定配置网格、调好的 AoI/EH 前沿、**具有相同预测与观测的普通 MPC/随机控制**。
   旧 `rob3` 的失败**不等于**排除了鲁棒控制。

**本表不预设结论。** 它只把"是否存在未被覆盖的合法配置"从**修辞**变成**可执行的检查**。
