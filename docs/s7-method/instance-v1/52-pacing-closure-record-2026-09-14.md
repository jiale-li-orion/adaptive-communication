# 交付 3：**关闭记录** —— 找不到普通规则解释不了的轨迹

日期：2026-09-14。依据 [`48-...`](48-review-energy-placement-and-pacing-decision-2026-09-14.md) §5.3、§8.3，
以及 [`50-...`](50-pre-registration-pacing-baselines-2026-09-14.md) / [`51-...`](51-pacing-baselines-result-2026-09-14.md)
的预注册判定。

doc 48 §5.3 要求交付的是「**一个可定位的差额 _或_ 关闭记录**」。
**预注册 R3 判定为不成立**（见 doc 51 §四），因此本轮交付的是**关闭记录**。

## 一、结论

> **在已测的 N3 语境、三档中断条件、冻结的普通臂集合与公开服务容差下，
> 没有出现普通规则（固定周期族 ∪ 既有 AoI 代表族 ∪ 普通背压族）解释不了的轨迹。**
> ⇒ 按 doc 48 §8.2/§8.5 的分支：**不实现候选机制、不做消融、不接 LLM、
> 不补条件计划功能、不扩场景。**

**这一轮的答案就是"普通规则已覆盖"**，不是"没来得及试"。

## 二、为什么不成立（可复核的三条）

1. **每个容差下的最低成本位本身就是一条普通规则。**
   0%/1%：`fixed300`（＝`aoi_const300`，常数上报周期）；3%：`local`（零控制）；
   5%/P2：`pacing_bp1800`（普通背压）。**没有任何位置留给"别的方法"**——
   因为"最低成本位"这个位置已经被普通规则占满了。
2. **高服务端由常数规则覆盖，不是由动态规则覆盖。**
   0%/1% 容差下**背压族一条都不可行**（服务比地板低 3.1–6.0 个百分点）。
   ⇒ 想在高服务端省钱，**正确做法是把上报周期设成常数 300 s**，而不是动态调节。
3. **唯一一次普通背压取胜是边际的、且只在接入中断档出现。**
   P2 的 5% 档地板 **379.75**，`pacing_bp1800` 是 **380.1**（**只高 0.35 条**）；
   **同一档在 P0/P1 不可行**（地板 477.6 / 371.35，而它是 471.5 / 368.4）。
   ⇒ 它**不构成稳健、可复现的差额**；按文档 §50 R4，"放宽容差后某点胜出"**不足以晋级**。

## 三、doc 48 §5.3 要求的"差额解剖"为什么没做

那一句要求的是：**若差额存在**，则记录"每段节省了哪些上行、当时哪些数据已在网关、
哪些仍在节点、恢复后的首次新数据/首次有效降档延迟、代价是否超过节省"。
**本轮没有差额可解剖**，因此这条链**不成立**，也就不进入最小机制与消融。

**但边界已经写清并守住了**（doc 48 §3）：
仓库的 `backhaul_forward()` 能在回传恢复后**独立转发网关已有缓存** ⇒
**已经抵达网关的样本不需要节点再次上行**。
因此将来任何候选要改善的损失**必须定位到尚未抵达网关的数据、状态更新或配置纠正**，
**不得**把全部恢复积压算到 Class A 窗口等待上。
本轮的两条相关事实：
- **缺采在全臂、全三档上都是 0.0**（doc 51 §六.4）⇒ 本轮**没有**出现"以新增缺采换成本收益"的情形；
- 背压臂省下的上行（`fixed300` 1255 → `pacing_bp1800` 558）**并没有换来可比的交付**，
  它换来的是**服务少 5.9 个百分点**（P0）。⇒ 这些省下的上行**不是"推迟但仍会送达"的样本**，
  而是**根本没有进入交付窗口的样本**。这正是"代价是否超过节省"的直接答案：**超过了**。

## 四、doc 48 §5 列的「不足以晋级」理由，本轮逐条核对

| 理由 | 本轮情况 |
|---|---|
| 仅比中心 `ea_nb` 好 | 不适用（本轮不涉及 `ea_nb`） |
| 只比高速上报省 | **这正是普通背压的情形** ⇒ 不足以晋级 |
| 删除全零种子后才好 | 未发生（本轮缺采全 0、无全零种子问题） |
| 放宽容差后某点胜出 | **发生了**（P2 的 5% 档、边际 0.35 条）⇒ 不足以晋级 |
| 载体支持下发 | 本轮不涉及 |

## 五、若将来要重开这条线，需要什么（写给下一轮，**不是现在的授权**）

必须同时满足：

1. **存在一条臂**在**同一服务容差**下成本低于**固定周期族与背压族（全部成员）**，
   且**缺采不高于参照**；
2. 该差额**超出逐种子不确定性与参数选择造成的小波动**（给出同种子配对区间）；
3. 差额能**定位**到：少发了哪些上行、当时数据在网关还是在节点、
   恢复后首次新数据与首次**有效**降档的延迟、以及**代价是否超过节省**（按 doc 48 §3 的边界）；
4. 之后才做**最小机制 + 消融**，再用**未参与开发的种子**验证。

**四条都不满足时，不得用"实现更完整"替代研究进展**（doc 48 §5）。

## 六、这一轮真正留下的东西（不认领为方法收益）

- **一个共享的强基线集合**：固定周期全集 + AoI 代表 + 普通背压 + 迟滞背压，
  在同一接口、同一配置集合、同一执行位置下可比（`results/pacing_baselines.json`）；
- **一个新增的、对全部臂同等开放的证据接口**：`gateway_pending_depth` 与
  `gateway_last_forward_ok_at`（网关本地可观测，`_center_view` 不填）；
- **一条负面结论**：在 N3 的 900 s 义务下，"回传受阻就放慢"这一类动态节奏
  **不能**替代"把上报周期设成常数 300 s"在高服务端的表现，而它在低成本端的优势
  已被零控制（`local`）与普通背压覆盖。
- 按 doc 48 §5 末段：**这些都不构成本文的独有机制收益**；第三列仍为空。

## 七、限定

- 单一来源 **N3**、单一执行位置（gateway）、背压慢档只声明 **{1800, 3600}** 两档、
  **20 种子**、**只报均值包络（未报配对区间）**。
- 本轮**没有**改采样、事件、缓存与打包纪律、能源参数；**没有**接 LLM；
  **没有**补剩余 37 档突发扫描（doc 48 §5 明说不必）。
- 结论**只对已测的这三档条件与冻结臂集合**成立；**不外推**为"双跳节奏控制整体无用"。
  能说的只是：**在这一语境下，普通规则已覆盖全部有效工作点。**
