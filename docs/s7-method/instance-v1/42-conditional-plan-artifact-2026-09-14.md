# 条件计划作为**可下发产物**：七要素、准入检查、以及执行保真

日期：2026-09-14。**这是清单上最后一块**：判别 A 只做了「同一策略换个位置求值」（§31 第 53 行的
第一项判别），**没有把条件计划编译成可下发的产物**。本文补上 §31 第 43、45、49、55 行的要求。

代码 `code/instance/plan.py`；验证 `code/experiments/test_instance.py` 的测试 [35]（8 条断言）。

## 一、七要素逐项对应（§31 第 45 行）

原文：「计划包含：**适用节点与已有字段、合法观察量及其采集时间、条件分支、允许的配置集合、
资源限制、计划版本与有效范围**。」

| §31 第 45 行 | `plan.py` 里的结构 |
|---|---|
| 适用节点与已有字段 | `PlanBranch.applies_to`（节点 id 元组或 `("*",)`）+ `target` 的字段名 |
| 合法观察量**及其采集时间** | `PlanBranch.evidence`（必须在 `EVIDENCE_AVAILABLE` 登记）+ `gateway.now_s`（采集时刻） |
| 条件分支 | `ConditionalPlan.branches`，按 `priority` 取第一条成立者 |
| 允许的配置集合 | `ConditionalPlan.allowed_configs`（越界即准入出错，**不是静默下发**） |
| 资源限制 | `resource_limits`（`dwell_s` 等）；**逐节点下发上限本轮留 `None`** |
| 计划版本 | `version`（与 `plan_id` 一起构成身份） |
| 有效范围 | `valid_from_s` / `valid_to_s`；**过期只阻止后续执行，不撤销已生效配置**（第 49 行） |

**计划是数据不是代码**：`ConditionalPlan` 是 frozen dataclass，可序列化、可带版本下发——
这正是"可下发产物"的含义。`plan_bytes()` 给安装/更新报文尺寸：**`aoi` 编译版 = 603 字节 / 2 个分支**。

## 二、准入检查：**哪些分支可下沉、哪些必须留在中心**（第 45 行的要害）

### 判据（本文的实质产物）

> **一个分支可下沉，当且仅当它用到的每一个观察量都在网关位置的可得集合里。**

### 观察量可得性表（`EVIDENCE_AVAILABLE`）

| 观察量 | 网关可得 | 中心可得 | 说明 |
|---|:---:|:---:|---|
| `node.soc_wh` / `node.sample_interval_s` / `node.report_period_s` / `node.newest_sample_taken_at` / `node.cache_level` | ✅ | ✅ | **网关原生**：中心也读得到同一个量，只是**经回传、更旧** |
| `gateway.in_flight` / `gateway.now_s` | ✅ | ✅ | 同上（网关队列状态／时刻） |
| **`center.newest_sample_taken_at`** | **❌** | ✅ | **中心实际收到**的最新样本——网关在路径上，**没有延迟版本可读** |
| **`center.report_received_at`** | **❌** | ✅ | 回执到达中心的时刻 |
| **`center.task_update`** | **❌** | ✅ | **不可见的任务更新** |
| **`center.intent_history`** | **❌** | ✅ | 中心自己的意图历史 |

### ⚠ 一个我第一版写错、被测试抓住的地方

我最初把"位置"写成了**"只在那里可得"**，于是判出"`node.*` 的证据在中心不可得"——
**这是错的**。真实的不对称性是：

- **网关原生的证据在中心也可得**（只是更旧）⇒ 它**不是**下沉的障碍；中心执行 `node.*` 分支时
  读到的是**同一个量的旧版本**——这正是判别 A 对照的那件事
  （`node.newest_sample_taken_at` 是网关侧的，`center.newest_sample_taken_at` 是中心侧迟到的）。
- **中心独有的证据在网关根本不可得**——网关不在那条路径上，**没有任何版本可读**。

⇒ 所以判据是单向的：**center-only 的证据会阻止下沉；gateway 原生的证据不会阻止中心执行。**
测试 [35] 的「同一份计划在中心侧可全部执行」这一条就是专门钉这个不对称性的。

### 行为

`admit(plan, position)` 返回 `AdmissionReport`：`executable` 与 `held`（+ 逐条原因）。
`raise_on_held=True` 时**整份计划被响亮拒绝**。两条硬约束：
- **未登记的观察量**在**构造期**即被拒——未登记就无法判断可得性，因此不允许下沉；
- `on_missing` 只允许 `wait` / `request_update`，**"按保守值猜"被拒**——
  猜测会把未知伪装成已知（与 §31 第 89 行同一精神）。

## 三、执行保真：计划在网关执行 **≡** 同一策略在网关就地执行

把既有 `AoiPolicy(stale_s=3600, fast_s=300, slow_s=900, dwell_s=600)` 的规则
**编译成一份两分支条件计划**（`compile_aoi_plan`），两个分支都只用网关本地证据，
然后在**网关位置**分别跑：
(a) 同一个 `AoiPolicy` 对象就地求值；(b) 执行那份**被编译出来的计划**。

结果（测试 [35] 第 8 条，12 h 片段实例、网关布置）：

> **全部行为字段逐位相同**——`intent_log`、`mixed_config_ticks`、`command_seq`、
> `counters`、样本集合**一致**；只有 `arm` 名（本来就是两个臂名）与
> **诊断用的** `skip_reasons`（`AoiPolicy` 根本不记、而计划解释器记）不同。
> 三个种子的服务也逐位一致（167 / 168 / 149）。

⇒ **"把规则编译成计划再下发"不会改变行为**——计划是一个**忠实的载体**。

## 四、与判别 A 的关系，以及这一块**没有**改变结论

- **判别 A 测的是"位置"**：同一策略放中心 vs 放网关，四档条件，业务差 ≈ 0
  （`aoi` 臂在含中断三档 Δ = 0.00，20/20 逐位相同）。
- **本文测的是"载体"**：条件计划能不能忠实承载那条规则？**能，逐位忠实。**
- 两者合起来：**位置与载体都不是业务瓶颈**。所以 §31 第 57 行设想的论文增量——
  「给出在双跳间歇网络中**哪些条件分支可下沉、哪些需要中心证据**的判据」——**本文给出了这张判据表
  （第二节），但它是一个"能力边界"结论，不是一个业务收益**。
- 按 §31 第 110 行的三列分账：**架构收益 0、普通算法收益 0、本文额外机制收益空**——
  与 doc 39 的表一致，本块**不改**那张表。

## 五、明确**未做**的（不得当成已完成）

1. **只编译了 `aoi` 一条规则。** 带滞环／去抖状态的 `ea_aoi`、`eh_aoi` **没有编译成计划**——
   它们的条件依赖策略自己的历史状态，要把那些状态也搬进计划的数据结构（或声明为计划局部状态），
   本文**没有做**。
2. **安装/更新/撤销的字节没有计进任何臂的成本。** `plan_bytes()` 只给**尺寸**（603 B）；
   本轮**没有任何一次运行把安装费计入成本**。理由是这条能力按声明**全基线共享、预装**，
   把安装费只记给一条臂就是能力不对等。**把它真正计进成本模型是一项未完成的工作**（§31 第 55 行）。
3. **`resource_limits` 只放了 `dwell_s`**，逐节点下发次数上限留 `None`——**没有实现**。
4. **没有做"计划在失联期间过期"的端到端运行实验**——有效范围的语义由测试 [35] 单点验证，
   没有跨四档条件的读数。
5. **没有把计划执行放进判别 A 的四档条件重跑**：因此"计划版的位置对照也是 Δ≈0"是**推断**，
   不是**实测**。（推断的依据是第三节的逐位保真 + 判别 A 的实测。）

## 六、限定

- 测试 [35] 用**单个节点、12 h 片段实例、2 档参数**（`uplink_p_arrive=0.74`、`backhaul_p_good=0.62`），
  **不是**判别 A 的 14 节点四档条件。
- 计划解释器支持的条件名是**封闭集合**（`aoi_missing_or_gt_stale` / `always` /
  `soc_lt_threshold` / `soc_ge_threshold` / `center_newest_sample_stale`）；
  计划里出现未支持的条件名会**响亮报错**，不会静默不匹配。
- `center_newest_sample_stale` 这个条件**是故意保留的**：它用来演示准入检查会把 center-only 分支拦下来，
  **不是**本文推荐使用的条件。
