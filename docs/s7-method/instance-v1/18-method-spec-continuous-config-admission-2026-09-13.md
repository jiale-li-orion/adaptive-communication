# 方法规格（一页）：持续配置的资源准入

日期：2026-09-13。对应五小时计划 §1–2h。**本页不认领收益与新颖性**——§五给出的是一句
可能成立的自我否定。

---

## 一、它要解决的那个具体失效（已由 0–1h 闸门定位）

`out3`（中心在 h1 下发加密、h3 起接入中断）下，节点 `n02` 的 SoC 从 0.0195 掉到 0.0002、
h8 死亡、缺采 11。而 **h1 那次读数（0.0195）是准确的、健康的**——中心按当时的证据做的是
**一个合理的决定**。失效不在"读错了"，在于：

> **一次下发把持续负载写进了端侧，而这次决定是在"我还来得及改回来"的隐含前提下做的。
> 那个前提在 `out3` 里不成立。**

`noout` 下同一策略、同一读数，因为证据持续更新，中心在 h5–h7 降档、节点存活、缺采 0。
**唯一的区别是"我还能不能再改"。**

## 二、候选：准入式

主提案策略**只用 `ea_nb`**，不新增端侧租约、自动降档、健康旁路，也不新增任何能直接改节点
状态的 host 动作。动作集合仍是 `(sampling interval, report period)` 两个字段。

**在把一条会增加持续负载的配置发出去之前**，对每台节点、每个候选配置 `c` 检查：

```
∀ u ∈ [t, t+H] :  battery_lo(u | history, c)  ≥  reserve(u)
```

- `H`：**保护时域**。第一版**只用已声明的有限任务/运行边界**（本实例 = 运行结束）。
  **不得**使用真实中断结束时刻，**不得**用平均坏突发冒充硬上界。
- `battery_lo`：从**带源时刻**的最近一次合法电量读数出发（`CenterView.soc_age_s`），
  减去"读到它之后按可能已生效配置发生的消耗上界"，再按**声明界**逐时推进：
  电池容量上限、采能下界、可选的采能溢出。
- `reserve(u)`：保证义务还做得起所需的余量（第一版取"不因缺电停采"的最小余量）。

**四条必须一起成立的性质**（对应计划 §1–2h 的"保证条件"）：

| # | 性质 | 为什么必须 |
|---|---|---|
| 1 | **在途/部分生效按上界算**：降档只发出未确认时，**不得**提前按低负载计算 | 端侧可能仍在跑旧的高负载配置 |
| 2 | **源时间不被接收时间替代** | 证据年龄决定 `battery_lo` 要往下推多久 |
| 3 | **未知状态不释放已承担的负载** | 失联不等于负担消失 |
| 4 | **不可行时返回拒绝/延后理由，不静默换目标后称原动作成功** | 否则读数上的"服务"是虚的 |

**代码入口**：一个 `GatePolicy(inner, gate)` 包装器，`inner = ea_nb`；`gate` 只能
**否决或放行** inner 提出的意图，**不能自己生成动作**（否则就不是"准入"而是新策略）。
拒绝时记 `(节点, 配置, 拒绝原因)` 进账本。

## 三、必答问题 1：比"调高电量阈值"多处理哪种状态？

**阈值只问"现在够不够高"；候选问"按时域内观测到的收支，够不够用"。**

两者在**读数健康、但收支为负**的节点上给出相反答案——而那正好是 `out3` 里死的那些节点：

- `out3` 的 `n02`（`hetero` 低采能节点）：h1 读数 0.0195 ≈ 满容量的 98%，**任何低于 0.0195 的
  阈值都会放行**；把阈值抬到 0.0195 以上等于**永远不介入**，而计划已把"全部拒绝介入"
  排除出方法增量。
- 反之，一个读数只有 0.012、但观测到采能明显为正的节点，阈值会拒绝而候选可以放行。

⇒ **阈值的状态量是"电平"，候选的状态量是"电平 + 观测收支 + 剩余时域"。** 这不是调参差异。

## 四、必答问题 2：比**同等信息、同等模型边界**的鲁棒安全过滤器多处理哪种不确定性？

标准鲁棒预测安全过滤器（Wabersich & Zeilinger 型）在**扰动不确定性**（采能实现、量测噪声）
下验证递归可行性，但它默认**未来输入仍然可选**——即"我现在这么做，等会儿还能改"。
本问题里真正致命的那一维**不在物理扰动里，而在执行里**：

| 不确定性 | 标准过滤器 | 本候选 |
|---|---|---|
| 采能实现 | 下界（≥0） | 同 |
| 量测噪声/陈旧 | 误差界 | 同 |
| **纠正命令的到达** | **有界延迟**（D 小时内必到） | **在保护时域内可以永不到达** |
| 部分生效（降档未确认） | 通常假定输入已施加 | **按上界算，未确认不释放负载** |

**这是本规格最弱的一环，也是必须先说清楚的**：若把鲁棒过滤器的纠错延迟上界设为 `D`，
把候选写成同一个模拟器在 `D → ∞` 处的端点，那么**两者是同一个机制的端点，
候选就没有独立机制**。计划对此的处置是明确的：**答不上就合并两臂、承认是标准方法适配。**

因此本轮实现按**同一个可行性模拟器 + 一个参数 `D`（纠错机会上界，单位小时）**来做：

| 臂 | 含义 |
|---|---|
| `ea_nb` | 原执行层（无准入） |
| `ea_nb` + 阈值/新鲜度过滤 | 预先列 **3 个**阈值候选 + 1 个新鲜度候选，与其它参数同等开发机会 |
| `ea_nb` + 鲁棒可行性过滤 | 同一模拟器，`D` = **3 h**（有界纠错延迟） |
| `ea_nb` + 候选 | 同一模拟器，`D = ∞`（时域内不假设能再改） |

**如果 `D = 3 h` 与 `D = ∞` 在开发集上的缺采/服务没有差别，就按"标准方法适配"合并两臂，
不称候选。** 这是本轮预设的**主要否决出口**。

## 五、声明界（建不起来的就不声称安全保证）

| 量 | 第一版取值 | 来源 |
|---|---|---|
| 采样能耗上界 | `sample_wh = 4.7e-4 Wh` / 次 | 实例声明值（Ragnoli 实测剖面换算） |
| 空口上行能耗上界 | `UPLINK_WH = 2.33e-5 Wh` / 次 | 实例声明值 |
| 接收窗口能耗 | 随上行必然发生，按 `RadioEnergy.add_rx` 计入 | 实例声明值 |
| 采能下界 | **0** | `hetero` 模式下 40% 节点恒为 0；中心无法分辨是哪一台 |
| 电池容量上界 | 由设备档案声明（本实例 0.02 Wh） | 实例声明值 |
| 事件负载界 | **未建立** ⇒ 不把它算进保证，只在 `reserve` 里留固定余量 | 触发是外生的，中心看不到 |
| 电量误差界 | `bias=1`、`loss=0` 的本轮条件 ⇒ 误差界取 0；**偏置条件下界未建立** | 本轮只用 `bias=1` |

**采能下界取 0 的直接后果**：在 `noout` 里，任何节点的"永不再改"可行性都要求
**稀疏档也撑得住整个剩余时域**。实测 `n02` 在稀疏档下 13 h 只掉 5.6e-3 Wh，可行；
但若保护时域取整个 12 h 且残余电量低于稀疏档的总需求，候选会拒绝介入 ⇒ **退化成 `local`**。
这正是计划点名的停止条件之一（"过于保守、最终始终退回 local/aoi"）。
