# 判别 A 结果与判定：把条件判断交给网关，在本实例**没有业务收益**

日期：2026-09-14。判定规则**先写定**在
[`33-pre-registration-placement-2026-09-14.md`](33-pre-registration-placement-2026-09-14.md)，
本文只报读数与判定，**不回改规则**。

结果文件：`results/placement_contrast.json`（20 种子 / 3 臂 / 2 处放置 / 4 档条件，含带 trace 的因果轨迹）。
代码：`code/experiments/placement_contrast.py`；能力实现见 `Instance._gateway_view` /
`ControlPlane.gateway_send` / `_send_command(origin=…)`。

## 一、做了什么

按 §31 §三第 45、53、108 行，把**同一套确定性规则**放在两个位置求值，其余一律不动：

| | 中心放置（`placement=center`，现状） | 网关放置（`placement=gateway`） |
|---|---|---|
| 规则 | 同一个 `CenterPolicy` 子类、同一构造参数 | **完全相同** |
| 证据 | 中心**收到**的遥测（`Center.reports`） | 网关**自己听到**的上行（`Instance.gateway_reports`） |
| 命令路径 | 经回传 → 网关队列 → 接收窗口 | 网关本地 → **同一个**队列 → **同一个**接收窗口 |

**声明的 A 层能力**：网关具备可编程的条件执行软件。节点仍只接受原来两个字段；
没有新增无线覆盖、没有强制接收、没有设备自动回退。两处放置共享同一个策略对象，
因此能力天然对等。

**唯一改动的变量**只有两个：规则**在哪求值**、命令**从哪产生**。义务、初值、空口机会、
节点队列、接收窗口、能耗模型、**未来外生过程**（同一批种子）全部相同。

## 三、逐条判读

### R5 纪律 —— 通过

- `run_checks.py` **18/18（`EXIT=0`）**；新增测试组 [32] 覆盖位置对照的仪器不变量。
- **`placement="center"` 与改动前逐位相同**：把改动 stash 掉重跑同一命令，两侧 `runs` 去掉新增的
  `placement` 一列后 **json 完全相等**（`True`）。

### R1 负对照 —— **报警了**，但事后诊断为**控制设计错误**，不是仪器错

预注册写的是「C2 接入中断下网关位置的周期交付不得优于中心位置（容差 0）」。
实测 `ea_aoi` 在 C2 下 **Δ = +0.55（6 好 / 0 坏 / 14 平）** ⇒ **R1 按其字面成立，报警。**

按 R1 的原文，报警意味着"网关拿到了不该有的信息或权力，先修仪器"。**我逐项查了，不是这个原因**：

1. **信息侧是干净的。** 测试 [32] 钉住：整段接入中断里 `gateway_reports == {}`、
   `gateway_newest_taken_at == {}`，于是 `soc_of()` 必为 `None`，策略**只能**走它自己写明的
   「从没收到过 → 先加密」那一支（实测下发值恒为 `fast_s`）。没有任何证据驱动的判断能在
   "没听到"的情况下发生。
2. **权力侧也是干净的。** 网关命令走 `gateway_send`、`backhaul_accepted == 0`；下游仍是同一个
   节点队列、同一个接收窗口、同一份空口能耗。它没有白拿机会——实测它的**下行尝试反而更多**。
3. **残差的来源是"回传跳"本身，而它在四档里都存在。** 无中断档 Δ 已是 **+0.30**，
   而回传是逐小时的 62% 可用：中心的证据要等回传，命令也要等回传。接入中断**放大**了这个
   既有的结构差（C2 中心 AoI 5314 s vs C0 3207 s），而不是**制造**它。

⇒ **根源是预注册的负对照选错了。** 我挑"接入中断"是想让网关也失去新证据，但网关的优势
本来就不来自中断，而来自**它比中心少一跳**——无中断时它的证据年龄中位数就已经是 60 s vs 5760 s
（96×）。一个在无中断档就存在的差，不可能被"再叠加一次中断"消掉。

**我没有回头改 R1。** 它按字面报警这件事记在这里；上面三条是**事后的**诊断，并已用测试 [32]
补成可回归的仪器不变量。**下一轮若要用反例控制，应当控制的是"给中心也免掉回传跳"**
（即把中心直接放到网关位置），而不是制造接入中断。

### R2 主判读 —— 生效时刻确实变了，但**没有转化成业务量**

预注册要求「配置生效时刻应显著早于中心位置，且缺采不劣化」。实测：

- **生效时刻的确显著变早**：决策证据年龄中位 **11520 s → 60 s（192×）**；
  配置生效变化 **175 → 182 次**。这一条**不是噪声**。
- **缺采不劣化**：四档两处全部为 **0.0**（原因见下一节）。
- **但业务量几乎不动**：C1 下服务 **129.1 → 129.3**，即 **+0.3/168 = +0.18%**；
  `aoi` 臂在含中断的三档 **Δ 恒为 0.00，20/20 种子逐位相同**。

⇒ R2 的第一、二个子句成立，第三个（业务）不成立。**判读落在 §31 第 53 行末句**：
「若『恢复低电量反馈』对业务和成本均无作用，此候选在当前实例就没有继续开发理由」。

### R3 成本 —— **成本是负的**

网关位置省下的只有**回传下行这一跳**，而它换来的是**更多**的下行活动：

- 下行尝试：`ea_aoi` C1 **58.3 → 66.3（+14%）**；`aoi` C1 **63.9 → 112.0（+75%）**。
- 能耗：`ea_aoi` **0.4388 → 0.4479 Wh（+2%）**；`aoi` 基本持平（−1%）。
- 节点上行：基本持平或略降，**接收窗口的次数不受益**（机会仍然一次上行一次）。

⇒ **不是"用更少的通信换同样的业务"，而是"用更多的下行换同样的业务"。**

### R4 诚实边界 —— **第二项未启动**

预注册写明条件计划与"预装完整传统策略／预下发开环序列"的比较**须在第一项出现收益之后**才做。
第一项收益 ≈ 0 ⇒ **第二项按规则不启动**。

**而且最强反例在这里是平凡成立的**：既然位置带来的业务差本身 ≈ 0，
**任何一个预装的完整传统网关策略都必然"完全关掉"这个差**——因为几乎没有差可关。
这不构成对候选 1 的额外证据，只是说明第二项在这个实例上**没有判别力**。

## 四、为什么没有收益：机制（这是本轮真正的读数）

**缺采在四档两处全部为 0.0，而缺送才是全部损失**（C1 下 39.0/168）。
也就是说：节点**照常采样并缓存**（接入中断只断上行，不阻止采样本地发生；失电才会真的缺采），
**所有丢失都发生在交付侧**。

⇒ 而**交付容量与"配置决策在哪儿求值"无关**：两个位置的下行都要排同一个节点队列、
等同一个接收窗口、付同一份空口能耗。把判断搬得更近，只是让配置**更早、更贴状态**地变化，
而**配置变化本身并不是这个实例的义务瓶颈**——义务节奏由节点本地自治与既有的两个周期字段承担，
瓶颈是"现有链路一次能送走多少条"。

这条机制解释同时说明了为什么 C3（同时中断）的 Δ 最大（+0.65）却仍然无关紧要：
在同时中断下中心**连命令都发不出去**（回传也断），网关还能把命令排进本地队列，
所以"能不能动手"这一维确实变了——但**能动手不等于能送达**。

## 五、这一轮关闭了什么、没有关闭什么

**关闭的（具名子假说）**：
「**把同一套条件判断从中心移到网关，能在本实例的 v1.1 业务口径下改善服务或减少不可恢复缺采。**」
证据：20 种子、2 条传统臂、4 档条件下 Δ 服务 ≤ +0.65/168（≤0.39%），其中 `aoi` 臂在含中断的三档
**逐位不变**；同时下行 +14%~+75%、能耗 +2%。按 §31 第 53 行末句，**候选 1 在本实例关闭**。

**没有关闭的**：

1. **条件计划 vs 预装完整传统策略**（§31 第 55 行第二项）——未做，且在本实例上无判别力（见 R4）。
2. **换一种业务口径**。本实例的义务是**常态周期**（3600 s 一份、12 h 共 168 条），
   节点自治已能承担；若义务变成**低时延事件**或**接入中断真的造成缺采**（例如缓存溢出、
   或节点因此失电），"现场更早看到状态"可能才有效。**本轮没有测这类口径**，
   不得把本结论外推成"位置下沉在通信方法上无用"。
3. **交付侧本身**。既然全部损失在交付侧，而 §31 候选 2（合法配置网格）与备选 3（一次机会
   承载哪些记录）正好作用在**产生与发送节奏**和**载荷选择**上，**这两条仍是活的**。
4. 长任务、第二业务节奏、突发链路结构下的同一判别。

## 六、必须声明的限定

- **单次建模简化**：`in_flight` 在 `center` 视图里本来就按"网关队列非空"定义，
  即中心已被赋予对网关队列的可见性（仓库既有选择）。两处用同一表达式，因此不给网关侧优势；
  但"中心并不知道队列"这一更严格的读法**未被测到**。
- **只测了两条臂**（`ea_aoi`、`aoi`）与**一条重放轨迹族**；结论是这三者与四档条件下的读数，
  不是"所有策略"的。
- **`local` 参照线的读数一并登记**（C0 149.5 / 0.1006 Wh），以便读者自行判断"介入"本身的净值。
  本轮不把 `local` 与各臂的对比列为本判别的结论——那是另一个问题。
- **负对照按字面报警**（R1），原因已诊断为控制设计错误而非仪器错，但**预注册原文不改**。
- 判定只针对**一个实例、一个义务口径、一个已登记条件族**；不外推到全部合法通信方法。
