# 损害进 Pareto 目标：**未通过**——它几乎不改变前沿，原先那条 evaluation finding 要撤回

日期：2026-09-13。目标第 4 项。工具：`code/analysis/pareto_front.py --with-harm`。

---

## 一、做了什么

给 `pareto_front.py` 加了第二个目标族 `HARM_OBJECTIVES`：

```
("缺采",   "routine_missing_collection", −1)
("节点小时", "deficit_h",                  −1)
```

`deficit_h` 的口径沿用已登记定义：**跨节点累计不可供电时间的种子均值**——不是 Wh，也不是单节点持续时长。
两个字段**本来就在聚合里**，所以**不需要重跑任何实验**。

`--with-harm` 加到六目标：交付↑、上行↓、下行↓、AoI↓、缺采↓、节点小时↓。**仍然不做加权。**

## 二、结果：**284/285 个文件的前沿一字不变**

对全部登记结果文件做了 4 目标 vs 6 目标的前沿对比：

| | |
|---|---|
| 前沿**不变**的文件 | **284** |
| 前沿改变的文件 | **1**（`pair_summer`）|

唯一改变的那个，`dense600` 被 `dense1800` 摘掉，两者**交付/上行/下行/AoI 四个目标逐位相同**
（17.50 / 20.25 / 13.80 / 22600.81），差别只在**不可供电节点小时 168.09 对 163.01**——
即**唯一一次"损害目标起作用"，是裁决两条几乎一模一样的臂**。

### 为什么几乎不起作用：损害与既有四目标高度同线

损害大的臂**同时交付也低**，所以它在原来的四目标上**早就已经被支配了**。最干净的例子是 `out3`：

```
local   (56.30, 52.00,  0.00, 16133.00,  0.00,  0.00)   ← 六目标全部严格优于 ea_nb
ea_nb   (49.10, 61.00, 21.00, 16306.25, 10.50, 14.22)
```

**`local` 在四目标上就已经支配 `ea_nb` 了**（交付更高、上行更少、下行更少、AoI 更低）。
所以"把损害加进来会让 `ea_nb` 掉出前沿"这个预期，在本实例上**是多余的**——
它本来就不在前沿上。

## 三、要撤回的那条

我在 `README.md` 顶部与 `21-regime-map-partial-pass-2026-09-13.md` 里写过一条 evaluation finding：

> "在 persistent actuation 系统里，只看 service 的评测会把 destructive adaptation 当成有效控制。"

**按实测，这条在本实例上不成立，撤回。** 正确的表述是：

- **损害几乎从不改变前沿**（1/285），所以"只看 service 的评测**选错了前沿点**"这个说法**没有证据**。
- 但**189 个文件里，前沿上确实坐着有缺采的臂**——`cap0.008` 的前沿是 `{dense1800, local}`，
  两者缺采都是 21.3；`blackout4_0.6` 的前沿是 `{dense600, ea_i600}`，缺采 23.2。
  ⇒ 真正站得住的陈述是：**Pareto 前沿本身不是安全性陈述，把"在前沿上"读成"安全"才是那个错误。**
  这与"加一个目标就能修好"是两件事。

## 四、还站得住的那半句

`out3` 里 `aoi`/`local` 的零缺采，**部分来自它们根本不写 `sampling_interval`**
（`FixedPeriodPolicy` / `AoiPolicy` / `AoiLinkPolicy` 只写 `set_report_period`）。
这条是**代码事实**（`center.py` 逐类可查），不依赖前沿重算，**保留**。

但它同样只在 `out3` 这种"能量不吃紧、而有人去动了危险字段"的条件下才是**区分性的**：
到了 `cap0.004` 这种深度绑定条件，**连 `aoi` 自己都有 29.85 条缺采**——
那时损害不再由"谁碰了危险字段"决定，而是人人有份。所以它是一条**条件性的**解释，不是普遍的。
