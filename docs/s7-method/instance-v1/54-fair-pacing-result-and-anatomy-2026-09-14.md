## 一、这一轮与上一轮的差别只有两处（正是那两处决定了结果）

1. **臂集合给动态节奏公平机会**：加 `fast_s = 300` 配 `slow_s ∈ {900, 1800}`
   ——`slow = 900` 就是上一轮**完全缺失**的那一格「**按义务节奏封顶 + 未受阻时全力**」；
   并加**第二条普通规则族**（按网关缓存里最老待转发记录的年龄判受阻）；
2. **补逐条解剖**：每条义务定位到 **采到 / 已到网关 / 已到中心** 三级。

## 三、解剖：**省下的上行是冗余重试，不是损失**（doc 48 §5.3 要求的链）

`pacing_backlog900_300` 相对参照臂 `fixed300`（20 种子均值）：

| 条件 | 服务 | 缺采 | 上行 | 总能耗 | **采到 / 到网关 / 到中心** | **未到网关的增量** | 翻转（新增/丢失） |
|---|---|---|---|---|---|---|---|
| P0 | 511.2 → 508.2（−2.9） | **0 → 0** | 1255 → **880（−375）** | 0.3951 → **0.3808（−3.6%）** | 672 / **672** / 508 | **+0.0** | 0.0 / 3.0 |
| P1 | 404.9 → 402.1（−2.9） | **0 → 0** | 1412 → **844（−568）** | 0.4088 → **0.3828（−6.4%）** | 672 / **672** / 402 | **+0.0** | 0.0 / 2.9 |
| P2 | 413.4 → 410.4（−3.0） | **0 → 0** | 944 → **679（−265）** | 0.3855 → **0.3751（−2.7%）** | 672 / **672** / 410 | **+0.0** | 0.0 / 3.0 |

**逐条回答 doc 48 §5.3 的四问**：

1. **少发了哪些上行**：每条件 **−375 / −568 / −265** 条到达的上行；
2. **当时数据在网关还是在节点**：**每一条义务的样本都到了网关（到网关 672/672，上行侧损失 0）**；
   损失**全部**在回传侧（已到网关但未到中心：164 / 270 / 262）；
3. **恢复后额外等待多久**：P1/P2 下**首条窗后样本到网关延迟 1530 s、到中心延迟 2115 s**
   （严格降档 **0** 次——节奏臂只写上报周期，不动采样）；
4. **节省是否抵得过损失**：**省 375–568 条上行 + 2.7%–6.4% 总能耗，代价是 2.9–3.0 条交付
   （−0.43 个百分点）、缺采变化 0**；而这 2.9–3.0 条**全部落在回传侧**
   （Δ回传侧损失 = +2.9~3.0，Δ上行侧 = +0.0）。

**⇒ 关键判读**：**省下的上行没有让任何一条义务的样本少到网关**（未到网关增量恒为 **+0.0**），
所以它们**是冗余重试**——每一条交付义务本来就要撞出多次上行才成功（接入 0.74、回传 62%/h），
节奏变慢只是**少了几次冗余的撞运气**，代价是那 3 条义务少了撞上回传窗口的机会。

**按 doc 48 §3 的边界**：候选要改善的损失**必须定位到尚未抵达网关的数据、状态更新或配置纠正**，
**不得**把恢复积压算成 Class A 窗口等待。而这里 **"尚未抵达网关"的那部分恒为 0** ⇒
**在这一档里，"尚未抵达网关的数据"这个改善对象根本不存在。**

## 四、裁决（按预注册逐条）

- **R1 —— 前提不成立**（1% 档最低成本位是动态臂，不是固定臂）。上一轮的对应结论**作废**。
- **R2 —— 成立。** 1% 档三条轴上的最低成本位是 **`pacing_backlog900_300`**，
  它属于**报压族 B**（缓存积压信号）⇒ **普通背压已覆盖该档** ⇒ 保留为**强基线**，**不实现候选**。
- **R3 —— 不成立。** 没有任何臂的成本低于「固定族 ∪ 报压族 A ∪ 报压族 B」的**全部成员**——
  因为赢家**本身就在族 B 里**。按 R3，**不进入最小机制与消融**。
- **R4**：不足以晋级的理由照旧并未触犯——这条收益不是"只比高速上报省"而已被普通规则复现，
  所以它**不构成候选差额**。

> ### 裁决（措辞严格限定到本轮臂集合）
> **在本轮 20 条臂、三档条件、公开的 0%/1%/3%/5% 服务容差内，
> 没有任何工作点需要比「按缓存积压触发的、以义务节奏封顶的普通背压规则」更复杂的规则才能达到。**
> 那个 1% 工作点由 `pacing_backlog900_300` 取得，它是**普通规则收益**，
> **不是本文机制收益**（doc 39 第三列仍为空）。
>
> **并且这一次它带着解剖**：要改善的对象（未抵达网关的数据）在该档**恒为 0**。

## 五、这条结论的强度与它的边界（不许省）

**能说的**：
1. **上一轮的"固定臂通吃"是臂集合缺陷造成的**，本轮更正后**动态普通规则在 1% 档取胜**；
2. 那条取胜规则是**普通背压 + 义务节奏封顶**，其收益是**普通规则收益**；
3. 省下的上行经三级解剖确认是**冗余重试**，**未抵达网关的损失恒为 0**。

**不能说的**：
1. **不穷尽**。本臂集合覆盖「两种本地受阻信号 × 四组快慢档 × 迟滞」，**没有**覆盖按**预测**选档、
   按**义务剩余时域**选档、以及**中心侧**执行的同名规则（doc 53 §7 已先声明）；
2. **不外推**。只有 N3（900 s 义务）、`placement="gateway"`、20 种子、三档中断窗；
3. **不得**再说「普通规则覆盖了全部有效工作点」——只能说「**本轮臂集合内**没有工作点需要更复杂的规则」；
4. 本轮**没有**做最小机制与消融（R3 不成立），因此**没有**任何"本文机制"的主张；
   **不接 LLM、不补条件计划功能、不扩场景**。

## 六、附带确认的两件事

- **`heard ≥ delivered` 的不变量成立**（新增 `heard` 字段后实测 0 违反；`delivered` 必然先到网关）。
  该字段默认关闭，**现有读数与已登记文件逐位不变**（`run_checks.py` 18/18）。
- **恢复链仪器可用**：`post_outage` 给出"中断结束 → 首条窗后样本到网关 → 到中心"两个延迟
  （P1/P2 下 1530 s / 2115 s），这是 doc 48 §5.3 要的"恢复后额外等待多久"。
