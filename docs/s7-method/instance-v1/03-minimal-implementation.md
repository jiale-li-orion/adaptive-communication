## 一之二、第一份多节点、有地形差异的分列读数

```bash
python3 code/experiments/instance_run.py --seeds 20 --task-hours 12 --tail-hours 1 --tag base
```

产物 `results/instance_base.json`。实例 = 网关带雨量计 + **13** 个坡面位移测点（真实 SRTM/ITM
布点，绕射边缘上的 3 个位点已排除）；义务 12 h + 尾部观察期 1 h；20 种子。

| 分列 | 读数（20 种子均值） | 手工核对 |
|---|---:|---|
| 周期交付率 | **0.89**（160/180 量级） | 缺采 **0**、缺送 **18.5** |
| 周期 AoI 均值 | **2,211 s** | 小时级上报，量级合理 |
| 事件名额采集匹配率 | **1.00** | 与单种子手算 21/21 一致 |
| 事件交付率 | **0.80** | 缺送 **4.2/21** |
| 检测时延 | **0 s** | 本地规则在触发同 tick 唤醒 |
| 中心获知时延 | 均值 **1,116 s**，p90 **2,847 s** | 首条常卡在回传中断的那个小时 |
| 上行 / 被听到 | **169 / 124.6** | 169 = 13 节点 × 13 h；124.6/169 = **73.7%**，对上设计的 0.74 |
| 网关转发 | **152.9** | 高于被听到数，因为网关自己的遥测不走接入跳 |
| 右删失 | **0** | 1 h 尾部覆盖了全部观察截止 |

**中断 3 h 的对照**（`instance_outage3h.json`，回传在第 4–7 小时中断，其余同）：

| 恢复分列 | 读数（20 种子均值） |
|---|---:|
| 落在中断+恢复观察期的义务 | 56 |
| 其中交付 | 35.1 |
| **采集缺失** | **0** |
| **交付缺失** | **20.9** |
| 自动补发追回的样本 | **42** |
| 中心获知时延均值 | 1,116 → **1,219 s** |

**这组读数正是 v1.1 §5.3 要的那个区分**：中断期间节点有电、照常采样，所以**采集缺失为 0**；
丢失全部发生在交付侧，而自动补发把 42 条追了回来。**采集缺失与交付缺失分开报，是为了不把
"补不回来的"与"能补回来的"合成一个"丢了多少"。**

同时钉住了一条性质：store-and-forward 下中断**只改时延、不改总转发数**（两次运行都是 147）。

**这些读数能支持什么。** 分列指标自洽且可手工核对；地形决定哪些节点可达；网关与坡面节点的
接入差异真实存在（前者无接入跳）；事件名额无复用；传播的两段时延可分；中断的损失落在交付侧
且可被自动补发部分追回。

**这些读数不能支持什么。**

- **任何方法优劣**——这是单条自治基线，没有对照臂。
- **任何能源结论**——采能是合成的恒定过程（A 层）。
- **任何"中心改配置更快"类结论**——实例不含中心下发动作。
- **跨站泛化**——单一片段、同一天、同一设备，只能报案例级诊断。
- **"发现慢"与"服务慢"的差**——本实例没有第二条获知渠道，两者同一时刻（已在
  `event_propagation` 的 `note` 里写明）。
- **恢复的完整图景**——只测了**回传中断**一种；节点失电、接入中断、以及中断期间同时产生事件
  流量都没有单独跑过。

## 二、验收：十二组，46 项，全部通过

```bash
export PYTHONPATH="$PWD/libs/pylibs"
python3 code/experiments/test_instance.py
```

| # | 查什么 | 为什么查 | 结果 |
|---|---|---|---|
| 1 | 义务在运行前定好 | "改变策略不改变需求分母"必须是结构性质，不是约定 | 21 条，同一输入同一集合 |
| 2 | **失电不补造样本** | 死后再产生样本会让"服务连续性"变成假的 | 死前 5 条、死后 0 条、义务一条不少、缺采 17 / 已采 4 / 共 21 |
| 3 | **旧数据不冒充事件观测** | 三个名额必须各用不同样本 | 0 条越界、0 个样本被共用、窗外样本一律不匹配 |
| 4 | **遥测不提前到达** | 时刻顺序错了，任何时延指标都没有意义 | 采集 ≤ 网关听到 ≤ 中心收到，逐条成立 |
| 5 | 手算数目对上 | 算错不会自己报错 | 12 h = 12 常态 + 7×3 事件 = 33 条；规则义务 21/21 |
| 6 | **反向检查：这一列真的会动** | 恒 0 或恒 1 的列不能拿来做扫描 | 关掉本地事件上报，事件交付数 **17 → 6** |
| 7 | 片段解析 | 公开片段的偏差必须保留，不能吸附成理想时钟 | 14 个间隔 **286–318 s** 全保留 |
| 8 | 多节点 + 真实地形 | 可达性是外生事实；绕射边缘位点不能被当成地形事实 | 主实例 13 个，排除 3 个并单列；无实体被要求提供它没有的测项 |
| 9 | 多节点闭环 | 分列读数自洽，且没有整段无观测这类结构性错误 | AoI 1806 s、**无观测 0 s**；网关 33/33 无接入丢失，坡面 153/156 有 |
| 10 | 事件传播 | 检测与获知必须分开，否则"本地没检测到"会被读成"通信慢" | 检测 0 s vs 获知 463 s |
| 11 | 尾部观察期与右删失 | 尾部决定**哪些义务可以被判定**，不是"跑完就算失败" | 运行 1h → 删失 2；运行 3h → 删失 0；分母不变 |
| 12 | 中断与恢复分列 | 采集缺失（补不回来）与交付缺失（可补发追回）必须分开 | 中断期缺采 **0**、缺送 29、补发追回 42；中断只改时延不改总转发数 |

**第 6 条是这一轮最该有的一条。** 上一轮审计里最贵的一课就是"在一个恒为 0 的列上做扫描"
（D45：`declare()` 零调用）。所以任何一个要拿来做结论的列，必须先证明它会动。

## 三、刻意没做的，以及为什么

| 没做 | 理由 |
|---|---|
| 中心下发动作（`set_report_period` 等） | 需要"命令到达节点接收窗口"的完整链路；在 v1.1 §4 的可见历史 `O_center(t)` 与命令回执语义定下来之前接上，会凭空造出能力 |
| 显式区间／游标／预算补传 | **抽象物，无确切协议原文**，属扩展项（v1.1 §6） |
| 备用路径 / 中继切换 | 目标站点**已有还是待建设未知**；不做 agent 的"增强信号"按钮 |
| ~~尾部观察期与右删失~~ | **已实现**：`evaluate(..., task_hours=...)` 把义务区间与运行区间分开，截止超出运行末的义务标右删失并留在分母 |
| 配置正确性指标 | 最小实例**没有外部配置要求**，无法定义"错误配置"。返回 `None` 并在 `not_applicable` 写明——**返回 0 会被读成"没有错配"** |
| ~~事件"中心何时获知"的时延~~ | **已实现**：`scoring.event_propagation` 从记录里推导三个时刻；**本实例无第二条获知渠道，"获知"与"首份新数据"同一时刻** |
| 真实地形与能量物理 | 复用层已存在且经过验证；最小实例先用恒定采能把闭环跑通，避免一次引入两个变量 |

## 四、已知的实现简化（必须随实例发布）

| 简化 | 影响 | 处置 |
|---|---|---|
| **tick 是原子的** | 采样→上行→网关→回传在同 60 s tick 内完成，因此会出现 0 时延样本 | 60 s 分辨率下的声明选择。要知道：**"遥测不提前到达"这条验收在跨 tick 时有牙齿，在同 tick 内是平凡的** |
