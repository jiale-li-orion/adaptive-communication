**三列读法（不许混用）**：

1. **第三列尚未建立独有机制收益。** 当前已测差额由既有规则、配置或执行位置解释；这不等于证明所有后续方法的增益都为零。
2. **第一列按条件判断。** 判别 A 的供电宽松上下文中业务差接近零；§47 的能源受限 `ea_nb` 在回传中断中有正差，接入中断中没有。两项实验使用的策略也不同，不能据此声称只改变能源参数就解释了全部差异。
3. **现有规则与网关自治都保留为强基线。** 新增的位置正结果不得算给条件计划格式或 agent；成本包络也不直接构成新算法。

## 二、早期 gate 处置记录（⑦）：当时**不启动**

本节保留历史推导，当前依据见第一节及 §48。候选 2 因 R1 而关闭的理由已撤回；候选 1 已补出条件性的架构正差。当前继续暂缓 agent 2×2 的依据是尚无超出共享强基线的本文机制增量。

### §28 交付 4（小型闭环对照：成熟规则 workflow vs 完整适配 agent）

**§28 自己写的 gate 是"须先过 3"。** 交付 3 的实况：

- §30 的三个判别候选**没一个够格承担判别**（已分别在 §7.x 记录并逐条给出理由）；
- 本轮改以 §31 的两个主候选判别替代，**两个都已关闭**：
  候选 1 按预注册（业务无作用、成本为负），候选 2 按预注册 R1（补全 38 条既有臂后业务口径 0/30 非支配）；
- 备选 3 的两个新假说**以证据关闭**（Δ = 0.00 五档）。

⇒ **交付 3 没有产出"可解释差额"**，因此**交付 4 不启动**。这不是"没时间做"，
而是 §28 的 gate **未被满足**：一个"共享能力、共享目标、共享预算、共享工具"的闭环对照，
**需要一个值得用闭环去解释的差额**；当前没有。若强行启动，它只能测出"规则 workflow 与适配 agent
在**没有差额**的任务上是否同样好"——那已经由 §7.113 的 v5 结果回答过（LLM 的服务与最优/匹配的
传统臂**逐位持平**），不必再花一次闭环。

### §31 第 111 行的小型 2×2（规则 planner vs 适配 agent × 原执行路径 vs 候选）

**原文的前置是"只推进出现可解释差额的一项。随后才接真实 agent 的少量闭环"。**
两处"'可解释差额'都不存在"：

- **候选 1**：位置带来的业务差 ≈ 0（`aoi` 臂含中断三档逐位不变）⇒ 没有差额可拆；
- **候选 2**：网格在业务口径下 0/30 非支配；唯一有差的一档由**既有臂**拿到，**不是本文机制**
  ⇒ 差额**不属于**本文，2×2 拆出来的将是"既有臂 vs 适配 agent"，与本文的方法主张无关。

⇒ **小型 2×2 不启动。**

### 什么条件下才应该启动（写给下一轮，不是现在的授权）

必须**同时**满足三条：

1. 某一项出现**本文机制**（而非既有臂/既有成果）的可解释差额——即"换掉本文机制、差额消失"已被验证；
2. 该差额在**共享能力、共享目标、共享预算、共享工具**下仍然存在；
3. 已排除**普通算法**解释（普通搜索 / 同信息 MPC / 成熟调度），否则应先把那个普通算法作为强基线。

**本轮三条都不满足。**
