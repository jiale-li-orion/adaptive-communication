# 公平节奏对照预注册：把臂集合做成**给动态规则公平机会**的版本

日期：2026-09-14。**本文件在任何正式对照运行之前写定**，此后不得按结果修改臂集合或判定规则。

依据 [`48-...`](48-review-energy-placement-and-pacing-decision-2026-09-14.md) §4、§5，
以及上一轮的审查更正（[`52-...`](52-pacing-closure-record-2026-09-14.md) 文首、§7.133）。

## 0. 为什么要重做（上一轮的臂集合有先验排除）

上一轮四条背压臂是 `fast_s = 900`、`slow ∈ {1800, 3600}` ⇒ **只能比义务节奏（900 s）更慢**；
而**除 `fixed300`/`aoi_const300` 外没有一条臂以「达到最高服务」为目标**。
⇒ 0%/1% 档「可行 2 条」是**构造出来的**，**不是**「动态规则达不到」的证据。
**本轮把 `fast_s` 打开，给动态节奏一个公平机会**；结论措辞一律限定为「**本轮臂集合内**」。

## 1. 固定的东西

N3 基底（`instance_ccorral_iid_c0.05`：**900 s 义务**、无事件、`hetero`、cap 0.05）的
**采样节奏、事件逻辑、缓存与打包纪律、能源参数**，以及**网关执行位置**（`placement="gateway"`）。
**唯一改变的是 `report_period` 策略**；任务 12 h + 1 h 尾窗、分母 **672** 沿用。
三档 **P0 无强制中断 / P1 回传 [4h,7h) / P2 接入 [4h,7h)**，**四个中断字段逐档写全 + 断言**
（防静默继承基底 config）。所有臂 `dwell_s = 600`。

## 2. 臂集合（**冻结**，共 20 条）

| 组 | 臂 | 说明 |
|---|---|---|
| 零控制 | `local` | 不下发命令 |
| 固定全集 | `fixed300/600/900/1800/3600` | **只写上报周期**；`fixed900` 即"保持原配置" |
| AoI 代表 | `aoi`、`aoi_const300`、`aoi_f600`、`aoi_t7200` | 已登记前沿的端点与常数臂 |
| **报压族 A（转发受阻信号）** | `pacing_bp{slow}_{fast}`，`(slow,fast) ∈ {(900,300), (1800,300), (1800,900), (3600,900)}` | 判据＝`gateway_last_forward_ok_at` 距今 ≥ 1800 s **且** `gateway_pending_depth > 0` |
| **报压族 B（缓存积压信号）** | `pacing_backlog{slow}_{fast}`，同一组档位 | 判据＝`gateway_oldest_pending_age_s ≥ 900 s`（**同一"受阻"谓词的另一种本地信号**） |
| 迟滞版 | `pacing_bp900_300_hyst`、`pacing_backlog900_300_hyst` | 连续 2 次同侧才切换 |

**关键新增**：`slow = 900` 配 `fast = 300`（「**按义务节奏封顶 + 未受阻时全力**」）——
**这是上一轮完全缺失的那一格**，也是唯一可能在高服务端竞争的类型。
**参数不单选：上面所有档位组合全部报告，禁止事后挑参数。**

**输入只用网关本地可观测的量**（`gateway_pending_depth`、`gateway_last_forward_ok_at`、
`gateway_oldest_pending_age_s`、既有的节点回执与新鲜度）；**不读**环境 `path_available`、
未来恢复时刻、节点真实未上报缓存、中心未确认的交付真值；**没有反馈接口时不慢化**。

## 3. 参照服务与容差

参照服务**只来自冻结的普通基线集合**（`local` ∪ `fixed*` ∪ AoI 代表）；
**新增的报压族不参与参照的确定**，也不能改变分母或回头选择容差。
服务容差 **{0,1,3,5}% × 672**，**主报告 0% 与 1%**。
**缺采约束**：不得以新增缺采换成本收益；包络里显式列出违反者。
成本轴**分列**：上行、下行尝试、上行空口、总能耗；AoI 另列。

## 4. **逐条解剖（本轮必须做）**

给 `scoring.evaluate` 的逐义务台账加可选 `heard`（**默认关闭；已核 18/18 且现有读数不变**），
把每条义务定位到三级：**采到（样本存在）/ 已到网关 / 已到中心**。
每个 (条件, 臂, 种子) 保存 **`delivered_bitmap` 与 `heard_bitmap`**（义务按 `oid` 定序的位图，hex），
以便**精确算出与参照臂的翻转集**。另保存 `post_outage`（中断结束 → 首条窗后样本到网关 → 到中心）。

必须给出：
1. **少发了哪些上行**（上行差 + 到网关差 + 到中心差）；
2. **当时数据在网关还是在节点**（`heard` 与 `delivered` 的两级差）；
3. **恢复后首次新数据延迟**（`heard_delay_s` 与 `received_delay_s`）与**首次有效降档延迟**；
4. **节省是否抵得过损失**（省的资源 vs 丢的义务，按同一服务容差）。

**边界（doc 48 §3）**：`backhaul_forward()` 能在恢复后独立转发网关已有缓存 ⇒
**已抵达网关的样本不需要节点再次上行**；**不得**把恢复积压都算成 Class A 窗口等待。
⇒ 因此第 2 条的判读是：**若"未到网关"的那部分很小，则省下的上行主要是冗余重试，不是真损失。**

## 5. 预注册判读规则（先写死）

- **R1**：若在 **0%/1% 容差**下，**最低成本位全部由固定周期臂取得** ⇒ **本轮不实现候选**。
  **⚠ 且事先声明**：这只说明「本轮臂集合内没有工作点需要更复杂的规则」——
  因为本集合仍未穷尽动态节奏规则，**不得**读成「普通规则覆盖了全部有效工作点」。
- **R2**：若某条**报压臂**（任一族、任一档、含迟滞）在 0%/1% 下**成本不高于最低成本位、
  服务不低、缺采不劣** ⇒ **普通背压覆盖** ⇒ 保留为强基线，**不实现候选**。
- **R3**：只有当**某条臂在同一容差下成本低于固定族 ∪ 报压族 A ∪ 报压族 B 的全部成员**、
  缺采不劣、且差额**超出同种子配对自助区间**时，才做**最小机制 + 消融**，
  再用**未参与开发的种子**验证。
- **R4**：不足以晋级的理由照 doc 48 §5：「仅比中心 `ea_nb` 好」「只比高速上报省」
  「删除全零种子后才好」「放宽容差后某点胜出」「载体支持下发」。
- **R5**：纪律——预注册先于运行；不新增无线覆盖/强制接收/设备自动回退；未来真值只供独立评分；
  `run_checks.py` 18/18（**先看 `EXIT=$?`**）；结果登记**只在表尾追加**；
  **单种子数字不得下结论**（多种子均值 + 配对自助区间）。

## 6. 明确不做的事

不实现候选机制、不做消融、不接 LLM、不补剩余 37 档突发扫描、
不新增探测/回执（若将来需要则**逐项记账**）。

## 7. 本预注册自己承认的局限

**本臂集合仍然不是动态节奏规则的全集。** 它覆盖了「两种本地受阻信号 × 四组快慢档 × 迟滞」，
但**没有**覆盖：按**预测**选档、按**义务剩余时域**选档、以及**中心侧**（而非网关侧）执行的同名规则。
⇒ 即使 R1/R2 成立，也只是「**在本轮这 20 条臂内**」的结论。
