**全局研究复盘：现有 agent 方法能否迁入，以及下一步应验证什么**

2026-09-14。审查基点 `e474c02`。本文件是研究建议，不是新的任务冻结、方法晋级或实验授权。本轮阅读 Human 复盘、后续实验报告、当前 LLM 协议和相关作者全文；未重跑实验、未改代码或当前协议。检查时 `results/llm_naive_v5_full.log` 已存在，只有启动信息，不能据此报告全量结果。

**结论。** 当前困难有两层：现有通信 agent 的原生决策能力与本站的动作能力不同；本站当前 LLM 实验又把配置目标交给规则产生，因此主要测执行行为。继续增加这一实验的模型调用，不能自动回答“既有 agent 调度方案在山区监测中有什么缺陷”。建议保留该实验的窄用途，同时把下一步收束为一个有明确目标、完整保留规划与反馈环节的方法迁移。是否有方法增量仍待实证，不能预设一定能找到 agent 错误。

**场景需要什么，以及当前调度方法实际暴露了什么。**

来源支持的任务要求监测数据持续产生、断连时保留、恢复时送达。现有本地事件响应、缓存和自动补发承担了大量工作。中心的两个主要干预是采样间隔和上报周期：前者改变采集负载，后者改变通信负载及 Class A 接收机会。两者的价值取决于当前瓶颈；事件响应列在既有实例中恒定，也就不能承载中心策略收益。

仓库已经给出几种明确反例：标定固定配置对资源变化不稳健；直接使用陈旧 SoC 的阈值策略可能维持高负载；部分配置会产生无法靠后补采集弥补的损失；大量动作不能穿过当时不可用的回传。它们反驳的是这些具体实现或简化假设。把它们扩大成“传统 AoI、优化或控制方法默认完全观测和可靠动作”不成立。例如 [Semantic-aware Sampling and Transmission: A POMDP Approach](https://arxiv.org/html/2311.06522v2) 已联合处理部分可观测源、采能、采样与发送代价及不可靠信道。这不是本任务的直接可用解，但足以限定先行工作主张。

还有一项容易被忽略的区分：在 `noout` 与 `out3` 分叉之前，如果两条轨迹给控制器的历史相同，因果策略就不能预知后者会断开。事后知道哪次介入造成死亡，可以证明后果和鲁棒性不足；不能直接把“没有预知未来中断”记成 agent 推理错误。要评价其选择，应预先说明允许的资源取舍、风险处理和可用信息。

**当前 LLM 实验为什么难以回答论文问题。**

A′ 的目标 `desired_target` 已由 AoI 规则计算。LLM 决定是否下发该目标，不负责产生通信调度方案。v5 为单步 JSON 决策，未复现 WirelessAgent 的完整 workflow 或 ICLDC 的历史反馈与 verifier；其输入也没有实际 SoC 数值。它可以评价指定目标下的执行行为，不能同时检验能源规划或代表相关论文的调度能力。主机每个 epoch 固定调用一次模型，也意味着 intent 数不能直接充当本可省掉的 LLM 调用数。

采用 A′ 是此前隔离执行问题的合理选择；现在研究问题转向“现有 agent 调度方案”，就需要另行明确二者的关系。不能把 A′ 重命名成既有方案复现。v3/v4 的零动作记录还受仪器或描述问题影响，应按最新记录解读，不按旧报告标题收盘。

**通向方法增量，尚缺哪一步。**

分列报告多个指标是正确的评价纪律，但它没有自动定义 planner 应如何取舍。现有前沿包含不同服务、AoI 和开销选择；不能让 agent 用一句“做好监测”同时胜过所有点，也不能先由 AoI 规则给出答案，再期待它表现另一类规划能力。

建议先把已有目标操作化成可比较的问题。例如，在同一业务义务、节点资源和明确通信预算下，比较周期有效交付，并继续分别报告 AoI、采集缺失和能耗。预算是 A 层研究条件，可以选现有前沿的若干工作点，不能称合作方 SLA；每档传统方法也应得到公平调整机会。这里没有增加中心必须行动的义务，本地自治足够时仍是正确结果。该建议触及此前 B′ 的目标欠定义问题，需要形成新的明确决定，不能静默重开 B′ 或 C′。

在这个目标下，完整 workflow 可以读取合法历史，调用共享的计算/评价工具，提出已有字段的配置，再根据真实反馈继续。计算工具不增加无线能力，也不得读取未来真值。传统调度器可作为 agent 工具和比较对象；不要求 LLM 心算本已有算法能解决的数值问题。

下一步需要找到的是一个具体决策差距：同样可见的信息、动作和预算下，存在更好的可执行选择；迁移后的 agent 稳定选错；错误可以归因到某一缺失信息处理或执行环节。只看到原生 agent 在异构环境下分数变低，或一个离线 oracle 预知未来后做得更好，都不满足这个条件。

若差距来自可见历史被误用，可研究表示或 belief 更新；若来自配置到达后才成立的前提，可研究既有校验环节如何评估真实动作后果；若来自原方法本不具备的硬件能力，应停止该迁移的性能比较。这些是归因后的分支，当前不晋级任何一个机制。缓存新鲜度、belief、准入、去重、等待和 backpressure 本身已有先行工作，也已有仓库探索；名称不能承担贡献。

**下一轮建议交付。**

1. 按当前协议完成或如实报告 v5，给它一个窄结论；不以是否出现坏重试作为筛选模型或 prompt 的标准，不干预本轮进行中的运行。
2. 给出一份 WirelessAgent 适配差异表：原方法组件保留什么；现场动作为什么合法；哪些仅是本地计算；输入历史、目标、反馈、停止条件、计算预算怎样对齐。不能只交一个声称“像 WirelessAgent”的 prompt。
3. 从已有条件和记录建立少量有判别力的决策案例，先确认在同一目标下存在可利用的选择差异。先检查已有证据；若需要局部反事实，未来真值只供独立评分，不能反馈给 planner。特别区分分叉前无法预见的未来差异与分叉后已经可见却被忽略的信息。
4. 通过上述判断后，再做一轮小型闭环对照：成熟规则 workflow 与完整适配 agent 共享能力、目标、预算和工具。对实际出现的差距，分别诊断信息与执行，不同时把观测和动作都理想化。不在这一轮预装“本文机制”。

此轮的研究交付应是：**可迁移的方法、明确的决策目标、可重复的差距与归因**。若只剩普通参数调优，或成熟 workflow 已承担全部有效决策，就如实结束这条 agent 方法假说；benchmark 是否可发表还需另做贡献评估。若出现可修复差距，再要求小机制保留正常条件收益、在相同资源下改善业务，并击败合理的现成处理方式，才能推进方法论文。
