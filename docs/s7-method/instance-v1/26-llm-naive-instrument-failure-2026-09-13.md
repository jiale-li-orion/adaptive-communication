# 真实 LLM naive baseline：**仪器失效，本实验没能回答预注册问题**

日期：2026-09-13。协议 `llm_naive_v1`（`sha256=11a0ce44…`）。基线 `5db8509`。

## 发生了什么

全量跑（3 条件 × seed 0 × 13 h）在**第一个条件结束后崩溃**——崩点是我自己的打印语句：
`episodes = 0` 时 `amp_intents = None`，而我对 `None` 做了 `:.2f`。**崩溃把 `adm_noout` 的
动作分布、service、tokens 全丢在进程内存里。已修**（统一走 `_fmt()` 处理 `None`）。

崩溃前已打印的结果：**`adm_noout`：778 次 planner invocation、0 个 semantic episode、0 闭合。**

## 决定性判读：**不是接口坏，是模型每次都选 noop**

修好后做 30 次调用的受控探针（条件**不变**）：

| 量 | 值 |
|---|---|
| `actions` | `{'noop': 30}` |
| **未下达动作的原因分类** | **`{'action_noop': 30}`** |
| **原始输出采样** | 5 × `{"action":"noop"}` |
| 解析失败 | **0** |
| tokens | 27/次调用（327 in / 6 out） |

原因分类里**没有** `node_not_in_view` / `no_valAM` / 解析失败 ⇒ **我的接口没有把合法动作误判掉**。
**模型是真的每次都回答 `noop`。**

（`service`：`adm_noout` 160.0/168、`adm_out3` 45.0/168、**`polar_c0.05` 0.0/168 且 AoI 为 `None`**——
最后一条与 §7.95 的发现一致：**polar 在 seed 0 下链路根本没有交付**。）

## 为什么这**不能**用来判预注册判据

`episodes = 0` ⇒ `amplification = 0/0` **无定义**。更根本的是：

> **我给模型的状态里没有任何"现在有事情不对"的信号。**
> 节点已经在 `sampling=3600 / report=3600`，而 `obligation` 只是一句字符串
> （"one routine report per 3600 s per node"），**没有逐节点的"新鲜度 vs 义务"对照**。
> 一个理性的回答就是"没什么要做的"⇒ **永远 noop**。

所以"零动作"**既不是"LLM 克制"、也不是"没有 planning amplification"**，
而是 **prompt 没给出行动的理由**。按预注册判据 1 直接记"scripted 发现没有自然迁移"
**会是错误的**——那会把一个**仪器设计缺陷**读成一个**关于 Agent 的结论**。

**这正是要防的那类错误的反面**：不故意把 LLM 弄傻，但也**不能把它放进一个不需要动作的世界里，
再把"它没动作"当发现**。

## 已确认不是问题的部分

- `thinking` 关闭有效、JSON 严格、无解析失败（`bad = 0`）
- 接口的 node id 校验没有误杀（原因分类可证）
- 成本口径：**327 输入 / 6 输出 token 每次调用**，与预估一致
- 崩溃**只发生在打印阶段**，仿真与调用链路本身是好的

## 下一步需要决定的事（我不擅自改冻结协议）

按我自己定的规矩：**协议一旦冻结，改它必须新建 `protocol_id` 并重跑**，不能原地改。
所以把问题交出来：

**选项 A（推荐）**：新建 `llm_naive_v2`，在状态里补上**中心真的知道**的两样东西——
① 逐节点的**新鲜度 vs 义务**（它最后一次被听到距现在多久、义务周期多少）；
② 逐节点的**电量与证据年龄**。**不添加任何"该怎么办"的提示、不添加策略智慧**，
只是把"现在有没有事情不对"这个**中心本来就掌握**的事实呈现出来。
然后重跑 3 条件 × seed 0。

**选项 B**：接受"在当前 prompt 下 LLM 从不动作"，把它记成**baseline 的失败**而不是发现，
并据此说明**这个 benchmark 的 naive-LLM 基线需要一个明确的 objective 表达**——
但这更像是 benchmark 设计问题，不是 agent failure。

**选项 C**：先补 scripted 的**"有动作"对照**（`aoi`/`ea_nb`）在同一 seed 下的 action 数，
确认"中心确实有可做的事"，再决定 A 还是 B。**这个最便宜，也最能防止我们误判。**
