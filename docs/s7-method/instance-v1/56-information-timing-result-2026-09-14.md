**裁决：本轮没有产生新方法候选。** 普通数据包 ACK 已经可以在同一调度周期里改变后续路径；

在两档都被普通 ACK 支配。所以不实现新 infra mechanism，不接 LLM。

## 1. 本轮真正修正的是时序语义

旧 `run_probe_ablation.py` 的探测结果下一小时才能被决策使用，且零尝试记录会刷新冷却，
同拍 probe/data 记录还会相互覆盖。新微环境固定以下顺序：

1. 样本到达与过期；
2. 可选付费探测；
3. 探测结果返回；
4. 数据包尝试；
5. ACK 返回；
6. 用这个结果选同一 epoch 的下一次尝试；
7. 时间推进 1 h。

一小时内真实链路状态不变。probe 和 data 使用分离的随机键，因此加 probe 不会改变已配对的
数据包丢包结果。零尝试不产生证据；同拍 probe/data 保留为两条记录。八项语义测试全部通过。

**同拍返回 ACK 是 A 层接口假设**，不是仓库已有案例证据。如果真实设备只能下一小时返回，
则该信息对当前 iid 状态无预测力，不应用本结果宣称可实施收益。

## 2. 四臂主对照

四臂共享同一外生 trace、业务队列、EDF/event 优先出队、能量配给、路径容量和卫星配额。
`history_only` 整拍提交；`data_ack` 逐包贝叶斯更新后重选路径；`paid_probe` 在事件积压时
先发一条探测，且探测与数据包同占容量、能量、费用和卫星配额；`current_truth` 看当前真值，
但使用同一条贪心分配规则。最后一臂不可实现，也不是有限时域上界。

## 3. 为什么更快更准的 ACK 反而少交付事件

事件小时内，`history_only` 平均尝试 109.4 次，其中 29.9 次失败；`data_ack` 尝试 87.5 次，
只失败 9.0 次。后者确实根据失败 ACK 避开坏路径，却也少了 22 次事件期尝试。
在 2 h 截止下，整拍臂用更多低效重复换回约 2 条事件交付。因此“减少坏路径发送”和
“提高截止前可靠性”并不等价。

这个现象不是能量激进系数没调好：事后只扫 `{2,3,4,6}` 四个事件能量系数，两臂读数几乎不变，
因为事件期的路径容量已先绑定。再把 ACK 聚合粒度设为 1/2/3/6 包，event 从
83.37% 升到 83.75/83.75/84.55%，routine 从 88.53% 变为 88.78/88.12/87.14%，尝试从
1470 增至 1516/1553/1639。六包档与整拍臂的 event 差仅 −0.17 pp（−0.43…+0.08）。

**这是一条普通控制前沿：ACK 聚合越慢，事件可靠性越接近整拍重复，但坏路径浪费随之回来。**
不能把单 ACK 过度反应命名为 agent failure；普通多样本过滤和滞回就能在这条前沿上移动。

## 4. 方法闸门

- **付费探测关闭**：当数据包本身会返回同质 ACK，且探测与数据占同一次机会和成本时，
  探测少了一次载荷交付机会，实测被 `data_ack` 支配。
- **信息时序保留为 failure insight**：证据必须在最后可挽回机会前回来，但返回后仍需按观测噪声、
  截止期与机会成本选聚合粒度。“更新鲜的信息”本身不保证更好的业务结果。
- **不晋级方法**：同拍 ACK、简单贝叶斯更新、多包聚合已构成可实现强基线。本轮没有一个
  仅能由新 infra mechanism 解释的增量。

重开只需一条硬条件：现场接口证明存在**比载荷数据更快、更便宜或可观测不同隐状态**的探测，
并且该差异在原场景的发射机会和截止期内可用。在此之前，不再扩预算、K、UAV 或 LLM。

## 5. 证据边界

- 多路径环境是 A 层扩展；ChirpBox 的 LoRa 突发参数被迁移成 WAN 状态过程，不是实测蜂窝回传。
- 卫星、UAV、配额、费用、小时级 ACK 和 1950 发射预算均是研究参数，不冒充中通服现场配置。
- 所有对照共用一条简化分配规则，没有证明 POMDP 最优性，也不证明其他在线控制器无法改善。
- 事后能量系数与 ACK 聚合网格用于解释首轮取舍，不是预注册主结果。
- 本轮是 20 个开发种子的案例级诊断，不认领跨站泛化。
