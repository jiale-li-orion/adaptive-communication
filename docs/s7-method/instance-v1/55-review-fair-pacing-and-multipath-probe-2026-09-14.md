# 公平节奏更新与未提交多路径探针的研究审查

日期：2026-09-14。已提交锚点 `0e90b40`（含 `3b91f3d` 的措辞更正）；另读取尚未跟踪的 `multipath_probe/` 全部核心代码、README、STAGE2_FINDINGS、最终结果与探测实验。此次没有改实现、没有跑仿真或 LLM，只重算已有统计、检查时间语义、构造一个不执行环境步的探测输入，并核验相关一手文献。

**决策：继续研究，但不接受“最强传统方法已到顶，所以接 LLM + 模型漂移”的 GO。** 主仓库新增的是有数值支持的普通动态规则服务—成本取舍；多路径目录新增的是合成扩展模型中的信息待遇对照。两者都可以保留，不能直接合并成 agent 的可实现方法优势。后续优先解决信息何时可用、能否合法取得、取得后是否仍来得及改变服务，而非扩大预算扫描或立即调用 LLM。

### 1.1 三级台账还不能证明“省下的上行全部冗余”

`code/instance/scoring.py` 的 `heard` 判定是：某个匹配样本的 `heard_at is not None`。它没有检验 `heard_at <= obligation.deadline`，也不记录比较所需的第一次到网关时刻。因此它表示**运行结束前曾到网关**。

相同样本最终都到过网关，但一臂到得早、赶上了回传窗口，另一臂到得晚、错过该窗口，两者仍会得到相同的 `heard=True`。所以 `heard=672` 不能推出：上行慢化没有交付损害、损失全部由回传外生状态造成、改善对象不存在。§54 的成本取舍有效，这段因果解释尚未闭合。

下一次确需解剖时，记录每条义务的源样本身份、第一次匹配样本到网关/中心的时刻、固定截止时刻；分别比较准时到网关、晚到网关、准时到中心。不能按“最后未完成的阶段”自动划分因果责任。已有到达位图无法恢复这些时刻，只有这部分可能需要原条件的有限轨迹重放。

同样，`post_outage` 的 1530/2115 s 是候选的绝对延迟，不能直接叫“额外等待”。本轮从已有摘要复算：P1/P2 相对 `fixed300` 的首条窗后样本到网关延迟均值 **−465 s**，到中心为 **0 s**；这两个单一恢复指标也不能解释其余义务的迟到。

### 1.2 R3 应作为候选评估门槛，不能作为候选产生的前提

在全部由普通规则构成的臂集合里，赢家落在普通规则集合中不构成算法空间已耗尽的证据。`3b91f3d` 已纠正这点，但 §53/§54 仍以“赢家本身在族 B，所以 R3 不成立”作为不做任何机制工作的理由。

我此前 §48 的表达也有责任：把“已有可解释差额”与“先有超出强基线的新方法增益”混在了一起，容易形成候选尚未实现就要求其先证明获益的循环。今后应区分：**有来源的失败假说足以支持一个小候选实验；同信息、同能力下优于强基线才足以晋级方法主张。** 当前可以因为缺少额外具体假说而暂停，不能宣布未测试的算法都没有余量。规则短小不等于缺乏新颖性，是否新颖仍需对最近先行工作逐项比较。

## 2. 多路径探针的正数目前说明什么

`multipath_probe/results/final_arms.json` 中，`chirpbox` 条件下 `oracle − belief_mpc` 的事件服务差在预算 1950/1800 为 **4.27 / 8.19 个百分点**。这与报告吻合，但该表不能把两者之间的空间全部认作 agent 可恢复收益。

若强调同一求解器的信息干预，正确的直接比较应是 **`cheat_mpc − belief_mpc`**，对应均值为 **4.72 / 7.92 个百分点**。文件只保存了均值和 `oracle_minus` 的区间，没有逐种子原值；不能用两个 `oracle_minus` 区间相减构造该对比的配对区间。后续如重放一个代表条件，应保存五臂逐种子服务、routine、能源、配额和观察/动作摘要。

可接受的描述是：**在这一实现与合成模型里，给近似控制器当前状态点信念，会改善部分紧预算条件下的事件交付。** 当前没有可实现控制器用相同合法历史取得了这部分提升。

### 2.1 “全知参照接近”不能认证部分可观测最优性

`OracleController` 是看到当前信道状态的贪心控制器；它不求有限时域最优策略，也不预留未来事件的最优资源。坏态仍有 0.02 成功概率，故“从不在坏态发送”也不自动最优。应称当前状态全知贪心参照，不能声称严格上界。

`BeliefMPC` 则是 6 步、12 个随机情景、6 个 α 的近似搜索，不能命名为传统方法天花板。`cheat_mpc` 接近上述贪心参照，只表明确定状态下两种实现的成绩接近。隐藏状态下如何安排未来信息获取、预留资源和处理截止期，仍可能存在求解器损失。区间跨零也不等于经等价检验证明相同。

对一个统一奖励目标，概念上的分解为：

`全知实现 − 历史实现 = 最优信息待遇差 + 历史求解器损失 − 全知求解器损失`。

只有分别控制后两项，才能估计最优信息待遇差；即便估计了它，也不意味着同信息 agent 能跨过它。本报告没有证实“残差全部无法由任何历史策略消除”，也没有证实“agent 在正确模型下不可能超过这个近似 MPC”。准确推断和准确决策是两个不同问题。

### 2.2 当前 rollout 的信息语义还不支持“强信念规划已排除”

以下不是要求现在大修所有代码，而是决定如何使用当前结果：

- `_rollout()` 抽出每个情景的隐藏 `good[p]` 后，立即用对应的 0.95/0.02 成功率分配发送，包括 `h==0`。真实执行时当前分配只能用后验期望。这种先看到情景再分配与实际“先选动作、后见结果”的顺序不同，不是完整的可执行观察分支树。
- 模拟未来观察后，belief 被直接赋成隐藏真值 0/1，未按同一带噪观测模型更新；还在一次循环中先预测再赋当前真值。不能将其称为精确的闭环信念传播。
- 事件积压用 `be*0.5` 平分两个年龄桶，View 没有精确年龄组成；“两龄桶精确维护截止期”不成立。真实环境还保留 `deadline_t == t` 的样本，其可发送时段需和前滚明确定义一致。
- 未来步重复使用当前 `sat_quota_left`，未在 rollout 内逐步扣减和日重置。确定状态臂与贪心分数接近不能消除这些近似在不确定情形下的影响。
- 无硬预算时 `BeliefMPC` 直接退回 `RuleMpcController`，且该分支绕过 `cheat_mpc` 注入的状态覆盖。因此 loose 档并未保持与紧预算档完全相同的同求解器信息对照。

直接比较两种信息输入仍有描述价值；这些限制使“100% 纯信息价值、没有求解器缺口”的认证过强。

## 3. 当前探测消融没有测到可购买的信息价值

`env.step()` 对每条路径每小时都追加一条历史，包括 `attempted=0`。`RuleProbe` 用最新历史时间计算冷却，因此正常运行中每拍距最新历史都只有 1，小于默认冷却 2。首次空队列时也不探测。即使路径一直没有发送，冷却仍会被这些零尝试记录刷新。本轮用构造 View 验证了这一点；没有执行新的环境轨迹。

此外，同小时 probe 与 data 记录会被 `_markov_belief()` 的 `{t: (a,s)}` 历史字典折叠，后追加的数据记录覆盖探测记录。即使修复触发，信息也可能未被吸收。

更深的限制是执行顺序：`run_probe_ablation` **先决定 allocation，再在 step 内探测；结果下一拍才用于决策**。在 iid 小时状态下，上小时的探测无法预测本小时状态。因此这套时间语义下，免费 probe 也不能等价于 oracle 的“决策前知道当前状态”。必须区分探测噪声、返回延迟、成本和可用动作；价格为零不代表获得当前真值。

如果真实设备允许先发一个数据包、取得 ACK 后再决定同一信道持续期内余下发送，最先应检验这种普通顺序发送/反馈机制；所有对照共享这项能力。如果真实接口只能下一小时给结果，就应保留这一不可用性边界。不能由任一种假设推导“LLM 能猜出”当前 iid 状态。

`diagnose_belief.py` 的“坏态误报率 100%”来自将固定先验 0.688 以 0.5 为阈值硬分类，不能称后验失准；其诊断历史也由 `rule_mpc` 产生，并非最终 `belief_mpc` 的观察轨迹。信息诊断应分别报告校准、决策损失及产生该历史的策略。

## 4. 这不是原灾前监测任务的直接消融

原 [`task-contract-v1.1`](../task-contract-v1.1.md) §1、§6、§12 将备用 WAN 控制放在有条件扩展里。探针目前独立生成网关侧队列、1 h 决策、2 h 事件截止期、12 h 常态截止期，并引入卫星与 UAV、全局发射预算；它没有复用原来的节点采样、Class A 配置过程和来源义务。

因此可作为 **A 层机制探针**保留，但需要逐项桥接才能进入原论文。尤其：

- ChirpBox 的 0.0712/0.1567 来自上海 LoRa 数据。将其迁移为蜂窝回传状态过程是研究假设，不能因两个数有出处就称实测蜂窝信道。卫星规格表与实际 `BAD_BURST_HOURS` 也应统一；环境实际用的卫星 chirpbox 平均坏突发为 4.57 h，而 README 表列参数导出的是 2 h。
- UAV 接触窗口、短报文额度、每路径成本、两个截止期与价值权重均需自己的来源或明确 A 层定位。“形状参考 Wang”不足以继承 Wang 的业务含义。
- 预算目前只有发射支出，无采样/待机/采能/容量溢出；它不是原节点能源模型的复现。数值单位和共享电源对象需说明，不能直接引用为现场 Wh。
- K=1 仍有“现在发或等待”的时间选择，能源有限时状态信息可能有价值。“单路径若存在差额则仪器有 bug”的 P1 不成立。原单路径测试未施加最终紧预算，不能证明多路径必要。
- 当前 `generate_trace` 的事件日程会随 K 改变：本轮用 seed 0 构造轨迹，K=1 与 K=3 事件小时不同；相同 K 下三种 burst 的事件小时相同。跨臂配对成立不代表跨 K 的任务因素已隔离。
- 初版 P2 预测突发越长 gap 越大，最终发现的方向相反。应记为原预测不成立后的探索性发现，不能写成原 gate 全部通过。紧预算阶段也没有完成“去任一因素即消失”的完整对照。

仓库 s2 已收录 Kumar 等灾前滑坡监测的多 WAN 容错证据，可作为备用回传扩展的优先桥接来源；这比新增 UAV 接触计划更贴近原范围。但摘要级来源不提供本探针所设额度、耗能与截止期，需继续区分。

## 5. 不按当前提案直接做“错误模型 MPC vs agent”

“固定错误参数 MPC 会变差”不能证明 agent 优势；传统方法可以在线估计模型、检测变化或维护参数信念。把天气/运维侧信息只交给 agent，同样改变了信息待遇。

已有一手先行工作足以反驳“参数化方法装不进未知模型/探索”的笼统表述：[Bayes-Adaptive POMDPs](https://proceedings.neurips.cc/paper/2007/hash/3b3dbaf68507998acd6a5a5254ab2d76-Abstract.html) 将学习模型、识别隐状态和获得奖励联合规划；[Adaptive MPC under Time Varying Uncertainty](https://arxiv.org/abs/1909.13473) 在其约束线性系统假设下在线缩小参数集合并处理时变不确定性。这些不是本站可直接套用的完整基线，但模型未知与漂移显然不是 LLM 的专有能力。本轮核对前者正文 §1–§3 和后者作者摘要。

若以后研究漂移，比较至少应包含同信息的在线估计/变化检测控制器，且同等开放侧信息、更新机会与资源预算。否则再次得到的只是“适应方法优于冻结错误模型”。目前不选择 API 或 LLM 型号，不以制造漂移作为论文已恢复的证据。

## 6. 下一步只要求三个有判别力的产物

1. **统一主张与范围。** 将 §54 的动态成本收益保留为强基线；撤掉“最终 heard 全满所以全是冗余”的归因。多路径报告改成当前状态待遇的近似控制器对照，去掉“严格上界”“传统天花板”“剩余必由 agent 接管”“三者缺一不可”。为新动作、源任务、信息返回时刻和成本写一页原场景桥接表；没有来源的 UAV/卫星设定留在探索附录。
2. **选择一个代表条件验证可获得信息。** 优先用当前已报告的 `chirpbox/1950`，保留 loose 作为边界；先定义决策、首次尝试、反馈返回、后续尝试和截止的顺序，再比较无主动探测、普通数据包带 ACK 的顺序决策、付费探测、不可实现的当前真值参照。后三者是否能同拍反馈必须由接口支持，不能只改探测价格。先做小状态/短时域的语义核验，再决定是否值得原条件重放；不扩预算或 K 扫描。
3. **给出可实现增量或准确的暂停理由。** 所有可实现臂同信息渠道、同发送能力、同目标和预算，求解器近似透明；保存逐种子分列指标。若普通反馈/在线估计就取得提升，保留为强基线；若在同能力下仍存在一个由证据选择、时机或资源分配导致的具体失败，才为该失败设计最小机制。候选无需先证明胜利才能获准小试验，但有分数差也不直接构成论文新颖性。

两批更新共同提示的研究问题是：**成本付出后得到的信息，能否在最后一个有效动作机会之前到达，并改变尚可挽回的服务？** 主仓库的最终 `heard` 和新探针的下一拍 probe 都没有独立回答这一问。这使“信息获取与及时使用”值得被明确建模；它尚非方法贡献，更不要求先让 LLM 犯错。
