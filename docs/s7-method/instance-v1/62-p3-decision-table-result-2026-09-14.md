## 3. 一个正例、一个无效例与完整时间线

**先声明例证与统计的关系**：下面的链条是**单种子（seed 0，P1 回传中断）**的逐事件展开，
**只是例证**；它成立的依据是同一效果在 20 个开发种子上已由配对区间确立
（`oblig_copies3 − pacing_backlog900_300` 服务 **+1.35**，CI95 **[0.65, 2.15]**，13/1）。
**不是从 5 条翻转义务里挑出来的孤例。**

### 3.1 正例：一条命令让一条具体义务从「晚 900 s」变成「准时」

义务 `n01:routine:00004`（节点 `n01`）：**释放 3600 s，截止 5400 s**。

**① 所读证据 → ② 目标产生 → ③ 命令生效**（`oblig_copies3`，k=3）：

| 时刻 s | 读到的证据（网关本地合法可见） | 目标 | 命令 | 生效 |
|---|---|---|---|---|
| 900 | —（初始） | 快报 300 | — | **900 生效 300** |
| 1560 | `pending_depth=46`、`oldest_pending_age=1560`、`last_forward_ok=0`、**本窗副本数 3** | 慢报 900 | sent 1560 | **1800 生效 900** |
| 2160 | `pending_depth=62`、`oldest_pending_age=2160`、**本窗副本数 1**（< k=3） | 快报 300 | sent 2160 | **2700 生效 300** |

**④ 具体义务改变**（同一义务、同一节点、同一种子）：

| 臂 | 首次到网关 | 首次到中心 | 准时（网关/中心） | 送达 |
|---|---|---|---|---|
| `oblig_copies3` | **3900** | **3900** | **True / True** | **True** |
| `pacing_backlog900_300` | 6300 | 6300 | False / False | False |
| `oblig_slack` | 6300 | 6300 | False / False | False |

**链条闭合**：义务 3600 s 释放，落在 **2700 s 生效的快档（300 s）** 窗口内 ⇒ 3900 s 就有合格
副本到网关并转达到中心，**比 5400 s 截止早 1500 s**；而在 `pacing_backlog900_300` 下同一义务
**6300 s 才首次到网关，晚于截止 900 s**。这是「**读到的证据 → 目标 → 生效 → 义务改变**」的完整链。

**⚠ 归因边界**：表中「所读证据」抄的是**候选自己**那次运行的视图；`pacing_backlog900_300`
的**决策链没有逐条重建**（它的视图因配置不同而略有差异），因此上表的对照是
**实测结局对照**，不是两条决策链的逐步对照。例证证明「该机制能产生这个改变」，
**不**证明「只有它能产生」。

### 3.2 无效例：候选与它的消融**逐位相同**

同一条义务在 `oblig_slack` 下与 `oblig_copies1` 下**逐位相同**
（`slack_equals_copies1_obligations/routine/communication` 三项全为 `True`）——
因为 doc 61 §3 的退化是**解析的**：义务截止期 = 窗口末端 + 一个周期 ⇒ 剩余余量恒在 `(period, 2·period]`
⇒ 「下一窗口仍有余量」恒真、「来不及」在 `command_delay_s ≤ period` 时恒假。
**因此 `oblig_slack` 的完整时间线就是 `oblig_copies1` 的时间线**，
它在本轮**不构成**对「余量／生效延迟」机制类的检验（既非正例也非否证）。

**仪器自检**：时间线用的「所读证据」记录器**只读不改**——脚本逐位核对
带记录器与不带记录器两次运行的 `routine`／`communication`／`_obligations`，**五条臂全部 `True`**；
不成立时脚本直接 `assert` 失败。

| 裁决 | 是否成立 | 依据 |

## 5. 文献差异与 agent 适配前提（doc 58 §5.4 要求的一页说明）

* **收益**：普通背压节奏（`pacing_backlog900_300`）在 1% 服务容差下省 **−30% 上行**（1255→880）、
  空口 **−43%**（0.0999→0.0574 h）、总能耗 **−3.6%**（0.3951→0.3808 Wh），
  代价是服务 **−2.95 条**（−0.43 个百分点）；
  **下行不是收益而是代价**：它要花 **107** 次下行去改配置，而固定臂只花 **19** 次（+463%），
  这是动态节奏在本表六列里最贵的一列（§1 第 3 点）。
  **不得写成延寿**：采样项占负载 94.0%，无线层节省几乎不转化为总能耗（doc 45）。
* **文献差异**：Zakeri 等 POMDP（arXiv 2311.06522）已含部分可观测 + 采能 + 采样/传输成本 + 不可靠信道
  ⇒ **这些因素的罗列不构成贡献**。本实例与之相关的**结构性**差异只有两条：
  ① 动作是**持续配置**（改的是节点此后行为），不是直接采样/发送；
  ② **两跳到达且不可即时纠正**（节点→网关→中心，命令生效有 600–900 s 的下界）。
  本轮**恰好是对第 ② 条的一次压力测试**：以两跳到达的**下游**统计量（副本份数）为信号去控制**上游**动作，
  **不可控**（doc 61 §4.2）。这是**负结果**，但它落在了 doc 58 §4 圈定的那条结构差异上。
* **agent 适配前提（当前不满足）**：doc 58 §4 要求「通信结果之后做一次 2×2（规则 planner／真实 agent ×
  现有执行路径／候选机制）」。**候选机制不存在** ⇒ **2×2 无法进行**，
  现在做只能得到「规则 planner 也获益」这一条，那**支持通用通信方法、不证明 LLM 必要**。
  这是**有意的阻塞**，不是遗漏。
