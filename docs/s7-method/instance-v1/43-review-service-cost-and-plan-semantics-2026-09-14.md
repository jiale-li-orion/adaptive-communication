**判别 A 没有覆盖原能源反例。** 从 `placement_contrast.json.config.base` 与已登记 `instance_adm_out3.json.config` 直接比较：

| 参数 | 判别 A 的四档共用上下文 | 已有持续耗电反例上下文 |

因此它是有效的供电宽松条件对照，未回答“更及时的现场能源证据能否阻止原反例中的缺采”。这里无需改义务或寻找更紧事件 deadline；可以复用已登记的能源上下文，保留接入中断负对照，再声明一个同时间窗的回传中断组合。这个组合是新的因子对照，不能称已有结果重放，但没有增加任务或硬件能力。先使用已实现的策略就地执行，不需要编译有状态计划。

即使该补充得到网关收益，它首先属于传统现场能源控制与位置收益；预装同一能源规则必须是强基线。该对照的价值是补齐原假说的适用边界，不能提前记入本文独有机制收益。

**二、候选 2 的预注册 R1 没有按原目标触发**

[`config_grid_run.py`](../../../code/experiments/config_grid_run.py) 的 `OBJECTIVES` 是：服务↑、上行↓、下行尝试↓、缺采↓、AoI↓。预注册 R1 要求所有网格点被现有前沿在前述指标上支配。

从 [`config_grid.json`](../../../results/config_grid.json) 的条件均值独立重算，使用原脚本 `1e-9` 容差、全部 38 条旧臂：

| 条件 | 五项目标：未被旧臂支配的网格点 | 加入网格相互比较后仍非支配 | 仅服务、缺采：未被旧臂支配 |
|---|---:|---:|---:|
| N1 无中断 | 20/30 | 13/30 | 0/30 |
| N2 介入后失联 | 14/30 | 11/30 | 0/30 |
| N3 第二来源节奏 | 20/30 | 13/30 | 0/30 |

因此不能同时声称“按原预注册 R1 关闭”及“关闭依据是业务两列”。后者是更窄的事后分析。加入能耗后，对旧臂的非支配数量为 20/14/24；这也不等于方法收益，只说明资源目标不能从判断中消失。

这些是样本均值的支配关系，不是带统计置信保证的前沿。部分点可能仅靠小差额或重复配置的执行时序保持非支配；不能据此认领 20 个有效创新。应分析哪些点扩大了具有实际意义的资源—服务取舍，再与普通算法比较。

一个全部来自旧臂的例子：N1 中 `aoi_const300` 与 `aoi_f900` 分别为：

| 臂 | 服务/168 | AoI s | 上行 | 下行尝试 | 能耗 Wh |
|---|---:|---:|---:|---:|---:|
| `aoi_const300` | 155.45 | 3737.08 | 764.60 | 18.75 | 0.118980 |
| `aoi_f900` | 155.35 | 3839.91 | 352.25 | 18.75 | 0.106285 |

后者的服务少 0.10 条，即少 0.0595 个百分点，AoI 多约 103 s，上行少 53.9%、能耗少 10.7%。选择哪个工作点依赖业务容忍范围。它不支持本文方法；它说明只看服务最大值会忽略与低功耗、低成本需求直接有关的量。

§38、§39 中“+13.6/672（+2.7%）”也应拆开：按固定分母约为 **+2.02 个百分点**，相对原服务 497.5 条的提升约为 **2.73%**。两种量都可报告，名称不能混用。

**三、当前普通滚动搜索没有排除成本控制或一般 MPC**

其目标先最大化预计交付，同分才最小化能耗；这相当于给予微小交付增量高于所有非平局成本差异的优先级。因此它长期选择最快上报档，并不能回答“允许一个明确服务容差时，最少需要多少资源”。

此外，预期交付式 `1-(1-p_u*p_b)^n` 将多次机会按独立尝试处理。模拟器的回传状态在一个小时内共享，同一小时内多次发送不具备该独立性；突发接入还有持续状态。这个搜索可称使用简化交付模型的滚动启发式，不能凭它的失败排除同信息下更合适的随机控制或 MPC。

“两个字段的实际等待被仿真器执行”和“优化器预测中计算了等待、部分生效及缓存过程”也应分开。目前前者发生，不等于后者已经完成。无需为审阅立刻实现完整 MPC；只需避免把一个简化模型的负结果扩大成方法家族的负结果。

**四、条件计划的三层正确性要分开**

**数据依赖可得性。** 当前登记表可用作静态准入的一部分。分支依赖量在某个位置存在，并不保证那一时刻已有足够新鲜的值，也不保证整个决策列表的语义在下沉后保持。`gateway.now_s` 是当前时刻，不能替代每项证据的 `read_at` 或样本 `taken_at`。

**决策列表语义。** `admit()` 将不可执行分支移到 `held` 后，解释器只遍历 `executable`。如果一个高优先级分支依赖中心证据，低优先级分支是 `always`，前者被保留后后者可以执行；原计划中前者可能为真并阻止后者。逐分支可得性不能据此构成“整个计划可下沉当且仅当……”的充分判据。要么保留优先级阻塞依赖，要么证明分支可独立拆分；当前 AoI 两个本地分支的验证没有覆盖这个情况。

**产物自包含性。** 本轮直接构造对象得到：

```text
compile_aoi_plan(stale_s=1800) == compile_aoi_plan(stale_s=3600)  -> True
compile_aoi_plan(dwell_s=1200).resource_limits['dwell_s']        -> 1200
PlanGatewayPolicy(该计划).dwell_s                              -> 600
```

`stale_s` 没有进入产物，解释器另取参数；`dwell_s` 虽进入资源字段，解释器默认值没有从中读取。因此当前三个种子的默认参数对齐，应称固定参数下的行为验证，不能推广为任意参数计划经过序列化、下发、重建后保真。

另外，目标是否属于 `allowed_configs` 的检查发生在执行循环，尚非 `admit()` 中的构造/准入检查。已有 `version` 字段及 603 B 尺寸不等于已经实现安装、更新、撤销或成本归账。交付方已经明确部分未做项，应维持这些边界。

这些问题不推翻既有默认规则对齐数值，也不产生论文新颖性。建议先收窄 §42 的结论，不把补齐解释器当下一轮主任务。只有要继续使用计划产物时，再做必要修正。

**五、AoI 的接收位置是物理语义，不能仅作为字段别名**

`_center_view().newest_taken_at` 来自中心实际收到的样本；`_gateway_view()` 同字段来自网关听到的样本。在回传中断时，网关 AoI 可以很低，中心 AoI 却持续增长。它们描述不同接收端的知识。

所以“相同策略代码在两处运行”是合法的架构比较，但不等于中心 AoI 判据被精确搬到了网关。当前编译的 `aoi` 相对于网关版策略对齐，不能证明相对于中心交付目标的语义等价。网关若要估计中心状态，需要有来源、带时间的确认或估计；不能把本地新鲜度作为中心新鲜度的别名。

这对方向的影响比单个字段缺陷更大：位置下沉只能使现场证据更早可得；若策略没有使用回传交付状态，其决策仍可能没有针对限制端到端服务的那一跳。相同 AoI/SoC 规则搬迁的负结果，不能单独排除利用不同合法网络证据的两跳节奏控制。

**六、哪些宏观解释还需要收窄**

- §35 将位置实验的近零业务收益解释为“performance 首先由 control authority 决定”，证据不足。既然该干预改变了证据和执行时刻却很少改变业务，它支持的是这些闭环内部变化在该条件下价值有限；无法据此重新确立早期已收窄的 authority 主张。
- §41 的零种子审计支持所测 8 条臂服务接近；不证明所有策略、全部成本或所有模型都接近。全零种子应保留在主要业务统计中，条件分层作诊断。不能为了制造方法差额选择删除零点或修改突发参数。
- “任务延长不能保证跨过随机中断”成立；“所以延长任务没有任何研究意义”不成立。指数/几何尾部没有有限确定上界，足够长时域仍可能改变经历转移的比例。当前没有必要为此补 37 档扫描，更不能把补齐扫描当作方法创新的前提。
- 当前两跳模型的突发接入在好/坏状态内分别完全收/不收，i.i.d. 接入则逐尝试抽样；这是会影响重试价值的模型选择。来源拟合不足以支持外推时，结论应保留到该模型，不能把前沿塌缩全部解释为现实网络中的控制权消失。

**七、当前只保留一个待判别方向：有监测服务约束的双跳上报节奏控制**

问题：当节点仍能到达网关、但回传暂时无法交付时，如何减少端侧通信支出，并避免在回传恢复后因此前拉长上报周期而继续错过有效交付？采样和本地事件响应沿用原义务，不用少采样改善成绩。

最小机制构想：使用网关实际收发产生的回传可用证据、缓存记录的采集时间、节点已报告的配置与电量，在已有 `report_period` 取值中选择节奏。选择较慢节奏前，同时评估资源节省与下次合法 Class A 机会带来的恢复延迟。证据过旧时维护不确定性，不能直接读 `path_available` 的环境真值。采样配置初期保持任务要求；先隔离发送侧，不同时加入多个优化器。

可解释的冲突是：继续频繁上报可能无法增加当前端到端服务；放慢上报又会推迟后续可控机会和新数据抵达网关。原先“缩短上报修复回传不可达”的主张仍然关闭；这里评价的是这段不可达期间的成本及恢复后的服务。

它尚未被本轮直接测试：判别 A 固定了 AoI/SoC 规则；判别 B 是固定配置及优先最大交付的搜索；缓存判别只运行 `local`，未测节奏与有效数据积压的交互。但“未测”只是留下问题，不能保证余量。

普通数据平面背压是必要强基线。仓库已收录的 [PermaSense 原文](https://essd.copernicus.org/articles/11/1203/2019/) 明确描述节点在拥塞/失联时本地存储，以及基站侧的间歇存储。因此不得认领“山区监测中首次使用背压”。它与早期意图合并/减少 LLM 调用的 backpressure 是不同操作，但两者都已有成熟先行工作。

必须同时比较：整族固定上报配置；简单“回传受阻则放慢、恢复后加快”规则；带普通迟滞/切换成本的规则；同信息下的资源受限调度。候选若只击败 `aoi` 或只重复普通背压结果，不晋级。

候选可在已声明的网关执行能力上承载为条件计划，但计划格式本身不承担贡献。是否有实际网关收发回执/失败通知可作为输入，需要接口级说明；知道自己本次转发失败不等于知道未来恢复时刻，也不等于知道中心已收到全部数据。

新颖性仍未闭合。[Fountoulakis 等的联合采样/传输成本优化](https://doi.org/10.3390/e26121018) 已研究 AoI 约束下最小化采样和传输成本；[Zakeri 等的 POMDP 工作](https://arxiv.org/abs/2311.06522) 已处理部分可观测与能源约束。候选可能需要进一步从双跳间歇、状态设置持续生效、Class A 恢复机会以及监测完整性约束中推导算法结构，不能仅更换目标函数命名为新方法。

1. **先修研究判读。** 更正 §34/§38/§39 的 R1 与百分点口径；将 §42 限定为默认规则的数据载体和对齐验证。本轮不要求立即补齐计划安装/撤销、所有策略编译或跨 42 档全量运行。

4. **补原假说的一个缺口。** 采用已有 0.02 Wh、异质/零采能上下文，以同一策略比较中心/网关；无中断与接入中断保留，再声明同窗回传中断组合。各中断条件共享中断前外生过程；两位置可能在中断前已不同，需借无中断配对分离其影响，不能把全部差异归给失联期间。记录电量、证据、降档生效和逐义务缺采。无需扩大到 42 档，无需新解释器。若普通网关规则保护了采集，只记架构收益。
5. **只在存在资源余量后，才考虑小型节奏对照。** 固定源任务、采样自治、缓存能力和部署；比较简单背压与候选，并保留无中断、回传中断、接入中断负对照。记录少发的每批数据当时能否改变固定义务，以及恢复后付出的延迟。不增加 LLM 调用。这一项位于前述诊断之后，当前不直接实现。

若简单规则或固定配置已经覆盖有意义的成本工作点，就停止该候选，保留工程与评测成果。只有同信息、同能力下存在算法差额，才接既有 agent 工作流检验兼容性与业务效果；不得以载体变得完整代替算法差额。

**九、已有结果复算方法**

以下只读取结果文件，不运行仿真：

```python
import json
x = json.load(open('results/config_grid.json'))
obj = [('service', 1), ('uplinks', -1), ('downlink_attempts', -1),
       ('missing_collection', -1), ('aoi_mean_s', -1)]
def dominates(a, b):
    ds = [(a[k] - b[k]) * s for k, s in obj]
    return all(d >= -1e-9 for d in ds) and any(d > 1e-9 for d in ds)
for tag, condition in x['conditions'].items():
    rows = condition['rows']
    surviving = [g for g in x['grid_arms']
                 if not any(dominates(rows[b], rows[g]) for b in x['frontier'])]
    print(tag, len(surviving))
# N1_no_outage 20; N2_access_outage 14; N3_second_source 20
```
