# 从现有失败分析到通信方法：历史复核与候选

日期：2026-09-14。复核锚点：`e07df35`，当时共 223 个提交。本文是研究建议，不修改任务契约、正式决策编号、已有实验结论或运行中的实验。

本轮通读提交主题的完整历史，按阶段核对关键报告、Human 复盘、现行任务契约和策略/观测接口；没有逐个审计 223 个提交的全部 diff，也没有重跑数值实验。阅读期间仓库继续推进，已纳入 `61c87c5`、`dc60ffd`、`e07df35`。引用旧报告时以下面的限定为准。

**建议的范围**

保留灾前山区固定监测站、间歇接入与回传、有限能源、来源支持的监测义务。贡献用业务交付、缺采、AoI、能量和通信开销判断。LLM 的记忆、反思、提示词优化不作为本轮主方向。

保留两个主候选：① 根据证据所在位置执行条件控制计划；② 在已有采样/上报字段内合成满足约束的配置。另列一项有现成数值证据、但先行工作风险很高的备选：③ 依监测义务选择每次上报的缓存记录。三者都尚未证明方法收益或新颖性；先做通信对照，再决定是否值得接完整 agent。

**一、历史结果实际排除了哪些东西**

| 阶段 | 经复核保留的认识 | 不应扩大的结论 |
|---|---|---|

| 来源任务与实例封版 | 自治采样、事件响应、缓存/补发承担大量业务。达到义务节奏后，中心额外控制在突发链路下收益很小 | 外生义务不等于无决策；同一批策略接近不能证明全部合法策略最优 |
| 连续配置与准入 | 一次高负载配置可以在失联后持续消耗能源；零采能硬保证会拒绝部分介入。修正剩余时域后，原候选在目标条件仍被 `local` 支配 | 未证明风险化控制有效，也未证明一个特定 dense 配置被拒就不存在有益的中间配置 |

**二、这个场景给方法施加的结构**

中心目前主要在配置一个已经会自治运行的监测系统。`set_sampling_interval` 改变未来样本产生和采样负载，`set_report_period` 改变未来发送过程和通信负载；物理效果从远端实际应用开始，持续到下一次生效的变更。配置请求只是其中一个事件。完整评价对象应是这段持续运行过程。

现有证据显示三个不同控制点：配置决定产生与发送节奏；接入/回传决定何时可见、可控；节点缓存纪律决定一次已有机会承载哪些记录。当前中心策略的相互接近，只对第一个控制点的一组实现有约束力。缓存对照已显示第三个控制点存在收益；第二个控制点中，执行位置是否有用仍需同逻辑对照。

两个字段和节点数量本身不提供复杂规划的充分条件。若节点没有实际共享约束，很多决策可以逐节点分解；本地自治已完成的事件响应也不能重新收归中心制造工作量。论文若保留 agent，其合理入口是监测目标到设备配置/现场执行计划的组织；其必要性或跨任务便利性须另证，不能从“使用了 LLM”推导。

传统方法的缺口也须限定到具体实现。[`EnergyAoiPolicy`](../../../code/instance/center.py) 组合 SoC 与 AoI 规则，`EhAoiPolicy` 引入二维门限结构，均不等于完整求解了本任务。另一方面，已有 [POMDP 采样与传输工作](https://arxiv.org/abs/2311.06522) 已处理部分可观测源、采能、采样/发送成本与不可靠信道；[自触发能源控制](https://www.research-collection.ethz.ch/handle/20.500.11850/626180) 已联合长时域能源管理与控制更新。仅加入不确定性、能源预测或 MPC 不构成新的缺口。

**三、候选 1：将条件控制计划交给有证据的网关执行**

研究问题：同一条监测策略，若每次条件判断都依赖中心收齐遥测、再下发一个配置值，其有效性会怎样受回传突发限制？能否在可连接时安装一段有限条件计划，由网关使用随后实际收到的状态，在合法 Class A 机会内执行？

与现有机制的差别：shadow 保存当前目标值，条件计划保存未来证据到目标值的映射。排队重试能送达旧目标，不能替代失联期间依据新电量、新缓存情况作出的目标变化。更换备用回传路径也不等于移动条件判断位置。

最小方法可用确定性解释器，无需在网关部署 LLM。计划包含：适用节点与已有字段、合法观察量及其采集时间、条件分支、允许的配置集合、资源限制、计划版本与有效范围。编译/准入阶段检查某个分支的证据是否在执行位置可得：网关能读取自己收到的节点状态，但不能把中心实际收到的最新样本或不可见的任务更新当成本地知识。依赖中心信息的分支保留为等待或请求更新。

例如已有策略要求“能源允许时采用某组采样/上报配置；收到低电量证据后降低负载”。网关已收到新的 SoC，而回传中断使中心仍持旧读数。两处执行同一逻辑，可能产生不同的配置生效时刻。此处收益来源是可用证据与执行位置；不需要 LLM 犯错。

**能力变化必须明示。** [任务契约 §10](../task-contract-v1.1.md) 允许网关/分布式控制比较，[S2](../../s2-scenario/pre-disaster-runtime-decision-2026-09-12.md) 也讨论断云后的现场规则；但这些不能证明目标设备已有可编程网关。需要新增并声明 A 层网关软件执行能力，所有相关基线共享。节点仍只接受原来两个设置字段；没有新增无线覆盖、强制接收或设备自动回退。网关没电、节点接入断开时，该方案同样受限。计划到期只阻止后续执行，不会自动撤销设备上已经生效的配置。

**第一项判别无需 LLM：** 同一确定性策略分别放中心和网关，比较既有无中断、回传中断、接入中断、同时中断条件；保持监测义务、初值、空口机会与规则完全一致，只允许读取各位置实际可见的信息。记录服务、缺采、能源、配置生效时刻和通信量。接入中断应作为负对照。若“恢复低电量反馈”对业务和成本均无作用，此候选在当前实例就没有继续开发理由。

若位置对照有收益，再比较三种同位置方案：预装完整传统策略、预下发开环动作序列、有限条件计划。普通事件触发控制、设备管理、版本持久化均共享。计划安装、更新、撤销的字节和开销记账；不能只拿逐 tick 调用 LLM 的人为高开销作对手。

**可能的论文增量：** 给出在双跳间歇网络中哪些条件分支可下沉、哪些需要中心证据的判据；把 agent 工作流转换为受权限、观测和能源限制的执行计划；用同策略位置对照说明通信依赖如何改变服务。仅把一个 if/else 搬到网关，或泛称“云慢边快”，不足以支持新颖性。[The LLM as a Network Operator](https://arxiv.org/html/2509.10478v1) 已讨论慢时标 LLM 与快时标控制器及结构化策略翻译。若预装完整小策略已经全面追平，agent 专属方法主张仍需撤回，保留架构结果。

优先级：最接近原先想做的小型 agent 通信执行机制；但它是明确的架构扩展，不能称为既有中心 runtime 的公平增量。

**四、候选 2：从二元准入转为监测目标约束下的可行配置合成**

研究问题：给定合法历史和剩余监测义务，在两个已有字段的组合中，是否存在原有 dense/sparse 门限没选到的配置，在相同资源约束下提高交付或减少不可恢复缺采？目标是具体通信控制算法，LLM 只可作为高层目标入口。

直接线索来自 [21 §八](21-regime-map-partial-pass-2026-09-13.md)：同一来源派生采能片段，`dense600` 负载 `3.0012e-3 Wh/h`，约 6.50 h 耗尽；`dense900` 负载低约 31%，零采能可支撑 9.46 h，给定采能轨迹下跨过补能时段，在 12 h 任务窗内未死。这只证明中间配置会改变物理可行性，不证明它改善业务；它也不是 `adm_out3` 的直接改进读数。不能用已知未来的这条轨迹指导在线方法。

候选输入为中心已收到的 SoC/配置及其时间、已有发送记录、任务窗口和明确声明的能量/链路模型。保留实际生效配置的不确定性；没有回执时不得直接按“我要求的配置”扣算能源。未来采能只能用历史标定得到的预测或不确定集合；实际未来天气和应用时刻只供独立评分。

最小解法是在合法 `(sampling interval, report period)` 集合上作短时域联合搜索，候选含保持现状。评价包含：两次字段写入实际等待、可能的中间配置、采样能耗、上报能耗、有限电池溢出、缓存和剩余义务。输出可行替代配置或保持原配置的原因。无需先引入神经网络或新的风险指数。

目标沿用 v1.1 的固定业务分母和分列报告。可在共同给定的资源预算下最大化按期交付，并报告缺采及 AoI；预算点取既有前沿的多个工作点，不为候选挑一个有利权重。若引入允许失电概率，它是新增研究约束，必须公开并同等给予对照，不能写成中通服既有 SLA。

这里区分两种任务：业务目标允许选择配置时，修复为 900 s 可以合法；外部明确要求 600 s 时，擅自改为 900 s 就没有完成指令。当前 v5 的“给定目标执行”不能用来评价这种规划层改进。论文应把它归入配置选择，不能全算作 runtime 收益。

**第一项判别：** 在已登记的能源片段、无中断/介入后失联和第二来源节奏下，补一个所有合法配置的静态前沿及简单滚动搜索参照。先问是否有合法、非全知的选择超出当前 `local`/`aoi`/`ea_nb`/`eh_aoi` 前沿；找不到就不接 LLM。找得到再分离收益来自联合选值、预测、持续配置建模还是信息估计。

**强对照：** 合理固定配置网格、调好的 AoI/EH 前沿、具有相同预测和观测的普通 MPC/随机控制或适用的 POMDP 方法。旧 `rob3` 的失败不等于排除了鲁棒控制。少量网格搜索就拿到全部收益时，应先承认阈值基线覆盖不足。

**可能的论文增量：** 从持续配置和不确定生效过程推导可行状态/动作的结构，并由此得到在相同信息与计算预算下有效的算法；或证明某种紧凑状态估计足够支撑采样—回传联合决策。仅“两个字段一起优化”“加入 MPC”“调好 dense900”不够。已有联合采样/发送与能源控制文献构成实质竞争。

优先级：保持当前设备动作面的最低成本候选；相较候选 1，更接近通信控制方法，新颖性不确定性较高。它可以服务 agent 系统，但现有证据没有支持 LLM 对数值决策的独特增益。

**五、备选 3：按监测义务使用一次已有上报机会**

直接证据：[11 缓存服务实验](11-aoi-defect-and-cache-service-2026-09-13.md) 在 48 h 任务、0–40 h 接入中断、20 种子条件下，`local` 从 FIFO 的 19.5% 服务、10686 s AoI，变为 LIFO 的 22.7%、4465 s。相同机会和能量下，载荷内记录的选择影响业务。`latest_only` 又会丢掉仍有价值的历史义务，因此仅刷新最新时间不能代表全部监测目标。

可探索的执行规则是：在包容量内优先保留能新增覆盖尚有效监测义务的记录，避免多个记录只服务同一义务；兼顾当前新鲜度和历史保留约束。评价每次包选择增加了哪些义务的交付可能性，不能只看包数或缓存清空率。打包端不知道中心已收到哪些记录时，按合法确认历史保留不确定性。

这需要明确的设备缓存/打包软件能力。当前 `cache_service` 是实例属性，中心不能通过原来两个字段修改它；不得把更好的固件悄悄只给本文。若瓶颈在节点，单改网关队列也不能替代。正确激活量是积压记录数超过一次载荷容量；只有采样与上报周期相同的特殊情况下，才能把它简写为“断链超过 32 个上报周期”。

**第一项判别：** 使用已有 48 h 缓存对照与较短任务负对照，加入 EDF、LIFO、`latest_only`、按有效义务匹配的普通贪心。先不做 agent；如果标准算法已经拿走收益，就把它作为所有方法共享的成熟本地能力。40 h 中断单点不能证明实际部署常见收益，应在现有来源节奏/链路片段上量激活频率及效应，不能只挑长中断。

这项有最直接的通信数值依据，但 LIFO 已经是仓库成果，不能再算新候选贡献。新的匹配规则很可能落入成熟截止时间调度。只有多个既有监测目标之间确有取舍、简单策略不能覆盖时，才值得进一步推导算法。优先级低于前两项。

**六、怎样使用现行 agent 通信论文而不换成 LLM 论文**

[WirelessAgent](https://arxiv.org/html/2505.01074v1) 可作为规划/工具组织的适配参照，保留目标、观察、验证与反馈环节；原生网络切片动作不能直接用两字段实验替代。[ICLDC](https://arxiv.org/html/2504.14556v2) 的协议直接选择传感器并通过 beacon 收集，已有 verifier 与反馈；本站 Class A 下无法照抄这个动作。TopoLLM 的 UAV 拓扑变量在固定站点也不存在。论文应明确标注 adapted workflow，不能写成复现击败原论文。

有通信收益之后再作小型 2×2：相同目标/可见信息下，规则 planner 与适配 agent，分别接原执行路径与候选。候选 1 另拆位置因素，候选 2 另拆配置优化因素。这样能回答“相同 agent 换通信机制是否改进”以及“强规则是否同样获益”。后者成立仍可支持通用通信机制；它不会自动支持 agent 必要性。

真实 agent 可以贡献任务组织、工具选择和对已有不同监测配置的复用，但这些便利性需要实际测量。单个稳定任务下，两字段决策若被一条小规则完整覆盖，就不应靠更复杂 prompt 或反复挑模型制造胜负。也无须把下一轮再变成大量推理调用实验。

**七、下一轮交付建议**

1. **一张候选边界表。** 沿用本文两个主候选，逐项确认能读什么、能改什么、谁执行；把网关解释器列为 A 软件扩展，把配置合成列为原动作面内算法。无需重写任务或加新业务义务。
2. **两个独立的通信判别。** 候选 1 做同规则中心/网关对照；候选 2 做合法配置前沿/普通搜索对照。优先复用现有条件和开发区间，不把同一批开发轨迹包装成泛化。保留相同策略、相同预算、相同未来外生过程；只在预定差异处改变。
3. **每项一条有量纲的因果轨迹。** 候选 1 记录新证据何时在网关和中心分别可见、目标何时生成/生效、如何改变缺采/交付；候选 2 记录为何中间配置可行、它增加的是哪条固定义务的服务、付出多少资源。评分真值独立。
4. **一张正结果与最强传统解的差额表。** 把“架构收益”“普通算法收益”“本文额外机制收益”分开。若只剩普通本地策略或网格搜索获益，保留它为强基线，不立即命名方法或定 venue。
