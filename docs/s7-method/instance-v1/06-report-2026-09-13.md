## 一、先说必须纠正的：`logical` 身份缺了字段维度

契约层的 `logical` 曾写成 `f"{node_id}:period:{generation}"`——**没有字段维度**。同一次配置决策
的两个字段共享一个身份，于是第二个字段在远端与"第一个字段的重发"不可区分，被当重复**永久丢弃**。

后果隐蔽，而且**正好污染本轮要下的结论**：

| 表现 | 实际原因 | 读起来像 |
|---|---|---|
| `atomic` 的业务数字与 `local` 逐位相同（149.5 / 18.5 / 2211 / 169.0），落地 0 条 | 原子层永远凑不齐一对 | "正确但没用"的结论 |
| `contract` 的上报周期恒为默认值（下发次序先间隔、后周期） | 每代只落地一个字段 | "契约反而有害" |

**作废**：旧的"上行 466.5 → 433.1（−7.2%）"那一版量的是这个缺陷。

**旧文件 `instance_execlayer.json` 不受影响、保留**：那条臂是单字段策略（`aoi` 只下发
`set_report_period`），身份碰撞不触发。这是**实测复现**确认的（重跑逐位相同：154.9 / 13.1 /
2032 / 466.5 / 433.1），不是推理。

修法两条，都是实质性的：

1. `logical = f"{node_id}:{op}:{generation}"`——身份必须按字段定。
2. "世代到齐"由**这次决策意图写的字段集合**定义（报文带 `fields`），不是硬编码"两个字段"。
   否则单字段策略 `AoiPolicy` 在原子层下会被**整类丢弃**——那比缺陷更难发现，因为它让策略与
   执行层从此不可比。

**回归测试 `test_instance.py` [14] 在旧实现上精确红 3 项**，诊断串直接给出症状：
"契约层 间隔动了 13 个、**周期动了 0 个**"、"原子层 **0 个节点配置改变**"。

## 二、⑥ 的结论：执行层的价值由**能量稀缺度**开关

三层执行层，同策略、同动作集合、同预算，差别只在报文**怎么被执行**：

| 层 | 报文携带 | 生效语义 |
|---|---|---|
| `naive` | 无 | 谁到谁生效，迟到的照常覆盖 |
| `contract` | `logical` + `version` | 重复不生效、更旧不覆盖；**逐字段**生效 |
| `atomic` | 上面两个 + `generation` + `fields` | 这一代意图写的字段**全部到齐**才一起生效 |

### 能量宽松区（容量 0.05 Wh，20 种子）

| 臂 | 层 | 周期交付 /168 | 缺采 | 缺送 | AoI s | 上行 | 混配 min |
|---|---|---:|---:|---:|---:|---:|---:|
| `local` | ×3 | 149.5 | 0.0 | 18.5 | 2211 | 169.0 | 0 |
| `ea_i600` | naive | 151.8 | 0.0 | 16.2 | 1431 | 376.9 | 822 |
| `ea_i600` | contract | 151.8 | 0.0 | 16.1 | 1606 | 340.8 | 840 |
| `ea_i600` | atomic | 151.0 | 0.0 | 17.0 | 1705 | 308.8 | **0** |
| `dense600` | naive | 154.3 | 0.0 | 13.7 | 984 | 543.1 | 0 |
| `dense600` | contract | 154.3 | 0.0 | 13.7 | 1222 | 495.7 | 0 |
| `dense600` | atomic | 152.8 | 0.0 | 15.2 | 1305 | 437.2 | 0 |
| `aoi` | ×3 | 155.8 | 0.0 | 12.2 | 2030 | 431.6 | 0 |

**这一区是代价机制**：交付不动或变差，AoI 一律变差（984 → 1305，+33%），唯一稳定收益是上行
（543.1 → 437.2，−19.5%）。

**这一区是正确性机制，而且随层级单调**；容量再小一半，同一顺序、同一幅度复现。

### 机制：差**不在跑了什么配置**，在**什么时候被切过去**

单种子解剖（容量 0.008，`dense600`）：

| 层 | 采样次数 | 采样能耗 Wh | 总耗 Wh | 亏空 h | 被切到密集的时刻 |
|---|---:|---:|---:|---:|---|
| naive | 549 | 0.2580 | 0.2704 | 30.9 | **全部 4.17 h**（同一刻） |
| contract | 468 | 0.2200 | 0.2312 | 23.8 | 逐节点推迟 |
| atomic | 444 | 0.2087 | 0.2194 | 20.2 | **5.17–11.17 h** |

1. **末态配置三层逐位相同**（13 个节点 600 s、1 个 3600 s）→ 差异不来自"最终跑什么"。
2. 总耗差 0.0510 Wh 里，**采样差占 0.0494 Wh（97%）**，空口只占 0.0017 Wh（3%）。
3. 差来自**切换时刻**：原子层要求整代到齐，`set_sampling_interval` 被扣留 3 h → 切换逐节点推迟
   → 少采 105 次样 → 少耗 0.049 Wh → 亏空少 10.7 h → 缺采少 10.9 → 周期交付多 10.0。
4. 中介量可测：**能量亏空**。宽松区亏空恒 0，这条通道不存在，执行层就只剩代价。

### 不扣留的对照（重要）

去掉扣留后 `contract` 与 `naive` **逐列全同（连上行都一样）**：契约字段只在乱序/延迟下起作用。
而 `atomic` 的 AoI 代价**不是扣留造成的**——不扣留照样 +199 / +205 s。混配也不是扣留的产物：
常态就有 1422 min。

### 三条必须一起引用的限定

- **`aoi` 三层逐位全同，但这不是"治理得好"。** 它从不下发采样间隔，而混配要求两个字段的世代
  **都非空**才能比较 → **混配无从定义**，不是 0 分。且它目标被回执确认后不再重发，既没有重复
  也没有可拒的陈旧写入。**一列不动，要先说清是"没有危险"还是"量不出来"。**
- **`ea_i600` 在绑定区三层全同**，因为它对电量不健康的节点退回稀疏配置、之后基本不再改配置。
- **正面效应来自"阻止策略在缺电区重复写入配置"，不是"执行层本身更好"**；同一属性在宽松区是
  AoI +33% 的纯代价。**两侧都不能单独当主结论。**

## 三、零 的结论：换掉 regret 的分母，headroom 只有 8–13% 且几乎全在链路侧

### 旧分母为什么不能留

- 事后最优固定配置（`best_fixed_posthoc`）**随测试条件变化**——同一个策略在不同条件里对着不同
  分母算 regret；而且**它不是上界**（`ea_i600` 超过过旧的"全知上界"）。
- `dynamic_upper_bound` 两条松弛叠起来**恒为 168/168**。拿它算 regret 等于用常数当分母：
  `local` 与 `dense600` 在它眼里一模一样。

### 新真上界

`oracle.py:dynamic_oracle`：逐节点、逐小时的离线动态规划，状态是离散化的 `soc`，每小时选一个
档位（300/600/900/1800/3600）或"本小时不采样"，读**完整未来采能轨迹**。只松弛可交付性；
**不松弛**档位离散性与能量的小时耦合（含容量溢出截断）。

**造它时踩的三个错，全部记档**（两个是我自查出来的，第三个是测试抓到的）：

1. **重复计数**：闭区间窗 `[h*3600, (h+1)*3600]` 用严格比较，第 h 小时的义务在第 h+1 小时又被
   记一次——12 条数成 23 条。
2. **把"电量耗尽"当成"整条轨迹不可行"**：`reward + (-inf) = -inf` 而 `-inf > -inf` 为假 →
   档位留 `None` → DP 强迫节点撑满整个时间窗。0.004 Wh 的节点**能采 8 小时却被报成 0 条义务**。
   加"本小时不采样"动作后修好：物理上耗尽就是**停止采样**。
3. **上界被真实策略突破**：纳入事件义务后，容量 0.05 下 `dense600` 交付 **184**、上界只有 **171**。
   实例在触发时刻做**触发锚定**的本地采样（触发落在 1052 s 这类实时钟时刻，不在 300 s 网格上），
   上界的动作集只有周期档位，够不到那些点窗。**这是 `test_instance.py` [15] 抓到的**，不是自查
   出来的。于是上界现在**只覆盖周期义务**——这也与既有纪律一致（事件列在全部臂上恒定
   21.0/16.8，明令不得支撑结论），而且它让上界更强：真实策略还要为事件采样花电，上界不给这笔电。

### 结果

| 容量 Wh | 真上界 /168 | 最好可实现的臂 | 周期达标率 | 缺口拆解 |
|---|---:|---|---:|---|
| 0.05 名义 | **168.0** | `dense600`/`900`/`1200`/`1800` = 154.3 | **91.9%** | 13.7 = 缺采 **0.0** + 缺送 13.7 |
| 0.008 绑定 | **168.0** | `local` / `ea_i600` = 147.2 | **87.6%** | 20.8 = 缺采 2.5 + 缺送 18.3 |
| 0.004 强绑定 | **146.2** | `local` = 127.2 | **87.0%** | 上界本身掉到 146.2 |

**分解是精确的**：`168 = 周期交付 + 缺采 + 缺送`，三档逐条核对均成立。

### 这一节改变了"策略余地"的判断

- **headroom 是 8–13%，不是旧上界暗示的 0%。** 但拆开后结论反过来：
- **名义条件缺采恒为 0，缺口 100% 是交付丢失**——名义条件下**没有"更聪明的采样调度"的余地**，
  能争的只有"用上行次数换交付成功率"（`dense600` 用 561 次上行把缺送压到 13.7，`local` 只用
  169 次、缺送 18.5）。
- **绑定条件下 `local` 的缺口 20.8 里 18.3 是缺送**，策略可争的只剩 2.5 条 = **1.5%**。

**所以 goal 第五项要检定的那句话——"headroom 仍 >99% 说明本 task 不需要智能 planner"——方向
成立、数值要改**：不是"没有余量"，而是"余量几乎全在链路交付侧，不在调度侧"。而且这次是用一个
**紧到能区分策略**的上界得出的。
