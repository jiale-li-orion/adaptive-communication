**新增的缺口接口**（doc 48 §4 要求"明确接口和时间戳、同等给所有臂"）：`CenterView` 增两个
**网关本地可观测**字段 `gateway_pending_depth`（网关自己压着多少条）与
`gateway_last_forward_ok_at`（网关**上一次真的把缓存交给中心**的时刻）。
**`_center_view` 不填它们**（中心在回传那一跳的另一端）；**不读**环境 `path_available`、
未来恢复时刻、节点真实未上报缓存、中心未确认的交付真值。

## 四、逐条判读

- **R1（固定配置是否已覆盖）—— 成立。** 在**主报告的两个容差（0%、1%）**下，
  三条条件的**最低成本位全部由固定周期臂取得**：`fixed300`（及与它读数逐位相同的 `aoi_const300`）。
  ⇒ **普通固定配置已覆盖高服务工作点**，按预注册 R1，**不实现候选**。
- **R2（普通背压是否已覆盖）—— 在 0%/1% 不成立，在 5%/P2 成立。**
  0%/1% 下**背压族一条都不可行**（服务比地板低 3.1–6.0 个百分点），所以它在高服务端**不构成覆盖**；
  但在 **P2 的 5% 档**，`pacing_bp1800`（及其迟滞版）**确实是三轴上的最低成本位**，
  且缺采不超过参照 ⇒ **这一档普通背压覆盖了**。
  **边际性必须报告**：P2 的 5% 地板是 **379.75**，`pacing_bp1800` 是 **380.1**，
  **只高出 0.35 条**；同一档在 **P0/P1 不可行**（地板 477.6 / 371.35，而它是 471.5 / 368.4）。
  ⇒ 这条覆盖**是边际的、且只在接入中断档出现**，不能当成稳健结论。
- **R3（是否存在普通规则解释不了的差额）—— 不成立。** 每个容差下的最低成本位**本身就是一条普通规则**
  （`fixed300` / `aoi_const300` / `local` / `pacing_bp1800`）。**没有出现任何一条臂在相同服务容差下
  成本更低而固定族与背压族都无法复现** ⇒ 按预注册 R3，**不进入机制一步**。

## 五、结论：**这一小轮结束**（⚠ 强度已按 doc 52 文首的审查收窄）

> **限定（必读）**：本轮臂集合**全部由普通规则组成**，因此「最低成本位是普通规则」**近乎同义反复**；
> 且**背压族只能比 900 s 更慢**（`fast=900`、`slow∈{1800,3600}`），**没有一条臂以「达到最高服务」为目标**。
> ⇒ 下面的「覆盖」只能读成「**本轮臂集合内没有工作点需要更复杂的规则**」，
> **不能**读成「普通规则覆盖了全部有效工作点」或「动态节奏没有空间」。详见 doc 52 文首。

按 doc 48 §8.2 与 §5 的晋级条件：

> **普通规则已经覆盖了本轮暴露的全部有效工作点。** 高服务端由常数上报周期（`fixed300`/`aoi_const300`）
> 覆盖；低成本端由零控制（`local`）或普通背压（`pacing_bp1800`，仅 P2 的 5% 档、且边际）覆盖。
> **没有出现普通规则解释不了的差额。**

⇒ **不实现候选机制、不做消融、不接 LLM、不补条件计划功能、不扩场景**（doc 48 §8.2/§8.5 的分支）。
前一节保留的双跳节奏候选**仍未获得增量证据**。

## 六、读到的几件具体事实（其中两条对后续有用）

1. **本轮那两条背压实现服务代价很大**：`pacing_bp1800` 相对 `fixed300` 少 **39.7 条（5.9 个百分点）**，
   `pacing_bp3600` 少 **100.1 条（14.9 个百分点）**。它确实省上行（1255→558）与总能耗（0.3951→0.3707），
   **但达不到高服务**——这正是 doc 48 §4 担心的"把'本次不能向中心交付'等同于'本次上行可全部推迟'"。
   迟滞版只把服务抬回 0.9–1.9 条，**没有改变方向**。
2. **`fixed900` 与 `local` 的服务逐位相同**（P0 496.2、P1 392.1、P2 399.8）——
   因为 N3 的**出厂上报周期本来就是 900 s**，所以 `fixed900` 是**值域空操作**。
   ⇒ 这同时验证了"**保持原配置**"确实在臂集合里（doc 48 §4 要求）。
3. **AoI 轴在这一轮没有形成取舍**：最省 AoI 恒为 `fixed300`（上报最快者），
   而它同时服务最高 ⇒ AoI 与服务的取舍在 N3 上**同向**，没有额外信息。
4. **缺采在全部臂、全部三档上都是 0.0** ⇒ 预注册 §5 的**缺采约束无区分力**（没有被违反，也没有筛掉任何臂）。
   这一点必须写明：它意味着本轮**没有**出现"以新增缺采换成本收益"的情形，而不是"已经证明了不会出现"。

## 七、限定

- **20 种子**、**单一来源 N3**、**单一执行位置（gateway）**、**背压慢档只声明了 {1800, 3600} 两档**。
- **只报了均值包络，没有报配对自助区间**——预注册 R3 要求区间是在"要晋级"时才需要；
  本轮 R3 不成立，因此按纪律**不晋级、也不算区间**。若后续要重启这条线，须先补区间。
- **包络按服务筛选，"可行"不等于"缺采/采集完整性可行"**（doc 48 §5）——
  本轮因缺采全为 0 而没有暴露差别，但该限定照写。
- 本轮**没有**改采样、事件、缓存与打包纪律、能源参数，**没有**把能源反馈采样混进来。
- N3 基底 × [4h,7h) 窗是**本轮新声明的条件**，不是旧结果的重放。
