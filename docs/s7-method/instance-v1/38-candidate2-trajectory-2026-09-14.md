## 二、**为何中间配置可行**（第 109 行第一问）

`(sampling 900, report 300)` 在**能量上完全可行**，而且可行性与"稀配置"**无关**：

- **死节点 0**（三个臂都是 0）；
- **末电量最低值**：`aoi` 0.02098 → `aoi_const300` **0.02005 Wh**（−4.4%）；
- **能耗** 0.3752 → **0.3947 Wh（+5.2%）**。

原因是登记的负载式子 `load_h = (3600/i)·4.7e-4 + (3600/r)·4.53e-5`：
**采样项占 94.0%**（`(600,900) = 3.0012e-3`），把上报周期从 900 压到 300 只多 **+4.5% 负载**
（测试 [33] 已手算钉住）。⇒ **这一档的可行性约束不在上报周期上，而在采样间隔上。**

## 四、**为何端点够用 / 自适应为什么反而差**（机制）

**两个臂实际用到的配置**（从 trace 的 `state` 事件读节点**真实**配置）：

| 臂 | 用到的配置 | 配置变化次数 |
|---|---|---|
| `aoi` | **`(900,300)` 与 `(900,900)` 两种来回切** | **28.3** |
| `aoi_const300` | **只有 `(900,300)`** | **13.0** |

⇒ **机制一句话**：`aoi` 的自适应在 `(900,300)` 与 `(900,900)` 之间**来回切换**，
每次切换**花掉一次下行机会**，而切到 900 会把上报间隔拉长、**丢掉本可送达的义务**。
`aoi_const300` **只做 13 次变化、恒定在最密的上报档**，于是：
**下行 40.4 → 18.9（−53%）**，**服务 +13.6**，**AoI −186 s**。

**这是一个"自适应反而不如常数"的实例**，而且成因是**自适应的切换成本**，
不是"自适应这个想法错了"——它的 `stale_s = 3600` 门限在 900 s 义务的节奏下**判断错了带宽**。

## 六、限定

- **逐义务做差是 seed 0 的单种子**（逐义务台账只对首种子保存）；服务与资源列是 **20 种子均值**。
  按 §7.120 的教训，**单种子读数不得单独作证据**——所以本文只把它当作"哪条义务"的**举例**，
