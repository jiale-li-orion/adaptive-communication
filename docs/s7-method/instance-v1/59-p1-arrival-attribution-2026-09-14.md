# P1 结果：损失**不在网关侧准时性**，而在**网关→中心那一跳的副本覆盖率**

> ## ⚠ 本文的机制解释已被更正（2026-09-14，见 [doc 64](64-first-heard-sufficiency-audit-2026-09-14.md)）
>
> **撤回**：本文 §四.4 与 §四 处置段里「每条义务本来要靠**多份**缓冲副本去撞回传窗口；
> 候选减少上行 ⇒ 副本变少 ⇒ 首份更早到也撞不上」。**在当前 v1.1 的 store-and-forward 语义下，
> 增加副本在机制上不可能增加撞上回传窗口的机会**：
> `backhaul_forward()` 一旦可用就**把所有** pending 一起交给中心，失败不丢、等下一次，
> **没有**「每个副本各自买一次回传尝试」这回事；而同一个义务的更晚副本只会与首份**同在**
> 或**更晚**被转发。doc 64 用 **161,280 条义务级判定核对**给出了正确结式
> `ŷ = 1[h* ≤ B(d)]`（`B(d)` = 截止前**最后一次可回传时刻**），**不一致 0 项**；
> 并给出一个副本数完全相同（`n_heard` 都是 2）却结局相反的逐义务反例。
>
> **保留**：本文的全部**数字**（到达台账、Δ准时到网关 +6.45/+6.35/+7.25、
> Δ卡在网关→中心 +9.40/+9.25/+10.25、Δ送达 −2.95/−2.90/−3.00）与仪器自检。
> **改写**：这些数字的**解释**——「准时到网关」用的是阈值 `d`，而**交付用的阈值是 `B(d)`**，
> 两者相差 `d − B(d)`（均值 1245 s / 3073 s / 1245 s，中位 0）。
> 落在 `(B(d), d]` 这条**无效带**里的义务，在本文记账下算「准时」，在交付上却注定失败；
> 逐义务配对显示候选在这些单元里**新增交付 0 条、只丢失 24–186 条**
> ⇒ 本文头条那个「+6.45 准时到网关」**没有任何一条转化为交付**。
>
> **仍然成立**：以「网关侧准时性（`h* ≤ d`）」为目标的形式**目标选错了**——
> 但错的原因不是「副本覆盖率」，而是**用 `d` 而不是 `B(d)` 当阈值**。

## 三、裁决：**损失被定位到网关→中心那一跳，不是"省下的上行是冗余"**

三档同向、20/0、区间不含 0，得到一条**与我原先撤回的那句话方向相反**的机制：

1. **候选让更多义务准时到达网关**（+6.4～+7.3）——所以它**完成了** doc 58 §P1 第 1 问设的那个目标
   （"加快上报能否改变截止前到网关时刻"）：**在这个实例上，网关侧准时性对候选而言是饱和的，不是杠杆。**
2. **它却让更多义务卡在网关→中心那一跳**（+9.3～+10.3，**20/0**）——净服务损失正好出在这里（−2.9～−3.0）。
3. **"从未到网关"恒为 0**，而**"晚到网关"有 154～260 条** ⇒ 我原先"最终到过 ⇒ 省下的是冗余重试"
   的那条推断**不仅是无证据，而且方向是错的**。
4. ~~**正确机制**：每条义务本来要靠**多份**缓冲副本去撞回传窗口（回传 62%/h）；
   候选减少上行 ⇒ **副本变少** ⇒ 即使首份**更早**到网关，能撞上窗口的**份数**也少了。
   ⇒ **省下的上行买的是"回传窗口的覆盖率"，不是"冗余撞运气"。**~~
   **⚠ 本段已撤回（doc 64 §1/§4.1）**：这条机制在当前模型里**不存在**——
   网关一旦可回传就**全量**转发且失败不丢，同一义务的更晚副本只会与首份**同在或更晚**被转发，
   所以副本数不进入交付判定。**正确机制**是：候选把 `h*` 推过了 `B(d)`
   （截止前**最后一次**可回传时刻），而**首次到网关**才是唯一承重的中间量。

这正是 doc 58 §4 说候选增量必须处理的那个结构：**两跳到达 + 不可即时纠正**。

## 四、按 doc 58 §P1 的否证出口处置

doc 58 §P1 的出口写的是「若这些历史**没有可执行的选择差异**，明确关闭『该实例上的义务驱动节奏』」。
**这里是有选择差异的，所以不触发该出口**；但差异的**方向**改变了候选的目标：

| 形式 | 处置 |
|---|---|
| **以「网关侧准时性」为目标的义务驱动节奏** | **目标饱和 ⇒ 该形式不成立**：候选已经做到（+6.4），且它仍亏在别处 |
| **由本次解剖指出的目标：网关→中心一跳的逐义务副本覆盖率** | **保留为待检验命题**——它是**逐义务**状态量（网关知道自己为某义务收到过几份），而现有全部规则（整体积压／最老待转发年龄／上次转发成功／逐节点 AoI）**都不含它** |

**⚠ 一条自律要求**：doc 58 §P2 的最低比较集合里列的是「**逐节点截止期阈值** + 原有迟滞/去重」。
本次解剖说明**截止期阈值不是正确的那条普通对照**（候选已在网关侧准时性上赢过它）。
按解剖指出的机制，**必须先上场的最可能竞争者是「逐义务副本数阈值」这条普通规则**：
它是普通规则、实现很短、且**直接盯住被定位的那一跳**。
**若它也能拿到同样的成本节省而不亏服务，则候选没有余量**，如实收口。
