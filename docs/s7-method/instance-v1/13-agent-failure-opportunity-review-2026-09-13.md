这些引用用于证明“已经探索”，不重新认可早期文档的性能、新颖性或正确性主张；早期读数有后续撤销，当前业务结论以最新汇总为准。

更值得核对的是**旧方法保护的操作语义在当前任务中是否仍有独立价值**。早期运行时保护操作身份、执行历史与结算；当前 canonical 能力主要是两个配置字段。独立测量请求和区间补传已因证据或承重性限制降级。配置赋值的许多恢复问题可由期望/报告状态与版本处理，这与先前公平影子对照相符。配置暂态仍可能损失数据或耗能，因此这不是“当前状态足以决定一切”的定理，也不能据此免除队列、版本与时效处理。

下一步的设计审查应复用既有方法，明确某条现有业务义务、合法执行历史、成熟基线保留的信息与本方法额外信息，指出后者为什么会改变任务损失或有实测价值的成本。没有这样的反例，不再新建等待/准入机制。若只找到同等服务下成本改善，应按成本主张检验，不能改称业务正确性收益。

## 1. 当前证据支持到哪里

已读 `12-two-phase-summary`、`09-phase2-synthesis`、实例代码和意图结果。新状态已超过 `206df5a`：已有来源派生天气、第二业务来源、突发链路、时长扫描、修正后的 AoI 与生成原因账本。本轮没有重跑这些实验。

当前对照限制了“在既定动作空间内更换中心策略能提升多少监测交付”的主张。它们没有检验真实 tool-using agent 在等待、不确定结果与恢复上的行为。因而：

- “尚无 agent infra 证据”成立；“agent infra 路线已排除”不成立。
- 方法贡献不能由修复本项目自己的 AoI、抽样或计数错误自动得到。benchmark 贡献也仍需说明外部用户能复用什么、测到什么、相对既有评测增加什么。
- 对基础设施方法，合理目标可以是**同一 agent、同一任务、同一能力下保持业务服务，同时减少推理／操作成本和错误宣告**。不必超过最优传统控制器的交付率，但必须比较成熟异步执行与预算管理。

## 2. 初版候选失效（优先推荐已撤回）

**通信尚未提供新的执行机会或证据，agent 宿主却把一次等待升级为新一轮推理／恢复。**

候选时间线（待验证，不是已经观察到的 LLM 轨迹）：

1. agent 根据合法的已收遥测，提出一次现有能力内的配置操作。
2. 操作被网关接收但等待节点窗口；或已发出而执行结果尚未获知。
3. 宿主把轮询超时或仍未变化的缓存值表示为失败／未完成，重新调用模型。
4. 模型可能重发、重规划或提前终止；但链路尚未产生能改变判断的新信息。
5. 长突发使这种循环持续，推理预算可能在恢复前耗尽；恢复后的继续执行和必要新任务可能受损。

第3—5步需要真实 agent 及宿主验证。不会默认每个模型都犯错，不通过删除 wait 能力、隐藏 pending 状态或每分钟强制调用模型制造问题。

**通信放大的是等待与决策的时间尺度差。** 同样次数的独立短失败和同一长中断不应被当作同等数量的新恢复机会。节点窗口、回传与被动状态到达决定何时能获得证据；中心不能偷读下一次恢复时刻。

## 3. 初版候选语义（与既有方法重叠）

限定为 **host／adapter 侧的等待与恢复契约**。采样、上报、现场自治和远端能力保持原定义；不新增原子固件、健康旁路、路由或补传动作。

操作句柄保存逻辑任务身份、原参数、发送阶段、最近证据标识和下一项合法唤醒条件。至少区分：

| 观测到的状态 | 宿主行为 |
|---|---|
| 确认尚未发出／仍在本地排队 | 保存待执行操作；由传输调度器处理，不能虚构远端执行结果 |
| 已发出、尚无足够执行证据 | 保持未决；同一缓存的再次读取不构成一次新的后置条件验证 |
| 明确拒绝、前置条件改变、业务目标改变 | 交给 planner 作新决定 |
| 满足已声明完成条件的证据到达 | 结算并继续依赖它的后续任务 |

挂起的是受影响的操作，不冻结整个监测网。唤醒来源可以是合法获得的新状态、任务变化、时效边界和有界探测结果。时间流逝能改变 AoI 与任务紧迫性，因此“遥测不变就永不唤醒”不正确。不得假设链路会主动通知恢复；无可用通知时保留有预算的探测／重试，并计其成本。

同一显式逻辑任务下重复提交相同操作返回既有句柄；不得靠字符串相似度合并不同任务，也不能吞掉一次合法新观测请求。不同参数的重新决策不能被静默归并。取消与过期不能被解释为在途远端效果已撤销。

**预算分开记**：模型推理、host 本地轮询、无线尝试、真实墙钟等待。等待不能被伪装成已完成；减少模型调用不能掩盖恢复迟缓或服务下降。

这套语义是候选设计，尚未证明比成熟异步工具执行有增量。若 MCP Tasks 加事件驱动调度已经达到同等结果，应承认主要工作是协议适配，不认领新的运行时机制。

## 4. 初版候选取舍记录（不再作为排期依据）

| 候选 | 支持与优先级 | 最强反对解释 |
|---|---|---|
| **等待被升级成恢复／重规划** | 优先核验。当前生成账本已有线索；可在 host 层处理，不扩大远端能力 | 合理异步宿主、退避与预算已解决；LLM 本身可能正确等待 |
| 基于陈旧证据的配置，在真正到达时前提已变 | 保留。能源与延迟确实提供潜在后果，但尚无该 agent 失效轨迹 | FreshCtx、TTL、CAS、端侧低电保护已经覆盖；host 无新信息时不能凭空判安全 |
| 跨字段混配、日志恢复、重复副作用 | 暂不作为突破口。仓库已做大量检查，业务收益常与切换时机／省电混杂 | 配置原子性与持久化的既有机制；若新增固件能力，已改变公平比较条件 |

不把“找到一个 LLM 会错的提示词”作为机制需求。目标是明确可重复的接口失配，以及它在代表性 agent 宿主中是否自然出现。

## 6. 初版研究准备建议（暂停，先按更正核对历史）

1. **画清调用边界**：planner → host → 网关／节点，逐项标 accepted、dispatched、effect observed 的证据来自哪里。沿用既有任务和合法动作。
2. **固定三条短时间线**：未发出而等待；已发出但回执未到；断连期间出现合法新需求或恢复。前两条检验无效循环，第三条检验“少调用”是否以错过工作为代价。使用现有来源条件，不以超高故障率保证胜出。
3. **逐步推演强基线**：显式 pending／wait 的合理 ReAct 宿主；退避＋预算；MCP Tasks 风格事件执行；验证恢复。若无需新机制已经处理三条时间线，记录候选被解决，先不扩实现。
4. **仅在上述比较留下具体缺口时定义实现与小规模模型试验**。模型和提示词先固定，允许合法不动作；先做组件回放定位机制，再做同模型闭环配对，不能冻结整个闭环动作序列却声称已评估模型行为变化。

最终评价需要同时包括：监测服务、模型调用／tokens、正确继续执行、恢复后响应时延、错误完成／失败宣告、上下行开销。预先定义服务非劣界和成本判据；不能事后用有利权重合并。

第一轮成功条件是识别一个真实可复现的失效及其最小修复，不要求此时完成论文。停止该候选的条件：合理异步基线已经解决；坏行为只在刻意削弱的提示／宿主中出现；减少的意图没有实测成本或业务影响；节省预算依赖推迟或放弃合法任务。

## 7. 借用旧 LLM 路径前的三处边界

- `code/monitoring/compose.py` 的 `LLMPlanner.decide` 末尾 `return intents if intents else floor` 会将空意图交给规则补做。因此合法 wait/no-op 与生成失败需要区分；不能把规则代办计为 LLM 成功或错误。
- 同文件 `_has_decision` 只检查需求与已报配置是否匹配。没有新证据但仍不匹配时持续返回 true。若直接逐 tick 调用，模型成本会由调用调度器人为放大，不能据此声称现有 agents 普遍如此。
- 当前 `code/instance/network.py::_center_view` 直接读 `plane.queued_count`，`CenterView.soc_of` 用接收时刻判断观测年龄。接真实 adapter 时必须分别说明队列知识的合法来源、源生成时间与收到时间；不能带入模拟器特权或把晚到遥测当成刚生成。

这些是接入前的实现检查项，**修掉本仓库这些问题不单独构成论文贡献**。

## 8. 本轮决定的范围

撤回“通信等待—agent 恢复边界”作为新突破口的优先推荐。当前没有经审查选定的新机制。保持现有 task，不增加第三场景、不扩大长时扫描、不立即接 LLM，不恢复任何性能或唯一性主张。

保留的研究判断有两条：第一，当前 scripted 结果没有建立真实 agent 的失败及修复收益；第二，缺少 LLM 不是既有机制对照失利的通用解释。运行时性质与执行反例可以先用确定性轨迹检验；涉及模型自身行为、推理成本和闭环适应性的主张才需要真实模型参与。接入 LLM 可以检验这些缺口，不能自动产生方法新颖性。

当前只建议做既有方法与当前任务的语义对应审查。产出应是一条有业务后果、能区分成熟基线的反例，或者明确记录该候选已被既有机制覆盖；不再以增加 TODO、机制名称或故障扫描代替这个判断。
