## 一、最重要的单条结果：**在有出处的链路结构下，策略维度归零**

### 1.1 起因是一个缺陷，不是一个发现

实例的回传一直是**逐小时 i.i.d.**（`stable_uniform(seed,"backhaul",hour) < 0.62`），
而仓库自己从 ChirpBox 拟合出的平均下行突发是 **6.38 h**（**突发度 4.39×**，i.i.d. 对照 1.45 h）。
**在一个 residual 主要落在 delivery 侧的实例里，连已有的拟合都没接上。**

### 1.2 接上之后，服务与臂间差距一起塌

| 链路结构 | 平均坏突发 | 突发度 | cap 0.05 服务 | **臂间极差** | **链路损** |
|---|---:|---:|---|---:|---:|
| i.i.d.（原实例） | 2.63 h | 1× | 89.0–92.5% | **3.5 点** | 9.1 |
| ChirpBox（上海） | 6.38 h | 4.39× | 71.8–74.1% | 2.3 | 41.3 |
| ChirpBox 同均值 | 11.5 h | 4.39× | 66.4–68.1% | 1.7 | 53.2 |
| 更重 | 20.0 h | 7.6× | 65.3–66.9% | 1.6 | 54.6 |
| **LoRa-on-Ice（南极）** | **72.4 h** | **27.5×** | **38.5%（十臂全同）** | **0.0** | **84.0** |

**单调**，而且到第二个来源时**臂间差距归零**——`local`、`aoi`、`aoi_f600`、`aoi_t7200`、
`aoi_t1800`、`aoi_s3600`、`aoi_const300`、`dense600`、`ea_nb`、`eh_aoi` **十条臂交付数逐位相同**。

**第二个来源是本地就有的**：LoRa-on-Ice 的南极冰面部署（18600 次发送、跨度 12.9 天、
中位间隔 10 s）。偏远部署的突发度 **27.5×**，是城市部署（4.39×）的 **6.3 倍**——
**只用 ChirpBox 会系统性低估**。

### 1.3 Pareto 前沿随之塌缩

| 链路结构 | cap | 非支配点数 | 非支配点 |
|---|---:|---:|---|
| i.i.d. | 0.05 | **9 / 11** | 八个 `aoi*` 变体 + `dense600` + `ea_nb` + `local` |
| 上海突发 | 0.05 | 4 / 10 | `dense600`、`ea_nb`、`eh_aoi`、**`local`** |
| **南极突发** | 0.05 | **3 / 10** | `dense600`、`ea_nb`、**`local`** |
| i.i.d. | 0.004 | 5 / 11 | `aoi_f600`、`aoi_t7200`、`ea_nb`、`eh_aoi`、`local` |
| 上海突发 | 0.008 | **2 / 10** | **`ea_nb`、`local`** |
| **南极突发** | 0.008 | **2 / 10** | **`ea_nb`、`local`** |

**在有出处链路结构下，所有 `aoi*` 变体全被支配**，前沿上只剩**零中心控制**（`local`）与
**最小控制**（`ea_nb`）。cap 0.05 南极条件下 `local` 与 `aoi` **交付数与 AoI 完全相同**
（64.6 / 2367），而 `local` 上行更低（169.0 vs 181.5）、下行为零——**`aoi` 被严格支配**。

**读法**：链路可用时，默认 3600 s 已经足够；链路不可用时，任何报告周期都送不出去。
**`aoi` 的额外控制流量在突发链路下是纯粹的浪费。**

## 二、各轨做到哪

### 轨 A · Task / benchmark —— **做到了"结论有多宽"的一半**

| 项 | 状态 |
|---|---|
| 来源派生辐照（NASA POWER 2023/2022/2024，坐标与部署点逐位相同） | **已闭** |
| 多年份天气 | **已闭**（三年；2023 最冷，≥5 °C 小时 19.0% vs 21.7% / 21.5%） |
| 能量尺度不变性 | **已闭且为决定性**：λ∈{0.25,1,4,16} 逐位相同 ⇒ **绝对 Wh 不是现实部署数值** |
| 无量纲律 | **已闭**：可行性 ⟺ **初始自主小时数 ≥ 最长无采能时段** |
| 低温闸门敏感性 | **已闭**：二值开关，`dense600` 91.0% → 21.1%（−70 点），三年稳定 |
| 静息功耗敏感性 | **已闭**：改变绝对值，不改变 cliff 存在性 |
| **第二个链路来源** | **已闭**（LoRa-on-Ice 南极，27.5× vs 上海 4.39×） |
| **第二个业务来源场景** | **未取得** —— 见 §四 |

### 轨 B · Classical control —— **做到了"传统方法还能吃掉多少"，答案是"几乎没有"**

- 完整 Pareto frontier 已画出（11 点、四目标、无加权）。
- 文献结构已接入（有限电池 EH 的 (电量, 年龄) 二维联合门限）。
- 交付四分解已完成：`168 = 交付 + 转发损 + 择时损 + 采集损 + 链路损`，恒等式逐条成立。
- **但以上全部建立在 i.i.d. 链路上**；接上有出处链路结构后，前沿塌缩到 2–3 点。

### 轨 C · Agent / runtime —— **做到了账本，未到 planner**

- 意图准入账本三处闭合（生成端/到达端/落地端），修掉一列死列。
- **服务几乎相同（91.5–92.5%）而意图生成率相差 11 倍**（`ea_nb` 45.3 → `eh_aoi` 498.6）。
- **78–84% 的意图拿不到下行机会**，且**不花信道也不花能量**——是"生成速率与可执行速率脱节"的证据。
- 两种结构不同的浪费模式：`aoi` 是**无信道**、`ea_i600` 是**同值写入**。
- **真实 planner 一支按纪律延后**（只有它自然产生坏 intent 时 agent infra 才接回来）。

## 三、三条轨各自支持哪一种论文形态

**先给判据（目标里写死的三种结局）**，再逐条对照。

### 结局 1：传统方法已把 task 做满 → **source-grounded benchmark + failure analysis**

**证据强度：强。**
- 在有出处链路结构下，**前沿上只剩 `local` 与 `ea_nb`**，所有自适应策略被支配；
  十臂交付数逐位相同（南极来源）。
- 名义条件下固定配置的达标率（91.9%）**高于任何反馈策略**（`aoi` 90.4%）。
- 交付四分解显示：**转发损 1–2 条、链路损 9.1→84.0 条**（随链路结构），
  而**择时损在 i.i.d. 下 1.4–7.9 条**——策略能动的那一维本来就小。
- 无量纲律与尺度不变性把实例从"某组绝对数值"提升成**比率驱动的、可移植的**构造。

**这一条支持的主贡献**：一个**来源接地（source-grounded）的灾前监测 benchmark**，
加上一份**失败分析**——"什么时候控制策略有用、什么时候完全无用"的边界图。

### 结局 2：传统 controller 仍有明确 residual 但不需要 LLM → **通信/系统控制方法**

**证据强度：弱，且方向不利。**
- 在 i.i.d. 链路下确有 residual：`aoi` 距真上界 7.5%（cap 0.05）、12.4%（cap 0.004）。
- **但接上有出处链路结构后，这个 residual 的主体是链路自身的平稳不可用率**
  （84.0 / 168 = 50%），不是策略可及的部分。
- 存在一处**观察到的机会**：只上行突发下**择时损 33.0 条**——即"若节点能选择在哪些小时发送"。
  **但补它需要新增动作（上报相位／重传调度），那是改动作面，不在冻结范围内。**

**结论**：这条路的空间**比 i.i.d. 链路下小得多**；要走它必须先证明
"在不新增动作的前提下还有明确 residual"，**当前证据不支持**。

### 结局 3：真实 agent planner 引入传统 controller 没有的执行/意图问题且 runtime 能解决
→ **agent infra contribution**

**证据强度：尚未开始，但有一个有利的起点。**
- **账本已经显示两条结构不同的浪费模式**（无信道 / 同值写入），且**都能靠生成侧规则消掉**
  （`ea_nb` 生成 0 条）。
- **但这全部来自 scripted policies**。按纪律，**只有真实 LLM planner 自然产生**
  重复/冲突/无证据动作，**且**一个 host-side admission/runtime 在**不改 task 与动作面**的前提下
  减少成本或业务损失，才把 agent infra 接回来。
- **当前证据不能支持这一条，也没有被否掉**——它是唯一还开着的门。

## 四、第二个业务来源场景的结论（第 12 轮新增）

**做法**：动作面、任务结构、10 条基线一个字不改，只把业务节奏换成来源里读出的值
（`--sample-interval-s 900 --report-period-s 900 --routine-period-s 900 --no-events`）。

| 场景（10 臂，20 种子） | 非支配点数 | 非支配集 |
|---|---:|---|
| Wang · i.i.d. · 0.05 | 9/11 | 八个 `aoi*` + `dense600` + `ea_nb` + `local` |
| Wang · 南极突发 · 0.05 | 3/10 | `dense600`、`ea_nb`、`local` |
| **Cleveland · i.i.d. · 0.05** | **8/10** | 六个 `aoi*` + `eh_aoi` + `local` |
| **Cleveland · 南极突发 · 0.05** | **3/10** | `aoi_s3600`、`eh_aoi`、**`local`** |
| Wang · 南极突发 · 0.008 | 2/10 | `ea_nb`、`local` |
| **Cleveland · 南极突发 · 0.008** | **7/10** | 七个（含 `local`、`ea_nb`、`dense600`、四个 `aoi*`） |

### 复现了什么

**"在有出处依据的突发链路上，默认 `aoi` 被零控制的 `local` 严格支配"在两个来源上同向。**
Cleveland cap 0.05 南极条件下两者**交付 256.8、AoI 1013.85 s 逐位相同**，而 `local` 下行为 0。
⇒ 它不再是"Wang 一个片段"的产物。轨 A 的**外部效力风险因此实质性下降**——
但**没有消除**：两个来源结构同构（常态周期 + 阈值加密），差别只在周期长度与有无事件加密。

### 变了什么（这才是有价值的部分）

1. **非支配集的成员变**：Wang 南极下是 `dense600`/`ea_nb`，Cleveland 下是 `aoi_s3600`/`eh_aoi`。
   所以正确的表述是**"前沿收缩到少数几条低成本控制臂 + 零控制端点"，而非"只剩某三条臂"**。
2. **能量绑定会让前沿重新展开**（Cleveland 0.008 南极下 7/10）。900 s 的采样密度是 Wang 的 4 倍，
   能量开始咬人，臂在采集侧重新分化。
   ⇒ **"策略无从竞争"不是普遍规律，而是"宽松能量 + 突发链路"这一格的产物。**

### 更正：把任务时长与义务节奏**各自单独动一遍**之后（同日再补）

上一节与 §四 的"前沿塌缩到 3 个点"**必须削弱**。实测：

1. **任务时长 12 → 96 h（8 倍），南极突发下跟得上义务节奏的 8 条臂极差 0.00 / 0.04 / 0.16 / 0.29 点**；
   同一批臂在 i.i.d. 下是 3.5 / 4.2 / 4.3 / 4.4 点。
   ⇒ **"中心策略对服务水平几乎无影响"不是 12 h 任务的产物，由链路时间结构决定。**
2. **但"前沿只剩 3 条臂"随任务变长消失**：12 h 南极下 10 条臂交付**逐位相同（64.600）**、
   8 条连 AoI 也逐位相同，`local` 借此把它们全部严格支配；48 h → 7 个非支配点，96 h → 8 个。
   ⇒ **"前沿塌缩"是"多条臂读数逐位并列"的派生物**，不能当独立结论写。
   能写的只有**"额外控制没有业务收益"**。
3. **真正的边界是"上报周期 vs 义务节奏"的匹配**。第二场景（义务每 900 s 一条）里，
   `aoi_s3600`（30.2/31.1%）与 `eh_aoi`（21.9/22.3%）比其余 8 条臂低 8–18 点，
   原因是 **3600 s 报一次在物理上不可能满足 900 s 的义务**——这是硬约束，不是调度好坏。
   其余 8 条臂在 12 h / 48 h 下的极差只有 **0.06 / 0.25 点**。

### 与上一节"归零"结论的关系

上一节的"十臂逐位相同"发生在 **Wang 12 h + 每小时一条义务**这一格。
第二场景把义务密度提到 4 倍之后，**同一格内的臂间极差也变了**，
且能量绑定后前沿重新展开。**这正好验证了 §三 的限定**：结论绑定在"任务时长 / 义务节奏"与
"能量是否绑定"两个坐标上。**任何"策略无用"的说法都必须带上这两个坐标，否则是过度外推。**

### 下一轮最该做的三件事（按价值排序）

1. **形态更不同的第三来源**：PermaSense 马特洪峰（`120 s → 30 s → 3600 s` 三层节奏 +
   **backpressure 本地补传** + 逐样本三时间戳）——它能检验"多层节奏 + 设备侧补传"是否改变结论。
2. **把任务时长作为显式坐标**：缓存服务次序的激活条件是"断链 > 32 × 上报周期"，
   已证明 12 h 下为零、48 h 下 +0.4~+1.2 条。**做一条"任务时长 × 服务次序"的曲线**，
   把"策略无用"的适用范围定量画出来。
3. **轨 C 接真实 planner**：只观察坏 intent 是否自然出现，不人为提高故障率。
