20 种子/臂，义务 12 h + 尾部观察期 1 h，多节点 + 真实 SRTM/ITM 地形（网关带雨量计 + 13 个坡面
位移测点，绕射边缘上的 3 个位点已排除）。

**先写判据（v1.1 §10 预注册）。** 若成熟基线在业务指标上追平，**按事实报告**，不因为"我们的方法
没赢"去改任务、也不追加未经证实的中心义务。下面的解析按这条写。

## 三、数据说了什么

**一、中心介入真的有收益，而且只在周期侧。** 从 `local`（零下发）到任何一条下发策略，
周期缺送 **18.5 → 12.2**（−34%）；中断工况下 **42.5 → 36.0**（−15%）。机制是清楚的：现场自治的
上报周期是 3600 s，而周期义务的观察窗只有 3600 s + 3600 s 宽限，一旦某次上行在接入或回传上丢掉，
节点要等下一个小时才重传，往往已经错过。中心把周期改短，等于给了更多次重试机会。

**二、但自适应没有赢过一条调好的固定配置。** `fixed900` 与 `aoi` 在**每一个业务列上逐位相同**
（交付 155.8、缺送 12.2、AoI 2030 对 2032、事件 21.0/16.8），而代价是 **上行 352.4 对 431.6
（少 18%）**、**下行尝试 17.9 对 99.8（少 82%）**。中断工况下同样逐位相同（131.9 / 36.0），
上行 414.6 对 513.1。**按预注册判据，这是"成熟基线追平"：自适应机制在当前实例上没有赚到主张。**

**三、我原本假设的那个机制，读数方向是反的。** `aoi_link` 比 `aoi` 多了一条"最近完全没消息的
节点先不下单"（理由是节点静默与回程丢失不可区分、机会该省着花）。结果是它**更差**：
交付 154.7 对 155.8、缺送 13.3 对 12.2，而代价并不更低（上行 370.2 对 431.6，下行 72.4 对 99.8）。
可读的解释是：被它跳过的那些节点大多只是暂时静默、稍后就会回来，省下的机会不值那些延迟。
**这是一条负面结果，照实记录。**

**四、事件侧对所有臂完全相同。** 采集 21.0/21、交付 16.8/21 在五个臂上逐位一致——因为事件响应是
**现场自治**（本地触发、立即上报），中心的下发一个字都没碰到它。**所以"中心介入的收益"在本实例里
完全落在周期侧，事件侧没有任何可分离的贡献。**

**五、比 900 s 更密是纯浪费。** `fixed300` 与 `fixed900` 的业务列逐位相同（155.8 / 12.2），
但上行 **761.5 对 352.4**——**多花了 116% 的机会买同一个结果**。原因是周期义务的窗宽与宽限是固定的
（3600 s + 3600 s），一旦上报周期短于某个阈值，再密也不改变"某条样本能否在截止前到达"。
**在本实例里这个阈值在 900 s 附近。**

## 四、这些读数能支持什么

1. **在共享的间歇链路上，中心对现场周期配置的下发能显著改善周期服务的交付完整性**
   （缺送 −34%），且收益可以用"多给几次重试机会"解释，机制清楚。
2. **一条按回执重试的静态配置就能拿到全部收益**，不需要依据观测自适应。
3. **比必要值更密的上报周期是净浪费**（+116% 上行、零业务收益）。
4. **回传中断期间采样不受影响（缺采恒为 0）**，损失全部在交付侧，且自动补发能追回一部分
   （42 条）。**"采集缺失"与"交付缺失"是两个不同的量，不能合并。**

## 五、这些读数不能支持什么

1. **不能支持"自适应调度有价值"**——它没赢过 `fixed900`。按预注册判据，这条主张到此为止。
2. **不能支持任何能源结论**——采能是合成的恒定过程，电池恒满、约束未触及。
3. **不能支持跨站泛化**——单一片段、同一天、同一设备、一个监测单元。
4. **不能支持"中心不可或缺"**——本实例里中心只改变了周期配置这一个字段；`local` 已经有 149.5/168。
5. **不能支持事件侧的任何中心收益**——事件对五个臂完全相同。
6. **不能支持"跳过静默节点更好"**——读数方向相反。

## 六、为什么这仍然是可用的结果

按 v1.1 §10 与 D50 的预注册：**任务真实性、方法收益、本文独有优势是三件事**。这一轮回答的是第一件
和一件负面结论：

- **任务侧**：多节点、真实地形、外生事件、有限机会、可回执的中心动作全部接通，分列指标可手工核对；
  这是此前一直缺的那一层。
- **方法侧**：**"依据观测自适应"在本实例上不优于"依据回执把静态配置调对"**。这是一条干净的负面
  结论，且有代价读数支撑（下行尝试 5.6 倍、上行多 22%）。

**下一步该做的不是把 `aoi` 调参调赢，而是改变"什么样的情况会让固定配置不再是答案"**——
按第四节的第五条，本实例里中心只动了一个字段，且周期义务的窗/宽限结构使密集配置饱和。
若要让调度真的有选择空间，必须引入**固定配置无法同时满足的义务冲突**，而不是换一个更聪明的策略。
