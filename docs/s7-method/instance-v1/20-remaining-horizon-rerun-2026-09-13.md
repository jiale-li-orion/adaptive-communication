# 剩余时域修正后的 closure rerun：**cand 不再退化成 `local`，但在它要修的那一格被 `local` 严格支配**

日期：2026-09-13。**本文推翻 `19-admission-result-and-stop` 的判定依据**（不是推翻它的结论方向）。
两处实现偏差由外部复核指出并被证实；修好之后重跑了同一批开发条件，**其它一个字节没动**。

---

## 一、被证实的三处问题

### 1（实质性）保护时域写成了固定值，而不是剩余时域

`18-method-spec` 写的是在时刻 `t` 检查到 `[t, end]`。实现却在**构造策略时**一次传入
`horizon_s = task_hours * 3600`，而 `ResourceGate.check()` **每次从 `t = 0` 跑满它**。于是：

| 时刻 | 规格要求问的 | 第一版实际问的 |
|---|---|---|
| h1 | 还能不能撑到任务结束（剩 ~11 h）？ | 能不能再撑 13 h？ |
| h6 | 还能不能撑剩下的 ~6 h？ | **能不能再撑 13 h？** |
| h10 | 还能不能撑剩下的 ~2 h？ | **能不能再撑 13 h？** |

**这不是小误差**：它把"剩余时域变短 ⇒ 加密变得可行"的中间态整个压掉。实测
`accept = 0 / checks = 171.9` 与"八列逐位等于 `local`"**有相当一部分是实现出来的**。

**修**：`check(soc_lo_wh, config, remaining_s)`，`remaining_s = end_s − view.t_s`。
**边界语义冻结在跑之前**：`end_s = task_hours * 3600`（**任务边界**，不是 13 h 运行边界）——
理由是义务只定义在 `[0, task_hours)` 上，尾部 1 h 只是观察窗。取运行边界只会让门**更保守**，
所以这个选择不会制造正结果。

### 2（表述）规格里写的"观测收支"没有实现

`18-method-spec` §三把候选与阈值的差别写成"电平 + **观测收支** + 剩余时域"。
实现里采能下界**固定取 0**，`_soc_lo()` 只用最近一次读数减最坏消耗。
⇒ 真正跑的是 **zero-harvest worst-case viability filter**，不是"从观测历史做持续负载核算"。
**规格已按实际实现改正**（§六）。这也意味着：**"cand 全拒绝"只能说明这个极保守实例化退化了，
不能外推成"持续配置的资源核算没有增益"。**

### 3（论证）`rob3 == ea_nb` 不能支持"标准鲁棒过滤器已覆盖"

`out3` 是 9 h 接入中断，`rob3` 却假定"最多 3 h 后可以纠正"——那个保证在这个环境里**不存在**。
修正后 `rob3` 在**每个剩余时域上都放行**（14 检查 / 14 放行 / 0 拒绝）。所以它能说明的只是
"一个假设 3 h 内必能纠正的过滤器在这里从不触发"，**不能**说明同等信息的鲁棒过滤器已经解决问题。
**公平的说法**：候选很可能就是**鲁棒安全过滤针对"持续远端配置"的一个实例化**——
这是**新颖性弱**的证据，与**性能无增益**是两件事。

### 4（撤回）"`D` 这一族只有全接受与全拒绝两端"

**撤回。** 只跑了 `D = 3 h` 与 `D = ∞` 两点，不构成"只有两端"。按声明的能耗手算，
临界 `D` 是**连续的**：

```
D* = (soc_lo − H·load_sparse) / (load_dense − load_sparse)
   = (0.0195 − 12×5.153e-4) / (3.0012e-3 − 5.153e-4) = 5.36 h      （H = 12 h）
```

已写成测试 [30] 的断言。`D = 3 h` 与 `D = ∞` 恰好落在 `D*` 的两侧，才显得"只有两端"。
**不扫 `D`**——它必须有现实语义（可证明的纠正时延上界），本轮没有这样的证据。

## 二、修正后仍然成立的那条硬结论（不是实现问题）

在 h1，节点剩余任务期约 11–12 h；加密在**零采能**下只撑
`0.0195 / 3.0012e-3 = 6.5 h`；设备**没有**本地 lease / 自动回退；中心**没有**任何可靠的下一次
纠正时间保证。于是：

> **任何要求 hard safety、又不假设未来控制恢复的准入，在 h1 都必须拒绝加密。**

⇒ 原来设想的"h1 放加密 → 可能失联 9 h → 同时保证不缺采"，**在现有动作面下做不到**。
这是一个 `T_survive(dense) < H_uncorrectable` 且无端侧回退的**不可能性式结论**，本轮保留。

**它的直接结构后果**：门的可行窗口**只能在剩余时域 < 6.5 h 之后打开**——
也就是说，这个机制**永远无法保护"早期的高负载介入"，只能许可一次"晚期的介入"**。
这正好解释了下面的分布。

## 四、判定（按你给的三种形态对照）

| 形态 | 是否出现 |
|---|---|
| ① 仍然 `accept=0`、逐位 `local` | **没有**（`accept ≈ 13.4`，八列不再等于 `local`） |
| ② 后期开始 accept，但业务/成本仍不优于 `local/aoi` 前沿 | **正是这一种** |
| ③ 后期选择性 accept，`out3` 保住 0 缺采**且** `noout` 留下原 `ea_nb` 的收益 | **没有** |

严格的支配检验（四目标：交付↑、上行↓、下行↓、AoI↓，不做加权）：

- **`out3`：`ea_nb_cand` 被 `local` 严格支配。** 交付 **56.3 = 56.3**、AoI **16133.0 = 16133.0**、
  上行 **52.0 = 52.0**，而候选多花 **9.4 次下行**、能耗 0.1154 对 0.0972 Wh。
  **它保住了 0 缺采，但 `local` 用同样的交付、同样的 AoI、更少的成本也保住了 0 缺采。**
- **`noout`：`ea_nb_cand` 不被支配**，是一个**新的前沿点**（比 `local` 交付 +0.7、AoI −230 s，
  代价是上行 169.0 → 249.7）。但它远低于 `ea_nb`（+2.7）与 `aoi`（+6.0）。

⇒ **判定仍是 STOP，但依据换了**：不是"退化成 `local`"，而是
**机制能动、却只在最后 ≤6.5 h 打开窗口；在它要修的那一格（`out3`）被零控制的 `local` 严格支配，
在 `noout` 只多出一个很小的前沿点。**

**留出仍未做**（开发集与 `out3` 支配关系都已否定"有增量"这一前提），**不拿开发结果替代**。

## 五、本次修正改变了什么、没改变什么

**改变**：
- "cand 逐位等于 `local`" —— **只在固定时域的实现下成立，已作废**。
- "`D` 只有两端" —— **撤回**。
- "标准鲁棒过滤器已覆盖候选" —— **撤回**；改为"候选很可能是鲁棒安全过滤的实例化，新颖性弱"。
- 规格 §三 的"观测收支" —— **撤回**，实现是 zero-harvest worst-case。

**没改变**：
- 0–1h 闸门的机制归因（证据陈旧且仍显示健康；`out0`/`out3` 对照；`aoi` 缺采 0）。
- 两个实现缺陷的修复与跳过原因账本。
- **`out3` 那格的不可能性结论**——它是结构的，不是实现的。
- `aoi` 仍是必须在 `out3` 跨过的门槛；候选**没有跨过**（交付低于 `aoi`、AoI 差于 `aoi`）。

## 六、规格文本更正（`18-...` §三）

原文："阈值只问现在够不够高；候选问按时域内**观测到的收支**够不够用。"
**改为**："阈值只问现在够不够高；候选问**在剩余时域内、按零采能最坏情形**够不够用。
本实现**没有**从历史估计收支（采能下界固定取 0），因此它是一个
**zero-harvest worst-case viability filter**；要变成真正的'收支核算'，
需要一条**可辩护**的采能下界（例如按观测到的 soc 轨迹给出带误差界的下界），
本轮**没有建立**，故不声称。"
