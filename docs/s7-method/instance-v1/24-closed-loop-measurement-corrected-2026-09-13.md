# 闭环测量的三次修正与最终判定：`A(a) = 0`，而真正的损失死在第一层

日期：2026-09-13。goal `goal-16f13d45` 的交付文档。基线 `e4cc546`。

> **本文取代** `§7.81–§7.82` 的 `A` 数值。那两节的数**不可承重**，原因是测量对象本身有三处定义缺陷

## 一、三处定义缺陷与修法（顺序按批评者给定）

### 1. identity 配对：按值配对会重复认领

旧写法「同节点 + 同值 + 之后第一个 `applied`」在 `aoi` **67% 重发**（§6.24）下会让
`plan₁`/`plan₂` **都认领同一次 `applied`**。

**修**：先做**一对一贪心**（每个 `applied` 只被认领一次，归给最早的未认领 plan），
再把真身份接进 trace——`network.py` 的 `_send_command` 在 `center_send` 成功分支补一条 `sent` 事件
（带 `logical`），两处 `applied` 事件带上同一个 `logical`。于是 `plan → sent → applied` 按**身份**串，
`logical = f"{node}:{op}:{generation}"`，与节点侧 `applied_logicals` 是同一个串。
无身份时（`send_contract_fields=False`）退回贪心，**并报出用了哪种**。

**结果：身份版的数与贪心版逐位相同**（落地数、`A` 都一样）。
⇒ 贪心版**没有被重复认领污染**；身份配对在这里的作用是**验证**，不是改值。

### 2. time-origin 口径：两个口径被拼在一起

旧算法拿 `T_loop = T_evidence + T_return` 去比 `T_harm^now`（决策时刻的"从现在起还能撑多久"），
而 `T_evidence` **发生在决策之前**——等于拿"从过去证据生成到动作落地"比"从现在开始还能活多久"。

**修（主口径）**：

```
A(a) = P(T_return > T_harm^now(a) | T_evidence ≤ T_deadline)
```

`T_evidence` **只作条件**（决定这条决策值不值得信），**不进生存预算**。旧拼接口径并排报出并标注
「**口径不一致**」，只作对照。

### 3. 右删失：`T_return = None` 不能一律当 ∞

任务结束前没看到 `applied`，只能说明"至少等了这么久"，不能断言超过 `T_harm`。

**修**：只有 `t_plan + T_harm^now ≤ t_trace_end` 仍未生效，才无争议记为 failure；否则标 **censored** 单列。
（`T_harm^traj` 已踩过同一个坑，见 §7.73。）

## 二、最终读数：**`A = 0.000`，10 格无一例外**

固定 `cap 0.05`，5 档链路 × 2 臂，3 种子。`n` = 条件样本量（`T_evidence ≤ T_deadline`）。

| 臂 | i.i.d. | ChirpBox 6.38 h | 11.5 h | heavy 20 h | polar 72.4 h |
|---|---|---|---|---|---|
| **`ea_nb` ★主口径** | **0.000** (n=88) | **0.000** (60) | **0.000** (90) | **0.000** (96) | **0.000** (52) |
| `ea_nb` 旧口径（不一致） | 0.216 | 0.167 | 0.156 | 0.177 | 0.231 |
| **`aoi` ★主口径** | **0.000** (n=114) | **0.000** (65) | **0.000** (94) | **0.000** (104) | **0.000** (24) |
| `aoi` 旧口径（不一致） | 0.289 | 0.308 | 0.170 | 0.163 | 0.167 |

**每一格的 `n_fail` 都是 0**，右删失 4–33 个。

单格对照（3 种子）：`noout` 旧口径 **0.269 → 主口径 0.085**；`out3` 旧口径 **0.652 → 主口径 0.000**。

⇒ **§7.81–§7.82 那条"0.14–0.23 的平直线"整条消失**，它是两处缺陷的合成：
① 口径不一致把 `T_evidence` 从当前生存预算里多扣一遍；② 把右删失当 failure。

**判定：预注册 ② 被干净地支持——`A(a) ≈ 0`，"authority failure"按此定义应当收掉。**
（预注册 ① 不成立：无上升趋势。）

### 但这个 0 的**适用域**必须写清

`cap 0.05` 下 `T_harm^now` 是 **6.7–16.7 h**，而 `T_return` 中位约 **2 h** ⇒ 只要证据按时到，
return leg 总短于剩余伤害预算。**要让 `A` 非零就得让 `T_harm` 小，而那要求压容量，
压容量又让证据变陈旧、把分母打没**——这是 §7.80 那条**分母/分子反向耦合**。

⇒ `A = 0` 是**可信的测量**，含义是「**在证据按时到达的区域里，return leg 够快**」，
**不是**「authority 概念无意义」。

2. **`out3` 是例外**：层 2 占 **63.6%** ⇒ 在**断链型**条件下该方向**才有依据**。

3. **层 3、4 在所有格子里恒为 0** ⇒ `intent suppression`/`coalescing`（层 3）与

## 五、G5 第二次收紧

原 G5：`observation channel = control channel`（结构同一性）。
第一次收紧（`21-...`/`23-...`）：`T_loop ≥ T_evidence`——reactive 闭环**严格难于**单向交付。

**第二次收紧（本条）**：

> **观测成功更新了对控制通道状态的信念，但不保证闭环能完成。**
> 因为「刚收到一次新鲜证据」这件事**本身就在筛选轨迹**——它告诉系统
> "我最近很可能处在 good 状态"（两态链下，bad run 变长时 good run 往往也变长）。
> 所以相关的量是
> `P(下一次控制机会在 τ 内 | 刚收到新鲜证据)`，
> **不是平均坏突发长度**。

**这条正好解释 §7.82 那条平直线**：无条件看，长 bad burst 极其可怕（链路损 9.1 → 84.0）；
但**条件在"证据刚按时到"之后**看，未来短时间仍可能留在 good run，
于是条件概率被钉住。⇒ **"平均坏突发长度"本来就不是 return leg 的自变量。**

## 六、必须记下的概念缺口

**`A` 是逐 intent 的，而"控制回路是否闭合"是逐 (节点, 事件) 的。**
被层 1 拒掉的 intent 若随后**重发成功**，就**不构成 authority failure**，
但逐 intent 计数会把它算成一次失败——现在**只靠右删失规则压住**。

⇒ 要做**回路级**的问题，必须换成按 **(节点, episode)** 聚合，而不是继续调 `A`。
**这是下一步，不是继续修 `A`。**

## 七、本轮我自己造出并当场抓住的三个错（如实记）

1. **`logical is None` 同时表示"没找到 `sent`"与"报文本来就没有身份"** ⇒ 落地恒为 0。
   修："无身份"与"未找到"**分开判**。
2. **给 `_greedy_one` 的插入锚点写错**（多写一个 `def`）**且那次替换漏了断言** ⇒ 函数未定义、`NameError`。
   修：锚点改正，并且**每次替换都带断言**。
3. **`stats_by_tag[tag] = st_` 在种子循环里被覆盖** ⇒ 印出的"落地/被拒"只反映最后一个种子，
   而 `决策 n` 是跨种子汇总的，**两个口径混用**。修：**累加而非覆盖**。

三个错共同的两个根因：**同一变量承载两种语义**、**替换不加断言**。
