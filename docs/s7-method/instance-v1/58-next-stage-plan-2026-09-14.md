上一轮我把 doc 56 写得过强，本次明确更正：

1. `information_timing.py:333` 的 `q <= 0.05` 固定停发不看剩余期限。真实坏态仍有 0.02 成功率；在最后机会、已有待交付数据、资源充足且以交付为目标时，永远停发显然不是最优规则。因此不能把该规则的损失归为“更多信息使业务变差”。
2. `_run_batch` 用期望剩余积压决定发送数量，`_run_sequential` 用实际剩余队列并逐次重选；二者的执行/停止规则也不同。共有一个选路函数不等于只改变了信息待遇。
3. 能量系数网格几乎不变，只说明扫过的系数不敏感，不能证明路径容量是唯一瓶颈；固定停发和剩余额度不足时整段 `break` 都需要进入停止原因台账。
4. `same_epoch_reroutes` 统计失败后相邻动作换路，整拍预排动作也会命中；它不是“因为 ACK 而重规划”的因果计数。`same_epoch_evidence_count` 也没有判断是否存在同一 epoch 的后续决策。运行器丢弃了 action/evidence 细粒度账本，因此不能把聚合计数当作已落盘的完整归因链。

对同一目标、动作与资源限制，若新信息可以选择忽略，则可用策略集合包含原集合，最优可达值不会因信息增加而下降。观测获取本身收费、或实现强制响应观测时，是另一个比较。此处是策略集合包含关系的推论，不是本轮新发现。

**修订后的关闭对象是：当前同价、同观测质量的单次探测启发式不晋级。当前规则之间存在经验取舍，但其帕累托最优性和探测动作族的最优性都未证明。**

## 2. 场景本质与主候选

现场自治已经负责采集、事件响应和缓存。中心/网关剩下的研究问题是：在相同监测义务下，什么时候值得改变节点上报节奏，什么时候只增加通信而没有增加及时可用的数据。上层产生意图很容易，样本和配置能否在期限前跨过两跳才决定后果。

现有 `ReportPacingPolicy._want()` 的快慢判断来自网关整体的 `pending_depth`、最老待转发年龄或上次转发成功时间。它给所有节点同一种受阻判断，没有把“此节点本周期是否已有合格样本到达网关”“下一个公开周期义务还有多久”纳入快慢目标。代码有逐节点新样本时间，但当前规则未使用这部分业务结构。

**候选：用逐节点的已知义务满足状态和剩余时间决定上报节奏，并把设置命令的实际生效延迟算进去。**

例子不是新增负载：同一网关看起来都在积压，节点 A 的本周期合格记录已经在网关，节点 B 的本周期合格记录还没有被听到。如果 B 仍有可利用的上报机会，二者继续慢报的代价可能不同。只有实际配置、Class A 机会和截止期允许改变这个差别，才有候选价值。若现有轨迹不存在这样的历史，不能用人为新增告警制造它。

合法输入与动作：

- 输入来自 `_gateway_view` 已有的节点回执、源时间、`newest_taken_at` 和网关本地转发反馈；周期义务的周期/相位/研究宽限作为公开服务配置同等给所有臂。
- 最新样本不能代表所有旧窗口是否覆盖。确需完整义务状态时，只从网关实际接收历史派生最小台账，并同等开放给对照；不读取节点真实未上报缓存或评分器匹配结果。
- 仅使用已有 `report_period ∈ {300,600,900,1800,3600}`，保持采样、事件自治、存储、执行位置、去重与版本能力一致。可以先只比较 300/900 两个已有档位。
- 命令经真实队列与 Class A 窗口生效。没有合法信息证明未来能改回来时，不以预知恢复时刻排程；不为候选添加 TTL/端侧回退。
- 不把“网关已听到”当作“中心已准时收到”；剩余回传延迟和中心交付仍由真实数据链决定。

与已测候选的区别：此次改变的是逐节点选择上报档位的依据；没有重新测试纯位置收益、条件计划序列化、静态 30 点网格或 FIFO/LIFO。doc 53 §7 已明确将剩余时域策略列为未覆盖，故这是一处有记录的未答问题。

### P0：多路径归因补件（约 0.5–1 小时，止于微型诊断）

修改范围限于 `multipath_probe/information_timing.py`、同目录测试与一个诊断输出；不再新建平行模拟器。

1. 为短时域固定历史记录停止原因：队列空、路径容量、日配额、总能量、epoch 额度、`q` 门槛。保留一条完整 action/evidence 台账。
2. 同一逐次执行循环增加“收到 ACK 但延后使用”的控制；保持队列可见性、预算计算与停止条件一致。旧 batch 臂作为历史参考，不再用于纯信息归因。
3. 先作一个不带新现场含义的有限状态校验：两条路径、一条有期限的数据、2–3 次尝试，用已知观测概率枚举期望交付；允许有反馈策略忽略反馈，应能复现无反馈策略。

### P2：只实现一个候选并给足强对照（约 1.5–2 小时）

在 P1 有对象时，候选首先用“合格样本尚未听到 + 期限余量”决定是否维持/请求快报；已满足当前窗口且下一窗口尚有余量时允许慢报。以真实命令到达和持续配置演化评价，不能即时改配置。

最低比较集合：

| 臂 | 用途 |
|---|---|
| `fixed300` 与 doc 53 已登记固定/背压/AoI 前沿 | 原有强基线与服务参照，不只挑一条弱基线 |

## 4. 论文与 agent 的进入条件

论文需要证明的是一个可复用的通信决策/执行机制为什么有效。当前最具体的待验证命题是：**网关整体积压不够表达各节点的监测需求；区分义务状态并考虑配置生效时刻，是否能在相同监测完整性下节省通信。**

新颖性最大风险是它退化为成熟的 deadline-aware scheduling 或事件触发控制。仓库已收录的 [Zakeri 等 POMDP 工作](https://arxiv.org/abs/2311.06522) 已同时考虑部分可观测、采能、采样/传输成本和不可靠通信；本次重新核对作者摘要。因此这些因素的罗列不构成贡献。候选若有增量，应进一步对照其动作是直接采样/发送还是持续配置，以及其状态/约束如何处理两跳到达和不可即时纠正。未做全文对应前不声称缺口。

对 agent 的适配在通信结果之后做一次小型 2×2：规则 planner/真实 agent × 现有执行路径/候选机制。所有臂得到同一公开目标和观测，不能先由 AoI 规则算好唯一目标再要求 LLM 照抄。如果候选会重写 planner 的数值指令，必须先定义目标级接口授权；纯执行器不得把改指令算作更忠实的执行。

规则 planner 同样获益可以支持通用通信方法，不证明 LLM 必要。TopoLLM 的 UAV 拓扑、WirelessAgent 的切片变量和本任务的周期设置不同，适配后只能称 workflow adaptation，不能称原论文复现或性能击败。只有接口迁移、少量运行与机制收益归因都闭合，才写 agentic 通信主张。

当前不选 venue、不扩 UAV/卫星，也不把全部负结果直接凑成论文；这些选择应在 P3 的明确结果后发生。
