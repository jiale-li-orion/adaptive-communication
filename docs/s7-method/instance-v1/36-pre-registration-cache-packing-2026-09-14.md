# 备选 3 预注册：按监测义务使用一次已有上报机会（设备缓存/打包纪律）

日期：2026-09-14。**本文件在任何对照运行之前写定**，此后不得按结果回头修改判定规则。

依据：[`31-communication-method-candidates-2026-09-14.md`](31-communication-method-candidates-2026-09-14.md)
§五（尤其第 87、89、91、93、95 行）。本文档**不修改** §31 原文。

## 1. 要判别的问题

在**已经存在**的一次上报机会里，**该让哪些缓存记录占用这次机会**，会不会改变业务？
评价对象是"每次包选择**增加了哪些义务的交付可能性**"，**不能只看包数或缓存清空率**（第 89 行）。

## 2. 声明的能力变化（A 层，**全基线共享**）

- **设备具备可编程的缓存/打包软件**。当前 `cache_service` 是**实例属性、中心不能通过原来两个字段修改它**
  （第 91 行），因此本轮把它显式声明为一项 **A 层设备能力**，并把它的每个取值
  **在同一轮里对所有臂跑一遍**——**不存在"把更好的固件只给本文"**。
- **打包软件知道自己被声明的监测义务节奏**（新增 `DeviceProfile.obligation_period_s`，
  由 `--routine-period-s` 喂入）。义务窗口 `k = taken_at // obligation_period_s`，
  其观察截止 = `(k+2)·period`，与 `exogenous.Obligation.deadline` 同定义。
  **`fifo`/`lifo`/`latest_only` 不使用它；`edf`/`obligation_greedy` 使用。**
- **节点仍只接受原来两个设置字段**；没有新增无线覆盖、没有强制接收、
  **打包纪律不是"自动回退"**——它只决定**已经缓存的记录**如何占用**已经存在的**那一次机会。
- **动作面不变**：换纪律等于换实例，因此同一轮里所有臂必须同值重跑（第 91 行）。

**一处必须写明的既有建模简化**：本实例的 `ack()` 在中心收到时**同步施加**且**不占空口**，
因此"中心已经收到哪些记录"对设备是**完全已知**的。§31 第 89 行要求的
「打包端不知道中心已收到哪些记录时，按合法确认历史保留不确定性」这一情形**本轮没有被触发**，
结论不得外推到手头没有确认历史的情形。

## 3. 五条纪律（**其中三条是既有成果，不得当新贡献**）

| 取值 | 规则 | 来源 |
|---|---|---|
| `fifo` | 最老优先（**默认，设备既有自动补发**） | 仓库既有，**基线** |
| `lifo` | 最新优先取一批，旧记录留在缓存 | **仓库既有成果**（`11-aoi-defect-and-cache-service`），**不得认领** |
| `latest_only` | 只留最新，旧记录**丢弃**并记账 | 仓库既有（AoI 文献标准队列纪律） |
| **`edf`** | 按义务窗口升序（＝观察截止升序），窗内按采集时刻升序 | **教科书最早截止期优先**，无调参权重 |
| **`obligation_greedy`** | **一条义务只花一个名额**：每窗只留窗内最新，再按窗口升序取 | "**按有效义务匹配的普通贪心**"（第 93 行），无调参权重 |

后两条**不使用任何需要调的权重**，也不需要未来真值。

## 5. 记录量

服务、**缺采**、缺送、AoI、能源、上行/下行/空口时长、丢弃条数，
外加**激活量**（第 91 行）：`cache_backlog.over_payload_ticks`（积压超过一次载荷容量
`CACHE_PAYLOAD_SLOTS = 32` 的 (tick, 节点) 次数）、峰值与平均缓存深度。

## 6. 预注册判读规则（先写死）

- **R1（负对照，证伪仪器）**：C2（12 h、无中断）下**激活量应近于 0**，且五条纪律的业务读数
  **应当没有实质差别**。**若在那里也出现明显差别 ⇒ 是仪器错**（纪律在没被激活时不该有作用），
  先修仪器、不得据此报收益。
- **R2（长中断档）**：C1 下若 `edf`/`obligation_greedy` 的服务或 AoI 优于 `fifo` ⇒
  记录**改善的是哪条固定义务**、以及**代价**（上行/空口/能耗/丢弃）。
- **R3（诚实边界，第 95 行）**：**`lifo` 已是仓库成果，不得算作新候选贡献**；
  新的匹配规则**很可能落入成熟的截止时间调度**。若标准算法（EDF 或该贪心）拿走增益
  ⇒ 按第 93 行**把它作为所有方法共享的成熟本地能力**，**不命名为本文方法、不定 venue**。
- **R4（激活阈值）**：验证"机制价值由**压力是否跨过激活阈值**决定"——
  即**无激活 ⇒ 无效应**、**有激活 ⇒ 有可测效应**。这条若成立，**是 Human 复盘第 70/72 行
  已提出的规律**，**不得**当成本文的新机制或新规律。
- **R5（纪律）**：`run_checks.py` 保持 **18/18**（先看 `EXIT=$?` 再提交）；
  `cache_service="fifo"`（默认）必须与改动前**逐位相同**；只维护唯一一份实例测试。

## 7. 明确不做的事

**先不做 agent**（第 93 行）。不新增无线覆盖、不强制接收、不做设备自动回退；
未来真值只供独立评分、**绝不反馈给 planner**；不把边缘自治的增益归因给 LLM；
不声称"传统方法忽略不确定性"（arXiv 2311.06522 与 ETH 自触发是实质竞争者）。
