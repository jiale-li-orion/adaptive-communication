# 能源位置正结果的审查与小型节奏对照决策

日期：2026-09-14。审查锚点：`218eb41`。本轮读取 §43–§47、原始结果结构、指标提取与控制路径，并复算已有聚合量及服务—成本包络；**没有重跑仿真，没有运行 LLM，没有新增方法实现**。本文件是后续研究建议，不是新方法的预注册结果或已执行实验。

**决策：`continue`，进入范围受限的节奏判别准备。** 接受“架构收益依赖已测条件”；不先补余下 37 档，不推进通用计划编译器，不启动 agent 2×2。现场反馈能力成为共享基线，本文额外机制收益仍未建立。下一步先补当前证据的保存与解释，再比较普通节奏规则；只有出现其不能解释的差额，才实现最小候选。

## 1. 正结果保留，但归因措辞需调整

依据 [`energy_limited_placement.json`](../../../results/energy_limited_placement.json) 的 `rows` / `paired`，同一 `ea_nb` 的网关减中心均值为：

| 条件 | Δ服务 | Δ缺采 | 相对 O0 的 Δ服务差 | 相对 O0 的 Δ缺采差 |
|---|---:|---:|---:|---:|
| O0 无强制中断 | +0.60 | −0.60 | 0 | 0 |
| O1 接入中断 | −0.50 | +1.00 | −1.10 | +1.60 |
| O2 回传中断 | +5.70 | −14.70 | **+5.10** | **−14.10** |

固定分母 168：O2 直接位置差为服务 **+3.39 个百分点**、缺采 **−8.75 个百分点**；相对 O0 的差中之差为 **+3.04 / −8.39 个百分点**。后两列是已有均值的交互对比，不能自动当成完全隔离的“失联期间因果效应”。当前 JSON 没有逐种子值，无法据此重算配对区间。

O0 是整个任务在无强制中断条件下的结果，不是 `t < 3 h` 的状态快照。O0 差异小不能证明两位置在中断前逐位一致；§46 R1 要求报告扣除基准后的差，§47 尚未完成这一项。应保留直接差与交互对比，并从保存的时间线检验前缀。相同随机种子保证配对的外生条件，不保证不同策略执行位置诱导出的轨迹相同。

O2 还伴随上行 **+14.3（+3.56%）**、下行尝试 **+16.8（+52.34%）**、上行空口 **+1.93%**，总能耗 **−0.00143 Wh（−0.38%）**。它保住了采集，也支付了更多通信成本；只报总能耗略降会漏掉这部分代价。最低末电量从近零回升可以报告绝对量，不以“95 倍”承担效果量或现实续航主张。

本对照支持：**能源受限时，回传中断仍保留网关—节点的观察和执行路径，使既有能源反馈规则能够减少不可恢复缺采。** O1 中这条局部路径也被切断，所测位置收益消失。`placement` 同时改变观察新鲜度和命令入队路径，因此本轮识别的是联合架构收益，尚未将“更新鲜的读数”和“仍能下发”的贡献分别隔离。

`local` 在两位置上相同是有用的负对照和实现自检；零控制臂不经过许多控制路径，故不能由它单独证明所有控制路径没有实现差异。

判别 A 与本轮所用策略和中断窗口也不同；“正差出现在已测能源受限上下文”成立，“只改变能源条件导致差额从零转正”尚未由一项完整的单因子对照证明。

## 2. 三处会影响论文机制解释的证据问题

**持续生效与重复执行要分开。** §47 同时写“中心既看不到也发不出”和“继续重申 dense 导致耗死”。在 `network._send_command()` 中，新的中心命令要经过 `center_send`；强制回传中断会阻止新命令进入网关。`EnergyAwarePolicy.plan()` 在已知配置等于目标时也会直接跳过。当前可以支持“中断前生效的高负载配置未得到及时降档”；不能把损害归给中断后的重复写入，除非逐命令记录证明它们确实生效并产生额外后果。中断前已排队命令也应按实际生效时刻区分。这不需要新增控制实验，先核既有时间线即可。

**台账未保存在交付文件。** `energy_limited_placement.py` 虽调用 `trace=True, obligation_ledger=True`，最终只把均值和配对差摘要写入 JSON；`runs`、`_trace` 和逐义务台账没有写入该文件。仓库所见证据目录也没有这一对照的新增逐种子文件。因此 §47“逐义务台账已按种子落盘”目前不成立。若运行进程之外没有另存，只需原条件重放并保存，先核对已有全部聚合列，不能借此扩大实验。

**“降档 10 次”还不是严格的转换计数。** `_config_changes()` 记录任一配置字段的变化，随后用新采样间隔 `>=3600` 筛选。它没有要求新采样间隔大于旧值，因此“已经稀疏、只改变上报周期”的事件也会被计入。下一次保存时间线时，以采样间隔的严格增大识别降档，分开报告节点数、转换次数、首次生效时刻；不预判更正后的数字。证据年龄目前也仅来自生成了意图的 `plan` 事件，是这组事件上的年龄统计，不能等同于全时域所有节点的观测新鲜度。

这些问题不直接撤销服务与缺采均值的正差，但使“归因完全闭合、降档恰为 10 次”的措辞过强。

## 3. 对方法方向有用的新信息

**架构修复的参照仍是一条有损害的策略。** O2 下，网关 `ea_nb` 服务 **43.5**、缺采 **0.1**、总能耗 **0.374041 Wh**；同条件 `local` 为 **49.1 / 0 / 0.101977 Wh**。前者总能耗约为后者 **3.67 倍**。O0 下网关 `ea_nb` 比 `local` 多 **3.3** 条服务，也从 **0.100627** 增到 **0.357479 Wh**。这说明存在代价和适用条件，不能把“修复中心 `ea_nb` 的损害”转换成“击败成熟调度”。本轮也没有重建含 `aoi_*` 的完整同条件前沿。

§45 的包络与 §47 的位置结果回答不同问题：前者证明上报节奏存在资源取舍，后者证明维持局部反馈在某种能源条件下有价值。二者没有共同证明新算法增益。

可继续检验的联系是：**节点上行同时搬运监测数据、提供状态证据、开启后续合法下行机会。** 当回传阻塞时，数据的即时交付价值可能很低，后两种用途仍可能存在。因此，普通背压若把“本次不能向中心交付”等同于“本次上行可全部推迟”，可能推迟后续纠正或恢复。该失效尚未在节奏实验中测到，不能提前命名为已发现的新失效。

另一条边界来自现有实现：`backhaul_forward()` 可以在回传恢复后独立转发网关已有缓存。**已在网关的样本不必等待节点下一次上行**。节奏放慢带来的额外损失只能从尚未抵达网关的数据、后续状态证据和配置纠正等具体对象中追踪；不能把全部恢复积压都算到 Class A 窗口等待上。

这仍属于 §43 已保留的双跳节奏问题。早期“无后续控制保证时，硬安全准入退化为 local”的结论不撤销；本轮没有增加无条件通信保证、节点自动回退或新的硬安全能力。

## 4. 下一轮范围：先用普通规则检验节奏冲突

**主诊断来源用已有 N3：`instance_ccorral_iid_c0.05`，常态义务 900 s。** 选择理由在结果出现前写清：§45 中 N1 已有固定配置用很低服务损失省掉大量上行；N3 的紧服务约束下，已测配置取舍更明显。N3 的 `aoi_const300` 为 **511.05 / 1241.55 上行**，`aoi_f900` 为 **496.2 / 676**；其差是 **14.85 条 / 672 = 2.21 个百分点**。这适合判别动态节奏能否接近前者的服务、减少后者以上的资源负担，不构成保证。

第一小轮固定 N3 的原始采样节奏、事件逻辑、缓存和打包纪律、能源参数以及网关执行位置，只变 `report_period` 策略。所有对照共享相同初始化和配置写入机制。避免 `ea_nb` 与节奏控制器同时写 `report_period`；第一次不把能源采样优化混进来。若后续确需能源反馈采样，先定义所有臂共享的采样控制器及唯一的上报字段写入者，再单独报告这一组合。

仅用三档：**无强制中断、回传 [4 h,7 h)、接入 [4 h,7 h)**。保留 12 h 原任务和原尾窗，使恢复后仍有真实的既定义务；窗形复用旧位置对照。与 N3 的组合属于新声明的实验条件，不能称旧结果重放。所有配置字段完整导出、所有臂同种子配对；原始任务与分母不变，不造低时延 SLA。

当前 O2 的 [3 h,12 h) 直到任务末才结束，只有原有 1 h 尾窗，适合检验长时间失联中的采集保护；不宜单独承担新策略的恢复期业务结论。O2 保留为已知架构边界，第一轮不要求再加一套能源控制方法。

必要对照：

- **固定上报周期全集**：沿用 `GRID_REPORT` 的合法取值，含保持原配置；初始化成本一致。
- **既有 AoI 规则族中的代表**：按开发区间和已登记前沿选择并冻结，不仅比较原始 `aoi`。部署变化后的数值不能直接从旧中心结果拼接。
- **普通背压**：依据网关本次实际转发成功/失败及缓存状态，受阻放慢、恢复加快；再给一条普通迟滞/切换成本版本。全部共享合法证据和配置集合。

先把这几类规则跑通并导出每次慢化—恢复的轨迹。若它们已覆盖有意义的服务—成本取舍，本轮就有答案，无需实现复杂候选。若存在“省资源时错过后续有效机会”的稳定差额，再检验最小改动：在普通背压拟议的慢周期上，依据尚未抵达网关的有效数据、合法反馈历史和下一次配置生效机会，限制慢化程度。**必须与普通固定最大周期/心跳及迟滞规则比较**；若只是选中了更好的周期上限，应归给调参或普通规则。

网关转发反馈需要明确接口和时间戳，并同等给所有臂；当前 `_gateway_view()` 尚未暴露完整的这类输入。不得读环境 `path_available`、未来恢复时刻、节点真实未上报缓存或中心未确认的交付真值。若新增探测或回执才能获得信息，逐项记账，不能用免费查询制造候选优势。单次转发失败只支持此次结果，不提供未来恢复时间或整批数据已获中心确认的知识。

模型候选若用概率或短时域预测，先声明和对照一致的模型；不得重用 §44 已指出的“逐上报独立回传”的近似而称精确 MPC。最小候选暂不承诺硬安全或无损交付。

## 5. 晋级条件与交付

服务容差沿用 **{0,1,3,5}% × 固定分母**，主报告预先选 **0% 和 1%**，其余用于显示取舍。参照服务值来自预先冻结的基线集合；不能由新候选改变分母或回头选择容差。当前包络只按服务筛可行臂，不能当成缺采或采集完整性的可行性保证。新对照另设缺采约束：不得以新增缺采换成本收益；AoI、上/下行、空口和总能耗分列。

首轮仍用开发区间、相同种子，结论只叫机制诊断。正差只有同时满足以下条件才进入独立验证：在同一服务容差下优于最省的合格普通基线；未增加不可恢复缺采；恢复期新义务与缓存交付的损失已分账；信令和信息获取代价计入；其差额超出逐种子不确定性与参数选择造成的小波动。后续使用原契约的未参与开发种子，不能把开发区间反复选出的最佳点写成泛化。

“仅比中心 `ea_nb` 好”“只比高速上报省”“删除全零种子后才好”“放宽容差后某点胜出”“载体支持下发”均不足以晋级。普通背压、固定周期上限或同信息资源受限调度若复现收益，将其保留为强基线，停止该候选的独有方法主张。

下一次希望交付三件具体产物：

1. **位置结果的可追溯补件**：原条件逐种子摘要、前缀状态/意图与真实生效日志、逐义务台账；原聚合列对齐；严格降档计数；直接差与 O0 交互差的配对区间。保存缺口需要重放时，只重放原条件。
2. **节奏对照规格与普通基线结果**：上述三档、完整配置、输入可见性与获取成本、固定/背压/迟滞参照、0/1/3/5% 包络。保存全种子，不先补剩余 37 档。若没有剩余差额，报告这个结论。
3. **一个可定位的差额或关闭记录**：每段节省了哪些上行、当时哪些数据已在网关、哪些仍在节点、恢复后的首次新数据/首次有效降档延迟、代价是否超过节省。只在这条链成立后，实现并消融那一个最小机制；否则不接 LLM、不补条件计划功能、不扩场景。

若前三档出现稳定且普通规则无法复现的差额，再从 §41 已审计的来源档选一个作外部条件检验，优先复用已有审计；只有选中的条件确实来自剩余 37 档，才补它自身的跨种子审计。不存在“必须先扫完才能研究方法”的依赖。

对 agent 的当前含义限于接口和部署要求：任何会下发持续配置的 planner 都依赖后续可观测、可执行的纠正路径。新结果没有实测否定 TopoLLM 等论文的原生方法，也没有证明 LLM 特有失效。只有通信机制对强基线有增量后，才用已有适配工作流检验该机制能否承接 agent 的输出。
