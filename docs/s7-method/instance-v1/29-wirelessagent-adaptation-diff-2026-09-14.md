## 一、原方法的组件与本站映射

原方法（arXiv:2505.01074 扩展版）是四个模块的 LLM agent 框架，实现于 **LangGraph**：
**perception**（文本／多模态理解）、**memory**、**planning**（reasoning / retrieval / reflection）、
**action**（文本生成、**tool manipulation**），配外部知识库与工具。
其案例研究是**网络切片管理**：意图理解 → 切片资源分配 → 维持性能。

| 原组件 | 本站映射 | 保留 / 替换 / 不可迁移 |
|---|---|---|
| **perception**（理解用户意图） | 读取**中心真视图**的结构化状态（逐节点 telemetry 及其 age、当前已确认配置、在途命令、最近工具结果） | **保留**（换成 JSON 结构化输入；**不给仿真真值、不预告中断**） |
| **memory** | 工作流状态 + 已确认状态 + 未决效果 + 历史工具结果 | **保留**（但**不塞完整对话历史**，见 §三） |
| **planning**（reasoning / retrieval / reflection） | 调共享计算工具的规划步骤 | **保留**（计算工具见 §四） |
| **action**（tool manipulation） | `set_sampling_interval` / `set_report_period` | **替换**为本站**已有字段**的动作面；**不新增动作** |
| external knowledge base | 任务契约、来源台账、实例 manifest | **保留**（作为只读上下文） |
| **网络切片 / 带宽分配案例** | — | **不可迁移**：本站没有切片与带宽分配能力 |
| Rayleigh/Rician outage 概率等物理层数学 | — | **不可迁移且不得引用**：那是**物理层中断概率**，**不是连接中断**（审计原文明确警告） |

## 二、现场动作为什么合法

- 动作面**只有两个字段**：`sampling interval` 与 `report period`，两者都是**来源支持**的设备能力
  （E：重庆官方接口 `0045` / `0042`），**不新造能力**。
- 两个字段的**时标作用不同**（已在 `21-...`/`23-...` 建立）：
  `report_period` 决定上行次数 → 被听到的上行 → Class A 接收窗口 → **未来控制机会**；
  `sampling_interval` 决定**采集负载**（能量杠杆高 10.4×），**对控制机会零影响**。
- **本地自治保持不动**：事件触发采样、本地缓存、自动补发**不由中心控制**，
  所以本适配**不是**在测"中心能否接管采集"，而是测**中心在这两个字段上的取舍**。

## 三、输入历史、目标、反馈、停止条件、计算预算的对齐

| 维度 | 原方法 | **本站适配版本** | 为什么这样定 |
|---|---|---|---|
| **输入历史** | 工作流状态 + 对话历史 + 工具返回 | **压缩结构化状态**（逐节点事实）+ `last_tool_outcome`；**不回放完整对话** | 回放历史会把"planner 是否自激"变成"上下文有多长"；且原始实验已证明它会制造 intent 膨胀 |
| **目标** | 切片资源最优（隐含 utility） | **必须显式写出**：同一业务义务、节点资源、**明确通信预算**下比较**周期有效交付**，并分别报告 AoI / 采集缺失 / 能耗。预算取现有前沿若干工作点，**标为 A 层研究条件、不冒充合作方 SLA** | §28 第 50 行；**A′ 的反面教训**：由 AoI 规则产生 `desired_target` 把调度选择交给了规则，只适合隔离执行行为 |
| **反馈** | 工具返回 + QoS 评价 + reflection | **真实执行反馈**：是否被 `center_send` 接受、是否进入网关队列、是否落地、是否被应用；**不给未来真值** | 这是"信息与执行分别诊断"的原料 |
| **停止条件** | 任务完成或迭代上限 | 业务义务满足 / 预算耗尽 / 时间边界；**并明确 `noop` 是合法答案** | 本地自治足够时**中心不动作是正确结果**，不得把"动手"设成目标 |
| **计算预算** | `Programmer` 3 retries + 30 s timeout（**作用于代码执行**）；ReAct `ToolAgent` 有 max iteration `I` 与连续失败计数 `n_fail` | **对等预算**：成熟规则 workflow 与适配 agent **共享**同一工具集与同一调用预算；LLM 调用数单独记账 | 原论文**没有**网络调用的 timeout/retry 语义（审计原文），所以本站的预算必须**自己定义并公开**，不能假装沿用原设定 |
| **不得做的对齐** | — | **不把原方法的 mutation dedup 当作运行时去重**；**不把 `Programmer` 的 3 retries 当作网络重试** | 审计已指出两者都不是语义契约 |

## 四、哪些只是**本地计算**（不增加无线能力）

适配版本允许 agent 调用**共享计算工具**，但每个工具都必须满足两条：
**① 不增加任何无线能力；② 不读取未来真值。**

| 工具 | 允许 | 边界 |
|---|---|---|
| `aoi_rule` / `energy_rule` 等**现有策略本身** | ✅ 可作为**工具**被调用，也可作为**比较对象** | **不要求 LLM 心算本已有算法能解决的数值问题**（§28 第 52 行） |
| 逐节点负载与自主时间的**查表/计算** | ✅ | 只用已声明常量与已收到的 telemetry |
| 链路突发的**历史统计** | ✅ | 只用**已观测**历史，不用未来突发 |
| 任何 oracle / 未来轨迹 | ❌ **禁止作为输入** | 未来真值**只供独立评分**，**不得反馈给 planner**（§28 第 62 行） |
| 直接改节点状态的 host 动作 | ❌ **禁止** | 与既有限制一致（不新增旁路） |

## 五、不可迁移清单（必须在结果里出现）

1. **切片 / 带宽分配**：本站没有这些变量与能力。
2. **物理层 outage 概率**：与"连接中断"无关，**引用即错**。
3. **`Programmer` 的代码执行预算**：不能当作网络工具预算。
4. **多模态 perception**：本站输入是结构化遥测，**不引入图像/文本理解**。
5. **MCTS 工作流搜索（`++`）**：本轮**不做**；若做，它属于"自动设计 workflow"，
   与"在固定 workflow 下比较规划能力"是两件事，**不得混为一谈**。

## 六、与 ICLDC / TopoLLM 的分工

- **WirelessAgent（适配版）**：**被测对象**——工作流方法在固定监测站任务里的表现。
- **ICLDC**：**调度形式与 verifier 的对照依据**。其 verifier 会**覆盖**不合适的选择、
  历史反馈进入后续决策；**删掉这些组件再比较会削弱原方法**，所以对照必须**保留 ICLDC 自己的
  反馈与校验结构**，否则不能称其为 ICLDC 的对照。
- **TopoLLM**：**规划工具层的 related work**。本站是固定站点，**没有其原生位置/拓扑决策变量**，
  且"计算工具成功 ≠ 远程设备执行成功"，**不能用本站否定其规划结果**。

## 七、这一轮明确**不**做的事

- 不预装"本文机制"（不做 belief / backpressure / 准入 / 去重 / 等待的任何新实现）。
- 不把"补上某个变量就有贡献"当既定（名称不能承担贡献）。
- 不把仓库阈值策略的失效扩大成"传统调度方法默认完全观测、动作可靠"
  （已有限定：POMDP 语义采样与传输已联合处理部分可观测源、采能、采样与发送代价、不可靠信道）。
- 不把"没有预知未来中断"记成 agent 推理错误。
