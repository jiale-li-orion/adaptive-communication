# 判别 A 预注册：同一确定性策略置于中心 vs 网关

日期：2026-09-14。**本文件在任何对照运行之前写定**，此后不得按结果回头修改判定规则。

依据：[`31-communication-method-candidates-2026-09-14.md`](31-communication-method-candidates-2026-09-14.md)
§三（尤其第 45、47、53、55、108、109 行）。本文档**不修改** §31 原文，只把它要求的第一项判别
固定成可执行的规则。

## 1. 要判别的问题

同一条监测策略，若每次条件判断都依赖中心收齐遥测、再下发一个配置值，其有效性会怎样受回传突发限制？
把**同一套确定性规则**改放到网关——用它自己听到的遥测求值、命令不经回传——会不会改变业务读数？

**这与"发现 LLM 犯错"无关**（§31 第 47 行：「此处收益来源是可用证据与执行位置；不需要 LLM 犯错」）。
本判别的收益来源被预先限定为：**可用证据的时点**与**执行位置**。

## 2. 唯一允许改变的变量（§31 第 108 行）

- 策略**对象与参数完全相同**：同一个 `CenterPolicy` 子类、同一构造参数、同一份规则。
- 监测义务、初值、空口机会、节点队列、接收窗口、能耗模型、**未来外生过程**全部相同。
- 只允许改变两件事：
  1. 规则**在哪求值**：读中心收到的遥测 vs 读**网关自己听到**的遥测；
  2. 命令**从哪产生**：经回传进网关队列 vs 网关本地直接进队列。

**网关侧信息的唯一来源**：`Instance.gateway_reports` / `gateway_report_at` /
`gateway_newest_taken_at`，在 `_note_gateway_heard()` 里由**实际被听到的上行**填充。
不读环境真值、不读节点缓存、不读中心收到的东西。

### 声明的能力变化（A 层研究条件）

新增「**网关具备可编程的条件执行软件**」这一能力。节点仍只接受原来两个设置字段；
不新增无线覆盖、不强制接收、不做设备自动回退。网关没电、节点接入断开时该方案同样受限。
**该能力由所有参与对照的臂共享**——本判别里两个位置跑的是同一个策略，因此天然共享。

### 已知建模简化（如实声明，不得隐去）

`in_flight` 在 `center` 视图里本来就按「网关队列非空」定义，也就是**中心已被赋予对网关队列的
可见性**——这是本仓库既有的建模选择，不是本次改动引入的。本次对网关用**同一个表达式**，
因此它**不会给网关侧带来相对优势**；但"中心并不知道队列"这一更严格的读法**未被测到**，
论文里必须写明。

## 3. 四档条件（照 §31 第 53 行）

| 档 | 含义 | 参数 |
|---|---|---|
| **C0** | 无中断 | 无 |
| **C1** | 回传中断：中心既听不到遥测、也发不出命令 | 回传窗 [4 h, 7 h) |
| **C2** | 接入中断：**负对照** | 接入窗 [4 h, 7 h) |
| **C3** | 同时中断 | 回传与接入同在 [4 h, 7 h) |

四档共用同一批种子，因此同一种子下的外生过程逐位相同。

## 4. 记录量（照 §31 第 53 行，五项）

**服务、缺采、能源、配置生效时刻、通信量。** 口径取仓库已登记的量：
`routine.delivered`（服务）/ `routine.missing_collection`（缺采）/ `energy.per_node` 汇总（能源）/
trace 里节点逐时段的 `sample_interval_s, report_period_s` 变化点（配置生效时刻）/
`communication` + `command_counters`（通信量，按来源分列）。

## 5. 预注册判读规则（先写死）

- **R1（负对照，证伪整个仪器）**：C2 接入中断下，网关位置的**周期交付不得优于**中心位置。
  网关这时**同样听不到新证据**，且两边的命令都要排同一个节点队列。若它仍占优
  ⇒ **是仪器错**（网关拿到了不该有的信息或权力）：先修仪器，**不得据此报收益**。
- **R2（主判读）**：C1 回传中断下，网关位置的**配置生效时刻**应显著早于中心位置，
  且**缺采不得劣化**。若 C1 下服务／缺采／生效时刻三者的差都在噪声内
  ⇒ 按 §31 第 53 行末句「此候选在当前实例就没有继续开发理由」，**如实关闭候选 1**。
- **R3（成本必须同报）**：任何收益都要与**通信量代价**并列报出。网关位置省下的只有
  **回传下行**，不省节点上行与接收窗口。若"收益"只是少发了命令，那是通信量节省，
  **不是业务改善**，必须分列，不得合并成一个"更好"。
- **R4（诚实边界）**：本判别**不**回答「条件计划是否优于预装完整传统策略」——那是 §31
  第 55 行的第二项，须在本项**出现收益之后**才做。**本轮不启动第二项。**
- **R5（纪律）**：`run_checks.py` 保持 **18/18**；`placement="center"` 必须与改动前**逐位相同**。

## 6. 明确不做的事

不新增无线覆盖；不强制接收；不做设备自动回退；不把未来真值喂给任何 planner
（真值只供独立评分）；不把本判别结果扩大成「全部通信方法已排除」。
