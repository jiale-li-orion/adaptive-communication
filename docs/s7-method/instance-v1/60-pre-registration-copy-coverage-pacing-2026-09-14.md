# P2 预注册：副本覆盖率导向的上报节奏（含最可能竞争的普通规则）

日期：2026-09-14。**本文件在任何对照运行之前写定**，此后不得按结果修改臂集合与判定规则。

依据 `docs/s7-method/instance-v1/58-next-stage-plan-2026-09-14.md` §P2，
以及 P1 的解剖结论（[`doc 59`](59-p1-arrival-attribution-2026-09-14.md)）。

## 0. P1 给出的两条前提（决定了本轮臂集合）

1. 候选 `pacing_backlog900_300` **已经让更多义务准时到网关**（Δ +6.4～+7.3，18/2 同向）
   ⇒ 以「**网关侧准时性**」为目标的形式**已饱和**。
2. 它的损失**全部**出在**网关→中心那一跳的副本覆盖率**（Δ 卡在该跳 +9.3～+10.3，**20/0 同向**）
   ⇒ 每条义务要靠**多份**缓冲副本去撞 62%/h 的回传窗口。

⇒ 因此 doc 58 §P2 表里列的「**逐节点截止期阈值**」**不是**正确的那条普通对照
（候选已在网关侧准时性上赢过它）。**必须先上场的最可能竞争者是「逐义务副本数阈值」。**

## 1. 固定的东西

N3 基底（`instance_ccorral_iid_c0.05`：**900 s 义务**、无事件、`hetero`、cap 0.05）的
采样节奏、事件逻辑、缓存与打包纪律、能源参数，以及**网关执行位置**。
**只变 `report_period` 策略**；任务 12 h + 1 h 尾窗、分母 **672** 沿用。
三档 **P0 无中断 / P1 回传 [4h,7h) / P2 接入 [4h,7h)**，四个中断字段逐档写全 + 断言。
所有臂 `dwell_s = 600`、`fast_s = 300`、`slow_s = 900`（**唯一例外见 §2 的参照臂**）。

## 2. 臂集合（**冻结**，9 条）

| 组 | 臂 | 定义 |
|---|---|---|
| 参照 | `fixed300` | 固定 300 s（上两轮的参照臂，doc 58 §P2 明列） |
| 上一轮赢家 | `pacing_backlog900_300` | 整体积压信号 + 义务节奏封顶（doc 54） |
| **普通竞争族（本轮新增，最关键）** | `oblig_copies{k}`，k ∈ {1,2,3} | **逐义务副本数阈值**：该节点**当前义务窗口**内已被网关听到的合格样本数 `< k` ⇒ 快报(300)，否则慢报(900) |
| 候选（doc 58 §2） | `oblig_slack` | 逐节点「当前窗口是否已满足 + 到该窗口截止的剩余余量 + 命令生效延迟」三者共同决定快慢 |
| 消融 1 | `oblig_slack_no_slack` | 候选**去掉剩余余量**（只看是否已满足） |
| 消融 2 | `oblig_slack_no_delay` | 候选**去掉生效延迟**考虑 |
| 消融 3 | `oblig_slack_no_obligation` | 候选**去掉义务区分**（退化成：窗口内听到过任何合格样本就慢报） |

**全部 9 条臂共享**：同一窗口配置、同一合法观测集合、同一 `report_period` 值域
{300,900}（本轮只用这两档）、同一链路估计信息、同一动作集合与预算、同一 `dwell_s`。
**候选不得比对照多出私有网关数据结构**——`oblig_copies` 与 `oblig_slack` 读的是**同一个**新接口。

## 3. 新增的合法接口（对全部臂同等开放）

`CenterView` 增 **`gateway_copies_in_window`**：`{节点: 当前义务窗口内已被网关听到的合格样本数}`。
它是**网关本地可观测**的（网关自己收到过哪些样本），不含环境真值、不含未来信息。

**不读**：环境 `path_available`、未来恢复时刻、节点真实未上报缓存、中心未确认的交付真值、
评分器的义务匹配结果。义务的**周期与相位**是**公开服务配置**，同等给所有臂。

## 4. 记录量

服务、**缺采**、缺送、AoI、上行、下行尝试、上行空口、总能耗、死节点——
**分列**；另用 P1 的到达台账（`on_time_heard` / `late_heard` / `never_heard` /
`stuck_at_gateway_hop` / `delivered`）定位每条臂的损失在**哪一跳**。

## 5. 预注册判读规则（先写死）

- **R1（普通规则是否已覆盖——决定性问题）**：若**存在 `k`** 使 `oblig_copies{k}` 在
  **同一服务容差（主报告 0%、1%）**下，**成本不高于** `pacing_backlog900_300`、
  **服务不低于**它、**且缺采不劣** ⇒ **普通规则已覆盖被定位的那一跳** ⇒
  **本轮不实现更复杂机制**，把它保留为**强基线**。
- **R2（候选是否有余量）**：只有当 `oblig_slack` **在同一容差下严格优于**
  「`fixed300` ∪ `pacing_backlog900_300` ∪ `oblig_copies{1,2,3}` 的**全部成员**」，
  且**缺采不劣**、差额**超出同种子配对自助区间**时，才认定候选有余量。
- **R3（消融必须解释收益）**：若 `oblig_slack` 有余量，则三条消融**必须**显示该余量来自
  被去掉的那一项；若消融与候选无差别 ⇒ 收益不来自义务区分/余量/生效延迟，
  按 doc 58 §P2「优先复用」的纪律**不得**把它写成候选机制。
- **R4（不足以晋级）**照 doc 48 §5：「仅比中心 `ea_nb` 好」「只比高速上报省」
  「删除全零种子后才好」「放宽容差后某点胜出」「载体支持下发」。
- **R5（纪律）**：预注册先于运行；`run_checks.py` 18/18（先看 `EXIT=$?`）；
  结果登记只在表尾追加；**单种子不得下结论**（多种子均值 + 配对自助区间）；
  `heard=True` **不承担准时归因**（用 `heard_on_time` 与 `stuck_at_gateway_hop`）。

## 6. 本预注册自己承认的局限

- 臂集合只覆盖「逐义务副本数阈值 × 3 档」与「候选 + 3 消融」，**不是**副本导向规则的全集
  （没有覆盖按**剩余时域**连续选档、按**预测**选档、或**中心侧**执行的同名规则）。
- 只用 `report_period ∈ {300, 900}` 两档；其余合法档位（600/1800/3600）**本轮不进候选**。
- 结论措辞一律限定为「**本轮臂集合内**」。
