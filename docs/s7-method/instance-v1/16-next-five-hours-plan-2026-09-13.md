# 持续配置候选：下一轮五小时工作计划

基线提交：`952171c`。本文件是工作建议，不修改 Task v1.1，不宣布方法成立。

## 决策

有条件进入判别3。先闭合直接机制与复现配置，再测试现有能力下的下发前资源准入。**不把“证据过期后中心发送降档”作为 out3 的有效修复承诺**：out3 是3–12h接入中断，期间没有可用接收机会；节点可能在恢复前就失去供电。

“中心能写就必须随时能收回”不是本场景可实现的要求。研究问题应为：在声明的无进一步有效控制时域内，如何限制已下发配置的持续资源风险，同时保留有用的介入。

## 0–1小时：闭合机制与复现问题（后续方法的前置闸门）

1. 记录 planner 每次跳过节点的直接原因，至少包含 in_flight、dwell、无电量、已达目标；同时记录源遥测时间、接收时间、可见电量、已知配置与本地待处理状态。诊断可以记录真值，但不得反馈给策略。
2. 核对 out3 未生成降档的真正原因。其 config 为 soc_max_age_s=None、soc_loss_p=0；缓存的已知电量不会仅因时间流逝自动变成None。EnergyAwarePolicy 在读soc之前先检查in_flight，现有plan日志不能区分这些分支。
3. 核对过期时间单位与清理路径。Instance构造消息时 expires_at=t_s+6*3600；ControlPlane.prune接收hour并直接比较，且当前实例中未见每tick的独立清理调用。修复应明确秒/小时边界并保护旧monitoring调用约定，只重跑受影响的既有小矩阵。
4. 时间线严格按已登记arm与exec_layer重建，不能固定contract=True重放naive结果；沿用统一配置恢复入口，保留None的语义。比较开关trace时所有嵌套业务/能量/通信/执行结果（排除_trace），不只比较顶层标量或三列计数；不一致时非零退出。burst参数等映射缺失也应拒绝或补齐，不默默回默认。
5. 将“安全性取决于谁写的”改为配置负载、可能生效状态和剩余资源；写入来源只是这批运行的代理变量。“deficit_h”是跨节点累计不可供电时间的种子均值，单位为节点小时，不是能量亏空Wh，也不是单节点持续时长。

退出物：一条精确到秒、与登记配置一致的seed 7/n02时间线；说明修复后哪些读数/解释保留。若时间超出1小时，继续闭合此闸门并削减后续范围，不并行堆方法。

## 1–2小时：最小方法规格与竞争解释

主提案策略先只用ea_nb。保留当前动作、观测权限和现场自治，不新增端侧租约、健康旁路、自动降档或可直接修改节点状态的host动作。

候选：发送增加持续负载的配置之前，基于合法电量证据、可能的在途/生效配置、公开模型及声明误差界，检查保护时域内的资源可行性。逐时计算电池容量、采能溢出、采样、上报及已有事件自治开销；已发送降档尚未确认不能被当成已经降低负载。

第一版保护时域使用已声明的有限任务/运行边界，不使用真实中断结束时刻，不用平均坏突发冒充硬上界。采能下界、能耗上界、事件负载界及电量误差界必须列明，无法建立时不声称安全保证。

写清准入拒绝/延后与原任务未完成的语义，不能静默换目标后称原动作成功。也不能为保持收益而读取未来事件或未来采能。

最近对照阅读只读与本轮有关的模型/假设：Wabersich与Zeilinger的预测安全过滤器（arXiv:1812.05506）、Stricker等的采能节点自触发控制（ACM TCPS 2023, DOI10.1145/3597311）。第三篇建筑runtime论文暂作近邻边界，不以未核全文内容作为本轮实现依据。

规格中回答：候选比“调高电量阈值”多处理哪种状态？比相同物理模型的鲁棒安全过滤器多处理哪种通信/执行不确定性？若回答为空，合并两臂，承认目前是标准方法适配。

## 2–3.5小时：最小实现与开发验证

对照最多六类：local、aoi、原ea_nb、ea_nb+阈值/新鲜度过滤、ea_nb+鲁棒可行性过滤、ea_nb+候选。标准过滤器须使用同等信息与相同模型边界；不能故意让它假定纠正即时到达。五小时内若只能实现简化过滤器，按实际名称报告，不称完整复现论文。

先bias=1，既有noout/out0/out3三条件、既有10开发种子。阈值至多预先列三个候选，与方法参数使用同等开发机会；不扩参数扫描。

保护相关检查：无通信时host回退不能直接改端侧状态；pending与部分生效分支核算正确；源时间不被接收时间替代；未知状态不释放已承担的负载；无可证明可行性时不假报成功。复用现有评分，保持外生随机过程寻址规则。

## 3.5–4.5小时：冻结后的最小留出检验

仅在开发结果留下增量且因果闸门通过后进行。冻结参数与实现，使用按现有种子纪律未参与开发的种子，建议10个；只跑上述三条件，不在留出结果上调阈值。预算不足则明确留出未做，不拿开发结果替代。

报告配对差值及区间：缺采、交付、AoI、累计不可供电节点小时、实际采样/无线能耗、下行；原提案数、被准入/拒绝数、拒绝原因。被拒但原本有益须有匹配的反事实回放支持；仅凭原提案数不能计算误拒率，未完成则标未识别。

noout收益基准重算：当前原始文件ea_nb150.9/168=89.82%，local148.1/168=88.15%，aoi154.1/168=91.73%；不要沿用报告91.5%/89.0%。同时比较AoI与成本，不能只要求超过local。

## 4.5–5小时：交付与路线判定

交付：

1. 一份更新后的审查报告：机制纠正、修复前后差异、保留/撤销主张；附完整JSONL时间线和重放命令。
2. 一页方法规格：输入、状态、准入式/伪代码、保证条件、与标准过滤器的差别、代码入口。
3. 同一版本的开发/留出结果表与逐种子JSON，配置、种子、预算、提交标识登记；缺失项明确说明。
4. 精简反例集与现有检查结果；不要为凑“全绿”重写检查判据。
5. 一段go/merge/stop决定：候选是否超过简单阈值和标准过滤器，是否只退回local/aoi，是否需要额外设备能力。

优先目标是out3减少不可补回的采集损失并保留noout服务/成本价值；接近零是与可行基线比较的目标，不承诺未知未来下无条件同时最优。全部拒绝介入、仅改变目标配置、或仅在额外固件能力下成功不能算当前候选的方法增量。

如果标准过滤器已处理全部失败，结论写为“该失效可由现有安全控制适配解决”；如果候选多处理了一类部分生效/纠正不可达情况且留出成立，下一轮再接真实LLM。此次五小时不做LLM、全量实验、第三场景或论文图稿。
