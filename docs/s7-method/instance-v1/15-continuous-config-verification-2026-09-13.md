# 持续配置的资源约束：**核验结果**

日期：2026-09-13。核查 HEAD：`6be36e6` + 本轮改动。
**本文是 `14-method-insight-from-existing-failures` 的核验记录**：它把那份候选审查里的每一条
数字与代码论断逐项对过，补出它明确标注"尚未连接"的那条时间线，并**更正其中两处**。

**结论提要**：候选假设**被证实**，而且比原稿更强——损害**不需要诊断用的偏置**就能复现；
但损害的直接机制**与原稿写的那条路径不同**（不是"纠正发出但没到"，而是"**纠正从未被发起**"）。

## 二、补出的时间线（原稿 §3 说"尚未连接"的那条链）

新增 `code/analysis/trace_seed_timeline.py`：把**一次运行**的逐事件链拉出来——
中心看到什么 → 下了什么 → 何时真的生效 → 节点在跑什么配置、还剩多少电、是否还活着。
时间线**默认关闭**（`Instance(trace=...)`），关闭时一个字节都不记；**开与不开的聚合量逐列相同**
（已写成测试 [28]，并在每次诊断里自检）。

**seed 7、`ea_nb`、节点 `n02`（其余被波及节点行为同构）**：

| 条件 | 中心为它生成的意图 | 节点侧生效的写入 | 死亡 | 缺采 |
|---|---|---|---:|---:|
| 读数准确、无中断 | 12 条（h1/3/4 加密，**h5/6/7 三次降档**） | 加密 h2/h3、**降档 h6 生效** | 未死（末 SoC 0.0035） | **0** |
| **读数准确、介入 0–3 h 后失联** | **只有 2 条（全在 h1）** | **只有 `interval=600` 在 h2 生效** | **h8**（末 SoC 0.0002） | **11** |
| 读数准确、**全程**失联 | 2 条（h12，失联结束后才发） | 无 | 未死（末 SoC 0.0139） | **0** |
| 读数 3 倍偏置、无中断 | 8 条（**h8 才降档一次**） | 加密生效、**降档未生效** | h8 | 11 |

三条读法：

1. **读数准确 + 中途失联，就足以造成同样的 11 条缺采**（第二行）。
   这一档里**没有偏置**——所以原稿"3 倍偏置只是诊断参数"这条保留意见，**对这条路径不适用**。
2. **"降档从未被发起"，不是"发起了但没到"**。失联之后中心再没有为这台节点生成过任何意图：
   计划事件全部集中在 h1。这与原稿 §3 表格第三行（"已发送加密或降档，但尚不能确认"）**不同**。
3. **"从不介入"确实是安全的**（第三行）：全程没有读数 → 策略一条都不发 → 节点保持出厂默认
   → **SoC 几乎不动（0.0195→0.0139）、缺采 0、亏空 0**。这证实了原稿对 §五"缺失会退回 `local`"
   的更正，并给出量化形态。

## 三、把机制写成一条**条件句**

原稿说"停止介入不等于恢复默认"。核验之后可以写得更准：

> `ea_nb` 的「无证据不下发」规则在节点处于**出厂默认**时是安全的，
> 但在中心**已经改过配置**之后，同一条规则使节点**无限期地跑在中心写的配置上**。

两种"未知"因此必须分开：

| 端侧此刻在跑什么 | 中心未知时的后果 |
|---|---|
| 出厂默认 | **安全**——不介入等于维持默认 |
| **中心曾经改过的配置** | **危险**——不介入等于把那个配置续期 |

这条条件句就是可检验的判据：**同一个规则，安全性取决于"配置是谁写的"**。

## 四、2×3 判别（原稿 §7 的第 2 步）

`--soc-bias ∈ {1,3} × 中断 ∈ {无, 全程(0–12h), 介入后失联(0–3h 后)}`，10 种子，
其余参数与 `instance_soc2_bias1.0.json` **逐项相同**（同一条外生链路时刻，不挑选有害中断）：

| 条件 | 臂 | 交付 | **缺采** | 下行 | **亏空 h** |
|---|---|---:|---:|---:|---:|
| 无中断 | `ea_nb` / `ea_aoi` | 150.9 / 151.6 | 0.6 / 0.8 | 48.0 / 62.3 | 1.11 / 1.33 |
| 无中断 | `aoi` / `local` | 154.1 / 148.1 | **0.0** | 73.9 / 0.0 | 0.00 |
| **全程失联** | 四条臂 | 24.9 | **0.0** | 0–9.6 | **0.00** |
| **介入后失联** | `ea_nb` / `ea_aoi` | 51.0 | **10.5** | 21.0 / 31.4 | **14.22** |
| **介入后失联** | `aoi` / `local` | 59.8 / 56.3 | **0.0** | 39.2 / 0.0 | **0.00** |

三条结论：

1. **"从不介入"是安全的**：全程失联下所有臂缺采 0、亏空 0——服务差异全部来自链路（都 24.9）。
2. **"介入后失联"确实放大损害**：同一中断窗、同一批外生时刻下，`ea_nb`/`ea_aoi` 缺采 10.5、
   亏空 14.22 h，而**同一条链路下的 `aoi`/`local` 缺采 0、亏空 0**。**差异只能来自那次生效的配置。**
3. **这一档与偏置无关**：`bias1.0` 与 `bias3.0` 的 `out3` 结果**逐位相同**
   （51.0 / 10.5 / 106.5 / 21.0 / 34.2 全部一致）——因为 h0–3 的读数无论放大几倍都高于
   `healthy_wh = 0.010`，中心做的是同一个决定；h3 之后没有读数，偏置无从起作用。

## 五、必须一起保留的三条反证与硬限制

1. **`aoi` 在同一条件下缺采 0**（`05-final-analysis` 已记录、本轮复现）。
   **候选机制如果不能胜过 `aoi`，就没有证明价值**——禁止加密采样本身不算贡献。
2. **偏置路径与失联路径是两条不同的路，不要合成一条**。无中断 + bias3 也给出 11 条缺采，
   但机制是"**决策延迟**"（中心 h8 才降档，而节点 h7 就已经耗尽），不是"配置失去控制"。
3. **当前设备没有经确认的"配置租约到期自动降档"能力**。host 侧写一个定时器不能声称失联节点
   会自动回退；保护时域只能来自任务边界或显式声明的风险假设，**不得偷读真实下次连通时刻**。

## 六、下一步（原稿 §7 的第 3 步）与停止条件

原稿第 3 步要的是"同一提案策略比较：原执行层 / 可调阈值或新鲜度过滤 / 标准鲁棒预测过滤器 / 候选"。
在动手之前，**本轮结果已经把判据钉死成三条**：

- 必须**在 `out3` 这一档把缺采 10.5 拉回接近 0**（不是拉回 `noout` 的 0.6，而是要恢复
  `aoi`/`local` 已有的 0）；
- 必须**同时保住 `noout` 下加密带来的收益**（`ea_nb` 91.5% 对 `local` 89.0% 那部分）；
- 必须**报告被拒但原本有益的介入**——不能把"少发命令"当成"少花资源"（本轮已证：
  损害增大的同时下行反而从 48.0 降到 45.3）。

**停止/降级条件**（沿用原稿）：损害只由额外放大的错误信息造成；调高一个阈值就全面等效；
收益全由改变目标配置取得；标准鲁棒过滤器已覆盖；持续配置核算不能胜过 `local`/`aoi` 前沿；
任何安全性质依赖未声明的自动回退、未来信息或无来源的恢复时间上界。

**尚未做的**：第 3 步本身（三种保护的对照）。**本轮不认领方法收益，也不认领新颖性。**
