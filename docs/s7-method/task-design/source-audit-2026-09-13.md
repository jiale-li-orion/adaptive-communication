# Task 设计原始证据复核（2026-09-13）

用途：为 [Task Contract v1.1](../task-contract-v1.1.md) 提供可定位的一手证据与移植边界。复核起点为 `e8d2eca`；已读 v1、A–D 提取件、s1/s2、旧契约及用户粘贴的建议。提取件属于导航材料，其作者判断不自动升级成外部事实。

本轮只更新文档和事实摘录；未实现新任务、运行仿真或复跑 `17/17`。文献地位与证据性质分开：作者报告自己的系统实验属于一手研究；同行评议、会议摘要、政府测试文件、厂商产品说明的验证范围不同。新闻中的转述另列，不统一把“论文”标为二手。

## S0：合作方需求

- 原始载体：[s1 用户 brief](../../s1-input/add.md)。用户转述中通服关注山区供电不足、通信中断、节点失联、数据不能回传，希望低功耗、低成本地维持监测通信；限定灾前。
- 性质：**利益相关方需求陈述**。可以决定研究范围；尚非可引用的站点统计、部署规格或验收 SLA。
- 公开资料中未检索到某个关键词，不能否定这项需求，也不能证明该企业不承担某项业务。v1 §六关于“公开的一切”“监测点位实际属于……”的全称判断不作为契约依据。
- 不从该陈述推出 Class A、中心 agent、统一电量预算、命令频率或 runtime 必需性。

### S1a：可公开核对的事件片段

Table 3 列出了 2020-01-06、EI01 的七组触发，各组三条记录。第一条的触发时刻为：`00:17:32`、`00:49:11`、`01:04:14`、`01:47:27`、`08:16:24`、`08:31:27`、`09:45:20`。原表数值转录见 [CSV](wang-2022-table3-excerpt.csv)。

CSV 保留原列的角色：`source_transmission_time` 是论文的加密传输时间，**没有改名成采样真值或中心接收时间**；空缺触发时刻不擅自填充成第二次触发。`burst_id`、`row_in_burst` 是本次整理字段。

这些是**已发表的触发／传输记录片段**。本轮未取得该站完整原始传感流、未触发区间、逐包接收日志或九个月连续 trace。不能由此推断一天只有七次事件，更不能将重复七次事件称为多个独立降雨过程。表中尚有 1–18 s 等时序偏差，应保留原值，不能默默改成理想时钟。

当前可以做两件不同的事：用该片段校验事件解析；按论文规则构造明确标为研究假设的理想突发。完整的“原始雨量 → 阈值计算 → 触发”重放仍缺累计窗口及原始输入。片段重放不需要猜这个窗口。

**角色限制**：该片段的事件发生在网关本地，雨量事件到中心主要经过 WAN；它不能单独检验终端 Class A 下行竞争。若把雨量计搬到叶节点，应登记为参考部署移植。

## S2：重庆官方接入文件——能力与回复语义

**来源**：[重庆市规划和自然资源局公开设备接入测试材料，62 页 PDF](https://ghzrzyj.cq.gov.cn/zwxx_186/tzgg/202005/P020200527440877815913.pdf)。2020 年链接。本轮读取官方 PDF 的网页解析文本；截图工具缓存失败，直接下载两次 TLS 失败，未完成图像级复核。下列条款在解析文本中连续可读；不据此声称设备互操作实测通过。

定位以 **PDF 第几页（1 起算）**为准；正文印刷页号在这些位置比 PDF 页序大 1。

| 定位 | 可核实的协议事实 | 不允许的推导 |
|---|---|---|
| PDF p.7，§2.3 | 接入测试使用 NB-IoT/MQTT，含 72 h 测试 | 72 h 不是灾前业务周期或能源续航验证时长 |
| PDF p.8，附1 §1–2 | 设置回复沿用平台消息序列号；心跳每小时一次 | 回复相关性不等于持久去重、执行完成或全局 fencing；心跳不等于新测值 |
| PDF p.9，附1 §2 注2 | 回复上报周期设置后须立即上报一条监测数据 | 不能假设设置和新测量必需两次独立下行；也未证明该数据一定在回复之后重新采集 |
| PDF p.10–11，附1 §4.4、§4.6 | `0042` 上报周期、`0045` 采样间隔，单位均为秒，存在设置和上报方向 | 两字段并不自动构成原子 profile 事务；支持配置不证明现场频繁使用 |
| PDF p.9–10，附1 §4.1 | 上报含电量、电压、信号等 | 可读缓存不等于免费的即时远端查询 |
| PDF p.11，附1 §4.7 | `00D0` 模式编码 NB-IoT/GPRS | 不能当作卫星／中继切换命令 |

附录按设备类型分别列能力。上述附1为地表裂缝仪；采用其他类型前需核对对应附录，不能宣称全部设备都具有全部命令。

本轮还确认目录及附录存在固件升级命令。B 提取件中的“未涉及 OTA”只能解释为其限定的二次材料没有提到，不能解释为官方原文没有此能力。**本任务仍不加入 OTA**：接口存在不等于与当前服务连续性问题相关。

## S3：Kumar 等——山区通信扰动存在

**文献**：Sangeeth Kumar 等，*Reliable network connectivity in wireless sensor networks for remote monitoring of landslides*, Wireless Networks 26:2137–2152 (2020)，2019 在线发表，DOI [10.1007/s11276-019-02059-7](https://link.springer.com/article/10.1007/s11276-019-02059-7)。本轮核到出版社摘要，未取得付费全文。

作者报告山区滑坡监测存在链路非对称、恶劣天气下网络变化、太阳能不足，以及切换／重连；系统采用中继和多 WAN。支持扰动类型、分层拓扑及既有恢复机制。不能标定西藏故障分布、Class A 参数、回执丢失率、中心命令频率或可靠性 SLA。

## S4–S5：相邻工程与产品能力

**S4：[平升电子西藏水文项目](https://www.data86.net/xzmdjybdtxdswjcxmalfx.html)**，本轮读取项目页：无市电／手机信号站，北斗通信与光伏电池，定时上电、采集回传后断电。属于厂商报告的相邻水文场景；支持离网供电和计划休眠存在，不证明滑坡站统计、中通服实际配置或通用电池低温阈值。

**S5：[MAS-RTU 产品页](https://www.masios.com/cpzx_1/53.html)**，接口功能第2–6项：自动补发、定期状态上报、阈值触发、远程采集当前测量、参数设置。属于厂商能力声明。支持保留记录／自动恢复及主动采集的可实现性；不支持通用的 `upload_records(range,cursor,budget)` 协议，也不支持中心补传控制在现场的普遍性。

## 仍需外部输入的证据

1. 目标站点一条具体运维工作流：谁观察到什么，谁授权哪些测点变更，完成标准是什么；不要求提供无关商业秘密。
2. 设备型号／协议与固件能力：读回值、配置回复语义、自动补发、存储与重启保持性；是否存在网关自治。
3. 可公开的完整连续事件序列及灾前时间边界；若仅有事件摘要，明确选择偏差与适用范围。
4. 目标硬件及能源／接入／回传过程的标定范围；同站联合记录优于异地数据拼接。

缺少这些信息时，可以冻结有标注的研究任务结构；不能把参考实例称为中通服现网 benchmark，也不能认领中心 agent 的必要性。
