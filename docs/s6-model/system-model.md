# 系统模型

论文 Section II 的初稿。每条参数标注证据层：**M** 实测、**S** 标准模型、**F** 拟合、**A** 假定。A 层参数必须做敏感性扫描，不能当实测值报告。

## A. 部署与几何

研究区域为西藏波密与易贡一带，是已记录的最大规模滑坡发生地之一。地形取真实 SRTM1（1 角秒，约 30 m），瓦片 N30E094 与相邻三片，原始海拔跨度 2025 至 6690 m。**M**

网关单点架设在 (30.330°N, 94.780°E)，海拔 2317 m。该位置处于谷地，四周山脊可高出 3300 m 以上，这一选择是场景的一部分而非疏漏：山区监测的现实形态就是谷地汇聚点加坡面节点。**M**

评估网格为网关周围 121×121 格点，点距约 204 m，覆盖 0.22°×0.22°。网格间距由高程数据与计算预算共同决定，不是物理量。**A**

监测节点布设在坡面，天线高度 2 m。**S**（工程惯例，与 `mountain_lora_link.py` 一致）

## B. 实体集合与能力投影

底层资源是通感算一体化的多实体集合，按灾损断点选取恢复手段：Sensor 接入用 LoRa / NB-IoT，蜂窝弱覆盖用 CPE / UAV Relay / UAV-BS，局部基站退服用便携站 / 应急车 / UAV-BS，光缆回传中断用微波 / HAPS / 卫星，大范围地面网络失效用 HAPS / 卫星 / NTN，电源失效用油机 / 移动电源。每个实体带角色与基础设施类型，并投影成 agent 可调用的 capability。**S**（出处见 README 第二节与其原始文献）

本文不研究该用哪一类实体，集合的选取已有答案。本文研究的是该集合随时间变动时任务如何继续。

## C. 信道模型

信道分两段建模，空间维与时间维来源不同，不能混为一段。

**空间维：地形损耗。** 用 Longley-Rice ITM v1.2.2 点对点模式，沿大圆路径按 DEM 原生分辨率采样，4/3 等效地球半径。参数为 868 MHz、发射 14 dBm、两端天线增益 2 dBi、馈线 1 dB、带宽 125 kHz、地面 ε=15 与 σ=0.005 S/m、大陆温带气候、mdvarx=11，可靠度取 90%。**S**

自由空间损耗在公里与兆赫口径下为 `20log10(d_km) + 20log10(f_MHz) + 32.44`，总损耗为 `FSPL + avar`，其中 `avar` 返回所请求分位的总衰减量。平坦地形回归必须复现两径地面反射模型，见 `results/itm_constant_check.txt`。**S**

**时间维：链路好坏的时间相关结构。** 用 Gilbert-Elliott 两态模型，参数由 ChirpBox 真实 LoRa 轨迹拟合：20,913 个快照、21 个节点、420 条有向链路、878 万次状态转移，得到 `p(good→bad)=0.0243`、`p(bad→good)=0.3026`，平稳丢失率 7.44%。平均下行突发 3.30 h，上行突发 41.09 h；同丢失率下 i.i.d. 模型只预测 1.08 h，相差 3.06 倍。**F**

ChirpBox 采自上海城区，不是山区。用它不是因为场景相符，而是因为它是公开可得、逐链路、逐小时、跨四个半月的唯一长时轨迹。时间相关结构被借用，绝对水平不被借用。**效力威胁**

**两级模型的耦合。** 空间维决定一个点位是否可能连通，时间维决定在可能连通的前提下何时连通。二者相乘给出任一点位在任一小时的可通概率。这个分解是本文的建模选择。**A**

## D. 能量模型

高海拔站点的失效由供电而非无线决定，因此能量必须建模。

储能取 LiFePO4：−20 °C 下可用容量约为标称值的 50%，且低于 +5 °C 无法充电。**S/M**

发电取光伏，气温基线由海拔推导。在 3925 m 处 1 月均温约 −19.5 °C、7 月约 −7.5 °C，日间温度全年低于充电下限，电池无法补充，系统只能消耗初始存量。**S**

由此得到三条与直觉相反的结论。加大光伏板无效：面板从 30 W 增到 200 W，停电率恒为 93.7%，发电被温度闸门掐死而非被能量禀赋限制。积雪掩埋在充电闸门打开之前不构成额外约束：发生概率从 0 扫到 0.20 每天，停电率不动。真正的杠杆是电池化学、加热电池箱，或把站点降到更低海拔。**M（模型输出）**

气候基线敏感性必须声明：整体平移 ±6 °C，停电天数在 342 天附近不变，只有夏季均温升到 0 °C 以上才改善至 217 至 260 天。所用基线可能偏冷约 10 °C。**效力威胁**

## E. 任务与业务模型

任务为灾前滑坡与泥石流监测的持续态势维持。监测对象包括降雨、孔压、水位、地表位移与裂缝开度，不同对象数据量与采样率不同。**S**

上行业务为周期性遥测，标称采样间隔 10 min 至 1 h，单包有效载荷 20 B 量级。**A**（由低功耗监测系统的常见配置取定，须扫描）

下行业务为配置与命令，量小但必须送达：采样率调整、门限下发、休眠调度、告警确认、网关切换、中继启用。**A**

到报率的合同基线可参照国内地灾监测项目的验收条款（广东 ≥70%、昆明 ≥95%、河南 ≥95%），但这些是合同值而非实测值，且公开文献中不存在中国地灾监测网络的实际到报率、在线率、掉线次数与断链时长。本研究给出的一切可靠性数值要么来自模型，要么是估计。**效力威胁**

## F. 实体变动过程

这是本文的研究对象，必须作为一等过程定义，而不是当作故障注入的附属品。

单个实体在时间轴上经历上线、可用、退化、掉线、恢复。对节点而言，掉线有两个独立来源：地形与传播决定的不可通（**持续**，任何自适应都无法挽回），以及能量与温度决定的静默（**季节性**，冬季长静默、夏季恢复）。

两个来源导致的变动在统计上不可区分于观测端，但处置方式完全不同：前者只能改架构（换位置、加中继、走中继回传），后者等待即可。把两者混为一谈是现有工作的常见简化。**本文的建模要点**

变动的时间尺度由三处实测决定：空间维给出 11.5% 的网格随时可通、88.5% 永久不可通；时间维给出 3.30 h 量级的平均中断突发；能量维给出以月计的冬季静默。三个尺度相差三个数量级，任何单一尺度的评测都会漏掉另两个。

## G. 决策问题

agent runtime 位于通信实体之上，在实体上线、掉线、退化、恢复的过程中维持任务执行。它的动作空间是：对某实体下发某个 capability 调用、等待、重试、改走另一实体、放弃并上报。

目标是在给定能量与频谱预算下最大化任务的存续，而"任务存续"需要精确到可观测量：一个监测周期内应到达的数据最终到达了多少、花了多久、消耗了多少能量、以及有多少条下行命令被重复执行或从未执行。

## H. 指标

| 指标 | 定义 | 为何需要 |
|---|---|---|
| 到报率 | 周期内应到达的采样包中最终到达的比例 | 合同验收用的就是它，但须按传感器与按时间分别统计，单一全局值会掩盖局部失效 |
| 到达时延分布 | 每个包从生成到到达的时间，报分位数而非均值 | 均值被少数快包主导，监测关心的是尾部 |
| 能量预算余量 | 站点剩余能量相对越冬所需的比例 | 决定该站点下一个冬季是否存活 |
| 重复执行次数 | 同一条逻辑命令被实际应用超过一次的次数 | 分布式执行的正确性，与任务正确性正交 |
| 零执行周期 | 应下发但最终未落地的命令数 | 与重复执行方向相反，必须同时报，否则可以通过放弃执行来"改善"重复指标 |

最后两条构成一对。只报其中一个会奖励错误行为，详见 `docs/s5-benchmark/s6-11-execution-layer-results.md`。

## 待补

- 采样间隔与载荷大小目前是 A 层假定，须从目标文献取实测值。
- 卫星与 HAPS 回传的链路预算尚未纳入，当前模型只有地面网关一种回传。
- 中继布设的能量可行性未验证，3925 m 的中继能否越冬未答。
- 气候基线需用气象站数据核对，当前可能偏冷约 10 °C。
