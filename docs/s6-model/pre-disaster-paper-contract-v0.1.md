## 1. 一篇论文的主线与撤回条件

工作题目：**Reliable Execution of Agentic Monitoring Workflows under Intermittent Connectivity and Energy Constraints**。

待检验命题：在灾前低功耗监测网络中，控制命令和执行证据共同竞争有限通信机会。利用任务时效、动作语义与跨断连记录管理这些机会，能否在相同设备及预算下，改善关键监测数据的及时可用性，并减少错误配置持续时间？

“持续稳定通信”转化为可考核的**监测服务连续性**，不承诺链路永不中断。通信技术提供物理路径，runtime 管理路径上的任务；永久无路径或无电仍需工程补盲、储能或维护。

| 候选贡献 | 必须取得的证据 | 什么结果会削弱它 |
|---|---|---|
| C1：有场景依据的执行问题与评测方法 | 工程接口→任务→报文→端侧效果→业务指标的完整链 | 动作仍是虚构阈值/计数器；关键现象仅在无依据的极端注入下发生 |
| C2：受限通信下的执行机制有实用增量 | 同能力、同预算强基线比较；业务收益、额外成本及消融 | 设备影子、本地规则或合理配置的 VTC 全面追平；收益来自更多硬件 |
| C3：机制适用于实际 agent 工作流 | 真实 LLM 闭环、参数和反馈；规则 planner 对照 | 主结果全来自预写调用序列，模型不参与后续决策 |

C3 不要求 LLM 优于固定规则控制器。若模型没有独立收益，定位为服务 agent 的执行基础设施，不声称新的智能规划算法。持久日志、幂等、EDF、fencing 各自不是新发明；需要证明其组合给出的资源—正确性—服务收益关系。

| 西藏无市电/无蜂窝水文站，北斗及定时上电；[厂商案例](https://www.data86.net/xzmdjybdtxdswjcxmalfx.html) | 小数据备用回传、按需上电具有工程可行性 | 独立验证的滑坡实测效果、中通服成本或通用北斗额度 |

参数登记为 **E：来源直接支持；A：研究参考假设；M：本项目测量**。来源设备和地点不同时，不把 E 自动转成目标场景的 M。现有证据足以支持问题及接口存在，不能证明其在中通服站点中占比最高。

本稿不另立“首次季节地形传播模型”贡献。覆盖增强文档中“完全无人做/零实测”仍需系统核实；Hochvogel 激光测项受雪覆盖的数据不能拿来标定无线传播。s3 的执行主线可以继续，而不依赖这些排他性主张。

## 3. 一个最小参考部署

**架构 A**：中心运行 planner/runtime；现场网关有缓存与预置自治规则；节点用 LoRaWAN Class A 接入；网关经间歇蜂窝回传。中心到节点的动作跨越回传和接入，证据沿相应路径返回。Class A 是本研究选择的配置，有[接收窗口依据](https://learn.semtech.com/mod/book/view.php?chapterid=127&id=172)，不是上述案例共同采用的协议。

取 **16 节点、2 个坡面组、1 个网关**（A），延续已有规模。固定测点坐标和选择理由，节点区分形变、雨量等角色；不把任意 DEM 网格点当作真实部署节点。风险窗口内关键测点集合由任务给出。

第一轮固定已部署硬件。第二轮仅增加一种资源，例如固定中继或备用回传，做“硬件有/无 × runtime 有/无”对照；不能给 agent 一个无条件成功的信号增强按钮。备用回传可能仍共享网关、电源与最后一跳，路径数增加不自动消除带外管理的质疑。另设独立可靠管理路径组，检验何时本文机制不再必要。

全部运行止于灾害发生前。风险公告、监测下限和本地触发规则是给定输入，不训练滑坡预测器，不将监测服务指标直接解释为减少伤亡。

## 4. 三个业务闭环与四个真实接口

任务表示为 `Task(id, node_set, measurement_type, release_time, sample_window, delivery_deadline, priority, policy_generation)`。由外部需求序列生成，不同方法共享需求分母；不能用各方法自行产生的样本数给及时服务打分。常规采样自主运行，不要求每次调用 LLM。

| 闭环 | 触发、动作及责任 | 独立评分的业务后果 |
|---|---|---|
| W1：风险上升后的加密观测 | 中心收到公告；读取有年龄的状态、确定测点与能力、设置 profile、必要时请求新采集、处理未决结果 | 有效配置是否及时生效；风险窗中新测量是否按期到达 |
| W2：断连后的关键数据恢复 | 恢复时有历史积压与新需求；读取游标、水位，优先新数据，限预算补历史，核验缺口 | 新数据是否被历史挤占；历史最终完整性 |
| W3：解除风险后的节能恢复 | 新解除公告与旧命令/回执并存；更新 profile，处理迟到与重启，保留未知事实 | 旧配置是否回滚新状态；多耗电量及对下次风险窗的影响 |

所有方法都有相同本地触发规则，保护预设监测下限。中心可以接收外部天气公告或跨节点任务，本地规则只使用本地可得输入。必须另测“本地规则已覆盖所有需求”的组，承认中心 agent 此时可能没有增益。

| 初始接口 | 实际效果与完成证据 | 约束 |
|---|---|---|
| `read_status(node,max_age)` | 时间戳、启动标识、配置版本、电量估计、缓存水位 | 新鲜缓存/被动遥测可直接读，额外远程查询才增加报文；不读模拟器真值 |
| `set_monitoring_profile(node,profile,generation,expires_at)` | 完整 profile 的版本化赋值，真正改变采样与上传调度 | 按 profile 冲突域排序；同值重发计成本，不算有害重复 |
| `request_measurement(node,request_id,deadline)` | 新采集及采集时刻、样本 ID、关联请求 ID | 旧缓存不能冒充新采集；物理采集与日志之间崩溃时按能力允许 unknown |
| `upload_records(node,range,cursor,budget)` | 已存在的记录被分包传输，接收端按 ID 去重并核验缺口 | 明确发送游标与确认游标不同；上传不必天然是消费式读取 |

每个动作带稳定逻辑身份、参数、冲突域、期限和证据年龄。分开记录 `applied_at`、`observed_at`、`currently_active`：配置曾成功，后来被合法更新，不倒算原成功声明为假。

原协议只有序号/回复，增强端侧才可能提供持久去重、版本拒绝和结果查询。**同一比较组对所有方法提供相同端侧契约**，不能只给本文臂 C1/C2 再归因于 runtime。配置回复是否顺带采集等副作用，要核对实际协议，不能仅按函数名字分类。

## 5. 首个可实现的 72 小时参考负载

以下均为 **A：诊断参数，不是地灾安全标准或客户 SLA**。用于先跑通因果链，再做敏感性。

| 参数 | v0.1 |
|---|---|
| 时长与风险窗 | 72 h；第 12–18 h、48–54 h 为风险窗；无实际灾害 |
| 常态 profile | 每 5 min 采样、每 60 min 上传 |
| 加密 profile | 每 1 min 采样、每 5 min 上传 |
| 低风险节能 profile | 每 15 min 采样、每 60 min 上传；不覆盖本地风险保护下限 |
| 常态需求 | 每 60 min 一个需求窗，窗内至少一个有效样本在窗口开始后 90 min 内到达 |
| 风险需求 | 关键节点每 5 min 一个需求窗，窗内至少一个有效样本在窗口开始后 10 min 内到达 |
| 诊断故障 | 请求未达；效果发生但确认丢失；旧命令迟到；协调者重启；端侧重启；仅回传中断；分别构造 |
| 敏感性 | 断连 5/30/120 min；常态上传周期 15/60/180 min；独立/成组中断 |
| 能量条件 | 先能源充足组隔离通信机制，再动作驱动的低补能/低初始电量组 |

频次有案例背景，但这里的组合、期限和事件时刻是研究假设。主分布中不让风险与故障总是完美重合；破坏模式切换的精确故障注入单列压力测试，不冒充自然频率。数据由真正的采样调度产生，外部评分器持有真值，agent 不可访问。

先运行六类故障各一条可逐事件审计的轨迹，加无故障轨迹；它们用于语义验证，不用于显著性结论。开发轨迹与测试轨迹隔离。

## 6. 仿真必须成立的因果关系

**通信。** 显式模拟上行、RX1/RX2、命令执行、应用回执及后续报告。一次 Class A 上行后通常至多一次成功下行，不是两个工具额度。各方法都允许遥测携带确认；额外上行可创造机会，但计能量与容量。明确网络服务器位置、网关预缓存能力及回传时延，不能让中心命令在窗口关闭后瞬时抵达。

用帧、字节、空口时间和能量计账；一个工具对应零个、一个或多个报文。LoRa 空口时间含调制参数、前导及协议开销，不用载荷/标称速率替代。明确区域配置；不能沿用 EU868 后宣称中国现场合规。

**能量。** 方法分别演化电量，共享外生天气和初始条件：

`E(t+dt) = clip(E(t) + harvested_Wh - sleep_Wh - sensing_Wh - tx_Wh - rx_Wh - storage_Wh - heating_Wh, 0, capacity_Wh(t))`。

功率乘小时为 Wh；电流要结合电压及持续时间。夜间不能重复加日发电量；加热要付功耗。温度、充电门限和容量曲线绑定具体电池资料或测量。现有 1200 Wh/100 W 默认节点与文献 12 V/10 Ah 不同，不能拼接成实测配置。能源充足组可先跑；续航主张等负载参数可追溯后再作。

共享错误发电轨迹不保证差值不变：断电阈值、重试与期限具有非线性。能源模型改后相关结论重算。固定 alive 轨迹只能隔离执行机制，不能支持策略节能。

**观测与状态。** 曾有上行不证明未来可达；未派发可声明 `not_dispatched`，派发后超时不能改称“未执行”。先落盘再宣告改善崩溃一致性，但证据仍需身份、版本和时效校验，落盘本身不保证陈述真实。

## 7. 方法抽象、强基线与 agent 归因

建议把方法组织成五步：任务/能力检查→持久登记意图→按动作语义处理重试/替换→在真实机会中安排执行与必要验证→证据驱动重启恢复及下一步决策。合并未派发的旧配置，不能靠删除日志抹去已经可能发生的物理效果。

已有日志、身份及 C1/C2 是基础；任务期限、机会调度和真实业务耦合仍需实现，不能写成现有成果。不预先宣称最优。

| 对照 | 公平实现要求 | 要回答的问题 |
|---|---|---|
| 本地规则 + 缓存补传 | 相同自治保护、硬件及需求 | 工程现状是否已足够？ |
| 版本化期望/报告状态 | 最新配置合并、断连排队、缓存与遥测版本 | 是否只是设备影子？ |
| VTC 风格验证恢复 | 稳定身份、True/False/Unknown、退避、被动证据与报文合并 | 相对验证循环还剩什么？ |
| 精确版本 CAS | 可缓存或从报告获得版本，不强制每次写前额外远程读 | fencing 成本比较是否公平？ |
| 本文及消融 | 相同端侧契约，消融跨重启记录、过时意图处理、机会调度 | 哪个部件导致哪种收益？ |

设备影子也可用操作对象表示一次性任务，不先验断言不能处理。公开基线实际保障范围；自实现称“某机制风格基线”，不冒称完整复现。通用队列、重试与调参给各基线同等预算。

实验分两层：固定任务/意图回放隔离 runtime；**规则 planner / 真实 LLM planner × 强基线 runtime / 本文 runtime** 做 2×2 闭环。闭环允许反馈导致不同动作，不要求各臂动作数完全一样。

开发阶段就接一个真实 LLM 小任务：输入任务、能力及有年龄的证据，输出带参数动作，再根据 unknown/过期/成功继续决策。固定模型与提示，记录调用、延迟、token、非法参数及反馈。只选工具名不够；也不能静默让规则器替模型完成失败动作。

## 8. 业务指标与统计

主指标：**按期有效监测覆盖率**。令 D 为各方法共同的外生需求：

`TimelyCoverage = sum_d w_d * I(valid sample taken in d.window AND received by d.deadline) / sum_d w_d`。

主表分别报常态、风险、关键节点，避免权重掩盖差异；权重预固定并做敏感性。永久不可达点仍进入端到端需求分母，另报物理可服务子集，二者不混用。

补充指标：中心 AoI 与最长空窗；实际/合法期望 profile 错配时间积分；“曾生效”和“当前有效”分别评分的声明可靠性；额外物理采集等有害执行；历史唯一有效样本完整性；节点/网关能耗、空口、日志成本、unknown 时长和 LLM 开销。同值配置重发只计资源成本。

以独立场景/轨迹为重复单位，报告配对差及区间；共享天气/网关故障下的节点不是独立重复。参考主试验可从每场景 20 seeds 起步，数量依开发集方差和目标精度调整，不挑 seed。按拓扑及完整轨迹分开发/测试，保存参数、版本、请求、报文、效果、证据与评分输出。

## 9. 最小成文证据包

| 正文部分 | 读者应理解或相信什么 | 必须有的产物 |
|---|---|---|
| 动机与相关工作 | 实际远程监测需求，及已有方案的边界 | 场景证据表；一条效果发生但回执丢失的时间线 |
| 系统与问题 | 谁控制谁、有效监测定义及资源限制 | 实体/依赖图、任务与动作定义、机会和电量模型 |
| 方法 | 生命周期与机会怎样结合，保障在哪停止 | 核心算法、状态流程和端侧能力契约 |
| 主结果 | 相同设备预算下服务是否改善、代价多少 | 及时覆盖、错配时长及成本表/曲线 |
| 分析 | 收益来源、适用边界及真实 agent 接入 | 消融、敏感性、2×2、完整失败案例 |
| 讨论 | 仿真支持什么，现场还缺什么 | 外推限制、移植成本、无路径与自治足够的边界 |

主结果外安排六项分析：①机制消融；②通信机会/断连敏感性；③动作驱动能耗；④本地自治与独立管理路径替代解释；⑤真实 planner 因子对照；⑥故障类型和残余失败。不做所有参数的巨大笛卡尔积。

仿真可以支撑完整论文；加软件进程级故障注入，验证真实接口、持久日志及重启，会增强系统证据。ns-3、硬件在环、外场各自证明不同层，不相互替代。无射频实测不声称实测覆盖，无现场日志不声称西藏故障分布，无 BOM/资费/工单不声称具体降本比例。

## 10. 执行顺序与决策闸门

**P0 定义闭合**：节点清单、profile、任务生成器、报文/效果格式；修能源积分、MAC 机会及动作参数闭环。按实际接口确认副作用。

**P1 小闭环**：跑 72 h 的六类诊断故障及无故障轨迹；同时纳入本地自治、版本化配置、VTC 风格基线和一个真实 LLM 任务。检查需求→采样→交付→评分贯通，无真值泄漏、无虚假能源、所有方法同窗口/能力。

**P2 冻结实验**：基于开发集修方法、选工作点，冻结测试配置，完成主结果、强基线及六项分析。在此之前暂缓大量旧年度曲线重跑；年度能源/地形扫描只在直接支撑主张时补。

**P3 写作**：问题、模型、方法和实验协议现在可以写；结果等待实际运行。每条贡献连到图表，旧合成副作用数字不充当新业务收益。

闸门不是“加 MAC 约束后，相对 VTC 的优势必须变大”：

- **继续主稿**：模型可行、强基线公平，业务收益稳定且值得额外成本。
- **收缩主张**：收益只在某种断连/重启/低机会条件成立，报告该区间。
- **调整方向**：成熟设备管理全面追平，不能硬写性能优势；评估评测/系统经验是否有独立论文价值，或结束该算法分支。

这比先全量重跑、看到优势扩大才补 agent 和业务指标，更早暴露论文风险。

## 11. 向中通服获取的最小证据

不必等完整外场数据才能开始 P1。后续优先获取：一套设备/网关协议；同时含上报、下发、回复、掉电/重启的脱敏日志；常态/汛期实际采样上传策略；最长缺报容忍度；电源配置和至少一种模式电流记录。成本主张再补 BOM、资费、维护次数。

最有价值的问题是：**最近一次连续缺报中，是节点没采到、采到了发不出、平台命令没到，还是命令到了却没有确认？现场怎样恢复？** 它决定优先模拟哪种故障。本轮未向外部人员发送消息。
