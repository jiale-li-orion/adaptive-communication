# Layer-1 v0.5 Dynamic Feasibility Frontier

状态：method-development prototype / not benchmark release

本轮严格落实 cache06 / Astra 两份审查中尚未落地的动态语义：

1. **重复 owner-scoped query**：同一 capability 可在旧请求完成后重新采样，request id 独立；同一 capability 不允许同一历史下无限并发自刷。
2. **sample / arrival 分离**：query 在 owner 读取时采样，响应晚到不会把未来状态倒灌到过去。
3. **执行阶段分离**：terrestrial send、gateway receipt、final delivery ACK 分开；未收到 final ACK 不视为完成。
4. **prefix consistency**：相同过去、不同未来的 worlds 在分叉前具有完全一致的合法可观测前缀。
5. **realized execution accounting**：沿实际 policy branch 统计 query/send/observation，不再把 enabled capability set 大小当作执行成本。
6. **动态 process generator**：两个报告流、六项 obligation、三阶段 terrestrial service，保留实际 Connecta satellite opportunities；未来状态在共享历史之后分叉。
7. **集合级 conflict frontier**：对未来可用 terrestrial send opportunities 做 flow/min-cut，维护 set-valued deficiency certificate，而非逐报告 mandatory 标签。
8. **incremental = rebuild**：query observation 只过滤相容 worlds 时复用已有 per-world certificate，0 次额外 flow solve；reference full rebuild 用于前缀对账。

当前明确没有 claim：

- v0.5 已击败 fixed pair / depth-k planner；
- v0.5 已形成 benchmark release；
- remote bytes / airtime / energy 已标定；
- 动态前沿普遍具有多项式复杂度；
- LLM / Agent 比传统 planner 更优。

下一阶段只剩 method validation：

- action/ACK/time/budget 事件后的 incremental frontier 与 full rebuild 前缀级一致；
- 用真正 depth-k / receding-horizon baseline 测 dynamic coupling；
- 计入所有 graph / flow / fallback cost 后比较端到端在线计算；
- 结构留出按 conflict overlap 与 event interleaving 做，不按 seed/id 做。
