# Agent 与通信执行：下一项判别

日期：2026-09-20。代码基点：`dd4f31a`。状态：研究假说细化，未实现候选、未调用 API、未形成新方法结果。本件将 Agent 与通信执行的结合恢复为主探索方向；反馈预算是另一个模型边界，不是该方向的前置条件。当前结果状态仍以 `results/CLAIMS.md` 为准。

## 1. 问题与当前证据

目标是在已有灾前山区监测任务中，让高层 Agent 使用普通通信工具，形成并维护能兑现授权要求的执行计划。评价落在按期交付、缺采、能源、实际通信代价和有益动作误拒；自然语言质量、少调用 API、少输出错误说明均不能单独替代它们。

当前实跑接口把这个目标压缩了：

- `code/v3joint/agent_mission.py` 的 `_observation()` 已给出结构化 `mission.schedule`、当前要求和四套规则的逐节点目标；`SYSTEM_PROMPT` 限定输出采样/上报周期。
- 同一提示明确将备份选包交给自动网关，Agent 不控制该环节。因此 r38 主要测调档建议的选择与改写，没有完整测任务理解及跨层计划生成。
- `code/v3joint/agent_cert.py` 的 `CertLLMDecider._prompt()` 在模型生成前插入由观测计算的文本。它没有读取模型随后提出的具体计划，不能据此声称已实现动作条件化的计划校验和修复。
- `code/v3joint/envelope.py` 已有确定性门，r39 已测位置；增加一个输出过滤器不是新构想。相同节点保护、expiry、shadow、身份与普通过滤器应进入所有竞争臂。
- doc33 已提出任务编译和增量修复，doc42 已对 H2 任务降级及未决效果做过普通组合对照，doc52/doc53 已提出证据接口与匹配能力验证。不能重新命名后称这些内容尚未探索。

现有 C5/C9 否定的是所测配置候选的独立算法增量。它们不等价于“相同 Agent 接入一种执行接口没有收益”。反过来，Agent 错得多也不足以证明需要新通信机制。

## 2. 修正判断门槛

区分两个研究问题：

1. **新通信控制算法。** 在相同合法信息与动作下，相对强普通控制器产生更好的服务—风险—成本工作点。
2. **Agent 通信执行系统。** 在任务、模型、输入信息、普通工具和本地保护相同时，一种执行接口减少错误计划的物理后果，同时保留有益介入。

第二个问题不要求超过已调好的确定性控制器；该控制器提供可达性能参照，Agent 系统可以以减少相对它的损失为目标。但第二个问题仍须比较同能力的普通工程组合，包括专家说明、明确动作语义、状态影子、参数检查和普通安全过滤。只打裸 Agent，或只把相同规则从 prompt 搬到代码，均不足以建立独立方法贡献。

因此撤下 `RESEARCH_PLAN` 中“先证明确定性控制器的独立增量，随后才允许 Agent 判别”的统一前置顺序。先用真实轨迹验证故障对象并通过普通组合筛选，就可以做小规模匹配 Agent 对照；若提出新的通信优化算法，再走第一类门槛。

## 3. 最近反方：已有工作覆盖了什么

本轮基于仓库历史调研，重新核查 [1–2] 的 HTML 全文及 [3–6] 的原始出版页/摘要。没有复现它们的实现。此表只支撑候选边界，不宣布文献空白。

| 工作 | 已有重叠 | 对本轮的限制 |
|---|---|---|
| WirelessOpsAgent [1] | 输入证据账本、候选输出绑定、依赖局部修复、执行前授权 | “证据图＋检查＋修复”已有；候选需用持续物理执行中的业务后果区分，并纳入其工作流适配对照 |
| Verified Tool Calls [2] | 后置条件核验、重试前核验、幂等键 | 不重开早期 outcome-unknown/去重线；它也明确承认核验器的过旧或不完整观测限制 |
| Agentic IBN [3] | 高层意图分解、专家工具及配置生成 | 单纯让 LLM 抽参数、调用求解器不够 |
| 部分可观测 shielding [4] | 状态估计与动作安全筛选 | unknown、安全动作集、拒绝危险动作本身已有基础 |
| 分散 shield [5]、组合 shield [6] | 不同观察者下的局部保护、分解约束 | 将规则放节点/网关、按位置拆检查本身不承担新颖性 |

与 [1] 可检验的差别应落在评测对象：其报告的是执行授权决策；本站可继续展开动作经 Class A 延迟生效、持续耗能、数据跨段移动后的结果。这个场景差异提供检验条件，尚未证明候选机制优于它的适配实现。

## 4. 主候选 A：针对剩余义务的计划修复

**假说。** 面对同一份合法证据，把 Agent 的具体动作与其仍能影响的监测义务及执行环节绑定，能减少错段干预与不必要重建，并保留普通安全过滤会放弃的有效进展。若完整普通组合已覆盖这些行为，候选关闭。

这延续 doc33 的任务编译方向。本轮缩小到一个实现差异：目前证书在生成前描述状态；拟议接口在生成后检查“这项动作准备改变哪段剩余工作”，结果在后续执行证据到达后更新。它不另造租约、能源规则或选包器。

最小表示包含：`授权任务片段 / 义务采样窗与交付期限 / 该动作的目标与生效位置 / 已见证进展及证据时刻 / 仍未完成的环节 / 未决效果 / 合法候选处置`。证据必须来自执行该检查的位置；中心没有网关或节点的最新证据时，相关项保持 unknown。不得把仿真缓存真值直接加入模型输入。

小机制分三步：

1. 将具体提议绑定到授权目标。调采样影响新样本，调上报影响接入机会，网关选包影响回传；配置已经生效和监测义务已经完成分别判定。
2. 只用有依据的条件排除无效分解。例如，已知合格副本在网关，继续采样无法解决**该条义务**的回传缺口；但这不授权停止未来义务所要求的采样。严格采样频率要求仍须满足，不能用一份旧样本偷换新观测。
3. 返回受影响部分的可执行修复选项，使用已有控制与选包工具；保留未受影响的有效执行。没有可证修复就报告 unknown/不可兑现条件，不能自动扩配额、改警级或删评分义务。HOLD 只改变提议状态，是否撤销待发目标、请求回退或继续现场自治必须明确区分。

不把任何新网关 API 视为现成能力。首轮可保留 maxcov 自动执行，先看已有两个配置字段是否出现可修的错段提议；若必须开放网关编排接口才能测，先登记它的合法调用位置、传输路径与各臂同等权限。普通逐字段检查和通用安全盾是必备对照。

**最强反证。** 这可能只是普通任务账本加领域规则，或 WirelessOpsAgent 工作流加正确通信模型。若其同能力适配覆盖结果，就只支持系统适配，不认领新计划修复算法。

## 5. 辅助候选 B：按执行依据变化触发重规划

记录计划依赖哪些任务版本、配置确认和通信机会。在无相关新证据、没有新的可执行选择时保留有效计划；当授权变化、依赖失效或新机会出现时，才请求 Agent 重规划，并只传受影响部分。

它延续 Human 的 intent backpressure 与条件计划线，不能当全新发现。普通事件触发、目标合并、重试退避必须同场；少 token 或少被准入拒绝的请求只属于计算/接口成本。只有同等真实服务下减少实际通信耗费，或更及时恢复有效执行，才作为通信方法证据。当前将 B 留为 A 的可选效率组件，不单开主论文方向。

## 6. 下一次最小交付

**第一步：既有轨迹的可修性清单，零 API。** 从 r38 全部真实轨迹筛选候选失效，分母固定，给出：当时合法证据、模型提议、之后真实执行、普通组合会如何处置、是否仍有未被覆盖的损失。历史轨迹只用于定位，不能把分叉后继续原样回放当成新的闭环 Agent 结果。

先排除四类：解析失败；已由 shadow/版本/去重覆盖；同一 L0 保护已消除；没有可行动机会、任何合法计划都不能改变该条损失。剩下的候选见证必须给出一条不读未来、不增加权限的修复动作，并核对是否只是少做本来有益的任务。

**第二步：小规模闭环，直接检验 Agent 接口。** 共用来源任务、合法观测、工具、解析预算、expiry、普通本地保护和资源，对比：普通结构化 Agent＋专家说明；再加普通状态/安全过滤；再加 A。强确定性控制器单列性能参照。先使用正确结构化任务，以隔离修复机制；自然语言输入作为随后单独的端到端层，来源任务和评分不变。新增输入呈现条件单列，不与旧 r38 混为同一实验。

评分使用物理结果，不用我们自己的 APPLY/HOLD 标签作唯一金标准；分列服务、缺采/失电、能源、实际空口、备用字节、被拒但原本可完成的任务与独立完成声明。固定可靠链路负对照。模型提议和实际动作分别保留，显示增益在哪一步产生。

**第三步：仅在独立作用出现后扩大。** 做去义务绑定、去分段进展、去局部修复的消融，并在既有中断/任务相位上验证。跨模型与更大批次随后进行。若仅普通过滤有效，结论归普通机制；若只改善表达与解析，归接口工程；若 A 改善真实任务结果且保留有益动作，才讨论 Agent 通信系统贡献。

候选 A 目前只晋级为低成本判别问题；方法新颖性和独立业务收益均待证。无需等待另一个新 TTL 或新 ACK 算法成功后再测。
