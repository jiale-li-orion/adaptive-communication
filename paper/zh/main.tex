\begin{abstract}
山地站点回传失效之后，网络继续执行的是失效之前安装进去的通信状态。未确认的记录继续占满仅有的几次恢复接入批次；一条再也撤不回的密集采样配置继续耗电过夜。本文研究这两类\textbf{持久安装状态（persistent installed state）}可以依据什么证据、在哪个位置终止，对象是电池加小光伏的 LoRaWAN Class~A 部署，网关现场自治，蜂窝主回传配按量计费的北斗短报文备用。两者归入\textbf{一个决策问题：部分证据下的本地终止}。节点只握有时钟、自身电量、缓存、最近接入收据与安装时刻携带的界，就此决定保留还是释放记录、维持还是退回配置，受无假释放、能量存续、证据局部性、无假完成四条约束。记录的终止时刻是业务期限，节点本地确定；该规则与标准 Bundle Protocol 的逐记录到期逐位相同，决定增益的是\textbf{跨段安置位置}：源端到期把中断按期交付从 \cThreeSeedZeroFifo 提到 \cThreeSeedZeroPurge、十种子 \cThreeRatio 倍，而只在网关抑制过期发送会把代价反压到接入段，按期交付掉 8 条。配置的终止时刻在节点侧不完全可观测。阴雨天气下时钟夜门留下 \cFiveNightfloorDeadA 至 \cFiveNightfloorDeadB 个节点死亡；固定 8~h TTL 在两个相位都达到零死亡且黄级交付总数不减（$\cFiveTtlEightYellowA/\cFiveYellowNA$、$\cFiveTtlEightYellowB/\cFiveYellowNB$），而按能量可行性推导的回退界虽同样零死亡，却少交付 \cFiveEnergyLostA 与 \cFiveEnergyLostB 条黄级义务。配置回退界的\textbf{在线推导仍是空缺}：候选界由完整任务时刻表离线给出，本实验未验证其在线推导与随配置命令安装。形成性 LLM 研究定位出设计所针对的接口故障：LoRa 接入收据被读成回传状态。全部结论来自确定性、仓库可复现的运行，端到端与跨模型验证列为后续工作。
\end{abstract}

\noindent\textbf{关键词：}持久安装状态；间歇回传；LoRaWAN Class~A；卫星短报文；期限到期；配置租约；部分可观测；灾前监测。

\section{引言}

现场节点正在执行一条已授权的密集采样档。蜂窝回传正常时中心下发配置，节点在下一个 LoRaWAN Class~A 接收窗口应用它。随后回传中断十六小时，三件事在没有控制路径的情况下继续发生。节点继续按密集档采样与上报，整夜消耗电池未必供得起的能量，而中断之后撰写的降档命令到不了它。节点缓存里的记录按标准的确认前保留边缘纪律，在每一次狭窄的接入机会上最老优先重传，其中包含业务期限已经过去的记录。中心与网关分不清缺失的数据是没采到、压在节点、已到网关，还是仅仅缺一个回传槽，也分不清一条命令是在队列里、在途中还是已生效。网络并未停住：\textbf{安装状态仍在执行}，它在再也无法满足任何义务的工作上消耗能量、接入时隙与计费的短报文字节。

这类失效有确定的形状：\textbf{持久安装状态的终止依赖一条恰好已失效的控制与确认路径}。SateRIoT 观测到有损卫星窗口浪费 COTS 电台重传，据此重做链路估计与多跳共享~\cite{sateriot}；语义 HARQ 复用成熟的 HARQ 原语，只改错误判据以匹配新的通信对象~\cite{razavivideo}。本文沿用同一思路，先问哪条普通机制已经在终止每一类安装状态，以及普通机制被公平施加之后真正的缺口还剩什么。

\subsection{两类持久安装状态}
\textbf{记录状态（record state）}是节点缓存里的未确认样本，在获得确认或被丢弃之前占据每一次未来接入批次的一个位置。\textbf{配置状态（configuration state）}是节点当前的采样与上报档，由已生效命令安装，在新命令或本地条件终止它之前持续驱动能量与空口消耗。两者都在连接期间产生，都比连接活得久。区别在终止它们所需的证据：记录的有效生命终止于一个绝对业务期限，源端凭公开任务节奏即可算出；配置的有效生命终止于它产出的数据再也送不到，而这取决于走故障回传才能到达的任务\textbf{修订}，以及掌握在网关的未来回传机会几何。这一不对称是全文的技术中心，\S\ref{sec:problem} 给出精确形式。

\subsection{成熟机制已解决的部分}
本文先搭出刻意做强的基线，并给它们同样的合法信息：能量感知前馈采样、全知离线装包器、滚动时域 MPC、最大覆盖加新近度的备份装包、最早截止优先与义务贪心队列、分段非预知任务视图、以及对称的资源放宽。在所测策略族上，固定资源内重新优化采集、调度或装包都没有得到稳健的按期交付增益，固定资源下的大幅增益必须增加回传容量或能量；这一读数按 scoped 负结果报告。另有两条普通终止机制同样有效。逐记录到期：业务期限一过就释放缓存记录，属于标准 Bundle Protocol 生命期管理~\cite{rfc9171}，此前的"证书驱动核销"与它逐位相同。本地时钟与能量门：日落时把密集采样降回稀疏的节点本地规则，在中断与日落同相、电池够用时消除过夜死亡。两者都明确记为成熟原语。

\subsection{残差}
实验揭示两类安置效果。在网关抑制过期记录发送而不动源端缓存，会扣住确认，使记录继续占据接入批次，按期交付从 202 降至 194；源端到期可以释放这部分状态。配置侧，时钟门到日落才动作，在两个阴雨场景留下 \cFiveNightfloorDeadA--\cFiveNightfloorDeadB 个死亡，提前预置回退时刻可以避免这些死亡。短到 4~h 的 TTL 在较长密采相位少交付 \cFiveTtlFourLostB 条黄级义务，而固定 8~h TTL 在两个相位均为零死亡且黄级交付总数不减；按能量可行性推导的回退界同样零死亡，却少交付 \cFiveEnergyLostA 与 \cFiveEnergyLostB 条。这支持研究断连前如何选定并安装回退界，尚未确立相对普通租约的增量；故障发生后才获得授权的降级时刻不能用于先前的安装决策。

\subsection{贡献}
\begin{enumerate}
\item \textbf{一个针对持久安装状态的终止问题}（\S\ref{sec:model}、\S\ref{sec:problem}）。记录与配置建模为连接期间安装、断开期间执行的状态，从义务链定义各自的释放时刻，给出一个受四条约束的本地决策问题——无假释放、能量存续、证据局部性、无假完成，并配一套 confirmed/unconfirmed/unreachable 三态声明纪律，让 unknown 成为一等结果。
\item \textbf{记录终止是标准到期，增益来自跨段位置}（\S\ref{sec:mech-record}、\S\ref{sec:eval-record}）。按期限对齐的源端到期与 BPv7 逐记录生命期在十种子上逐位相同。系统贡献落在端到端业务期限基准与源端网关一致性上：它把中断按期交付翻倍、把过期备份记录压到 1 条，而只在网关抑制会把代价搬到接入段。全时域时间感知归因纠正了此前把 830 条接入迟到记成回传容量失约的账。
\item \textbf{配置终止的受控对照}（\S\ref{sec:mech-lease}、\S\ref{sec:eval-lease}）。预置回退界消除时钟门留下的 20--31 个死亡，固定 8~h TTL 在两个相位也避免死亡，而较短 TTL 在较长密采相位损失黄级交付。本文明确交付推导租约所需的信息与安装条件，其在线增量仍待验证。
\item \textbf{定位接口故障的形成性真实 agent 研究}（\S\ref{sec:eval-agent}）。对称计量 1089 次真实决策，指出 LoRa 接入收据被读成回传状态这一双向故障；unknown 感知的投影器在离线重放中清除了健康链路上的假断言。agent 是\textbf{候选控制器}，问题的定义先于它成立。
\end{enumerate}
本文不主张 LLM 胜过求解器、不主张新的丢弃算法、也不主张全局调度上界；确定性机制是同一层里对规则、求解器与 agent 同等可用的工具。

\section{场景与工作点}
\label{sec:bg}

十四个传感器节点分两组监测坡体位移与降雨。节点经 LoRaWAN Class~A 上传到现场网关，网关经蜂窝回传转发到中心服务器；北斗短报文作为稀疏、计量的备用链路，只承载现场到中心的消息，不充当下行配置通道。节点由电池加小光伏供电，任务是灾前例行监测并带授权的预警等级变更，任何组件都不判滑坡风险。节点数、角色映射与扰动参数按冻结的 Task v1.1 实例清单，早期的 16 节点草图不作为现场事实。

授权边界来自两项中国地质灾害监测行业标准 DZ/T~0460--2023 与 DZ/T~0450--2023，条款在仓库内逐条审计~\cite{dzt0460,dzt0450}。\S5.3.3 允许按预警等级远程动态调整采样与上传频率且未给数值，因此本文使用的周期是已声明的研究选择；\S8.4.1 定义红橙黄蓝四级，\S8.4.2 允许会商后升级、降级或解除；\S5.3.7 在高风险极端天气弱覆盖下要求双模通信，该条只出现一次，属条件性条款，通信层标准并未通篇强制。北斗公开服务规范 BDS-OS-PS-3.0~\cite{bdsps3} 给出成功率 $\geq$95\%、平均时延小于 2~s、平均每 30~s 一次服务、单条消息上限 14{,}000 比特，同时说明实际频度与最大长度受注册参数约束，频度属于配额量。这些条款划出合法动作范围：在授权等级内重新编译频率并申请会商变更，静默删除义务与自行宣告风险都在界外。

备用链路每 1200~s 一个 78 字节包（20~B 包头、58~B 载荷；位移样本 6~B、降雨 4~B，每包约装 9--10 个）。升级后的黄级任务周期 300~s，交付期限为窗口开启后两个周期，即交付窗约 600~s，短于 1200~s 的备份槽间距。DZ/T~0450 的 200~B 单包上限与不小于 1~min 的周期（\S7.4.3.2、\S7.4.2.3，\S7.4.3.5 另有不小于 5~s 的消息间隔）分属不同的服务形式条款，不合并成单一的"北斗工作点"；1200~s/78~B 是已声明的研究选择。

\section{系统模型}
\label{sec:model}

时间以 $\Delta{=}60$~s 为槽，$t{=}0$ 为本地 06:00，故 $t{=}12$~h 是日落，日照周期在模型里显式出现。节点集 $\mathcal N$、测量量集 $\mathcal M$ 与网关 $g$ 构成现场，中心 $c$ 在回传之外。

\subsection{义务与交付链}
监测义务 $o=(n,m,[l_o,h_o),d_o)$ 定义在节点 $n$、测量量 $m$ 上，含采样窗口与绝对交付期限。周期为 $P$ 的例行义务有 $h_o-l_o=P$、$d_o=h_o+P$，即一个周期的宽限。样本满足 $o$ 的条件是测量量匹配、在窗口内采集、并在 $d_o$ 之前被中心收到，依次经过
\begin{equation}
\resizebox{\linewidth}{!}{$\displaystyle
\underbrace{\text{合格样本}}_{\text{节点}}
 \!\to\! \underbrace{\text{在 }g\text{ 被听到}}_{\text{LoRa 接入}}
 \!\to\! \underbrace{\text{在 }d_o\text{ 前回传}}_{\text{蜂窝/短报文}}
 \!\to\! \underbrace{\text{中心证据}}_{\text{义务满足}} .$}
\end{equation}
分段任务的首段用闭区间、后续段用半开窗口，等级变更后边界样本不会重复覆盖相邻窗口。

\subsection{链路、中断与可行动实体}
LoRa 接入（节点到网关，含 Class~A 下行窗口）每次机会以 $p_a{=}0.74$ 成功；主回传（网关到中心）在非声明中断期以 $p_b{=}0.62$ 良好。\textbf{控制中断}是区间 $\mathcal O=[a,b)$，其间主回传对中心到现场的流量不可用：中心命令与任务表段在准入处被拒、从未发出，短报文备用无法承载下行配置。中断期间能改变现场通信行为的只有\textbf{节点}（依据自身时钟、电量、缓存、最近接入收据，以及已生效命令携带的界）与\textbf{网关}（依据实际听到的样本、转发日志与已用备份槽）。中心保留授权变更的权力，没有安装变更的通道；在 $\mathcal O$ 内撰写的修订只能在 $b$ 时刻到达现场。

\subsection{持久安装状态}
\textbf{记录状态。}节点 $n$ 上的每个未确认样本 $s$ 有生成时刻 $t_s$，在本地已知节奏下业务期限 $d(s)=(\lfloor t_s/P\rfloor+2)P$，占用 $K{=}240$ 个缓存槽之一，在一次接入批次中最多占 $B{=}32$ 个位置。在所建模的边缘纪律下，它只在中心确认时离开缓存（确认按同步、不占空口建模，对各队列规则同等有利），在此之前按最老优先重发。

\textbf{配置状态。}节点对采样与上报运行同一个档 $q(t)\in\{P_0,P_1\}$（稀疏 $P_0{=}600$~s、密集 $P_1{=}300$~s），由带版本号的已生效命令安装。命令只有在后续节点上报确认新档之后才算已生效（Class~A 时延），排队或途中的命令不改变任何东西。生效期间 $q{=}P_1$ 每拍额外消耗采样与上行能量，直到有东西终止它。

\subsection{能量}
单次采样耗 $e_s{=}4.7{\times}10^{-4}$~Wh，单次上行耗 $e_u{=}2.33{\times}10^{-5}$~Wh，电池容量 $C{=}0.05$~Wh。日照输入是 12~h 半正弦，峰值 $\eta$（标称 $0.03$~Wh/h），叠加逐节点逐小时的随机云遮挡。主配置下电量归零的节点永久死亡。整夜维持密集采样消耗约 $0.071$~Wh，超过电池容量。

\subsection{释放时刻}
对每个状态 $x$ 定义释放时刻 $\trel(x)$：在此之后继续保留 $x$ 已不可能为任何被满足的义务作出贡献。记录有 $\trel(s)=d(s)$，业务期限一过，该记录无法满足任何义务，继续保留与重传的交付价值为零。配置档的 $\trel(q)$ 是该档数据仍能经某条可行路径满足的最后一条义务期限，
\begin{equation}
\trel(q)=\max_{o:\,\text{档 }q\text{ 产出 }o}\;
   \min\{\,d(o),\ \tau_{\text{last slot}}(o)\,\},
\label{eq:trelcfg}
\end{equation}
其中 $\tau_{\text{last slot}}(o)$ 是仍能被网关听到并在 $d(o)$ 之前转发的最后一次主回传或备份机会。与 $d(s)$ 不同，这个界把任务时序（当前档服务哪些义务）与回传槽几何（它们何时能被承载）合在一起，两者在 $\mathcal O$ 期间的节点上都不可完全观测。

该配置界目前是待验证表达式，不是已证成的在线释放时刻计算。停止新增密采不必停止已有记录转发，最早安全回退时刻还须区分这两类活动。

\subsection{服务损失与声明纪律}
目标函数计三项：按期交付的义务（服务）、节点永久死亡、以及存活超过释放时刻的状态所占资源——浪费的样本、接入尝试、短报文字节与能量。离线口径下，每条未满足义务记在乐观模型（后续假设一律放行）下的首个失败环节上，得到四个互斥段：\senergy（无合格样本）、\saccess（采到但期限前未被网关听到）、\stime（已听到但不存在回传机会）、\scap（存在机会但容量或拥塞承载不了）。在线观察者看不到某一环节时报告 unknown，不得猜测。每条可行性声明属于三态之一：\textbf{confirmed}（独立上报显示目标档，或有匹配样本被中心收到）、\textbf{unconfirmed}（命令在途中或收据不全，既不蕴含已生效也不蕴含链路已断）、\textbf{unreachable}（由明确的网络侧状态得知当前路径已断）。LoRa 接入收据只构成接入链路的证据，凭它本身永远不能确立回传可达。

\section{问题形式化}
\label{sec:problem}

中断 $\mathcal O$ 期间，每个可行动实体在每一拍 $t$ 对它能够触及的状态选动作：记录取 $a_t(s)\in\{\textsc{retain},\textsc{release}\}$，配置取 $a_t(q)\in\{\textsc{hold},\textsc{revert}\}$，其中 revert 把密集档退回最后一次确认的稀疏档。记 $\mathcal E_e(t)$ 为实体 $e$ 在 $t$ 时刻合法持有的证据：节点为时钟、自身 SoC、缓存内容、最近 Class~A 收据、以及 $a$ 之前已生效命令携带的界；未来任务表段、仿真全局样本、回传真值都在其外。本地终止问题即
{\small
\begin{align}
\textbf{Problem 1.}\quad \min_{\{a_t\}}\quad
 & \textstyle\sum_o \mathbf 1[o\ \text{未满足}]\notag\\
 & \textstyle{}+\lambda_d\sum_n \mathbf 1[n\ \text{死亡}]\notag\\
 & \textstyle{}+\lambda_w\!\!\sum_{x:\,t\geq\trel(x)}\!\! \operatorname{cost}(x\ \text{保留}) \label{eq:obj}\\
\text{s.t.}\quad
 & \text{(C1)}\ \textsc{release/revert}\Rightarrow t\geq\trel(x), \label{eq:c1}\\
 & \text{(C2)}\ \operatorname{SoC}_n(t)>0\ \ \forall n,t, \label{eq:c2}\\
 & \text{(C3)}\ a_t=f(\mathcal E_e(t)), \label{eq:c3}\\
 & \text{(C4)}\ \text{未知可行性}\Rightarrow\text{报 unconfirmed/unfulfillable},\label{eq:c4}
\end{align}}
其中 (C1) 无假释放、(C2) 能量存续、(C3) 证据局部性、(C4) 无假完成——未知可行性下既不得报已完成，也不得报不可达。张力在 (C1) 与 (C2) 之间，由 (C3) 限定可用信息：过早释放违反 (C1)，放弃仍可交付的工作；过晚释放违反 (C2)，节点在密采数据已不可交付之后继续付费，直至放电致死。全部困难来自两类状态对 $\trel$ 的可观测方式截然不同。

\subsection{记录子问题：$\trel$ 本地确定}
$d(s)$ 只用公开节奏，节点无需下行即可确定地算出 $\trel(s)=d(s)$。约束 (C1) 化为精确判据 $d(s)\le t$，release 同时释放备份发送与接入批次。最优本地规则就是普通的逐记录到期；\S\ref{sec:mech-record} 说明按证书索引的变体是同一条规则，唯一有可测后果的设计选择是\textbf{释放在哪里执行}，它由 (C3) 与跨段确认耦合决定。

\subsection{配置子问题：$\trel$ 本地不可观测}
$\mathcal O$ 期间，未来任务修订不能从缺失消息中推知。时钟门、固定时长租约与节点 SoC 能量门使用不同的本地可得信号，必须在相同任务先验与能量条件下比较可行性。当前实验评估时钟门与预置回退时刻，尚未在同一配置终止对照中评估节点 SoC 能量门。

\textbf{交付界租约候选。}如果任务有效期与相关回传机会在连接期间已经授权并已知，网关可以据此推导绝对界，随配置命令一起传输；后续修订应携带新版本与租约。如果降级在中断期间才获授权，该时刻不能进入此前的计算。当前原型从完整实验时刻表预置界，展示本地终止的效果，尚未实现随命令安装、绑定版本的租约，也未证明对 (C1)--(C3) 的在线求解。普通任务有效期到期机制必须获得同样信息并进入对照。

\subsection{这是通信问题}
Problem~1 定义在网络状态、证据局部性与回传几何之上，它有最优 oracle 解，也有不依赖任何 LLM 的普通规则解。agent 是同一决策的一种求解器，也是探测接口在何处误导规划器的便利探针；目标函数与约束里没有任何一项引用模型。因此机制部分全部确定性评估，LLM 研究按形成性研究处理。

\section{机制}
\label{sec:mech}

\subsection{记录终止：按期限对齐的到期}
\label{sec:mech-record}
每次上传机会上，节点删除 $d(s)\le t$ 的缓存记录，其余按最老优先发送。实现两种写法：\texttt{deadline-purge} 以义务节奏为索引，\texttt{generic-expiry} 是普通 BPv7 式逐记录生命期，在生成时赋值 $\text{expires}=t_s+((P-t_s\bmod P)+P)=d(s)$，不引用义务 id、槽几何或证书。网关变体在本地确认它将不发送的记录。EDF 与义务贪心队列只重排、从不释放；AoI 的 \texttt{latest-only} 无差别释放，只保留最新一条。丢弃陈旧或过期流量在 AoI 包管理与 DTN bundle 到期中已有充分积累~\cite{costa2014pm,kam2016deadline,dtnarch,rfc9171}，抑制超出时延界的传感流量同属先行工作~\cite{wada2009timeout}。本文不主张新的丢弃算法。系统层的内容是端到端业务期限基准（用业务期限，而非包龄、逐跳 TTL 或估计的单包时延）、零下行的源端安置，以及决定性的跨段一致性——确认耦合使得仅在网关释放并不能释放源端缓存。

\subsection{配置终止：本地门与交付界租约}
\label{sec:mech-lease}
已实现的\textbf{本地时钟门}每拍按本地时钟在夜间（hod $<06{:}00$ 或 $\geq18{:}00$）把采样与上报钳到稀疏，白天不动中心命令，默认关闭且关闭时逐位不变。节点 SoC 能量门是另一条普通对照，未包含在此时钟门实现中。

配置实验在初始化时向各节点本地门写入绝对回退时刻。到期后节点无需下行即可把密采与密报钳回稀疏。这是预置界实验：界没有通过配置命令接收、按版本续约或从在线网关证据视图计算。候选设置使用完整时刻表中的降级时刻，将最后一条黄级义务期限向上对齐到下一备份槽，该槽可能晚于期限，因此不等同于式~\eqref{eq:trelcfg} 的最后可行槽。实验数字作为回退时刻干预保留，不用来证明该公式已经实现。

\subsection{部分可观测投影器}
\label{sec:mech-projector}
编译期中心持有义务表、当前（从不预测）的网络侧中断状态与公开参数；任务表到达时网关只持有它听到过的东西。结构性无回传证书（\stime）仅由槽几何产生，并显式以主回传不可用为条件，几何本身从不断言中断。到达时刻投影器只在本地位证据能区分各段时给出标注，否则返回 unknown。unknown 感知的中心投影器只在存在明确网络侧字段时输出 unreachable（当前 harness 尚未提供该字段，故输出 unconfirmed），并用算出的能量台账替代一律夜间关停，使真正的能量不可行与保守建议区分开来。

\section{原型与方法}
\label{sec:proto}

全部机制运行在同一个 Python 事件步进仿真器里（60~s 一拍），实现 LoRaWAN Class~A 下行窗口、带版本的双字段配置命令（采样间隔与上报周期作为独立下发字段，跨版本混合配置会被检出）、确认前保留的边缘缓存、最大覆盖备份装包、随机日照与云遮挡、吸收态掉电，以及非预知的分段任务视图门。关闭备份可逐位复现 v1.1 仿真器（五个锚定不变量）；本地门与租约默认关闭。

使用两个受控场景。\textbf{Episode~I} 是 v1.1 清单工作点：$t{=}6$~h 升级到黄级，主回传中断 4--20~h，任务表在 20~h 到达网关，驱动前沿、归因、记录到期、执行位置与真实 agent 结果。\textbf{Episode~II} 是确定性的配置终止场景，除时刻表、中断相位与被扫描的采能外参数相同：为把白天降档放进中断之内，相位 A 取 $t{=}2$~h 升黄级、$t{=}6$~h 会商降级、中断 4--20~h；相位 B 取 $t{=}1$~h 升黄级、$t{=}8$~h 降级、中断 6--22~h；$t{=}12$~h 为日落。Episode~II 是为配置子问题显式构造的受控对照，不构成新的现场主张。节点死亡确定性强健，按种子 0--2 的总数报告；$n{=}3$ 下亚百分点级的平均服务差按不显著处理；种子 6--9 是重复使用的留出确认集，不是未被触碰的测试集。每张图都由登记在册的仓库脚本重新生成，检查套件报 20/20。

\subsection{形成性真实 agent 研究}
\label{sec:eval-agent}
在 Episode~I 中断上实跑 deepseek-flash：无辅助 agent（A0）、带普通待决命令清单的 agent（A0s）、带证书的 agent（A1）各三个种子，另加两个健康链路对照；每 30 分钟一次真实模型调用，每条轨迹 99 次，合计 1089 次决策。各臂共享 harness、合法观测、工具、历史与动作空间。这项研究用于激发并压力测试接口，不用来确立确定性机制。

\textbf{服务与存活（$n{=}3$，噪声大）。}A1 平均服务 0.358，与 0.360 的确定性安全底线持平，死亡 4；A0 为 0.296、死亡 35；A0s 为 0.222、死亡 39；健康链路对照下 A0 为 0.275、死亡 13，A1 为 0.511、死亡 0。逐种子服务区间重叠，故不就服务作显著性判断。实跑 agent 回路未接本地门，因此 A1 在种子 1 的 4 个死亡不由 \S\ref{sec:eval-place} 的确定性结果清除。

\textbf{调用账。}1089 次决策不等于 1089 次成功调用：52 次以解析失败退回 hold，成因是 \texttt{max\_tokens} 把 JSON 截断在字符串中间；412 条记录带有首次尝试的错误，即便重试已经成功，属日志痕迹。逐臂解析失败率为 A0 7.1\%（28/396）、A0s 6.4\%（19/297）、A1 1.3\%（5/396），因此臂间差异混合了输出格式可靠性与任何语义效应。

\textbf{接口故障与对称评分。}观测的 \texttt{link} 字段只承载 LoRa 接入收据（\texttt{n\_heard}），不含回传状态。强制中断窗内 A0/A0s 分别在 36/32 次决策上断言"link 在线、命令可以生效"（A1 在去掉 "uplink-only" 子串造成的分词假阳后为 1 次）。主回传全程中断，因此这是确定性的过度乐观，与无效的密集命令和死亡同时出现。反方向也存在：v4 证书在听到节点数不足全员时断言"控制面未交付"，在主回传实际可用的五个健康链路时刻触发，其中两次发生在 13/14 个节点已经确认密集档之后。此前的"谎报"计数在三处失效：只在命令密集的决策上运行（对以 hold 为主的 A1 是空集）；在健康组上从不运行（零来自初始化）；统计证书提示词自己教会模型的词（这类词出现在 317 次 A1 决策与 0 次 A0/A0s 决策中）。对相同快照离线重放 unknown 感知的 v5 投影器，在缺少网络侧字段时输出 0 条不可达断言，五个健康链路假警报全部变为 unconfirmed，并把 528 次一律夜间关停拆成 189 次真正能量不可行与 339 次建议性（临近黎明的 04:30--06:00 全部属于建议性）。诚实的结论是缺少回传状态信号会产生双向错误。要隔离投影器的任何独立增量，需要一条 matched-capability 臂（拿到同样的常量与启发式但没有投影器）、带显式回传状态字段的端到端 v5 运行，以及跨模型复现，三者均列为后续工作。

\section{相关工作}
\label{sec:related}

\textbf{应急与网络控制中的 LLM。}TopoLLM 把自适应工具学习用于灾后拓扑规划~\cite{topollm}；后续系统让 LLM 调度无人机路径与带宽、塑造 RL 奖励或编排恢复工具，涉及意图对象、预算与时限约束、候选方案检查、局部修复以及有文档的网络管理 API~\cite{icgrestore,ossgpt}。本文对"自然语言转约束"与工具编排都不主张新颖性。这些工作在假定控制路径可达的前提下决定网络资源或组合恢复工具，不处理路径失效之后仍须继续动作的状态，也没有在一段长期的例行监测工作流上维护 unknown 感知的三态状态。Agentic Wi-Fi 同样把 LLM 当作某个另行定义的协调协议的求解器；本文沿用这一顺序：问题在前，agent 可选。

\textbf{调度、新鲜度与能量。}状态模型上最近的先例是带每传感器有界队列、外生到达、有限服务机会与反馈的 LLM 上下文内数据采集调度器~\cite{icldc}；AoI 与能量采集控制，含瞬时电池阈值策略与部分观测采集，处理的是资源片段~\cite{bacinoglu1905,zakeri2311,costa2014pm}；空间链路的超额预订与接触感知转发~\cite{ccsdssabr} 与网络演算界~\cite{leboudec01} 是互补的确定性刻画。联合的采样、传输与能量优化已经确立，本文不作主张；本文的区分在于带 Class~A 生效时延的持久远端配置、分离的接入与主备回传路径，以及控制中断下的终止。一致网络更新研究早已处理逐更新的有效性、依赖关系与安全迁移~\cite{sdnconsistency}；本文沿用这一教训，补充断开且能量受限的边缘情形：已安装更新的自身数据在反向更新到达之前就变得不可交付。

\textbf{包丢弃、DTN 到期与接触。}AoI 管理抢占或丢弃旧更新~\cite{kam2016deadline,krishnan2019multihop}；面向时延的缓冲丢弃已与自适应 ARQ 结合用于视频~\cite{razavivideo}；DTN bundle 协议携带生成时刻的生命期并按 TTL 或相遇丢弃~\cite{dtnarch,iranmaneshdtnqueue,rfc9171}，托管传输~\cite{rfc5050} 把保留责任作为前向交接转移（该机制已从 BPv7 核心迁出）。乡村 LoRa 与低轨卫星系统围绕估计的卫星接触排程并利用网关空间分集~\cite{sateriot}。本文的记录处置就是 BPv7 式到期并给出等价性证明；配置侧评估的是预置回退界的效果。已支持的系统内容是带源端网关跨段一致性的端到端业务期限基准，以及提前本地回退相对日落回退的实测效果。在线推导并安装回退界、相对同信息普通租约的增量仍待验证。

\section{讨论与局限}
\label{sec:disc}

\textbf{范围。}吞吐负结果与资源墙限定在所测策略族与单一工作点，不构成最优解，更好的调度器可能存在。配置实验覆盖两个构造相位，A 相位五个采能水平、B 相位两个。它们支持提前本地回退可以避免时钟门留下的死亡；按报告的死亡与黄级交付总数判据，固定 8~h TTL 在两个相位也成功。候选界使用未来降级时刻并预置，依据安装时刻信息推导、命令传输、续约与版本语义尚未验证。未来才获授权的修订不能进入当前计算。物理参数的更广扫描应在该信息边界闭合后进行。

\textbf{模型简化。}中心确认按同步、不占空口建模，对各队列规则同等有利；实网中网关确认会消耗 Class~A 窗口。Episode~I 期间节点用变更前的公开节奏检验期限，升级后的期限只用于离线记账。单一固定周期任务使按义务索引与按期限索引的记录释放在此重合；多义务或任务版本重叠时，释放必须以该记录最后仍然有效的期限为索引。Episode~II 是配置子问题的受控场景，不是独立的现场测量。

\textbf{agent 证据。}实跑研究为单模型、每臂三个种子、温度 0，逐次运行方差大，且专家信息包存在混杂；它证明的是接口故障与投影器的离线效果，不是独立的 agent 增量。加固后的 harness（逐请求记账、对称评分、unknown 感知投影器与能量台账、默认关闭的本地门与租约）已在仓库中，使 matched-capability、端到端 v5 与跨模型研究可以运行而无需重新争论计量方式；这些结论本文明确不作主张。

\textbf{来源。}有一个标准获取渠道来自文档分享站（高等级文档配低等级复制链），原因是官方站本机 TLS 不可达；条款号由两份独立副本交叉核对，未核实的国际 LoRa 加卫星与厂商线不作为事实。本文没有执行被引系统的实现，也不主张对它们的复现。

\section{结论}
回传失效之后，此前安装的通信状态继续执行，它的终止等不到失效的控制路径。记录携带本地确定的业务期限；标准逐记录到期在源端一致安置，把中断按期交付翻倍，仅在网关抑制会把代价搬到接入段。配置实验显示预置本地回退可以避免日落回退留下的死亡，固定 8~h TTL 在两个相位也成功。交付推导租约仍是候选，其在线知识与安装语义有待验证。证据纪律要求区分已确认结果与未知状态；LLM 是候选控制器之一，形成性实跑研究暴露了把接入收据误读为回传状态的问题。
