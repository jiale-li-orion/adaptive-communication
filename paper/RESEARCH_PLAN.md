# 论文主线与闭环计划

决策日期：2026-09-20。证据基线：`adae80d`。本文负责研究取舍与写作安排；主张状态仍唯一取自 [`results/CLAIMS.md`](../results/CLAIMS.md)，实验口径取自 `spec/`，不在此另建状态表。既往叙事可由该提交恢复。

**优先级更新（`dd4f31a` 后）：Agent 与通信执行仍是主探索方向。** 具体判别见 [AGENT_RESEARCH.md](AGENT_RESEARCH.md)：先检查真实 Agent 轨迹中普通组合未覆盖的损失，再测针对剩余义务的计划修复。R1 反馈预算降为次级模型问题。配置算法已关闭，不构成暂停 Agent 接口研究的依据；后者不以超越最强确定性控制器为统一前置条件。

## 1. 当前选择

论文围绕一个问题展开：**灾前监测的控制回传中断后，已经安装的配置和未确认记录仍继续执行；哪些处置能凭现场证据完成，必须放在哪一层，怎样避免把局部进展当成端到端完成？**

采用通信系统论文路线，题名暂保留 *Local Communication Control for Pre-Disaster Monitoring with Intermittent Backhaul*。技术对象是采集—接入—回传链中的持续执行状态。标准 expiry、TTL、电量门、设备影子、版本控制和强选包器全部作为系统组成与普通对照。现有实验证实了若干组件的效果，尚未证明一个完整 runtime 相对同组件普通组合的独立增益。

当前可以写出的 insight：**完整根因诊断与可执行处置需要不同的信息。** 网关可能无法区分未采与尚未听到，节点仍能依据已知期限停止过期记录重传；中心可能判断应降档，但执行该决定仍需要已经中断的路径。系统设计因此同时检查证据、权限和动作来得及发生的位置。

普通规则反复追平有可解释的结构。已测任务主要由外部给定；配置停止族只有继续/终止两个动作，终止后不再进入密采；本地时钟、电量和预授权回退已覆盖大量判断。记录侧给定期限后，删除同样有直接判据。更复杂的 planner 在这些子问题里没有自动获得额外决策自由度。可探索的差额应来自尚未被单一局部规则解开的实际资源竞争或信息依赖；增加 prompt、状态字段或规则数量本身不会产生它。这个解释只针对上述已测子问题，不排除完整网络里的调度空间。

论文不再依赖“调度空间已被穷尽，所以只能做 runtime”的论证。资源放宽说明资源压力，不能排除同资源下的新策略。C5/C9 的限定负结果使配置停止算法退出主贡献；C10 是语义修正，不承担方法新颖性。任务始终由外部授权，业务分母始终由独立评分器生成。

## 4. 一个尚未覆盖的技术入口：有限反向预算下的保留责任

### R1：数据已交付，不等于源端已经获知可释放

现有 `network.py` 在中心收到样本时同步调用源端 `ack()`；`joint_plane.py` 的集中核销也直接释放源缓存。论文已经把这项零空口、即时反馈列为简化。它使「何时花一份反向机会结束上游重传」没有进入联合系统的资源分配。早期多路径数据 ACK 实验测量的是回执信息用于选路的价值，未测这条源端保留责任与配置下行的物理竞争。

因此，新问题可以保持原业务与设备不变：**在仅上行备用仍能交付数据、有限 Class A 下行还要承载配置的条件下，何时传递哪类收据，才能及时释放上游保留状态，又不挤掉更有价值的配置动作？**

可能的方法是按实际后果分配反向证据：区分接入成功、网关持久接管、中心完成；将能够释放多少仍有效重传、其剩余寿命、可避免的能量/空口，与同一窗口中配置动作的作用比较；到期仍由普通本地 expiry 处理。决策对象是可编码的确认集合与已有配置字段，允许合法捎带和聚合。Agent 提供授权任务与候选动作，确定性通信机制维护保留责任及接收窗口预算。

这项假说尚未实现，也未证明新颖性。它需要声明一个**共同的反馈模型扩展**，冻结当前结果不动；不能将旧模型中免费的动作只向基线收费，也不能新增人为网关故障来迫使托管对照失败。MAC ACK、应用层托管收据和中心交付确认分别定义；应用层释放字段若需固件支持，按系统扩展计入，而非声称现网接口已普遍支持。

### 最近反方与最小进入条件

普通托管本来就能转移保留责任；累计/位图确认及 ACK 调度也已有文献。本轮核查了 [RFC 5050 §5.10–5.11](https://www.rfc-editor.org/rfc/rfc5050.html#section-5.10)、[RFC 9171 的变更说明](https://www.rfc-editor.org/rfc/rfc9171.html#appendix-A)、[A2S2-LoRaWAN 原文](https://www.eurecom.fr/publication/6039/download/sec-publi-6039.pdf) 与 [FREE 摘要](https://arxiv.org/abs/1812.05744)。前两者用于保留责任语义，后两者提醒确认与调度已有成熟研究；涉及 MAC 扩展的方案不能伪装成当前 Class A 的原样实现。

先用来源与现有节点数/报文率确认反向预算会不会绑定；不借用欧洲频段占空比作为中国站点的默认事实。之后只做一个机制判别：

**先做字节与机会账，再实现策略。** 把一次上行所需的累计/位图托管收据、普通配置字段和协议头按允许的编码放进同一下行包，核对现有接收窗口、有效负载和网关空口约束。如果持久网关可以在下一次上行后顺带确认全部新接管数据，并同时容纳配置，立即托管就已消除候选声称的竞争。此时 R1 应关闭，不能人为禁止捎带、增加确认频率或缩小载荷去制造冲突。只有现有部署约束下仍存在未被普通聚合消除的竞争，才进入下列轨迹判别。

1. 全臂共享有成本的真实反馈、同样持久网关、相同配置/数据资源、同样源端 expiry；包含普通及时网关托管、累计/位图 ACK、允许捎带的常规 ACK/配置优先级组合。
2. 找到一条普通组合面临实际取舍的轨迹：立即确认会占掉有益控制机会，延后确认又使有效数据重复占用接入。若窗口足够、标准聚合已消除竞争，立即关闭，不开发求解器。
3. 只有取舍存在，才比较基于剩余重复工作与配置作用的联合选择，报告固定物理预算下服务、空口、能量和确认时延。单纯去掉免费 ACK 后让基线变差不算方法收益；提升必须相对新模型中的最强普通组合。

当前推荐：**V1 的 Agent 计划修复判别优先，R1 作为次级模型入口，V2 保留暂停。** R1 即使失败，也会明确当前源端安置结果对真实反馈的依赖，但无需先完成它才能研究 Agent 的执行接口。

第一份交付只需反馈路径与编码预算表、普通托管/聚合能否覆盖的判定，以及存在竞争时的一条逐事件见证。没有见证就不投入多种子或 Agent 批次。若进入方法阶段，再考虑按一次确认能够避免的剩余有效重传，联合选择确认集合与配置消息；该价值必须从当时合法状态估计，不能使用未来实际交付或真值缓存。当前尚无依据把这一选择称为新算法或预报其收益。

## 5. 已提出但尚未完成的验证

### V1：把执行证据用于动作准入与修复

这是 doc33/doc52 已提出问题的剩余验证项，不作为新发现重命名。现有 v5 projector 改善了输出说明，但尚未隔离它改变实际通信动作的价值。候选应针对一个动作给出：

`所服务的义务 / 证据所在链段与时刻 / 当前已安装效果 / 可执行位置 / 可接受处置及未决项`。

具体区分三种情况：

- 网关已有合格副本，缺口在回传：继续增加采样不能补该条义务的回传缺口。
- 合格副本尚未到网关，仍有可用接入与回传机会：允许既有快报动作；不得仅因缺确认就封锁它。
- 没有足够证据判定原因：保留 unknown，执行已有本地保护，不把 unknown 自动转换为不可达或全局停机。

候选增量只能来自**不同且有效的实际处置**，例如保留有益升级的同时减少持续无效密采、错段重试或错误完成声明。提示更长、解释更准确、解析成功率更高不能替代这些结果。

**最强反方。** 普通组合获得相同合法历史、影子、版本、expiry、本地保护、能量/几何常量和可调用的确定性判断，配常规检查与修复。规则 planner 与同一 Agent 都使用这份底座。公平问题是显式动作契约是否额外改变行为；若普通检查已覆盖，则承认系统集成价值，不宣称新准入算法。

### V2：控制机会与数据机会的联合准入（暂停）

已有 ODP 提供出发点。候选只使用现有采样/上报配置接口与固定备用配额，联合考虑命令所需的 Class A 接收窗口、后续上行以及共享备份槽。时间链必须覆盖命令生效后的数据机会，不能把承载命令的那次上行提前，也不能把最后回传槽的存在当成已经分到字节容量。

现有首次启动延迟对照没有穷尽这一问题，但其小收益与高信令也不支持立即建立大求解器。先对已有差额做一次因果归因，并加入同路径在线安装的普通固定快报与普通事件触发规则。只有出现普通对照未覆盖的服务—成本工作点，或同等服务的实际通信成本下降，才继续构建局部可达性检查。比较同一采样、能源、主备预算和义务分母，不通过资源扩张或降低业务要求产生候选收益。

**退出条件。** 强普通组合覆盖差额，或收益仅来自修复普通基线遗漏的字段去重/固定档位，就结束 V2。该退出只关闭所测问题，不写成整个通信控制空间的定理。

## 6. 论文闭环：三份交付

### A. 组合效应与通信代价——优先于更多算法搜索

固定任务、planner、合法观测、硬件预算和强选包器，对比普通通信栈、同组件普通组合、带 V1 动作契约的组合；做去源端释放、去本地回退、去动作契约的消融。组件对照使用相同默认配置和传输路径。

交付物是一张端到端结果表和一条从证据到物理后果的完整轨迹。分列报告按期服务、缺采/失电、节点能量、上下行实际空口、备用字节、有益动作误拒和完成声明；拒绝于准入的命令不计作已节省的空口。若完整组合与普通组合相同，正文定位为标准机制的系统适配与实证边界，不能靠系统名称制造差额。

### B. 有限迁移与实装成本——决定系统结果有多大适用范围

从既有、已有依据的扰动轴选择少量代表条件，覆盖中断相对昼夜/业务事件的相位、接入仍通或同时中断、采能宽松或受限。保留无中断负对照；事先给出条件集合，不事后挑出有收益的格。不要把所有轴做笛卡尔积，也不要新增任务来源来挽救主张。

报告期限字段/预授权回退所需的固件能力、配置字节与存储，以及本地决策开销。仿真测量、静态字节计数与真实设备测量分开；没有硬件就不声称实装验证。已知同步零空口 ACK、吸收态掉电和合成采能作为适用边界进入正文。

### C. Agent 接入——验证通信机制的消费者

先在一个模型上完成匹配能力的端到端 v5 对照：普通结构化 Agent＋专家规则，与同 Agent＋V1。两臂共用源端 expiry、本地保护、观测字段、工具、解析重试和 token 预算；可靠链路与中断链路同时计分。模型外规则按物理状态核对完成/生效声明，附有益动作误拒，防止“永远 hold”获胜。

新通信优化算法先用固定 planner 隔离机制。Agent 执行接口则可从真实轨迹的可修性清单进入小规模匹配对照，不要求先让规则 planner 超越强普通控制器。跨模型只在第一轮隔离出实际作用后确认。TopoLLM 等相关工作用于框定任务与控制范式；未运行其原始系统时，适配工作流明确标为 adaptation，不称作者系统被复现或证伪。

## 7. 写作与证据映射

| 正文任务 | 使用现有证据 | 本轮写作动作 |
|---|---|---|
| 定义失联后持续执行的通信对象 | C3、C6、场景规范 | 引言用具体失效建立动机，不先证明所有优化无效 |
| 给出处置契约与位置条件 | 现有字段/接口、C7 | 区分确定到期、授权回退、unknown；去掉未经验证的统一配置释放时刻 |
| 证明源端释放的物理后果 | C2、C3 | 保留主表与最新生成数字；突出跨段保留责任 |
| 说明普通保护足够到哪里 | C5、C9 | 配置矩阵与精确停止参照作为边界；不再把租约写作待兑现贡献 |
| 说明证据接口为何有必要 | C4、C7、C8 | 保留局部可判定范围及 Agent 失效；独立增量留给 A/C |
| 说明应用范围 | C1 与模型限制 | 资源反事实作背景刻画，讨论未测边界和部署代价 |

当前最影响投稿判断的缺口是 **A 的同组件比较与 B 的适用范围**。如果要在标题/摘要主张 Agent 效果，则 **C 同样是必需证据**。跨模型数量、更多种子、更多归档检查都不能替代这三个问题。

不再启动 C5/C9/C10 的算法搜索；不扩展灾后 UAV、RIS、自然灾害风险判断或新硬件资源；不把新候选的预期收益写入摘要。下一轮的结束点是一份能决定系统增量归属的证据包，而非又一轮无边界优化。

## 8. 对老师汇报的更新

前期已确认：控制回传中断后，未确认记录与已安装密采配置会继续占用现场资源，本地执行位置直接影响后果。进一步对照发现，普通记录到期、固定 TTL 和电量保护已经覆盖所测单项机制，因此不再把新租约算法作为预期贡献。论文正在围绕通信执行状态、局部处置与证据边界收口；下一步补同组件系统对照和部署代价，并先核实有限反向确认是否带来普通聚合无法消除的资源竞争。Agent 继续作为高层控制器接入，增益将通过同能力端到端对照判定。
