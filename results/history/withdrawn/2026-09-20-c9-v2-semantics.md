# C9 撤回：v2 口径的两处层级/结构错误

日期：2026-09-20。来源提交：`1a36d52`（v2 修正）与 `d813c08`。性质：结论撤回 + 口径重排。

## 撤回了什么

v2 把 C9 的结论表述为"紧能量格在严格口径下无可行策略"，并把它作为该格的实质结论。**撤回**：
这个结论本身在**声明模型内**成立（见下"保留"），但 v2 把"零失电"当成了**任务要求**，
那是层级错误；而且 v2 的"序列优化参照"在结构上是空的。

## 两处错误

**S1 层级错误：把风险口径当任务要求。** 仓库自身的来源不支持"全部未来不得死亡"这一层级：

| 来源 | 要点 |
|---|---|
| `paper/zh/main.tex` 系统模型 | 目标函数计三项：服务、**节点永久死亡**、浪费的资源——死亡是**被计价的项** |
| `paper/zh/main.tex` §执行位置决定存活 | A1 死亡 4、A0 死亡 35、A0s 死亡 39——死亡按臂**报告** |
| `v3joint_r02_restart.json` | 复机后采集 .41→.82；"0 存活主要是吸收态产物" |
| `r47_lease_energy.json` | "不能外推为全部合法稀疏策略的物理不可行" |

v3 因此把风险口径放回参数层（`strict` 只是 α=0 端点），主口径与论文一致：**死亡按次计价**，
报告 `(服务, 死亡概率, λ)`。

**S2 结构错误："序列优化"是空的。** 奖励非负（窗口内 12、窗口外 0）、终止是吸收态且值为 0、
又没有死亡代价时，"继续"恒弱占优，于是 v2 的精确最优**恰好等于**"还能安全多跑一小时就继续"的
贪心可行性规则。已由 `witnesses.degeneracy.strict_mode_equals_greedy_feasibility = true` 直接核对。
v3 用 λ>0（与论文目标函数一致）恢复取舍，那里的最优既不是贪心可行性规则也不是永不终止。

同时 v3 声明本模型是**最优停止**问题而非调度问题：窗口内各小时在目标里彼此可替代，因此"把密集
预算分配到哪些小时"这类问题不在本参照的范围内。

## 保留（没有被这次撤回触动）

* v2 已修好的两处：隐藏终点不得改变执行；等权三点的实际标准差必须等于声明 σ。
* `.012` 格的 strict 结论：全程稀疏在声明低采能未来里最低 −0.0087 mWh，低于 0.47 mWh 安全线，
  临界 σ*=0.0429 < 声明 0.047。**该结论只在 strict 口径内成立**，v3 在结果里给它加了 scope 字段。
* 台账校准（最大偏差 1.13e-4 Wh）、实测负载常数、云遮统计、核例（DP 20.0 = 穷举最优）。
* C1–C8 与 C5 的读数；目录、登记、检查、冻结参考体系。
